# 数据库表一览

系统里有四套数据库：**中心库**（人裁、册配置、字形库、进度）、**任务库**（重跑与性能）、**网站收件箱**（读者在网站上提交的东西）、**目录库**（书目与 book-text 元数据）。这页只讲每张表装什么、怎么用，不写它们存在哪台机器上（以后可能搬）。

读写原则：**表不手工改**。中心库走 `guji db pull / push`，任务库走 `guji pipeline job …`，网站收件箱由网站直写、`guji feedback cellvotes`／`guji feedback opinions` 读，目录库由 book-index 流程建。要直接查表，用只读的读令牌。

## 一、中心库

一个工作区（一部书一个仓）的配置、人裁、字形库和产物登记都在这里。几乎所有表的前两列是 `ws`（工作区）和 `src_path`（它来自仓里哪个文件）；`raw` 是原行文本，`rev` 是写入时的库版本，`row_sha` 是整行指纹——这三样是「逐字节还原回文件」用的，平时不用管。

### 库本身

| 表 | 一行是什么 | 怎么用 |
|---|---|---|
| `db_meta` | 库的键值（schema 版本、当前 rev 等） | `guji db status` 读它判断库是不是最新 |
| `imports` | 一次导入（谁、从哪个提交、rev 从多少到多少、统计） | 追查某批数据是哪次进来的 |
| `changes` | 变更账：每次写一行（哪张表、增删改、主键、改前改后指纹），`rev` 递增 | `guji db pull` 按 rev 增量拉；对账、回滚靠它 |
| `source_files` | 每个源文件的登记（表名、sha、字节数、行数、末尾换行） | 还原文件时核对「还原出来和原文件一样」 |

### 工作区与册

| 表 | 一行是什么 | 怎么用 |
|---|---|---|
| `workspaces` | 一个工作区（`ws`、目录、`workspace.yaml` 原文） | 决定一个工作区下有哪些书、怎么跑 |
| `books` | 工作区里的一部书／一册的配置（`book`、标题、版本、配置文档） | 册配置（开关、钉的语料号、字形库号）的真源，`db push` 推的主要是它 |
| `files` | 整文件原文（`kind`、sha、字节数；大文件正文放对象存储，`body_r2=1`） | 取仓里的清单、语料、配置文件原文 |
| `corpus_files` | 语料文件登记（sha、字节数） | 钉语料号时核对语料文件对不对 |

### 裁定事件与台账

> 「人裁事件」现在叫**裁定事件**：来源不一定是人，也可能是 AI 或规则；用 `level`（`human`／`ai`／`machine`，另有 `model`＝大模型判断、不算落定）区分。

| 表 | 一行是什么 | 怎么用 |
|---|---|---|
| `events` | 一条事件：`stream`（来源流）、`kind`、`actor`、`reviewer`、`ts`、`payload`、`target`（指向哪个格子），以及由原行现算的 `u`（字格永久编号）和 `level`（谁判的） | **裁定的真源**：定字、换图源、网页票落定都写成事件；`guji feedback collect` 落、`guji feedback` 查。事件只追加。`stream` 有 `events`（人与脚本的裁定）、`rulings`（大模型裁定）、`vision`、`uid`（[字格身份账](字格永久编号u与身份账)，每册每页每次切分一行）、`pin_state`（钉的删除与过期）。格级裁定带 `target.anchor.u`，裁定带 `payload.u`。**`u` 只在册内唯一，按它配条目或事件必须带册**；`level` 是按 actor、批次名等推的，不是事件里必有的字段（口径见 manager `doc/数据库/中心库.md`） |
| `verdicts` | 一个判定任务及状态（`task`、`status`、`label_origin`） | 审字任务的进度 |
| `consumed` | 各消费方读到哪一行（`consumer`、`src_line`） | 防重复消费：某个流程处理到哪就记在这 |
| `anchors`、`anchor_patches_meta` | 锚点事件与锚点补丁的元数据 | 版本换了之后把旧人裁「挪」到新格子（rebase）时用 |

### 待审条目与清单

| 表 | 一行是什么 | 怎么用 |
|---|---|---|
| `pending_items` | 一个待审条目的**一个版本**（`item_id`、`ver`、书、册、格号 `cell`、`u`、`state`、`op`、`src`、`why`、`recheck`；整条 JSON 在 `raw`） | **一格一条的待审条目**，只追加：改一次追一行，当前状态是每个 `item_id` 的最后一行。`state` 有 `open`（待审）、`closed`（机器不再判待审）、`resolved`（已有裁定）、`withdrawn`（撤下）。注意 `why` 列是**这次变更的说明**，待审原因码在 `raw` 里 |
| `list_rows` | 清单文件里的一行（`dataset`、书、`name`；`id`、`u` 现算） | `dataset` 分作废的 u（`u_void`）、网站票清单（`web`）、意见（`opinions`）、整章待审单（`proofing`，旧的按章形态）、冻结登记（`freeze`）、候选、台账等 |
| `ai_notes` | AI 对一个格子一轮分析的摘要（`u`、字、置信度、状态、模型，取最后一轮） | **只提示，不是裁定**；网站待审页挂在格上给人看 |
| `file_chunks` | 超大整文件的一块（`src_line`＝块号） | 两张超大的整章待审单放不进单行，切块存，拼回来和原文件逐字节一样 |
| 视图 `pending_current` | 每个条目的最新一行 | 「这册还有几格待审」就数它的 `state='open'` |
| 视图 `voids` | 作废的 u 和被删的钉 | 合成一份查 |
| 视图 `lists`、`batches` | `files` 里 `kind` 为 `list`、`batch` 的行 | 老入口，量不大 |

### 版本、冻结与快照

库里原本为「冻结基线」「cv 版本」「快照」预留的三张表 `freeze_baselines`、`cv_versions`、`snapshots` **一直是空的**，代码也不读写，11-27 已从线上删掉。冻结登记看 `list_rows`（`dataset='freeze'`），快照在对象存储里。

| 表 | 一行是什么 | 怎么用 |
|---|---|---|
| `freeze_baselines`、`cv_versions`、`snapshots` | （11-27 已删） | 不用 |

### 字形库

| 表 | 一行是什么 | 怎么用 |
|---|---|---|
| `glyph_sources` | 一个字形来源（书、册、版本、字体风格、年代、每页列数、每列字数） | 字形属于哪个来源；同来源才好比较 |
| `glyph_instances` | 一个字块实例（页、列、序、框、图块 sha、墨量、标签、标签状态、置信度、Unicode、IDS、保真度） | 字形库的主体：每个切下来的字都是一行 |
| `glyphs` | 一个字条目（刻本标签＋字：状态、已确认数） | 按「这个刻本里这个字」汇总，看字库覆盖 |
| `glyph_exemplars` | 某刻本某字的样例实例（`role`） | 挑给审字页、给识别用的代表刻形 |
| `glyph_admissions` | 实例放行进库的记录（字、依据） | 谁、凭什么把这个实例放进字形库 |
| `glyph_evictions` | 撤库记录（字、原因、时间） | 审出放错的，撤下并留痕 |
| `glyph_approx_labels`、`glyph_approx_clears` | 「近似」标注及其撤销（标签、IDS、审者） | 标「像某字但不是」，撤销也留痕 |
| `glyph_meta` | 字形库的键值 | 字形库版本号等 |

### 进度看板

| 表 | 一行是什么 | 怎么用 |
|---|---|---|
| `progress_section` | 看板的一个分区（标题、负责人、说明、排序） | 看板分栏 |
| `progress_volume` | 一册一行：阶段、文本／标点／实体版本、是否精校、冻结版本、cv 版本、语料号、字形库号、总格数、待审数、裁定数、待审单版本和时间（后两列按目标改成「待审数＋最后变更时间」） | 控制台进度看板的主表（各流程推数） |
| `progress_metric` | 一册某分区下的一个指标（键、标签、数值或文本、单位、写入方） | 看板上的各个数字，由各流程自己写 |
| `progress_meta` | 看板的键值 | 看板自身设置 |

## 二、任务库

重跑与性能的队列，库里用 `jobs` 命名空间。用 `guji pipeline job submit／ls／show` 操作，别直接写表。

| 表 | 一行是什么 | 怎么用 |
|---|---|---|
| `jobs.job` | 一条任务：`kind`、书、`spec`（提交后不改）、`spec_hash`、状态（排队／运行／成功／失败／阻塞／取消／重复）、优先级、依赖、提交人、阶段、进展、重试次数 | 提交与查看；同一册同一时间只许跑一条；`spec_hash` 相同的提交会标重复 |
| `jobs.attempt` | 每领一次单一行：哪个会话、哪台机、租约到几时 | 会话死了租约过期，别的执行方把单收回重排 |
| `jobs.event` | 进展流水（阶段开始／结束／警告／出错），只追加 | `guji pipeline job show` 的时间线 |
| `jobs.result` | 结果：存了哪个包、对比报告、检查数、评测输出 | 看一条任务产出了什么 |
| `jobs.worker` | 执行方登记：名字、心跳、在跑哪条 | 谁在线、空不空闲一眼可见 |
| `jobs.perf_run`、`jobs.perf_step` | 一次整册跑的耗时、每一步的耗时 | `guji pipeline perf` 的统计来源 |
| `jobs.meta` | 任务库的键值（schema 版本） | 升级任务库结构时用 |

## 三、网站收件箱

读者在网站上点的票、提的意见，网站的边缘函数直接写进来，一张表 `web_inbox`，按 `kind` 分：

| 列 | 说明 |
|---|---|
| `kind` + `key` | 主键。同键再写＝覆盖（读者改票） |
| `book` | 书（便于按书读） |
| `value` | 内容（JSON） |
| `ts`、`received_at`、`actor` | 读者提交时间、入库时间、写入方 |
| `seq` | 单调递增的序号，**增量读**靠它（`after=<seq>`） |
| `u` | 虚拟列：精校票、改字意见值里的字格永久编号（册内唯一，其他 kind 为空）；线上已加 |

| `kind` | 装什么 | 谁读 |
|---|---|---|
| `cellreview` | 精校票（单格、按条目两种键） | `guji feedback cellvotes draft`（缺省就读它） |
| `charfix` | 改字意见（`cf` 单字、`cs` 一段、`ce` 专名） | `guji feedback opinions ingest` |
| `thread` | 意见下的表态（`tv`）和回复（`tm`） | 网站公开清单、`opinions ingest` |
| `fixstate` | 整理组对某条意见的处理状态 | 网站公开清单 |
| `pending` | 线上待审单（旧的一章一张整单，太大时切块存；目标由 `pending_items` 一格一条取代） | 网站待审页读它；`guji feedback pending` 往里放 |
| `kv` | 其余网站键值：反馈、成员与邀请、错误上报、限速计数 | 网站自己用；管理员看反馈、成员 |
| `feedback` | 预留 | 暂未启用 |

用法：落定人审结果＝读 `cellreview`／`charfix` → 出草稿 → 写成中心库 `events`，全流程见 [线上待审单与投票](线上待审单与投票)。

## 四、目录库

书目、实体和 book-text 元数据的规范化库（55 张表）。一类记录一张主表，数组对象进明细表，`owner_id + seq` 保序；四类的异名都在 `alt_name`，相关版本／丛书都在 `related_record`；改过名的记录靠 `id_map` 沿链找到现行 ID。

**书目与实体**

| 表 | 装什么 |
|---|---|
| `work`、`book`、`collection` | 作品、版本（一部书的一个本子）、丛书 |
| `person`、`collective`、`publisher`、`office`、`place`、`seal`、`reign`、`entity` | 人物、团体、刻书者、官署、地点、印章、年号，以及实体总表 |
| `authorship` | 谁对哪部作品负什么责任（著、编、注…） |
| `alt_name` | 各类记录的异名、附刻名、实体别名 |
| `related_record`、`work_relation`、`entity_relation` | 相关版本／丛书、作品之间、实体之间的关系 |
| `member_of`、`collection_content` | 书属于哪个丛书、丛书收了什么 |
| `index_entry`、`source_ref`、`description_source` | 索引条目、出处引用、著录依据 |
| `resource`、`resource_group` | 馆藏资源（扫描、数字化链接）及分组 |
| `measure` | 版框、尺寸等量度 |
| `book_provenance`、`book_seal_mark`、`book_base_edition`、`book_location_history` | 递藏源流、钤印、底本、馆藏地变迁 |
| `entity_external_id`、`entity_dates`、`place_history`、`place_history_dynasty`、`person_office`、`person_office_source` | 实体外部 ID、生卒、地名沿革、任官及其出处 |
| `id_map` | 旧 ID → 现行 ID（合并、升格后查现行记录） |
| `build_meta` | 这一版库从哪个提交建出来 |

**book-text 元数据**

| 表 | 装什么 |
|---|---|
| `bt_item`、`bt_version`、`bt_manifest_version` | 一部书的文本条目、它的各个版本、版本清单 |
| `bt_chapter`、`bt_heading`、`bt_section`、`bt_section_work`、`bt_section_alt_title` | 章、标题、整理单位及其对应的作品、别题 |
| `bt_other_source` | 其他来源 |
| `bt_collated` | 整理本 |
| `bt_entity_layer`、`bt_entity_span` | 专名层与专名标注的跨度；视图 `bt_mention` 按条目汇总「某实体在哪出现几次」 |
| `fragment`、`fragment_*`（`based_on`、`collector`、`collector_section`、`piece`、`piece_collector`、`citation`） | 辑佚：辑本、所据、辑者、片段、片段辑者、引文 |

用法：目录库是**查询用**的（专名识别、网站搜索、统计），不回写；要改书目走 book-index 仓的 JSON，建库时自动进表。
