# 4a 待审条目上线

> 属于 [第四步 反馈迭代](第四步-反馈迭代)。现行结构见基准页 [待审条目与裁定事件](https://github.com/open-guji/guji-manager/blob/dev/doc/数据库/待审条目与裁定事件.md)；旧的「整张出单、换单、rev」做法已退役，原文存档在 [doc/archive](https://github.com/open-guji/guji-manager/blob/dev/doc/archive/README.md)。

机器和 AI 判不了的格，每格开一个待审条目，网站按章现拼成待审单，请读者对照原图认字。没有「出一张单、换一张单」这回事：条目各自开、改、关。

## 出包即收尾

**`guji pipeline <管线> <册> -w <工作区> --text-id <书ID>`**：cv 跑完，同一条命令接着 `guji land` 收尾并写回（`--land` 只出计划，`--no-land` 只跑 cv）。标 main 的钩子与 `guji swap run`（批量）走的也是它。收尾做这些：

1. 用新包对账中心库条目：没变不动、变了就地改（先认 `u`，再认图块指纹、格号）、新的开、机器不再判待审的关；已有裁定的格扣掉不开。
2. 变了的格出单格图、传 R2、存条目、`guji db sync --only` 推变了的文件，只发有变的册（串行、等空闲）。
3. 加 `--book-text <检出>`：包放行的字写回 book-text（独立 worktree、`local_check`、推 dev；1.x 册开 PR）。没有裁定的机器改字直接进文本。
4. 每册收完清盘。

旗标和守卫、收尾产物（`reports/<册>/_land/`）见 `guji land --help`；先计划后写：`--text`（只读）→`--text-apply`。

## 网站怎么看到

网站不读整张单。精校页按章取 Worker 的 `/v1/web/pending-doc?book=&vol=`：每个 open 且没落定的条目一格（带 `id`／`ver`／`u`），已落定的格读时扣掉；目录页取 `/v1/web/pending-live-index`。裁定事件进库后下一次读就生效，不等 collect、不等发站。

> 过渡：land 现在还导出一份 `<章>.pending.json`，只因 `proofing-sync` 要靠它找单格图传到 COS；网站读单已经不依赖它。

## 三条规矩

1. **网站只发 book-text main。** dev 上的新章、新 cord 网站看不到：首发后「校对页没有整页图、阅读页没有这一册」多半是只到了 dev。合 main（`scripts/daily_merge.py` 或单开 PR）后触发 kaiyuanguji-web `data.yml`（flow=text，约 40 分钟）；想先看 dev 效果，同一工作流选 target=staging、text_ref=dev。
2. **`guji land` 自己补候选、推库、发站。** 卡片缺格时先跑 `guji audit alt`（`--no-audit-alt` 关）；已发册要候选列表 `cands/1` 用 `guji audit cands <册>` 现算。`--apply` 末尾 `db sync --only`，推不成留 `_land/needs_sync.json`，下次先补推。
3. **主包一天标几次，别每次都追。** 条目是就地对账，追一次不丢票、不丢裁定，但每次都会让读者看到卡片内容变；等本书总览说这批稳了再标 main。

## 首发清单（书或新册第一次上网站，逐项勾）

- [ ] book-text 已合进 **main**，网站数据已重发（规矩 1）。
- [ ] `ops/iiif/pages-books.json` 有这本书各册，iiif 工作流跑完。
- [ ] 该章条目已开（`guji pending ls <册>`），卡片都有候选（`cands` 或过渡的 `alt`／`lib_top`）。
- [ ] 手动触发 proofing-sync（target=production、parts=publish、`only=<书ID>/<册>`）传单格图；workflow 显示 success 不算数。
- [ ] 核线上格数：`https://www.openguji.com/api/pending?book=<书ID>&vol=<章>` 的格数＝该章 open 且没落定的条目数。
- [ ] 打开校对页、阅读页各看一眼。校对页写「这一格没有整页坐标」＝cord 没上线。
- [ ] 冒烟对刚上传的图报 403：CDN 延迟几分钟，等一会儿再核，不是失败。

## 还会遇到的坑

| 坑 | 现象 | 做法 |
|---|---|---|
| 推库慢 | 全量 `db pull/sync` 约 90 秒 | 增量拉推已默认；多册合并同步一次（`swap run` 已按批同步） |
| 推库没成 | 条目只在本机，网站还是旧的 | 看 `_land/needs_sync.json`、`guji db status` 的 unpushed；补 `guji land <册> --apply` |
| 磁盘满 | `No space left on device`，`db sync` 半途失败 | 用完即删；land 默认每册清盘（`--keep-files` 不清），`--disk-report` 看谁占的 |
| 新容器缺件 | PATH 指错 cv、少令牌、book-text 稀疏检出没本书 | `guji feedback swap doctor --fix --env` |
| `db pull` 报本地有改动未推 | 拒绝 pull | 先 `guji db sync --no-glyph`；缺文件被拒（FileDeleteRefused）不要 `--allow-delete`：备份未推文件 → `db pull --force` → 只恢复自己的文件 |
| 网站发布并发互相取消 | 补触发的 run 被 concurrency 取消 | 补触发时加 `only=<书ID>/<册>` |
| 单里有图片格，book-text 拒推 | 校验 F-OV-13：有图没声明 `fig_file` | 导出带 `NNN.fig.json`、声明 `fig_file` |
| 重切后旧票锚不上 | 绑定 status=review，裁定不生效 | 票带 `u`，按 `(书, 册, u)` 跟到现格；u 已作废的票挂起（`moved`）进复审，见 [字格永久编号 u](字格永久编号u与身份账) |
| book-text 工作区不干净 | push 拒绝 | `git checkout -- . && git clean -qfd Book && git pull --rebase origin dev` |
| 用户在备注里说「要改的是前后格」 | 票落到被投的那格 | 按备注改写目标格的裁定，备注原话写进 `payload.note` |
