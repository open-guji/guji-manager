# 第二步　迭代

多册分批（一般 10 册一批），每轮统一冻结、发版、重跑一次，再按待审原因把剩下的格派给四个小步。**初期 b–d 人参与多，数据多了要逐步减少。**

## a 跑 CV 管线

一轮的固定动作：收修复 → 冻结发 cv patch 版 → 钉版本（`guji job precheck`）→ 交任务库 → 取包逐格比对 main → 切分不回退闸、标 main 前硬检查 → 标 main → 收尾 → 按层派活。交单与看结果见 [任务库与重跑](任务库与重跑)，产物包与 main 见 [中心库与产物包](中心库与产物包)。

![任务库](images/job-ls.png)

## b 切分检查与优化

格框对、格号对、配上整理本。`guji seg check／gate／premain` 给出结构列清单；先查根因台账，修法由便宜到贵：公用算法 → 书仓书级代码 → 本书配置 → 单页单列钉子。

## c 少见字入库、OCR 候选

库里无例、少例的字头补上本书刻例：快速审阅单 → 高置信 → 低置信 → 难认字四层页；认不出的字由 OCR、5b 笔画证据出候选。参校本对上字、还没放行的格先过快审分流减量：

![快审分流](images/triage-sheet.png)

## d 形近字处理

同组字（末未木、入人八…）、异体、码位，能靠字形和规则定的由机器定，**不用 AI**；要读文意的留给第三步。同一种刻法被认成几个码位时按组看图定夺：

![按组看图](images/group-view.png)
