# 安装与环境

## 装

guji-manager 依赖 open-guji-cv，**先装 cv 再装 manager**：

```bash
pip install -e <open-guji-cv 检出>            # 或 pip install "open-guji-cv @ git+https://github.com/open-guji/open-guji-cv@dev"
pip install -e ".[dev]"                        # 本仓；要快审分流再加 triage
guji-manager check                             # 核对装着的 cv 与本 manager 的契约是否兼容
```

装好后 manager 的子命令经入口点并进 `guji`，用法不变。0.4 起 `guji` 里只有识别本身的命令在 cv（`pipeline`、`step`、`status`、`export`、`rare`、`variants`、`split`、`binarize` 等），整理流程的命令都由本包提供：`db`、`source`、`store`、`recheck`、`glyphlib`、`rekey-cells`、`promote`、`corpus`、`glyph-db`、`model`、`font`、`products`、`rerun`、`pagekinds`、`cache`、`product`、`perf`、`job`、`events`、`gold`、`batch`、`label-batch`、`eval`、`check`、`groups`、`cards`、`progress`、`collate`、`close-check`、`exit-check`、`audit`、`char-diff`、`exp`、`snap`、`archive`、`release`、`deploy`、`opinions`、`cellvotes`、`freeze`。没装 manager 或版本太旧时 `guji <命令>` 会提示装法；整理脚本开工时会自动装好 manager 的 main。manager 自己的命令走 `guji-manager`（`check`、`pending-stats`、`central-gc`、`triage`）。

**册钉了字形库、模型或语料时，`guji pipeline` 要装了 manager 才跑**（开跑前由 manager 把钉版文件备好，跑完自动存产物包）；临时绕过加 `--no-prep`。控制台（guji-console）经 `guji_manager.console_api` 用两边的东西，所以装控制台也要装 manager。

兼容矩阵见仓里 [COMPAT.md](https://github.com/open-guji/guji-manager/blob/dev/COMPAT.md)：cv 讲的契约版本超出范围时，`guji-manager check` 和所有跑批入口都拒跑。

## 令牌

只写名字，**值不进仓、不进聊天**。

| 名字 | 用途 |
|---|---|
| `GUJI_DATA_TOKEN_READ` | 中心库只读：拉数据、取产物包、读票 |
| `GUJI_DATA_TOKEN_PROD` | 中心库正式写：推库、标 main、重出线上单（写前报条数、等用户点头） |
| `GUJI_DATA_TOKEN_EXP` | 实验分支读写 |
| `GUJI_DATA_TOKEN` | 命令实际读取的变量，现设成上面某一档 |

用最小的一档。云端会话的装法和完整令牌表见 [环境与令牌](https://github.com/open-guji/guji-manager/blob/dev/doc/00-总览/环境与令牌.md)。

## 开发

```bash
pip install -e ".[dev]" && pytest
```

CI 在推送、PR 时跑，另外每天对 cv dev 最新跑一次——cv 改了 manager 用到的内部，第二天就红。
