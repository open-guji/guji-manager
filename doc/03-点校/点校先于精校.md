# 点校先于精校（正式流程，2026-11-08）

> 状态：**正式**（sheldon 11-08 22:01 批准转正，范围限定见下「正式范围」）。sheldon 11-08 定：以后粗校完成（v0.1）后**先点校、再精校**。点校时用 AI 读整段文意，顺带判掉要靠文意才能定的字（日曰、己已巳等），同一遍加标点和专名号，用户只审剩下的字。完整方案、试点数据在 ai-team `domain/文本/点校先于精校/`。

## 正式范围（11-08 转正时定）
- **放行口径（sheldon 11-08 22:19 修订）**：点校过程中**靠文意比较确定下来的字，可以直接放行**——条件：①该格本来就是待审格（机器没有确认）；②判出的字在候选集内；③两路盲读同字且 high，并有文意依据（`why`）；④放行子集金标抽样 0 错才写库。日曰、己已巳折叠组是最典型的一类。
- **不放行、只作提示（`dian`）的**：管线已确认的机器字，AI 凭文意推翻它的（册04 这类 7 格看图全错）；候选外的字；L2 单路意见。
- 官／宮 不同义，绝不归一；宮／宫 按码位表归一。
- **保守起步、逐步放宽**（sheldon 11-08 定）：先按上面最严的条件做；以后按经验和反馈，每增加一类放行条件，须有试点数据和金标 0 错支撑，并记进本节。
- **默认只用 Sonnet**：L1 两路盲读负责放行与标点专名；Opus（L2）不进默认流程，只在需要第二意见时按需开。册04 数据：L2 259 格里 250 与机器字相同，改字 9 格只当提示，另错 168:5:3、129:2:4 两处，没有可见增益。
- L3 联网查证用 Sonnet，但须在能取维基文库正文的环境做；证据只认独立他书，干支推算不能代替原文。
- 必须带机器校验（汉字流＝机器字＋所判字）和单字修复；纯 AI 输出约 41% 的段有 1 字偏差。

## 顺序

```
粗校（v0.1 标 main、册配置冻结）→ 点校（整段读文意：判字＋标点＋专名）→ 精校（只审剩下的字，页上带标点专名和查证备注）
```

## 入口条件（点校）
- 粗校 v0.1 已标 main，册配置冻结：字格序列、图源、cv 版本都固定（标 main 时给点校一份「冻结的 cv 版本＋字格 hash」清单；点校 JSON 写 `base_hash`，变了就报警）。
- 页序正确；页序乱的册先出读序表。
- 冻结册（vol01–03、05）不适用。

## 一遍怎么做
1. **段输入**：按自然段切，≤约 1500 字。需判的格不填机器字，写成 `〔n:日|曰〕`（候选来自字组全集，不标哪个是机器字、哪个是参校字）；`□` 照带不猜。邻字取 ★main 的 `_clf_ctx` 文本（ctx 哈希以 main 键口径为准）。
2. **输出 JSON 分两块**：先 `cells[]`（候选、conf、why），再 `punct`／`entity` 按判定后的字写；low 的格按机器字写并标 `assumed:true`（只存 KV／旁路笔记，**不写进 book-text**）；实体 span 用句内偏移。
3. **只许单字替换**：补□、删衍格等增删格一律不在点校里做，留给精校（A32 分支流程）。

## 多级判读（简单模型先过，不够再升级）
| 级 | 谁读 | 放行 |
|---|---|---|
| L1 | 小模型（Sonnet 级）整段盲读，A（正序）／B（倒序）两路，不读别的文件 | 两路都 high 且同字、字在候选内 |
| L2（按需，非默认） | 强模型（Opus 级）更宽窗口，只凭知识重判，说明是否需联网 | 单路不放行，只作提示 |
| L3 | 联网做史实类交叉验证（维基百科、百科、人物库、书目库、**他书**记载）；**被校勘本书自己的录文（如殿本《總目》提要、《全唐文》本身）不算证据** | 至少一条史实类来源直接给出；每条证据记 URL、原句、`source_kind` |
| L4 | 人审（网站线上人审单） | 人裁永远最高 |

规则：H 类（日曰、己已巳）完全不看整理本，走 fold（`fold_ref_char:false`），不受 `ruling_override_groups` 白名单约束，候选集里不放参校字；文意只认 L2／L3，不认 L1 规则；放行子集金标 0 错才写裁定库；候选外真字（如「白」）不放行，转人审并报字形库、字组。

## 写回
1. 放行字写裁定库：套到 `llm_queue export` 出的问（l、r、ver）再 `import`，键按页内 8 字窗口，**不另起版本号**；没进字组的 N、P、L 类走 `final-review` 的 ctx-m1 键。随后从 `seed_admit` 重放（D 轮）。
2. 标点、专名按判定后的字入 book-text（punct、entity；11-09 起 book-text 只录首选字，`assumed`、候选、待审原因、人裁事件一律不进 book-text，都在 KV），入库**直推 dev**（或先合 main 再让精校从 main 起），避免 index.json 冲突。
3. 每级查证过程写旁路文件 `feedback/notes/<册>.jsonl`（`{group, prompt_ver, ctx:{left,right,hash}, cell, trace:[…]}`，管线不读；#361 起随 `guji db sync` 进中心库）。出单时 `guji_manager.review.dian_trace.dian_for(...)` 摘要成待审单每格 `dian={char, why, refs}`（#362 渲染，只提示不预选）；`sent`（句子带标点专名）由 `sent_export` 生成（#354）。

> 11-09 用户定：book-text 只录首选字，不录 pending_reason、decision.json；待审信息、候选、人裁事件都在 KV（book-text#427，导出见 guji-manager#429）。下面 `sent` 里的 `assumed*` 只在待审单（pending.json／KV 现算）里，不进 book-text。

## `sent` 格式（精校待审单的句子字段，A32/A33/A31 11-08 定稿，#354）
```
sent: [{"t": 句文本（不含标点，一字一格）, "at": "页:列:格"（句首格）, "n": 字数,
        "cells": [每字格号，长度 n], "h": sent_hash(t, cells),
        "assumed_cells": [...可选],
        "marks": [{"kind":"punct","ch":"，","pos":k},           # pos＝标记前的字数 0..n，可表开引号、书名号左半
                  {"kind":"entity","type":…,"start":s,"end":e,"entity_id":…|None,"status":…,
                   "targets":[…]可选,"coarse":…可选,"assumed":bool}]}]
```
- 偏移全部是句内、以字为单位；实体区间 [start,end) 左闭右开。
- 只收含待审格的句子；超过 80 字再按「；」「：」断。
- `h = sha1(t + "\x00" + ",".join(cells))` 取前 12 位十六进制；出单侧与测试共用，句子变了 hash 就变。
- 由 `guji_manager.review.sent_export` 生成；每格 `dian` 由 `dian_trace.dian_for` 摘要，和 `sent` 一起随待审单出。

## 交给精校的是什么
没放行的格进线上人审单：页上带标点专名号句子、点校倾向字（只提示）、各级分析和最多 5 条来源链接。人裁改字仍走 `punct_redo`（日曰这类字一改会动断句，重标量比现在大；`assumed:true` 的句子要复看，据 KV 里点校结果里的 `assumed` 查，不查 book-text）。
