# 按组看图定夺：一组字形一页看全，人一次定口径

> 状态：v1（2026-11-01，全唐文实测后整理；Sheldon 11-01：「对某一组字形找到它所有的图，让我整体判断……这个方法挺好的，效率也很高」）。
> 脚本与页面模板：[`tools/开书/按组看图/`](../../tools/开书/按组看图/)。在开书全流程里属 S13（铺开后每批收尾）里 M 类（码位）的处理，也用于异体单列；见 [开书全流程](开书全流程.md) S13 与第四节第 3 类。

## 一、解决什么问题

管线逐格比对时，**同一种刻法被认成了两个（或几个）码位**：
- 参校本（Kanripo 等）和借来的字形库各有自己的码位习惯，比如书上一律刻「爲」，参校本却写「為」，结果全唐文批 1 里 1,771 格放行成「為」、324 格放行成「爲」；
- 借来的库带着别书的码位表（总目 `codepoints.yaml` 约 95 对），在新书上有的对、有的不对；
- 逐格送审时，人看到的是一格一格的「這個是 X 还是 Y」，看不出它其实是整本书的口径问题，一格格点又慢又会前后不一。

这类问题**不是单格对错，而是全书口径**：一种刻法该落哪个码位。所以不逐格审，而是把一组字各自的样本图并排放在一页上，人看一眼整体定一次，定完写进书级配置，整书重落。

全唐文实测：33 组，Sheldon 一页点完（约 10 分钟），落成 `config/codepoints.yaml` 32 条＋异体登记 3 对；其中 2 组他指定合并到组外第三字（變/𠮓→𬽠、宼/寇→𡨥），模板因此加了「合并到别的字」。

## 二、什么时候用

| 场景 | 组从哪来 | 定完落到哪 |
|---|---|---|
| 码位归一（M 类） | 参考码位表（借来库的书的 `config/codepoints.yaml`）＋手加的对（如 為/爲、既/旣） | `config/codepoints.yaml` |
| 异体单列 | 快审里同一字几格全被标「不对」的字（情、柔、候、簡…），和它的候选码位组成一组 | 统一 → codepoints；分开 → `follow_ref` 异体登记 |
| 形近字组口径 | 字组里两边都大量放行、怀疑是同一刻法的 | 同上；真形近字（己已巳）不进这页，走文意 |

**不进**：要看上下文才能判的（己/已/巳、日/曰，见 [快审减量](快审减量.md)）。这页只看字形。

## 三、步骤（每步：输入 → 做什么 → 验收）

前置：工作区各册已有放行结果（`products/<册>/seed_admit/`，取任务库的包：`guji products pack fetch <册> --label <包名> --force`）。

**1. 找组**（`find_groups.py`，几秒）
- 输入：工作区、参考码位表、手加组、参校本逐列语料（可选，用于统计「整理本」列）。
- 做什么：统计每个字在全部已跑册里的放行格数（只算正文 slot>0、非小注）、参校本出现数；**只留组里至少两个字都有放行格的组**（同一刻法确实被认成了两个码位，才需要人定）；每字随机抽 8 格（种子固定，可复现）。
- 验收：组数合理（全唐文批 1：参考 97 对 → 留 33 组）；`groups.json`、`cells.jsonl` 产出。

**2. 渲图**（`render.py`，在 cv 环境里跑，几分钟）
- 把抽中的格渲成字块（写进工作区 `cache/<册>/char_patch/`）。验收：失败 0；有失败的格换一格重抽。

**3. 出页**（`build_page.py` ＋ `tpl.html`）
- 每格缩成高 72px JPEG 内嵌，整页自包含（33 组约 1.4 MB）。建议列：参考表里有的用参考表方向，没有的（為/爲）看图后用 `--suggest` 给。
- 发布：Artifact，声明 `capabilities: {db: {}}`，集合名缺省 `cp`（同一书再出一页换个名）。
- 验收：本地打开无报错、手机宽 400px 不横滚、每组每字都有图或写明「本书没有认成这个字的格」。

**4. 请人定**（交给人的第 3 类「决定」，一次一页）
- 每组四种选法：统一作组里某字／分开／合并到别的字（填组外字）／「其余按建议」一键填完未点的（要点两下确认）。点过即存（db），刷新不丢。
- 请审单写清：在哪、多少组、约几分钟、定完解锁什么（重落后 M 类待审降多少）、不审时默认怎么办（照参考表）。

**5. 读回并落配置**（`to_codepoints.py`）
- 用 ArtifactData `list` 把集合导成 JSON，转成 codepoints 片段：统一/合并 → 组里其余字「字: 目标字」；分开 → 列为异体登记。
- 分开的写 `config/book_defaults.yaml` 的 `params.seed_admit.follow_ref`，双向，如 `"獵=𤢪,𤢪=獵"`（判据见 cv `seed_admit.follow_ref_decide`）。
- **配置要进中心库**：执行机读的是中心库数据目录 `~/.guji-data/main/<书>/config/`（与 `books/` 同级），不是工作区 git 仓的 `config/`。做法：`guji db pull` → 拷进数据目录 `config/` → `GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD guji db push`。工作区仓可留一份作记录。
- 验收：`load_book('<册>').codepoints` 条数对；`guji db status` 无未推。

**6. 重落与核对**
- `codepoints` 是 `seed_admit` 的书级依赖：任务库各册**从 `seed_admit` 重落**，base 用各册最新包，cv 钉住不变。
- 验收：`human_chars` 检查过（人裁不丢）；`pending-stats` 对比上一轮，M 类应明显降，其他类不涨；抽看几格归一后的字。

## 四、页面模板要点（`tpl.html`）

- 一组一卡：组号、各字、建议；每字一行：码位（U+）、已认格数、整理本处数、8 格原图（悬停显示 册/页/列/字）。
- 选项：每个字一个「统一作 X」、「分开」、「合并到别的字」输入框；建议用虚线框。
- 顶部粘性进度条（已定 n / N）、「只看未定」、「其余按建议」（两次点击确认，不用 `confirm()`）。
- 存储：db 集合，doc id = 组 id，字段 `{chars, choice: unify|split|other, target, at}`；`onSnapshot` 读回，多人/多设备一致；没登录时提示「只留在本页」。
- 明暗两套配色 token、手机宽单列。数据由 `build_page.py` 填进 `/*DATA*/[]` 与 `/*META*/{}`，标题、说明、集合名可换。

## 五、经验

- **建议默认照参考表，但为/爲 这类参考表里没有、而本书大量出现的，一定要看图后单独给建议**（全唐文：书上是「爲」，参校本全写「為」）。
- 人可能要「合并到第三字」（變/𠮓 → 𬽠）：码位表左边两个字都映射到目标字即可，目标字不必在组里。
- 「分开」不是不管：要进异体登记（follow_ref），否则这两形还会在送审里互相拉扯。
- 首交重落前先确认配置真在中心库（全唐文首交 #1848–1858 就因为只推了工作区仓而白跑，撤了重交 #1859–1869）。
- 一页 30–40 组为宜（10 分钟内）；更多就按待审量排序拆两页，大头先定。
