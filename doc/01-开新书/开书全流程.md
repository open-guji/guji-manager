## 一、一页纸总览

### 目标

用户只给 **book ID ＋ 资源**（原图在哪、有没有整理本、想先做哪几册）。Claude 负责把中间所有能自动推进的事做完，推进到 **v0.1**：

| v0.1 的定义 | 怎么核 |
|---|---|
| 全部册的文本线在 book-text 上 0.1.0，`proofing: true` | 粗校 R1–R6（[02 粗校验收标准](../02-粗校/验收标准.md)） |
| 全部册的标点线 0.1.0 | 点校机检六项＋抽样（[04 点校验收标准](../04-点校/验收标准.md)） |
| 全部册的专名线 0.1.0，库无清单已交实体库 | 同上 |
| 待审格已上线网站，由读者投票推进 | 线上单存在、`sprites[]` 齐 |

v0.1 之后的精校（03）、冲 1.0，不在本流程范围内。

### 先行册

不是一册，是 **2–3 册**（理由：一册积累的字形太少，史记册 01 只有约 2,000 个；同一个字在不同册、不同位置能收到更多写法）。挑法：

1. 一册**正文最典型**的（全唐文选了册 04：卷 3–6，204 页，正文 183 页）；
2. 一册**特殊页型最多**的（卷首、序、目录、表、职名、考證多的册）；
3. 可选第三册：书的另一种体裁（史记：本纪／表／书／世家／列传各不同）。

先行册把切分、参照、字形库都磨好，再铺开。铺开时其余册直接套用先行册的册配置模板、套书、格位表脚本和字形库。

|---|---|---|---|

### 开书授权（建议一次给齐，避免全唐文线那种「等一句同意等 7 小时」）

全唐文册 04 的线程里，因为要「点头」而停下的有 4 次：带 `GUJI_ALLOW_NO_EVENTS=1` 续跑（等 43 分钟）、推中心库（等约 7 小时，中间还撞上改工作区 id）、丢 2 条落空人裁（等 51 分钟）、推册配置与语料（这次是用户主动「提前批准了可以推」）。这些都属于**只影响本书、可撤回或可重跑**的动作。建议把它们一次授权：

| 动作 | 建议 | 范围 |
|---|---|---|
| 新书首次 `seed_admit` 带 `GUJI_ALLOW_NO_EVENTS=1` | **授权** | 本书 |
| `guji db push` 本书工作区（册配置、语料、页钉位、格位表、人裁事件、字形库） | **授权**，推前在进度表记条数 | 只限本书工作区 id；不碰别的书、不碰共用 `corpus-base` |
| `guji products pack push`、新册首跑自动标 main | **授权**（标 main 本来就是代码自动做） | 本书 |
| 改切分后人裁落空、需 `GUJI_ALLOW_LOST_HUMAN=1` | **授权，但设上限**：每册 ≤ 20 条且已用缩略图重绑尝试过（S11）；超过上限照旧问 | 本书 |
| 本书套书目录 `books/<套书>/` 里改切分（cv 新规范：只牵动自己这一套就自己判、自己合） | **授权** | 本书套书 |
| book-text 本书新入库 0.1.0 的 PR、标点／专名 0.1.0 的 PR（按 ai-team 规矩自建自审自合） | **授权** | 本书 |
| 合 cv 的 PR | 只授权「只改本书套书目录或只改本书脚本」的；动 `seg/` 原语、Step 壳、`core/seg_set.py`、共用 Step 默认值的不授权 | — |

**永远要单独问的**（红线，不进授权）：改别的书或共用配置（殿本基础配置、`seg/` 原语、语料底库）；书影上网站等对外发布；删除（远端分支、旧产物、旧事件）；改生产、改权限、花钱（L3 文意模型的 token 预算超出约定）；打 1.0 标签、冻结；撤回已推的人裁。

**2026-10-31 用户已同意上表一次给齐。** 授权写进 `开书进度.yaml` 的 `approvals:`，每条标 `scope: standing`（长期）或 `once`（只这一次）。用户说「提前批准了可以推」这类话，记成 `once`，不外推。

## 三、分步清单

每步固定九块：**目的／输入／做什么／产出／自动判定（过关线）／交给人的／失败怎么走／耗时参考／经验**。命令细节链到旧文档，这里不重复。经验条目编号 `E<步>-<序>`。

### 阶段一 资源

#### S1 书目条目（book-index）

- **目的**：先有 ID 再开工；Book 挂好原图资源。
- **输入**：book ID（S0）。
- **做什么**：在 book-index 查 Work／Book（题名异体都要搜：鰲／鳌、須／须、雜／杂）；缺的建、重的并；Book 只挂一个最新原图资源；分类 members 文本插行。命令见 [01 步骤 §1](步骤.md)。
- **产出**：Work、Book 条目，PR 已合。
- **自动判定**：`check_schema.py`、`check_v2.py` 通过；Book 的 `resources` 只有一个原图资源；`page_count` 与原图页数一致（S2 后回填核对）。
- **交给人的**：只有版本选择有歧义时，一张决定卡，带推荐（选善本，理由写进案例页）。
- **失败怎么走**：`gh pr create` 走 GraphQL 被拦 → 用 `gh api repos/<仓>/pulls` REST 建、`PUT .../merge` 合。book-index 仓大，`git pull` 放后台。
- **耗时参考**：书已登记的（全唐文、史记都是）几分钟；新建 30 分钟内。
- **经验**：（空）

#### S2 原图：取得、拆页、登记 R2

- **目的**：R2 有页表，`guji source pull` 能取图。
- **输入**：Commons 文件名／分类，或 IA、馆藏链接。
- **做什么**：取源件（云端直连 Commons 常 429 → 在 cv 仓开一次性 workflow 让 GitHub runner 下载）；对开的拆半叶（`guji source spreads`，或像史记那样按版框找版心一图拆四）；`guji source commons … --dry-run` 核页数后正式登记。细节见 [01 步骤 §2–3](步骤.md)。
- **产出**：R2 `pack/source/pages/<书ID>/<册>/r001.json`；拆页核对图；分册表（哪几个原装册并成一个 cv 册）。
- **自动判定**：
  - 页数 ＝ 预期；Commons sha1 一致；
  - 拆页：标记落在折痕／版心上的比例（机检标记处无墨）；不明显的列出来；
  - 分册边界：每册首页是书名签／卷首（机检：首页墨量、版框有无）。
- **交给人的**：只看机检列出的「折痕不明显」的页，拼一张图一次看完；机检全过不打扰。
- **失败怎么走**：Commons 上没有 → 先传上去（原图以 Commons 为根）；有水印、灰度异常 → 记进 README「这套扫描」一节。
- **耗时参考**：编码＋上传，一册约 850 MB 时十几分钟。
- **策略**：**不必一次登记全书**。先登记先行册＋其后约 10 册，铺开时每次提前登记约 10 册（全唐文 GUJI-749 交接卡的做法：已登记 01–62，共 248 册）。
- **经验**：
  - E2-1 · 2026-10-28 · 全唐文 · 每个 CADAL 件＝原装一册（两卷），首页书名签、末页封底；cv 册＝相邻两个原装册，封面封底不入页表。· 已验证
  - E2-2 · 2026-10-28 · 史记 · 影印本一张 djvu 图是上下两开、每开左右两半叶，按版框找版心一图拆四（a/b 上开右/左，c/d 下开右/左）；书衣、目次等整张不拆；无版框题名叶按墨迹外框裁。· 已验证

#### S3 参校本（整理本）：找、做、记账

- **目的**：给每个格一个「参考答案」。没有它，align_ref、页钉位、快审都没有证据。**与 S2 同时开始找。**
- **输入**：书名、版本；候选来源：book-text 里已有的同作品 Work、Kanripo、殆知阁（含文渊阁阅读器 `sikuquanshu.daizhige.org`）、维基文库、国学大师。
- **做什么**：
  1. 找**逐列整理本**（一行＝一列，带半叶／叶标记，小注分左右）；只有电子全文的也收，但只能走 8-gram 对位；
  2. 同一部书的**另一个版本**也行（字面差异大的地方放行会少）；
  3. 做成语料：照 `make_witness.py`（史记）或全唐文的转法；
  4. 写参校本说明（来源、简繁异体规范化程度、已知与原书不同的地方），放工作区 README 和本书经验文件。
- **产出**：`corpus/<书>_*.txt`；册 yaml `references: [{file, quality: best, label, line_is_column: true}]`；参校本说明。
- **自动判定**：
  - 覆盖：参校本卷数／叶数与原图对得上（全唐文：Kanripo 1,000 卷 → 36.4 万列）；
  - 列字数分布与版式一致（全唐文版式九行二十二字：Kanripo 每行字数多数为 22）；
  - S7 的页钉位能「一一对应、不多不少」。
- **交给人的**：找不到逐列整理本时一张决定卡（接受慢冷启动，还是你另有来源）；多个候选时一页比对图（各抽 20 列对原图），带推荐。
- **失败怎么走**：参校本缺页、缺卷首题行、缺目录页文字 → 不是参校本不能用，而是那些页要另造参照（见 S6、E6-1）。
- **耗时参考**：有现成数据的 1–2 小时。
- **经验**：
  - E3-1 · 10-28 · 全唐文 · Kanripo KR4h0168（book-text Work `d59f2nqla48x`）一行＝一列；转语料去 `#` 标题行、`:zi[..]` 换 `㐀` 占位、去 `<..>` 夹注。后改成带半叶头的 `qtw_kanripo_grid.txt`（钉位要用）。· 已验证
  - E3-2 · 10-30 · 全唐文 · **参校本不一定可靠**：Kanripo 有自己的分行（一行 23 配下一行 21、小注并成一行），目录页文字、卷首「欽定全唐文卷N目錄」没有录入。列字数一致率 ~95% 就是这份参校本的上限，剩下的不是切分错。· 已验证
  - E3-3 · 10-28 · 史记 · 殆知阁文渊阁阅读器 `/data/0243.jsonl`、`0244.jsonl`：每叶带 `djvu` 页号，逐列分大字与小注（`r`/`l`），可直接对 Commons 页表；是光盘电子本不是 OCR，有少量异文。· 已验证
  - E3-4 · 10-28 · 通用 · 整理本把写本／刻本俗字统一成正字，会出现「整理本字 ≠ 原书字」的假不一致；冷启动不一致格多半来自这里。· 已验证（史记）

### 阶段二 工作区与环境

#### S4 工作区仓、中心库、会话环境

- **目的**：工作区进中心库；任何新会话都能在 10 分钟内接着干。
- **输入**：S0 的仓（`guji-workspace/<书ID>-<拼音>`，用户先建并装 App）、S2 页表。
- **做什么**：
  1. 仓根放 `workspace.yaml`（`id: <书ID>`，借库 `glyph_lib.borrow: [siku-zongmu]` 等）、`.gitignore`、`README.md`、`开书进度.yaml`；
  2. `guji db init` → `guji db push`（[01 步骤 §6](步骤.md)）；
  3. 会话环境自检（下面清单），写进 README「新会话怎么起」一节（史记仓的写法是好样板）。
- **新会话环境清单**（每次都要，按全唐文和史记踩过的坑整理）：
  - 开会话就把要用的仓一次挂好：cv、本书工作区仓、guji-manager、book-text（要写时 push 权限）；
  - `env | grep GUJI` 确认有 `GUJI_DATA_TOKEN_READ`／`_PROD`；没有就请协调者开新会话（Project 要选 Default 环境），不请用户配环境；
  - `/opt/guji-venv` 有没有；没有就在 cv 仓 `uv venv` 装 `.[console,torch,dev,datastore,shadow,pdf]`（**缺 shadow 时 seed_admit 拒跑**）；
  - 用本地改过的 cv：`PYTHONPATH=<cv 克隆>`；
  - `guji db pull` 单页 500 → 用 `pull_small.py`（PAGE=100），后台十几分钟；
  - 字体域：`fonts.sh`；生僻字索引：`guji cache pull-rare-index`；
  - 首次 seed_admit 前 `mkdir -p ~/.guji-data/main/<书ID>/feedback/events`；
  - 长任务一律后台＋`scripts/longrun.sh`，**跑一半就 `pack push`**（容器回收会杀进程，磁盘产物保留但会话没了就丢）。
- **产出**：中心库有本书 `workspaces`、`books`；`db status` 干净；仓里 README 有「新会话怎么起」。

#### S6 页型普查与分页型切分

- **目的**：不是一套算法切全书。正文、目录、职名、表、考證、序跋、书衣、印章页、空白页各有各的字数和版式，分开处理（用户 10-30：「职名页、目录页、空白页、签名页……可以有不同的算法」）。
- **输入**：S5 的试跑产物；全册页图。
- **做什么**：
  1. **页型普查**（机检）：按每页列数、每列字数分布、版框形态、与参校本对位率聚类，出页型表 `<册>.页型.tsv`（页号、页型、依据）；
  2. 每种非正文页型取 3–6 页，画叠图（绿框放行、红框未放行）；

  4. 统一处理三类假字：**印章、整列空白、版框细线**一律记空格，不出字（用户 10-31 定）。
- **产出**：页型表；各页型的处理方式；每页型改前／改后叠图。
- **自动判定**（暂定）：

  - 假字三类计数 → 0（机检：框内墨占比极低、扁条形、印章框内）；

- **交给人的**：**每个新页型一张叠图拼图**问一次「切成这样能不能接受」。看过的页型不再问。
- **失败怎么走**：页型本身占比小（如史记年表约 12.7%）而算法要大改 → 先标「另案」，不挡铺开，记入缺口清单。

#### S7 参照语料、页钉位、格位表

- **目的**：让每个格都有一个参考字，而且不靠识别。
- **输入**：S3 语料、S6 页型表。
- **做什么**：

- **产出**：`page_pins.jsonl`、`<书>_layout.jsonl`、册 yaml 改动。
- **自动判定**：

  - 锚定页数（全唐文册 04：钉位前 0/204，钉位后 167/183 正文页；没锚上的 16 页当时都是切分失败页）；

- **交给人的**：无。规则核不过 → Claude 自己换规则；两轮没改善才发决定卡。
- **经验**：
  - E7-2b · 11-01 · 全唐文 · Kanripo 半叶分界错：卷20–34 的 b 头早晚 1–6 行（#376 已修），另有 10 个 b 头偏 7–9 行，是长行（一行 144 字占 6 列）之后少数了；fix_b_heads 只搜 ±6 漏了，改用 check_pb_heads 的 ±30 扫出，册11 p150 看图确认。该类页整页 S3「锚不上」。· 已验证

### 阶段四 字形库冷启动

#### S8 借库首跑

- **目的**：在本书自有字形库为空时，借别家库＋参校本，把能自动放行的格先放出来。
- **输入**：S7 的钉位、格位表；借库（`workspace.yaml` `glyph_lib.borrow`）。
- **做什么**：
  1. **自行库为空 → 先借**：借殿本 `siku-zongmu` 整库（不是只借 `glyphlib-qkp-v1` 那 1,076 例；全唐文拉下来 21,305 个刻例），借来的实例记 `borrowed_human`，只进候选不当铁证；
  2. 同时借参校本（S3）做对位证据；
  3. `guji cache warm` → Step5a 起跑到 `seed_admit`（新书带 `GUJI_ALLOW_NO_EVENTS=1`，在开书授权内）。
- **产出**：先行册第一版放行率。
- **自动判定**（暂定）：
  - 放行 ≥ 60% 才进 S9；低于 20% 说明冷启动办法不对，**不要重跑同一组参数**，回头看借库、钉位、切分哪个没到位（全唐文首跑只用字体域、没借库、没钉位：3.7%，align_ref 0 页锚定）；

- **交给人的**：无。
- **耗时参考**：`cache warm` 全唐文实测每页约 20 秒（文档写 2.4 秒），204 页约 68 分钟；Step5–7 殿本一册约 60 分钟。

#### S9 第一轮快审

- **目的**：让人一眼确认「借库首位字 ＝ 参校本字」的格，作为本书第一批人审字形。
- **输入**：S8 产物。
- **做什么**：`scripts/char_review_sheet.py <ws> <册> out.html --grid 30 --per-char 3` 出审阅页，用 Artifact 发布（db 能力，后台自动存）。出页前先按 [快审减量](快审减量.md) 分流（第一轮没标注时只用规则跳过＋OCR 不一致撤下）。
- **审阅页规矩**（都是用户否决过别的做法后定下的）：
  - 只收两路独立证据一致的格（借库首位字 ＝ 参校本字）；
  - 每字挑 3 个**像素匹配度最高**的格（污渍残块自然排外）；
  - 一页 30 格，一图一字，**默认全对**，只点不对的，方向键翻页；
  - **每翻一页自动存到页面后台**（集合 `review`，文档 `b<册>_p<页>`），不用复制 JSON；
  - **不收要靠文意判断的字**：己／已／巳、日／曰（用户 10-30 定；cv PR #774 草稿让脚本默认排除，合并前要手动排除）。
- **产出**：人审确认事件（`confirm`，`source=char_review`），本书自有字形库第一批字形。
- **取数落库**：`ArtifactData list` 集合 `review` → `pull_char_review.py` → `ingest_char_review.py`（写事件、跑 `glyphdb_admit`），推中心库在授权内。
- **自动判定**：审阅「不对」率 < 2%（全唐文 47/4,136 ＝ 1.1%；史记 13/1,810 ＝ 0.7%）。高于 5% 说明筛选条件有问题，停下查，不出第二轮。
- **交给人的**：审阅页本身（先行册每册约 1–2 小时）。
- **审完怎么续**：**不需要用户说「完成」**。巡检发现后台出现新存档就取数落库；用户只审了一部分也照样落库、重跑（见第五节「部分审完」）。
- **经验**：
  - E9-1 · 10-29 · 全唐文册04 · 4,136 格（1,770 字，138 页）；用户确认 4,089、不对 47；落库重跑后放行 71.6% → **77.2%**。· 已验证
  - E9-2 · 10-28 · 史记册01 · 第一轮 1,797 对、13 不对（61 页）。· 已验证
  - E9-3 · 10-30 · 全唐文 · 第一轮里有 9 格 日／巳／曰 已被用户确认并入库；用户后来说这类判断不了。是否撤回这 9 条**还没定**（见第十节）。

#### S10 重跑与第二轮快审

- **做什么**：`--from glyph_match --force` 重跑（**必须 `--force`**：库变了 5a 只标漂移不自动重跑；借来的条目判 same 会被降成 unsure，所以要人审落进自有库后重跑，同字格才升 same）；再出第二轮 `--unadmitted`（只含参校本有字但还没放行的格，按字分组），**另开一个新 Artifact**（集合不混）。第二轮起用前几轮标注训练模型、`guji-manager triage route` 分流，只把 review 格上页（[快审减量](快审减量.md)）。
- **自动判定**：第二轮格数应 ≤ 第一轮的 20%（全唐文 583/4,136 ＝ 14%，史记 309/1,810 ＝ 17%）。
- **交给人的**：第二轮审阅页，可只审一部分。
- **经验**：
  - E10-1 · 10-30 · 全唐文 · 用户第二轮只审了 13 页（确认 343、不对 47），并说「后面很多是切分有问题」。→ **第二轮里不对的格多半是切分问题，应先修切分（S6/S7）再出第二轮**，别让人审切坏的格。· 已验证

#### S11 改切分后重绑人裁（只要动过 S5–S7 就必做）

- **为什么**：人裁按字位编号存。切分一变（多切少切一格、多认少认一条界行），编号就指向别的字（cv 设计稿 15）。全唐文册 04 改格距后，前两轮快审的 4,432 条人裁**全部**对不上格，被扣回待审；官方补锚只锚上 1,806 条。
- **做什么**：
  1. **改切分前**：备份当时的人裁事件和快审页（快审页里嵌有每格缩略图，是重绑的依据）；

## 四、什么交给人看，什么永远不交

### 只交给人的六类

| 类 | 形式 | 规模上限 |
|---|---|---|
| 1 冷启动快审（S9/S10/S13） | 一页 30 格审阅页，默认全对，后台自动存 | 一次 ≤ 40 分钟，超了拆成几批 |
| 2 新页型「切得行不行」（S5/S6） | 一张叠图拼图，FYI | 每型一次 |
| 3 决定（版本、参校本、方向） | 决定卡，带推荐 | 同一问题只问一次 |
| 3′ 口径（码位归一、异体）（S13） | [按组看图定夺](按组看图定夺.md) 页：一组字各 8 格原图并排，点统一／分开／合并到别的字 | 一页 30–40 组，约 10 分钟 |
| 4 红线动作（第二节） | 点头 | — |
| 5 标点冲突句、专名歧义（S15/S16） | 每册一页 ≤ 30 条 | — |
| 6 P 类只能人审格（S13） | 交精校（网站读者投票），不单独找用户 | — |

### 永远不交给人的

- 机检能判的：版框、闸放行、钉位一一对应、同字验证、列字数；
- 要靠文意判的字（己／已／巳、日／曰等）：走 seed_admit 字组流程（L1 规则、L2 文意头、L3 Claude 复核），判不了的进精校待审单，**不放进快审页**；
- 参校本对不上的格（职名、表、目录、卷首题）：先查为什么对不上、修切分或造参照，不直接交人（史记册 01 的 626 格）；
- 切坏的格：先修切分再出审阅页（E10-1）；
- 印章、空白、版框细线：一律记空，不问。

### 每次发给人之前的自检

1. 这里面还有机检能判的吗？
2. 能压成「一页 ≤ 30 条、默认值、点不对的」吗？
3. 写清了：在哪、多少条、预计几分钟、做完解锁什么、不审时默认怎么办？（runbook S11 的请审单格式）
4. 一次只给一类活。

## 五、「人不用催」机制

用户 10-31 的要求：人不用去催 Claude；Claude 去叫人审该审的，其余持续推进。

### 5.1 三条硬规则

1. **人审永不阻塞全局**。等人时，去推不依赖它的册、页型、步骤（5.3 车道）。
2. **审完自动续上**。审阅页后台一出现新存档就取数落库重跑；用户不用回「完成」。
3. **提醒是 Claude 的事**。按 5.4 的节奏提醒，提醒里带「做完解锁什么、几分钟、链接」。

### 5.3 车道：谁等人，谁不等

| 车道 | 例子 | 被什么挡 |
|---|---|---|
| 册间 | 册 04 等快审，册 05、06 照跑 S5–S8 | 执行机容量 |
| 步间 | 册 04 入库后马上开册 04 的标点，不等全书 | 该册 S14 |
| 页型间 | 正文页等快审时，目录页照做单独切分 | — |
| 准备间 | 等快审时，提前登记下一批原图、准备下一批格位表 | — |
| 书间 | 全唐文、史记各自一条 | 互不依赖 |

全唐文册 04 实测：第一轮快审发出到审完约 17 小时，这段时间里其实可以把册 05、06 跑到 S8。

### 5.4 提醒节奏

**一条汇总，不是一项一条。**内容固定：

```
【全唐文】有 2 件事等你，合计约 35 分钟：
1. 册 05 快审第一轮（30 页，约 30 分钟）→ 审完解锁册 05、06 的铺开。链接…
2. 目录页新页型叠图（1 分钟，FYI，不回也照走）。链接…
已在推进：册 06–08 首跑中；册 04 标点已开。
```

| 触发 | 动作 |
|---|---|
| 新增挡路项 | 合并 30 分钟内的新增，发一条汇总 |
| 只有不挡路的项（FYI） | 搭下一条汇总，或每天最多一条摘要 |
| 挡路项 24 小时没动 | 重发一次，只列挡路项，开头写「现在卡住了：…」 |
| 再 48 小时没动 | 再发一次，写清「已推进了什么、还剩哪条车道在跑」；之后间隔翻倍，最长 7 天一次 |
| 全部车道都被人挡住 | 发「全线待人」：列**单项最短、解锁最多**的那一项 |
| 审完（后台出新存档） | 自动续跑，不发消息；下一条汇总里一行报「已续跑，放行 x%→y%」 |

**部分审完**：用户只审了一部分（全唐文第二轮 13/20 页），审过的立刻落库重跑；剩下的留在队列，下一条汇总里说「还剩 7 页，约 10 分钟，可以不审」。

**默认值**：可撤回的步骤，提醒里写「不回的话 X 小时后按推荐项走」；不可撤回的（第二节红线）绝不默认。

### 5.5 Claude 怎么「醒着」

| 手段 | 用在哪 |
|---|---|
| `send_later`（单次定时唤醒） | 每轮做完给自己约下一次；长任务约在预计完成后；提醒按 5.4 递增 |
| `create_trigger`（周期例程） | 每本书一个「开书巡检」，每天一次（或每 6 小时） |
| 审阅页后台（`ArtifactData`，集合 `review`） | 巡检时读，有新存档就取数落库 |
| `subscribe_pr_activity` | book-text、cv 的 PR 评审与 CI |
| 任务库 `guji_jobs show` | 跑完不通知，只能巡检时查 |

**巡检固定顺序**（写进例程提示词）：
1. 读 `开书进度.yaml`；
2. `guji_jobs show` 查在跑的任务，完成的做对应的自动判定；
3. 读各审阅页后台，有新存档就落库、重跑；
4. 按 5.3 找第一条没被挡的车道推进；
5. 更新进度表，提交到工作区仓；
6. 按 5.4 决定发不发汇总；
7. 约下一次唤醒。

### 5.6 与项目结构的配合

- 每本书一个**常驻线程**（如全唐文现在的交接线程），它是这本书的「开书管家」，持有进度表、负责巡检和提醒；
- 大块的独立工作（某个页型的新算法、一批册的铺开）由管家线程请协调者开子线程，子线程干完把结果写回进度表和经验文件；
- 跨 Project 的事（找 A22/A23/A24）按 ai-team 规矩经协调者，消息四要素：要对方做什么、Jira 卡、何时前、没回的默认。

## 七、经验怎么积累

### 7.1 写在哪

| 内容 | 位置 | 谁写 |
|---|---|---|
| 跨书成立的做法、过关线 | 本文对应步骤 | 复盘时由各书线提升上来 |
| 本书的经验（可能只对本书成立） | `doc/01-开新书/开书经验/<书>.md`，按步骤编号分节 | 各书线各写各的文件，不会冲突 |
| 本书的数据现状（放行率、待审量） | 工作区仓 `开书进度.yaml` 的 `metrics` | 巡检自动写 |
| 某一步工具的坑 | 旧文档该步「常见坑」 | 谁踩到谁写 |

### 7.2 条目格式

`E<步>-<序> · 日期 · 书 · 现象 → 做法 → 效果（带数字） · 状态（已验证／待验证／待做／已过时）`

- 没有数字的经验标「待验证」；
- 一条经验被另一本书再次验证，在条目末尾加「· 史记 10-xx 复现」，两本书都成立的就标「通用」；
- 过时的不删，标「已过时」并写被什么取代。

### 7.3 每册必记的度量（用来比较哪种做法好）

| 指标 | 来源 |
|---|---|
| 放行率（全册、正文页、各页型） | seed_admit |
| 列字数与参校本一致率 | 格位表脚本 |
| 人审格数、人审用时（审阅页记录打开与最后一页的时刻） | 审阅页后台 |
| 介入次数、每次等了多久 | 进度表 `review_queue` 的 `created_at`→`done` |
| 墙钟、纯算时间 | 任务库、longrun 日志 |
| 抽检错放（按通道） | S13 |

### 7.4 复盘节奏

- 每过一道关口（A、B）各复盘一次，写进本书经验文件末尾「复盘」一节；
- 每本书到 v0.1 时，把「通用」条目提升进本文，并校准暂定线；
