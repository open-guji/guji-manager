# 01 开新书：步骤

> 迁自 ai-team `通用/新开一部书.md`。命令里的令牌写环境变量名，不写值。

## 总顺序

| # | 做什么 | 在哪 | 产物 |
|---|---|---|---|
| 1 | 查 Work／Book，缺的建、重的并 | book-index（PR） | Work、Book 条目，Book 挂原图资源 |
| 2 | 取源件（原图），对开的拆半叶 | 本地 → `guji source spreads` | 源件文件、拆页表、核对图 |
| 3 | 登记原图：源件存 R2、出页图、发页表 | `guji source commons／ia／register`（正式令牌） | R2 `pack/source/pages/<书id>/<册>/r001.json` |
| 3.5 | 找整理本（逐列），做成语料 | 殆知阁等 → 中心库 `corpus/` | 参校本语料 |
| 4 | 建工作区目录 | guji-workspace（PR） | `<书id>-<书名>/workspace.yaml`、`.gitignore`、README |

## 1. book-index：先有 ID 再开工

- **查**：按书名、别名、作者在 `Work/`、`Book/` 里 grep（题名常有异体：鰲／鳌、須／须、雜／杂，都要搜）；再看 `classification/` 里同类有没有挂。看哪几个是同一作品不同版本、哪几个只是书名像（《幼學須知》宋孫應符本、明《素翁雜字》本都不是这部）。
- **建**：id 用 `.claude/qa/mintid.py` 铸（`--lane <车道>`；车道对应 MachineID，自己的车道没有就在 `LANE_MACHINE` 里加一行，取 2000–2047 里没人用的号，免得同秒撞号）。Work 12 位、Book 10 位；路径分片＝id 末三位（`Book/o/h/s/998a1ukohs-<题名><版本>.json`）。JSON 缩进 2、`ensure_ascii=False`。改完跑 `check_schema.py`、`check_v2.py`。
- **Book 字段**：`edition`、`edition_type`、`dating`（朝代／年号／公元／确信度／依据）、`publication_info`、`page_count`、`provenance`（藏馆＋索书号），`resources` 挂原图。用户要求**只挂一个最新的**（这次是 Commons 全分辨率 PDF），馆方编号（哈佛 DRS、HOLLIS）写进该资源的 `metadata`，不另挂。
- **分类**：`classification/<体系>/members/*.json` 每行一条 `[work_id, source]`，按序插入；**别整文件 json.dump 重写**（会把一行一条的排版冲掉，diff 巨大），用文本插行。
- PR 草稿 → 自审 → 自己合并。`gh pr create` 走 GraphQL 会被拦，用 `gh api repos/<仓>/pulls --input pr.json` 建，`PUT .../merge` 合。

## 2. 原图：Commons 是根

规矩：原图一律以 **Wikimedia Commons** 上的文件为根（Commons 不在就先传上去），R2 只是它的派生存档。

- **取源件**：云会话直连 Commons 常 429，哈佛 DRS／IIIF 403。办法是在 cv 仓开一个一次性 workflow 在 GitHub runner 上下载、作 artifact 传回（这次的 `claude/commons-fetch-yxxz` 分支；用完删分支，见文末「坑」）。同时存一份 Commons imageinfo（`title／url／sha1／size／timestamp／pagecount`）成 `commons.json`，登记时核 sha1。
- **对开拆页**：馆藏扫描常是一开一张图（书衣、封底单页）。`guji source spreads <源件.pdf|.djvu|.zip> --vol 01 --out splits.json --sheet 核对图.png`：在版框上方的天头、下方的地脚里找书脊折痕（那里除了折痕没墨），右半叶记 `a`、左半叶 `b`。**登记前逐张看核对图**（红标要落在折痕上）；折痕不明显的会列出来。
  - 试过不行的判据：版框内列墨点最少、最亮纸带、两条最粗竖线中点——版框贴得近、插图页空白格亮，都会错（详见 `open_guji_cv/datastore/spreads.py` 文件头）。
- **页号**：cv 页号从 1 连续编；拆开的叶得页序 `<叶号4位>a/b`。这部书：1＝书衣（`0001`），叶 L 的 a/b ＝ 2L−2 / 2L−1，126＝封底（`0064`）。

## 3. 登记原图

```bash
export GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD     # 写 R2／页表要正式令牌
guji source commons <书id> 01 --djvu <源件.pdf> --commons-json commons.json \
     --ws <工作区短id> --book <册名> --splits auto \
     --why "<为什么>" --by <你>  --dry-run          # 先 dry-run，看页数对不对，再去掉 --dry-run
```

- `--djvu` 名字是历史遗留，PDF 也收（cv 2026-10-27 起，`pdfimages` 原样抽每页嵌入图，不重压）。`--splits auto` 现找书脊，表和核对图写在源件旁。
- 能连上 Commons 时用 `--file <Commons 文件名>` 直接取；IA 的书用 `guji source ia`；已有原图目录的老书用 `guji source register`。
- 产物：源件存 `source/orig/<书id>/<册>/`，页图按 sha 进正式桶，页表 `pack/source/pages/<书id>/<册>/r001.json`，by-ws 指针。这部书 126 页、PNG 共约 850 MB，编码＋上传要十几分钟。
- 单册书册号也写 `01`（北行日錄同）。

## 3.5 找整理本（参校本）

冷启动靠它：没有整理本，格没有「正确答案」，快审和 align_ref 都没有证据。**在登记原图的同时就要找。**
- 要的是**逐列整理本**：一行＝书里的一列，有半叶／叶标记，双行小注能分左右（我们的格式：`#@ <源>-<id> <叶> h0|h1` 开头，小注 `<右|左>`）。电子全文（不分行）也可以，但只能走 8-gram 对位，没法钉页位。
- 找法：先问用户有没有；殆知阁（`sikuquanshu.daizhige.org/data/<卷>.jsonl`，史记用的 0243／0244）、维基文库、国学大师等；同一部书的**另一个版本**也行，字面差异大的地方放行会少。
- 做成语料：脚本照 `domain/CV/新书登记/史记文渊阁/make_witness.py`；进中心库 `corpus/`，册 yaml 写 `references: [{file, quality: best, line_is_column: true}]`。
- 记下：简繁、异体字规范化程度（会直接影响放行）、与原书不一致的地方（俗字被统一成正字，就会出现整理本「没有」的字形，阶段三的不一致格大多来自这里）。

## 4. 工作区仓（一书一仓，2026-10-30 用户定）

从全唐文起，**每部书自己一个仓**，建在 `guji-workspace` 组织下（`github.com/guji-workspace/<书名拼音>`），**仓根即工作区**，不再往 `open-guji/guji-workspace` 里加目录（那个仓只留已有的老书）。仓名用户先建好；Claude 云会话要先让用户给该组织装 Claude 的 GitHub App（https://github.com/apps/claude/installations/select_target），否则 `add_repo` 只有只读。

仓根只放：`workspace.yaml`（**`id: <book ID>`**——**以后一律用书 ID，不起短 id**，2026-10-30 用户再次强调；全唐文原先用的短 id `qtw` 已改成 `995ejelvk0`）、`.gitignore`（`data_full/ output/ products/ cache/` 等不进 git）、`README.md`（书的来历、版式、坑）。`.central.json` 由 `guji db init` 写。

执行机（`guji_jobs`）：任务 spec 里带 `ws_repo: <owner>/<repo>`（cv PR #761），`rerun_prep.sh --ws-repo` 克隆该仓、仓根当工作区；老书仍走 `ws_glob`。

**改工作区 id 的做法**（全唐文 10-30 走过一次，cv 里没有现成命令）：先让所有人把改动推进旧 id；再在一个事务里复制 `workspaces` 行（`raw`／`doc` 里的 id、`source_files` 里 workspace.yaml 的 sha／bytes 同步改）、把各表 `ws` 外键改到新 id、删旧行；产物包 `products/<旧id>/` 复制到 `products/<新id>/`（manifest 的 `ws`／`name` 要改，tgz 原样）；`by-ws` 指针若有也要复制；最后删旧包。改前备份旧行。

## 5. 册配置

`books/<册>.yaml` 最少：`id`、`title`、`edition: keben`、`raw_dir: data_full/<册>`、`raw_pattern: "{page}.png"`、`expected_cols`、`chars_per_line`、`dev_set`。其余（`leaf_layout`、`period_prior`、`bottom_gap`、`top_band_frac`、`column_grid`、`font`…）都是**本书实测**才能写的先验，字段说明在 cv `open_guji_cv/core/book.py` 的 `BookSpec` 注释里，北行日錄的 `bxgb.yaml` 是写得最全的样板。**别抄殿本的数**，换书一律重量。
多册的书才用基础配置 `config/book_defaults.yaml`（殿本）；单册书不用。

## 6. 进中心库

中心库原先没有「新建工作区」的路：`db migrate` 要库里已有，`db push` 要先有 `.central-state.json`。cv 2026-10-27 补了 `guji db init`：

```bash
guji db init -w <工作区目录> --dry-run      # 读令牌就够；库里已有同名工作区会拒绝
guji db init -w <工作区目录>                # books/ 等挪进数据目录 $GUJI_DATA_HOME/main/<短id>/，记 rev 0
GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD GUJI_ACTOR=<你> guji db push -w <工作区目录> --dry-run   # 看 workspaces／books 各 insert 1
GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD GUJI_ACTOR=<你> guji db push -w <工作区目录>
guji db status -w <工作区目录>              # behind 0、unpushed []
```

之后册 yaml 改在数据目录里（`$GUJI_DATA_HOME/main/<短id>/books/<册>.yaml`），改完 `guji db push`。别的机器：克隆 guji-workspace 后 `guji db pull -w <目录>`。

## 7–8. 取图、试跑

```bash
guji source pull <册> -w <工作区目录>       # 读令牌就够，按页表落到 raw_dir
guji pipeline keben_body_v2 <册> -w <工作区目录> --pages dev_set --to border_detect --no-pack
```

`--no-pack`：试跑不存产物包。看 `products/<册>/border_detect_gate/p*.json` 的 `admitted／reject／flags`，再把 `border_detect/p*.json` 的版框、界行画到原图上逐页看。

**这部书的试跑结论**（叶 10、叶 30 各两个半叶）：
- 版框上下边基本找得到；
- **没有界行**（坊刻，列靠字距分开），Step1 只能拿文字缝凑竖线，竖线穿字，p18 探出 8 列被闸拦；
- **鰲頭两栏**：多数叶上栏是插图配大字或另起一段，下栏是正文，竖线从上栏一路穿到下栏；
- 大字正文夹双行小注、字号不一，`expected_cols／chars_per_line` 这种整册常量对它不成立。
现有 `keben_body_v2` 跑不了这部书。要跑得先在 cv 补：无界行的分列（按字缝，类似现代链 `line_detect`）、上下栏分开（Step0 `page_split` 只有影印本那种「两栏是两页」的 `two_rows_hline`，鰲頭的两栏是两路文字，读序要另定）、大小字混排。这是 CV 需求，不是配置能调好的。

### 版式和已有书一样怎么办
《史記》文淵閣本与《欽定四庫全書總目》武英殿刻本版式基本一样（满页 8 列、每列约 21 字、双行小注），所以直接沿用 `config/book_defaults.yaml` 里的殿本配置就能跑，**不用重新定义切分**，只改册 yaml 里的 `id／title／raw_dir`。判断办法：试跑 dev_set 的 Step1–4，看叠图列线是否落在字缝、版框是否包住全文。
**版式不一样**（无界行、双栏、字号不一，如《幼學須知》鰲頭本）：`keben_body_v2` 跑不了，要先在 cv 补切分（这是 CV 需求，不是配置能调的），本阶段到「叠图人看过、写明哪里不行」为止。

## 9. 阶段三：字形库冷启动（简要，详见专文）

1. 逐列整理本进中心库（`guji corpus init`，册 yaml `references:`）；
2. 页钉位（`scripts/make_page_pins.py`）：先确定「我们的页 ↔ 整理本半叶」的规则并核到「一一对应、不多不少」；
3. 借别家字形库（`workspace.yaml` 的 `glyph_lib.borrow`）跑 Step5a 匹配；
4. 借库首位字 ＝ 整理本字的格，出快审页（一页 30 格、一图一字、默认全对、点不对的），用户审完**自动存页面后台**（db 能力），我们用 `ArtifactData` 取、`pull_char_review.py` 合并、`ingest_char_review.py` 落库，**不再粘贴 JSON**；
5. `--from glyph_match --force` 重跑，把其余格由 5a 像素验掉，未放行的再出第二轮快审；
6. 推中心库（先报条数，等用户点头）。

## 10. 之后（这次没走到，按需）

- **语料、整理本**：`guji corpus init`、册 yaml `corpus:`、`references:`（证人）。没有整理本的书，align_ref 一路没有证据。
- **字形库**：新书的刻例与殿本字形不同，`glyph_pin` 怎么定要和 CV 组商量。**冷启动的做法（整理本钉位 ＋ 字形快审表）见 [冷启动快审流程](冷启动快审流程.md)**（史记文渊阁已走通）。
