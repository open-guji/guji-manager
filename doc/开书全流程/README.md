> 状态：框架 v0（2026-10-31，用户要求，全唐文线与史记文渊阁线起草）。**这是活文档**：两条线（全唐文 `995ejelvk0`、史记文渊阁 `988g3f0wsu`）和以后的新书，各自往清单每一步的「经验」区填东西。

## 目标

用户只给：**book ID ＋ 资源**（原图在哪、有没有整理本／参校本、想先做哪几册）。
Claude 负责：把中间所有能自动推进的事推进到 **v0.1**（粗校入库 0.1.0，标点线、专名线各 0.1.0）；**只把真正要人看的字交给人**，并且由流程**主动提醒人审**，人不用催。

## 总览（一条线上的状态机）

```
S0 立项 → S1 书目 → S2 原图 → S3 参校本 → S4 工作区仓+中心库 → S5 册配置/量版式
   → S6 页型与特殊页切分 → S7 参照语料/页钉位/格位表 → S8 字形库冷启动
   ══ 关口 A：先行册（2–3 册）达标 ══
   → S9 铺开整书粗校 → S10 入库 0.1.0
   → S11 标点 → S12 专名 ══ 关口 B：v0.1 ══ → S13 复盘回填
```

- **先行册**：先挑 2–3 册（含正文册、含目录／表等特殊页多的册）走完 S5–S8，关口 A 过了再铺开。理由见 [冷启动快审流程](../01-开新书/冷启动快审流程.md)（一册积累字形太少）。
- **车道并行**：S11 标点、S12 专名不必等整书粗校完；某册 S10 入库后即可开始该册的 S11／S12。同一时刻哪些步骤能并行，见清单「依赖」行。
- **关口**：每道关口有机检的达标线，达标由 Claude 自己判，不用问人；不达标自己回到前面的步骤找原因，**连续两轮没改善**才发人审队列，提「请你定方向」。

## 约定

1. **书 ID 即一切的名字**：工作区 id、仓名前缀都用书 ID（2026-10-30 用户定）。仓名 `guji-workspace/<书ID>-<拼音>`，例 `guji-workspace/995ejelvk0-quan-tang-wen`。
2. **每部书一个仓**，仓根即工作区；用户先建仓并给该组织装 Claude 的 GitHub App，Claude 才能 `add_repo` 写入（见 [步骤 §4](../01-开新书/步骤.md)）。
3. **写中心库／推产物包前要用户点头**，除非用户已提前批准那一批（例：「提前批准了可以推」只管那一次）。人审队列里这类项标 `kind: approval`。
4. **一个坑只写一次**：踩到新坑，写进**自己这本书的经验文件**对应步骤节（编号 `E<步>-<序>`；两条线各改各的文件，不会冲突；清单里的条目是起草时放的种子）；若是跨书通用的，在经验区标 `通用`，复盘（S13）时提升进该步骤的主体文字或旧文档的「常见坑」。
5. **经验条目格式**：`E<步>-<序> · 日期 · 书 · 现象 → 做法 → 效果（数字） · 状态（已验证／待验证／已过时）`。没有数字的经验要标待验证。
6. 公开仓：不写令牌、密码、内部地址。
