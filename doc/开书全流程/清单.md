# 开书清单 S0–S13

> 每步六块：**输入 / 产出 / 自动判定（机检过关线）/ 要人审什么 / 依赖 / 经验**。
> 「自动判定」是 Claude 自己能验的；写了过关线就不用问人。「要人审」只写**自动验不掉**的东西；写「无」就是整步不打扰人。
> 命令细节见链接的旧文档，这里不重复。经验区的条目由各书线往下追加（格式见 [README 约定 5](README.md)）。
> 人审项统一进 [人审队列](人不用催机制.md)，字段名（`kind` 等）与那边一致。

## S0 立项

- **输入**：book ID；用户给的资源线索（扫描本链接、有无整理本、优先册）。
- **产出**：工作区仓根的 `开书进度.yaml`（[模板](进度表模板.md)），登记书名、版本、册数、各步状态 `todo`。
- **自动判定**：book ID 在 book-index 查得到 Work／Book；仓 `guji-workspace/<书ID>-<拼音>` 存在且 Claude 有写权限（`add_repo access=push` 成功）。
- **要人审**：仓没建 / 没装 GitHub App → 一条 `kind: action`（附 [装 App 链接](https://github.com/apps/claude/installations/select_target)），**其余步骤不等它**，S1–S3 的调研先做。
- **依赖**：无。
- **经验**：
  - E0-1 · 2026-10-30 · 通用 · 书 ID 起工作区 id，不起短 id；起了短 id 的要迁（全唐文 `qtw` → `995ejelvk0`，迁移做法见 [步骤 §4](../01-开新书/步骤.md)）。状态：已验证。

- **输入**：书名、版本说明。

- **自动判定**：`check_schema.py`、`check_v2.py` 通过；PR 已合。
- **要人审**：版本选择有歧义（多个扫描本、多个版本）→ 一条 `kind: decision`，Claude 带推荐项（选善本）。无歧义则不打扰。
- **依赖**：S0。
- **经验**：命令与坑见 [步骤 §1](../01-开新书/步骤.md)。（空）

## S2 原图：取得、拆页、登记

## S3 参校本（整理本）：找、做、记账

- **输入**：书名、版本；殆知阁、维基文库、Kanripo（`book-text` 里已有 Work 的优先）等候选。
- **产出**：逐列语料（一行＝一列，有半叶头，小注 `<右|左>`）；一份**参校本说明**写进经验区或 README：来源、简繁／异体规范化程度、与原书的已知差异。
- **自动判定**：语料行数／字数与原图册页数、每列预期字数大致吻合（偏差大于 10% 的册标红）；能做 S7 页钉位的**一一对应校验**（多一个少一个都算不过）。
- **要人审**：
  - 找不到逐列整理本、只有电子全文 → `kind: decision`：接受「只能 8-gram 对位、冷启动更慢」，还是用户另有来源。
  - 同书多个候选整理本、质量不明 → Claude 抽 20 列对原图，出一页比对图，**让人选一个**。
- **依赖**：S1。可与 S2 并行。**越早找越好**，没有它 S7、S8 的冷启动都没有证据。
- **经验**：
  - E3-1 · 2026-10-28 · 全唐文 · 参校本选 Kanripo KR4h0168（book-text Work `d59f2nqla48x`，一行＝一列）；转语料时去 `#` 标题行、`:zi[..]` 换 `㐀` 占位、去 `<..>` 夹注。状态：已验证。
  - E3-2 · 2026-10-30 · 全唐文 · **参校本自己分行与刻本不同**（一行 23／21 字、小注并行）会让列字数对不上，这不是切分错；Kanripo 不一定完全可靠。状态：已验证。
  - E3-3 · 2026-10-28 · 史记 · 参校本取殆知阁 0243／0244.jsonl，用 `make_witness.py` 做成逐列整理本。状态：已验证。

## S5 册配置与量版式

- **输入**：S2 取回的页图；S4 的工作区。
- **产出**：`books/<册>.yaml`（最少：`id title edition raw_dir raw_pattern expected_cols chars_per_line dev_set`，其余是本书实测先验）；试跑叠图。
- **自动判定**：
  1. 先量再写，不抄殿本的数。**真格距**：对若干正文页量列字格的实际间距，与自相关估值比；两者差 >10% 就以实测写 `period_prior`，让 `column_gate` 回落先验。
  2. dev_set 试跑 Step1–4 的闸放行率；列线落在字缝、版框包住全文的页占比（机检：版框内外墨量、列线是否穿字）。
  3. 过关线（暂定，各书线按实测改）：dev_set 正文页闸放行 ≥ 90%；切分失败列 ≈ 0。
- **要人审**：叠图抽样 6 张拼成一页给人看一眼——「版式能不能这么切」。机检过关则**只发 FYI，不阻塞**（详见机制的「FYI 与阻塞」）。版式不适配（无界行、双栏等）→ 写成 CV 需求，`kind: decision`「是否值得先补算法还是换一册」。
- **依赖**：S4。
- **经验**：
  - E5-1 · 2026-10-30 · 全唐文册04 · 自相关把页级 period 估成 159（字少的页更离谱：82／79／102），真格距约 205px（一列 22 字占满约 4580px 版框）。册 yaml 写 `period_prior: 205`；`period_prior_tol`（缺省 0.10）让偏离的页回落先验。**切分失败列 170→0**。**其他册先量真格距再写。** 状态：已验证。
  - E5-2 · 2026-10-30 · 通用 · 版式和已有书一样的（史记文渊阁与殿本）直接沿用 `config/book_defaults.yaml`，只改 `id／title／raw_dir`；不一样的先看 [步骤 §8 末段](../01-开新书/步骤.md)。状态：已验证。
  - E5-3 · 2026-10-30 · 全唐文册04 · `frame_bar_strategy: border_line` 试过：放行持平、格边有墨 555→471，末格下框线仍留在字块里，但末格放行率本来就 96%，不影响。**结论：不值得默认开。** 状态：已验证。

## S6 页型识别与特殊页单独切分

- **输入**：S5 的试跑结果、全册页图。
- **产出**：页型表（正文／目录／表／考證／序跋／书衣封底／印章页…）；每个**非正文页型**一套单独的切分设置或算法，叠图。
- **自动判定**：
  - 页型分类：按「每页列数、字数、与参校本的对位率」聚类，把闸放行率明显低的页型列出来。
  - 各页型过关线：放行 ≥ 90%（目录页）；空白列／印章／版框细线不被框成字（机检：框内无墨比例、扁条形状）。
- **要人审**：**一张拼图看一个页型**（每型 3–6 页，已放行绿框／未放行红框叠图），问「切成这样能不能接受」。人只看新页型，已通过的页型不再看。
- **依赖**：S5。
- **经验**：
  - E6-1 · 2026-10-31 · 全唐文册04 目录页 · 目录页版式不同于正文，**要单独切**。做法：用 Kanripo 正文里的篇题给目录页**造参照文本**（每列识别出的字去本卷正文找最像的篇题；150 多列配上 133 列；跨两列的长题按图上字数拆；卷首「欽定全唐文卷N目錄」Kanripo 里没有，按图补）；再用这份参照生成目录页**格位表**去掉列端假字。
  - E6-2 · 2026-10-31 · 全唐文册04 目录页 · **三类假字要统一记成空格**：印章被切成格（第 1、204 页）、整列空白被框、版框细线被框。格位表里：版框扁条算假字、只有假字的列记空列、印章列跳过、列与参照按序对齐。放行：目录页 94.4%，全册 97.3%。
  - E6-3 · 2026-10-31 · 全唐文册04 目录页 · **短篇题**（如「遺誥」）因识别全错（认成「遣詰」）配不上参照，细线仍被框。补短题参照后目录页 96.7%、全册 97.4%；个别配不上的**手工按图补**（Kanripo 正文里查得到的篇题）。状态：已验证（册04）。
  - E6-4 · 2026-10-30 · 史记 · 被闸拦的是**年表页**（十表，横竖交叉格线，约 12.7%）和**考證页**（每半叶行数不足八行），要另做页型判别或放行规则，不是配置能调。状态：待做。

## S7 参照语料、页钉位、格位表

- **输入**：S3 语料、S6 页型。
- **产出**：册 yaml `references:`（`quality: best, line_is_column: true`）；页钉位表 `corpus/page_pins.jsonl`；逐列格位表 `corpus/<书>_layout.jsonl`（册 yaml `params.row_segment.layout_prior` 指它）；语料进中心库（`guji corpus init`）。
- **自动判定**：
  - 页钉位：「我们的页 ↔ 整理本半叶」**一一对应、不多不少**（先对 3–4 个开，写脚本全书核对）；钉了也对不上的页用 `pin_min_equal_frac`（0.15）兜底，不出标签。
  - 格位表：列字数与参考本一致率；册04 从 77.1% → 94.8%。过关线暂定 ≥ 90%。
  - 对位：`align_ref` 锚定页数；原先锚上的页要与钉位结果**逐格一致**（册01：2,261 格 0 不一致）。
- **要人审**：无。规则对不上（钉位核对不过）→ Claude 先自己换规则，两轮没改善才发 `kind: decision`。
- **依赖**：S3、S6。
- **经验**：
  - E7-1 · 2026-10-30 · 全唐文册04 · 格位表脚本 `make_qtw_layout.py`：有字格＋Kanripo 每行字数，**去列端孤立格**（版框横线被切成字，比参照多 1 格），字数对上才出行，含夹注的列不出。**可复用，但要先确认页钉位表。** 状态：已验证。
  - E7-2 · 2026-10-28 · 史记 · 页↔半叶规则：册内第 k 页＝拆页表第 k 行；djvu 一叶分上开 a／b、下开 c／d；殆知阁半叶头 id ＝ `4·(L−5)+下开`。**别书要重新核**。状态：已验证（仅史记）。
  - E7-3 · 2026-10-30 · 史记 · 诗页每列切 22 格而参校本 21 字（多一个 `-1` 槽）；双行小注页格数几何对不上，坐标对位整列放弃。修法是让坐标对位允许多一格／少一格。状态：待做。

## S8 字形库冷启动

- **输入**：S7 的钉位／格位表；一个**借来的字形库**（`workspace.yaml` `glyph_lib.borrow`）。
- **产出**：该书自有字形库初始人审字形（几百到几千）；`--from glyph_match --force` 重跑后的放行率。
- **自动判定**：
  1. **自行库为空时借参照**：自有库空 → 借别家库（殿本 `glyphlib-qkp-v1` 等；史记走的是这条）；借来的库认不了本书字体时，改用「参校本钉位 ＋ 人工快审种子」或版面位置锚定（全唐文册04 首跑卡在这里，最终靠参校本格位表＋快审人裁补上，见下 E8-1／E8-2）；
  2. 借库首位字 ＝ 参校本字的格，**两路独立证据一致**，自动列为快审候选；
  3. 5a 像素匹配 cov ≥ 0.996 判 `same`，**只有借来的条目判 same 会被降成 unsure**，所以人审落进自有库后必须 `--force` 重跑；
  4. 过关线（暂定）：放行 ≥ 90%，快审抽样不对率 < 2%。
- **要人审（只交这两类字）**：
  - **快审页**：一页 30 格、一图一字、默认全对，只点不对的；每字抽 3 个**像素匹配度最高**的格（污渍残块自然排外）。
  - **第二轮**：重跑后「参校本有字但还没放行」的格，按字分组（`--unadmitted`）。
  - **不放进快审页的格**：需靠文意判断的字对（**己／已／巳、日／曰** 这类，2026-10-30 用户定），这类走精校（S10 之后的 03 精校），不占快审名额。
  - 这些快审页**自动存到页面后台（db 能力）**，不用粘 JSON；每翻一页一存。Claude 用 `ArtifactData` 取，跑 `pull_char_review.py` → `ingest_char_review.py`。
- **依赖**：S7。
- **经验**：
  - E8-1 · 2026-10-28 · 全唐文册04 · **首跑结果**：seed_admit 放行 3.7%（1229/32819），align_ref 0 页锚定。原因：字形库只有字体域（`font:jigmo`、`font:iming`），没有任何全唐文刻例，glyph_match 候选全是噪声（cov≈0.76）。**动手前先定冷启动办法**（借殿本库／人工标种子页／版面位置锚定），不要重跑同一组参数。状态：已验证。
  - E8-2 · 2026-10-30 · 全唐文册04 · 切分改后前两轮快审的 4432 条人裁全部落空（没入字形库图块，官方补锚只锚上 1806）。办法：用快审 HTML 里嵌的缩略字块与现格字块比 NCC（`thumb_rebind.py`），锚上 4283 条，与参校本同字 4257、不同 1，写进 `feedback/anchors/04.jsonl`（source `backfill:review_thumb`）。放行 87.3%→95.1%（正文页 97.3%）。**教训：改切分前先备份人裁与快审页，改切分后第一件事就是重绑锚。** 状态：已验证。
  - E8-3 · 2026-10-30 · 全唐文册04 · 落空的 4 条人裁用户同意丢（`GUJI_ALLOW_LOST_HUMAN=1`）。**丢人裁要点头。**
  - E8-4 · 2026-10-30 · 全唐文册04 · 剩下 877 格抽 40 看，切分都对，是字形库没把握（606）和库里没有的字（149）。结论：靠下一轮快审补字例，不再调切分。
  - E8-5 · 2026-10-28 · 史记册01 · 两轮实测：第一轮快审 1,797 格对、13 格不对（61 页）；重跑后第二轮 309 格；最终放行 **93.8%**（冷启动前约 65%）。未放行 694 格里 626 格是参校本没有对应字（职名页 231、表／稀疏页 128、正文页 223）。状态：已验证。

## 关口 A：先行册达标（S5–S8 全过）

Claude 自己判，达标线（暂定，两条线实测后改）：

## S9 铺开整书粗校

- **输入**：关口 A 的册配置、字形库、格位表模板。
- **产出**：全册首跑产物包（R2）；每册自动标 main（新册首跑直接标 main，10-25 用户定）；粗校报告与异常表。
- **自动判定**：`guji close-check --tier rough`、collect_exit 取 R1–R6（[验收标准](../02-粗校/验收标准.md)）；每册放行率与先行册的差异 > 5pt 的册标「版式异常」，**回到 S5／S6 补**，不直接交人。
- **要人审**：每册的快审页（沿用 S8 的页型：全书一个 Artifact 集合，按册分页）。**按册分批投放，一批不超过 N 页（默认 ≤ 10 页）**，让人有节奏；批大小由机制配置调整。
- **依赖**：关口 A。册与册之间并行（受执行机容量限制，见任务库）。
- **经验**：
  - E9-1 · 2026-10-28 · 全唐文 · `cache warm` 实测每页约 20 秒（文档写 2.4 秒），整册约 68 分钟；容器重启会杀后台任务，磁盘产物保留。**排期按实测。** 状态：已验证。
  - E9-2 · 2026-10-30 · 通用 · 重跑规范见 [重跑需求与执行规范](../02-粗校/重跑需求与执行规范.md)；小修复攒一批再统一跑。

## S12 专名

- **输入**：标点完成的册。
- **产出**：book-text 专名线 0.1.0；「库无」清单交实体库。

- **依赖**：该册 S11。
