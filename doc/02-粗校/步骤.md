# 02 粗校：步骤

## 一、全流程

| 步 | 做什么 | 命令／文档 | 产出 |
|---|---|---|---|
| 1 立项 | 定册、钉 cv 版本和语料（册 yaml `cv_version`、`corpus`、`glyph_pin`） | [册配置](../参考/册配置.md) | 册 yaml 改动 |
| 2 跑管线 | 任务库提交整册重跑／首跑 | `export GUJI_JOBS_WHO=<你>`；`guji_jobs submit`／`ls`／`show <号>`；规范见 [重跑需求与执行规范](重跑需求与执行规范.md)。跑完**不通知**，自己 `show` 查 | 产物包（R2）、实验记录 |
| 3 出口检查 | `guji close-check --tier rough`、collect_exit 取 R1–R6 | [验收标准](验收标准.md) | 粗校报告、异常表 |
| 4 看图交代 | 页级跳过的页、三道闸失败列、对不上的列逐个看图，写异常表 | — | 异常表（每行有结论） |
| 5 入库 | 导出 char／cord／norm，book-text 开 PR，文本线 0.1.0（或 0.x minor），`proofing: true` | book-text `bump_original.py`、`local_check.py` | book-text PR、CHANGES.md |
| 6 分析 | 待审格分类，定每类归谁 | [待审分类规范](待审分类规范.md) | 分类报告 |
| 7 分流 | 把结论交各组 | 见第四节 | 带数字、样例、卡号的消息 |
| 8 复跑 | 对方改完 → 新需求单 → 重落 → 回到第 3 步 | 第二节 | 前后对比 |

## 二、什么时候重跑、跑多大

- **不是每次有新版本都重跑。** 小修复攒一批再统一跑；预期收益很小的不单独跑。
- 改动只落在 seed_admit（规则、字组、码位、文意表）→ 只从 seed_admit 重落；动了切分或更早的步 → 只重跑受影响页；`guji status` 无过期步 → 不跑。
- 需求单要写：为什么跑、范围、预计收益、起点步（和 `guji status` 对得上）、对比基线。
- **新册首跑**（没有 main 的册）跑完一律直接标 main，已写进代码自动做。
- 重跑完默认直接标 main、推库；标 main 后钩子自动重出线上单（`online_lists`，见 [环境与令牌](../00-总览/环境与令牌.md)）。有 `.punct.json` 的册或旧单已有票的只提示，交精校走 proof_cycle（[03 精校](../03-精校/)）。
- 结果取用：`guji products pack list/fetch` 取同一份继续分析；**分析必须用出单版的包**（按 cv 版本和出单时间对上），否则格号对不上。
- 换图源、整套迁移之类的大批量重跑见 [05 反馈迭代](../05-反馈迭代/) 与 [重跑需求与执行规范](重跑需求与执行规范.md)。

## 三、每轮重落后的分析动作

1. 取出单版产物包 → 跑 `1_dump`／`2_classify`（工具在 ai-team `domain/CV/质检/异体形近送审统计/`，只要读令牌）→ 出总账（四类 × 册）。
2. 对比上一轮：少了多少、少在哪类、新增了什么。
3. 每类写：占比、原因、能否高置信批量处理、证据（`3_sheet` 出图）。
4. 按收益排下一步，分流。
规则：需靠文意区分的字不放行；异体看刻形、形近不同义看文意；能用字组解决的尽量用字组。

四类定义见 [待审分类规范](待审分类规范.md)；遮挡卡的专门处理见 [印章遮挡卡](印章遮挡卡.md)（印章遮挡卡统一走快速确认，不推库）。

## 四、分流表

| 问题 | 交给 | 交什么 | 对方回什么 |
|---|---|---|---|
| 字形库缺字、生僻字识别、模板 | A23 | 字清单、册页格号、整理本字 | 补库／5b 改进，PR 号 |
| 形近字组、文意表缺、护栏 N | A24 | 字组／字对表、带图样例 | cv PR、文意表推库 |
| 对位问题（无整理本对位、对位替换） | A34（或 A23） | 页／列样例、错行类型 | 对位算法改动 |
| 切分系统错（重切清单、seg_defect） | A22 | 页／列清单、看图结论 | cv 修复 PR |
| 精校（人必须细看的格） | A32 | 待审单、数量 | 人裁事件 |
| 要用户定的码位 | 用户 | 带图字对表 | `codepoints.yaml` 决定 |

发现系统性识别错误：记录样例反馈 A22（切分）或 A34（对位／迭代），不要逐个手补。

## 五、入库后
粗校的待审单在网站上线后由精校接手（[03 精校](../03-精校/)）。粗校阶段产生的审阅卡片归粗校负责人，要推动用户点完。
