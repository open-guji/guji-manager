# 降人审迭代框架（执行版）

> 状态：现行（2026-11-05，A31；sheldon 11-05 定）。设计依据与三本书数据：ai-team `domain/CV/质检/迭代降人审框架/新书降人审迭代框架-2026-11-05.md`。
> **范围：只管开书到粗校完成、出 v0.1；精校、点校不在内，只列交接项。**
> 本文管「新书从首跑到人审率 0.1%–0.2%」怎么走；每一轮的细节仍见 [逐轮降人审节奏](逐轮降人审节奏.md)、[重跑需求与执行规范](重跑需求与执行规范.md)、[验收标准](验收标准.md)。

## 一、目标与口径

- **两个数都报**：首审人审率＝待审格 ÷ 全册格（写明包标签、扣 roster/table 页、书衣记 cover）；净人审队列＝扣掉大模型、算法已放的，真正排给人的格。
- **目标分档**：≤0.3% 稳定线；0.2% 目标线；0.1% 挑战线。`hard_pair`（日曰、己已巳）与 `occluded_no_ref` 单列，不混进可压的数。
- **目标按书定**（sheldon 11-05）：上面的分档是参考；清晰、版式简单的书压得更低，不清楚或复杂的书可以更高。R0 开书确认时按体检结果提目标值，用户定，之后可调。
- **速度目标**：终态是一本新书**一天左右**到目标线；眼下先按**约两周一本**，按各部分反馈逐步提速（新版式家族的第一本书另算）。

## 二、五个阶段与出口

| 阶段 | 区间 | 主要手段 | 出口 |
|---|---|---|---|
| S0 开书体检 | — | 试跑 samples 页；参校本体检（错率、半叶分界、脱字、造字→勘误层）；页型抽样；选套书与借库 | 试跑看图通过；`pending-stats` 诊断信号出表 |
| S1 冷启动 | >1% | 本书字样入库（快审页人裁）、glyph_pin、页型标注、stain_pages | ≲1%；常用字本书刻例 15–20 例/字；无整页整列成片错 |
| S2 配置爬降 | 1%→~0.4% | 诊断表对开关：`symbol_ref_blank`、`follow_ref_*`、`vline_overrides`、`row_pitch`、book_knn、码位对照 | 连续两轮收益 <5%（拐点） |
| S3 决策层漏斗 | ~0.4%→~0.2% | 见第三节 | 达目标线，或各层都跑过且收益 <3% |
| S4 收口出 v0.1 | 到本书目标线 | 判停；出 v0.1；交接单：剩余人审格（精校）、H01 极难字清单（列入交接单，不另行通知） | 收口单，用户确认 |

## 三、漏斗：按 pending_reason 走五层

| 层 | 做什么 | 放行条件 |
|---|---|---|
| L0 配置 | 开关、白名单、码位结局、页型 | 回放 0 错 |
| L1 算法 | 文本层取字＋私用码表、book_knn/near_knn、规则（P 取参校本字须两次 high）、切分归因 `seg_causes` | 留出 0 错 |
| L2 大模型只读文意 | 算法给候选（参校本、机器、库前五、解法、组成员），上下文按 `sort_by_reading` 前后 20 字；A/B 两路干净会话；不调 API | 两路都 high 且同字、字在候选里，**且**字形分够（该字在 glyph_match 产物 candidates 前五里的 score，无则 sim；殿本取 ≥0.95，各书按本书人裁金标标定）或 ≥2 个独立来源；越过参校本只放本书白名单组 |
| L3 独立复核 | 放行样本盲读；mid 加第三次读 | 见第五节样本量 |
| L4 人审批量页 | 点选页，预选答案；按杠杆排序 | 人裁；结果回流成库字样、白名单、码位、金标 |

去向对照（`pending_reasons.yaml` 的 route 为准）：Z01–Z05、N01、L02、P01/P02 → L2；R01 → L1 文本层（书没有文本层则 L4）；R02 → `symbol_ref_blank` 后 L4（只读文意不行）；L01、L03、V01、D02、S04、X* → L4；S01–S03 → 先归因再派；L04/L05、D01 → L1；H01 → 留后。

**不用 API**（sheldon 11-05 晚定）：所有要 AI 判的格由对话会话统一审一遍，结果写进裁定缓存，管线重跑只读缓存命中，不在线调模型（原 `group_flow_llm`、ctx_llm/panel 在线层同样改走这条路，代码由 A31 另一 thread 改）。每轮在出清单后、D 轮前做「AI 统一审」。

**大模型不看图放行**：字形侧由算法（字形分、字体渲染分）当图一致证人；大模型看图只用于给人审页预标注。

## 四、两档轮

| 档 | 改动 | 起跑 | 规矩 |
|---|---|---|---|
| D 轮（决策层） | 裁定、白名单、码位、放行规则、字形模型 | `seed_admit` | 不改格号；裁定键为（组、prompt_ver、前后 20 字窗口哈希）且整理本对位字一致才命中，**格号不在键里**，所以重切后仍能命中；裁定不进 Step 指纹，D 轮重跑 seed_admit 必须 force（本机 `--force`）；轮前 A/B 回归、轮后验收 |
| S 轮（结构层） | border_detect、cell_shrink、row_segment、页型、图源、语料、库快照 | 最早受影响步 | 攒批；标 main 前逐册比新旧格号，通知 A23/A30/A20 |

一天的目标形态：体检（0–2h）→ 并行首跑（2–4h）→ 诊断＋A 档配齐＋终审批次并行（4–5h）→ D 轮 1（5–6h）→ 人审批量页（5–7h）→ D 轮 2 标 main（7–8h）→ 需要时 S 轮一次 → 判停。D 轮频率与授权方式待 sheldon 定。

## 五、准确率守则

1. 每书每类维护金标（用户标注，不进提示词）。放行类别金标放 `gold/<书>/<pending_reason>.tsv`（列：cell_id、pack、ctx_hash、pending_reason、label〔字或 @seg/@unreadable/@human〕、labeler、labeled_at、source、note）；5a/5b 等组件评测金标留在 open-guji-dataset，只在 `gold/<书>/_index.yaml` 登记指针（name、kind、path、version、frozen_at、owner、used_for）。
2. 新自动放行类别上线前：金标放行子集 0 错；独立盲读抽样 0 错。样本量：放行 <100 格抽 30；>300 抽 100；>1000 抽 200（0/30 只说明错率上界约 10%）。
3. 有错就收紧（只收与参校本同字、只放白名单组、提高字形分），再测。
4. 放行后每轮滚动抽 30 格。放行字变、人裁丢失 → 停标 main。
5. 越过参校本：按书、按组抽 30 格金标定白名单，不继承别的书。

## 七、判停三问

1. 每类还有没有未跑过的层、或预计收益 ≥10% 的修法？
2. D 轮连续两轮收益 <3%，S 轮 <5%？
3. 净队列 × 点选速度是否在预算内？
都「没有/是/是」→ 出收口单（人审底、留后、精校待办）给用户确认。

## 十、数据与跟踪（每步看什么、在哪算、存哪）

**一处看全**：open-guji.com/admin/text 总览，每本书展开默认是「迭代轮次」页：首审人审率折线（虚线＝本书目标）＋轮次表；「各册」页是分册明细。数据都在中心库 `progress` 表，页面打开时实时读。

| 何时 | 看什么 | 在哪算 | 存哪 |
|---|---|---|---|
| R0 开书 | 体检信号（参校本错率、页型、借库）；**本书目标人审率** | `pending-stats` 诊断表；目标由用户定 | 目标：`progress.metric` rounds/`target`（`iterate push-rounds`）；体检报告进书项目仓 |
| 每轮跑完 | 首审人审率、待审格、全册格 | `guji-manager pending-stats`（线上单）／ai-team `按包统计人审率/run.py`（★包） | 每册：`progress.volume.extra['cv.pack']`（run.py `--push-progress`）；书级本轮：rounds/`r<N>`.value |
| 每轮验收 | 净人审队列、轮收益、回退格、变化最大的 pending_reason、红黄灯 | `iterate round-report`（两份 pending-stats 对比） | report.md 等进 `--out`；书级记录：`round-report … --push-progress <book>` 写 rounds/`r<N>`.detail |
| D 轮放行后 | 各层新放行（L0–L3）、放行抽检错/样本 | 裁定缓存统计＋`iterate audit` 抽检台账 | rounds/`r<N>`.detail `released`、`audit`（`--released-by-layer`、`--audit`） |
| R1–R4 用户审 | 审阅用时、结论（标 main／未采用） | 人工记 | rounds/`r<N>`.detail `human_min`、`verdict` |
| 派单 | 各 pending_reason 分到哪条线 | `pending-stats` 分类 | 报告进 ai-team `A31/待审分类/`；不进后台 |
| S4 收口 | 剩余人审格、交接单（极难字清单） | `round-report` 收口单 | 交接单随 v0.1；最后一轮 rounds 记 verdict=main |

**轮次记录字段**（`progress.metric` section=`rounds`、vol=''、key=`r<N>`，value＝首审人审率小数）：`kind`(S/D)、`date`、`cv`、`pack`、`vols`、`cells`、`pending`、`net_queue`、`gain`、`regress`、`released`{L0..L3}、`audit`{n,err}、`top`[{reason,delta,n}]、`human_min`、`verdict`(main/rejected/pending)、`note`。作废轮也记一条（verdict=rejected），页面上画空心点、不当「比上轮」的基线。

**谁写**：A31 每轮验收后跑 `round-report --push-progress`（各书线有自己的总览线时由它跑，书 id 换成自己的）。历史轮次回填：`iterate push-rounds --json <文件> --write`，三本书 11-05 前的轮次在 ai-team `domain/CV/质检/迭代降人审框架/历史轮次.json`。
