# 逐轮降人审节奏：统一一轮处理、统一重跑、按大头清

> 来源：用户 2026-11-02 转述 A31 在《欽定四庫全書總目》殿本上的做法，并要求史记按此推进。A31 的细节（脚本、数字线）待回信补入，标「待补」。

## 一、核心做法

```
 ┌─▶ ① 各方向各自处理一批问题（半天到一天）
 │   ② 收齐：各方向的改动合 dev、册 yaml 推中心库、跑批分支带齐
 │   ③ 统一发版，统一重跑（任务库，整批册一起）
 │   ④ 用脚本分析剩下的人审是哪些问题（pending-stats，见待审分类规范）
 │   ⑤ 从大头开始，分流给各方向 ─────────────────────────┐
 └────────────────────────────────────────────────────────┘
```

要点：
- **不是改一点跑一点。** 各方向（切分、对位、形近字、遮挡、字形库…）各做各的，攒成一批再统一重跑，对比才分得清、重跑成本才摊得薄。（受控重跑原则「一次只动一个变量」指的是单个方向内部；跨方向的批量见下文「收齐」。）
- **每轮重跑完先分析再动手。** 用 `guji-manager pending-stats --prev 上一份` 出总账，看各类增减，从格数最大的小类开始；不凭印象选题。
- **一轮的节奏约半天到一天。** 太短重跑成本不划算，太长问题堆在一起看不清谁改好了谁改坏了。
- **每轮前后对比照旧**（[验收标准](验收标准.md)：放行字变＝0、人裁没带过来＝0、人审率降且不靠松阈值）。

## 一·五、一本书的线程分工（用户 2026-11-03 定）

每本新书至少分四个会话（线程）：

| 线程 | 管什么 | 例（史记） |
|---|---|---|
| **总览** | 控制一轮一轮：宣布冻结／解冻、维护轮次台账、分派、收齐、对外联络（A22／A23／A24／A30／Console）、把经验写回文档 | 总览古籍整理流程并沉淀史记经验 |
| **切分** | 切分、对位、遮挡与印章、职名页、目錄页、年表／表页、版式槽位、列检测——凡「格切得对不对、配没配上整理本」 | 史记切分 |
| **字形库** | 本书字形库：补库、自建模板、快审表、库快照 g<N> 与 glyph_pin、库不认／乱码闸 | 史记字形库 |
| **形近字** | 形近字组、同义异体、文意链、码位异体、参校本可信度（N／Z／V／P 类） | 史记形近字与错字 |

- 形近字线程看情况拆成多个（例如同义异体一个、不同义形近一个）。
- 另有一个**跑批重跑**线程归总览调度：负责钉跑批分支、把各线合 dev 的改动移植、推册 yaml、交任务库、出分布。
- **新问题派给对应线程，不要再新开零散线程**；切分方面的问题一律派切分线程（遮挡、目錄页、对位都归它）。
- 各线程规矩：修复合 dev 后报总览；**冻结期不推册 yaml、不交任务库、不标 main**；公用函数的缺陷才交 A22（先自己查清成因）；写进册 yaml 的一律用缺省关、证等价的书级开关。

## 二、新书的阶段：什么时候进入逐轮降人审

| 阶段 | 做什么 | 人审的位置 | 对应文档 |
|---|---|---|---|
| ① 开书（先行册） | 页钉位、格位表、切分试跑、借库首跑 | 大规模快速标注：参校字快审，积累本书字形库（冷启动） | [冷启动快审流程](../01-开新书/冷启动快审流程.md)、[快审减量](../01-开新书/快审减量.md) |
| ② 快审 2–3 轮 | 每轮快审后入库、`--force` 重跑 5a，再出下一轮 | 只审拿不准的格（跳过列首尾、小注，模型放行、OCR 不一致撤下） | 同上 |
| ③ **转入逐轮降人审** | 先行册放行率达到关口 A（放行 ≥90%、正文 ≥95%）后；快审收益变小（新一轮人拦下率降到很低，或可放行的都放完） | 人审只留机器解不了的 | 本文 |
| ④ 铺开 | 其余册沿用先行册的书级配置，分批跑；每批同样走逐轮降人审 | 同上 | [开书全流程 S12–S13](../01-开新书/开书全流程.md) |

史记实际：10-28～10-31 做了 3 轮快审，字形库有了本书人裁；11-01 起转入逐轮降人审——先用 pending-stats 分类（A 职名页、B 对位缺格、C 圈号、F/G 字同参校被拦、H/I/E 字异参校与错字、年表页…），按类开线程，每线程改书级开关→证等价→合 dev→yaml 推中心库，再由跑批线程统一重跑。

## 三、每轮清单

1. **分析**：`guji-manager pending-stats --out … --prev 上一份`；正文与非正文（年表、职名、考證）分开报。
2. **选大头**：按「处理方式＝算法／数据可解」的小类格数排序；「待定口径」类出看图表请用户定；「只能人审」类汇总交精校。
3. **分方向处理**：每个方向的改动做成**缺省关的书级开关**并证明缺省等价，见 [书级开关与跑批分支](书级开关与跑批分支.md)。
4. **收齐**：全部合 dev → 册 yaml 推中心库 → 跑批分支带齐所有 PR（史记：`sj-fg-on-run` 加移植）。
5. **统一重跑**：任务库整批册一起交；跑完不通知，自己 `guji_jobs show`。
6. **对比与记账**：前后对比；每轮末把「改了什么、待审 A→B、哪几类降了」记进开书经验（`E10-*`／`E13-*`）。
7. **下一轮**回到 1。

## 四、什么时候停

- 正文人审率降到目标（粗校目标 <1%）；或
- 剩余待审全是「只能人审」或「待定口径」类，机器侧没有可做的大头；此时转精校（[03 精校](../03-精校/)）。
- 史记现状：正文约 1.56%（年表页另算），距目标还差约一半。

## 五、A31 在殿本上的做法（2026-11-02 回信）

完整原文在 ai-team：`通用/重跑轮次规矩.md`、`domain/文本/交接/粗校轮次经验-A31-给新书.md`、`domain/文本/交接/粗校流程-协调-验收-分流-A31.md`。要点：

**一轮 = 修复期 → 汇总冻结 → 统一重跑 → 统计分类 → 标 main → 换单 → 解冻。**
1. **修复期**：各线（切分 A22、字符库 A23、形近字 A24、遮挡与点校 A32）照常修，PR 合 dev；每条修复到位告诉轮次负责人（改了什么、动了哪步、从哪步重跑、影响哪些册页）。**各线不自己重跑整册、不自己标 main。**
2. **汇总**：负责人把本轮修复列成一页（修复项、起跑步、预计影响页数、要不要发 cv 新版）给用户看。
3. **冻结**：用户点头后宣布冻结，此后各线停止合入新修复（新发现的记着留下一轮）；冻结时钉 cv 提交、语料号、字形库快照号（写进册 yaml）。形近字线不设门槛，赶上冻结就进本轮，赶不上下一轮。
4. **统一重跑**：任务库一次性提交，从各修复里最早的起跑步起、只跑受影响页；看前后对比无程序级问题就标 main，钩子自动换线上单。
5. **解冻**：宣布「解冻、新结果可看」，附统计和分类，大家定下一轮修什么。

**命令**
| 步 | 命令 |
|---|---|
| 提重跑 | `export GUJI_JOBS_WHO=<你>`；`guji_jobs submit --book-id <书>`（非殿本必带）；`guji_jobs ls / show` |
| 取包统计 | ai-team `domain/CV/质检/按包统计人审率/run.py --ws <工作区> --vols … --pick latest|main|<子串> --prev <上份 summary.json>`（非 volNN 册名加 `--vol-names 01,02,…`；史记 `--glyph-db output/glyph-g1.db`；db pull 报 500 时用 `PYTHONPATH=/opt/guji-runner python -m open_guji_cv.cli_v2 db pull -w …`） |
| 线上单口径 | `guji-manager pending-stats`（只查中心库约 5 秒，反映线上单＝★main 包） |
| 标 main 与换单 | 钩子 `guji.post_promote` 自动换；有标点／实体层或旧单已有票的册走 proof_cycle |

**分流**：库缺字→A23；字组／形近→A24；对位→A34／A23；切分系统错→A22；重落→A30；人必须细看→A32；码位要用户定→用户。消息第一行 `【我→对方】`，带数字、样例、Jira 卡号；实质写进卡或文档，消息只放链接；发现系统性识别错误只记样例，不逐个手补。

**殿本实测**：vol04–20 首批超标册 1.0–1.9%，到 r3d 全套降到 0.31%（线上单口径 ★main 0.58%）。

**停止**：没有写死的阈值。入库 R3 目标 <1%（不卡出口，超标写原因）；是否继续看「大头类是否还有高置信可批量的修法」，没有就停、交精校；由轮次负责人判断后给用户确认。

**新书头几轮**：借字形库冷启动（如史记借殿本库）头几轮的目标是让库里有本书自己的字样，不是压人审率；人审率在数个百分点以上先大规模快审沉淀人裁，降到约 1% 上下、分类大头明确再转逐轮。新书首跑跑完直接标 main。

## 六、A31 补充的坑
- 分析必须用**出单版的包**；换单后线上单口径与 ★main 包口径不同，别混。
- 冻结后又有人合修复或自行重跑，结果互相覆盖、没法比。
- 整页／整列成片的切分问题要在粗校就拦下，不出 v0.1、不上网站（用户 10-30 定）；待审里有一批其实是切分问题。
- 动格线的修复（如 #842/#852/#858）会改列号，标 main 前须逐册比新旧格号，否则已有人裁／票错位。
- 借库冷启动：本书人裁实例与借来的库同挂 source 时，旧 export_store 整个 source 跳过，推库前看 `output/glyph_store/instances/` 是否为空，否则待审率虚涨（cv #816）。
- 动手提交任务库可能被自动审批拦，需用户明说「交」。

## 七、史记与殿本做法的差异（待统一）
- 史记各方向线程**不冻结**，各自合 dev、推中心库，由「重做职名页切分」线程统一钉跑批分支重跑；这在跑批分支漂移（见 [书级开关与跑批分支](书级开关与跑批分支.md)）上多次出问题。**建议采用 A31 的冻结／解冻**：轮次负责人宣布冻结后，各方向只报不合；重跑完解冻。
