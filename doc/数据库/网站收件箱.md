# 网站收件箱（web_inbox）

读者在网站上提交的东西，网站边缘函数直接写进中心库所在的 D1 库，一张表 `web_inbox`。11-21 起票与意见双写，web 0.2.30 起网站原 EdgeOne KV 的内容全搬进来、不再写 KV。
建表与接口在 guji-workspace-data `worker/src/webinbox.ts`；manager 侧读取在 `guji_manager/feedback/web_inbox.py`。

## 表

| 列 | 类型 | 说明 |
|---|---|---|
| `kind` | TEXT | 主键之一，见下表 |
| `key` | TEXT | 主键之一；同 (kind, key) 再写＝覆盖（读者改票） |
| `book` | TEXT | 书 ID，缺省空串；便于按书增量读 |
| `value` | TEXT | JSON 内容 |
| `ts` | INTEGER | 读者端提交时间（毫秒） |
| `seq` | INTEGER | 单调递增，每次写取 max+1；增量读 `after=<seq>` |
| `received_at` | TEXT | Worker 入库时间 |
| `actor` | TEXT | 写入的令牌名 |

索引：`web_inbox_seq (seq)`、`web_inbox_book (kind, book, seq)`。

## kind

| kind | 装什么 | key 格式 | 写 | 读 | 行数（11-23） |
|---|---|---|---|---|---|
| `cellreview` | 精校票 | `cr:…`（单格）、`cr:i:<书>:<条目>:<voter>`（按条目） | 网站 | `guji feedback cellvotes draft`（缺省读这里） | 2,159 |
| `charfix` | 改字意见 | `cf:`单字、`cs:`一段、`ce:`专名，如 `cf:<书>:<册>:…` | 网站 | `guji feedback opinions ingest` | 4 |
| `thread` | 意见下的表态、回复 | `tv:`、`tm:<书>:<册>:…` | 网站 | 网站公开清单、`opinions ingest` | 3 |
| `fixstate` | 整理组对某条意见的处理状态 | `fs:<书>:<册>:…` | 网站 | 网站公开清单 | 1 |
| `pending` | 线上待审单（`guji feedback pending` 出的单经 proofing-sync 写入），太大时切块 | `pd:<书>:<册>` | 网站 | 网站待审页 | 173 |
| `kv` | 其余网站键值，按 key 前缀分：`err_` 错误上报、`fb_` 反馈、`invite:`／`member:` 成员与邀请、`ratelimit:` 限速、`notify:` 通知节流 | 原 KV 的键 | 网站 | 网站自己、管理员 | 10,856（其中 `err_` 10,802） |

## 令牌

| 角色 | 能做什么 |
|---|---|
| `webinbox` | 只能 `POST /v1/web/inbox`（网站边缘函数） |

实际写入方（`actor`）现全是网站令牌 `kaiyuanguji-web`。key 只许字母数字与 `: _ . | ~ -`，≤200 字；value 是 JSON 对象，≤1.5 MB；一次最多 100 条。
| `web` | 网站令牌（proofing-sync＋边缘函数）：写收件箱、读待审单与公众意见文件 |
| `read`／`main` | 读收件箱（`GET /v1/web/inbox`，manager 用中心库读令牌） |

连法见 [README](README.md) 的 `[webinbox]`（缺省继承中心库）。
