# 中心库

> 原在 `doc/参考/中心库.md`（迁自 ai-team `通用/中心库设计.md`），11-22 移到本目录并按 D1 改写；**11-28 按线上 D1 实查对齐**（表、列、视图、行数都是 11-28 用只读令牌读线上库的结果；库版本 `max(changes.rev)`＝1,566,307）。建表语句 `guji_manager/datastore/schema_d1.sql`；Worker 在 guji-workspace-data 仓 `worker/`。

## 一句话

裁定事件、台账、待审条目、字形库、册配置、`config/`、语料清单这些**多人要写的数据只有一个真源：中心库**。
2026-11-18 起是 Cloudflare D1 库 `guji-data-main`（id `f276dcc3-…`），只能经 guji-data Worker（`data.open-guji.com`）读写；Neon 11-19 已删。11-23 库约 2.0 GB（D1 单库上限 10 GB；之后增长到 11-28 的 1,566,307 rev，大小未再量）。
连法写在 `databases.toml` 的 `[central]`，见 [README](README.md)。

## 数据放哪

| 放哪 | 放什么 | 怎么进出 |
|---|---|---|
| 中心库 D1 | 裁定事件、消费台账、锚点、金标、待审条目（`pending_items`，一格一条）、清单行（`list_rows`）、AI 分析摘要（`ai_notes`）、批次文件、册 yaml、`workspace.yaml`、`config/**`（含 `book_defaults.yaml`、语料清单、字形库快照清单、钉子账）、字形库各表 | `guji db pull/sync/push` |
| R2 正式桶 | 刻例图、锚图、整理本与大语料文件（按 sha256 寻址，只增不改）；产物包；每日备份 | 随 `db push` 上传；产物包见 [产物包与版本钉](../参考/产物包与版本钉.md) |
| R2 实验桶 | 实验分支上新增的图与产物包 | 同上，按分支自动选桶 |
| 本地 | products、cache、`glyph.db`、`glyph-g<N>.db`、字体域 | 由 `db pull` 和起跑前自动重建；不推 |
| git | 原图（guji-workspace）、代码（open-guji-cv、guji-manager） | git |

可重算的东西（`derived`、`cluster_*`、匹配用的 `glyph.db`）不进中心库，本地拉下后自己建。

### `events` 的 `u` 与 `level` 两列（虚拟列，由 `raw` 现算）

- `u`：字格永久编号，**册内唯一**（不是全书唯一）：取 `target.anchor.u`，没有再取 `payload.u`，都不是整数为 NULL。11-27：非空 87,381 行，其中 `stream=events` 74,098／277,909、`rulings` 13,283／74,421；`uid`、`vision` 流为 NULL。索引 `events_ws_u (ws, u)`、`events_ws_book_u (ws, book, u)`。**`u` 只在册内有意义，配对必须带册：按 `(ws, book, u)`，不要只按 `(ws, u)`**；但 `events.book` 与 `target.key` 前缀（`vol46`、`004`、`01` 三种写法）并不总能回答「哪一册」，存量补册是 11-27 清理计划 2.3 的事。
- `level`：这条事件是谁判的，推出来的列，**不是**事件里必有的字段。口径以 manager `guji_manager/feedback/levels.py` 为唯一定义，库里是它的镜像（11-27 收窄，`d1/migrations/2026-11-27-events-level-narrow.sql`；`tests/test_event_levels.py` 逐条比对）。判定顺序：`stream='uid'`→`ledger`；`rulings`／`vision`→`ai`；`payload.source` 为 `auto`／`knn_infer`→`machine`；为 `llm`／`vision`→`model`（模型判断，**不算落定**）；`payload.level` 显式写了 `human`／`ai`／`machine`→照它；`kind` 是 `needs_review`／`cell_review`／`admit_candidate`→`note`；`actor` 不是 `model`→`human`；批次名（去掉 `~` 后缀）在一份写死的人工批次名单里→`human`；其余→`ai`。Worker 只把 `human`／`ai` 算落定。
  - 11-28 各级条数：`machine` 156,297、`human` 116,962、`ai` 82,206、`ledger` 84,346、`model` 142、`note` 82。`model`（`payload.source` 为 `llm`／`vision`，大模型判断未经人点）与 `machine` 不算落定。
  - **AI 判、人点按钮确认的批次算 `human`**（Sheldon 11-27 定，如 `SJ-settle-1127-ai2` 不改判）。新写入的事件由 `write_events` 兜底补齐 `payload.level`／`by`／`channel` 三字段（取值见 [待审条目与裁定事件](待审条目与裁定事件.md)）；存量事件不改，仍由本列按规则推。
  - `book` 列：写入口必填；存量已按 `target.key` 第一段回填，仍有 43,079 行为空，多是 `stream=uid`（`ledger`）等不按册配对的流。

另有网站收件箱表 `web_inbox` 也在这个库里，单独成篇：[网站收件箱](网站收件箱.md)。`events`、`consumed`、`anchors` 是只追加台账：推送时少了行会被整次拒绝，防止拿旧数据冲掉新人裁。

## 读写权限

| 令牌（环境变量） | 能做什么 |
|---|---|
| `GUJI_DATA_TOKEN_READ`（角色 read） | 读：`db pull`、`db status`、`db diff`、取图、取产物包 |
| `GUJI_DATA_TOKEN_EXP`（角色 exp） | 开删实验分支、写实验分支、往实验桶存图和产物包 |
| `GUJI_DATA_TOKEN_PROD`（角色 main） | 写正式库（main 分支）、正式桶存包、标 main、`db import` 导回 |

- 命令读 `GUJI_DATA_TOKEN`；只读时可以不设，自动用 `GUJI_DATA_TOKEN_READ`。要写就 `export GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD`（或 `_EXP`）。
- 读写都经 Worker `POST /v1/sql`（读只收单条 SELECT；写整批一个事务，带库版本守卫，被别人抢先写回 409 重来）。D1 没有交互式事务：事务里读不到自己刚写的。
- 共享层工作区（`corpus-base`、`glyphlib-*`）普通 push 一律拒绝，只有升级脚本能写；`glyphlib-*` 发布后不可改。
- 令牌和连接串不进仓、不进 Jira、不进聊天。怎么在会话里配见 [环境与令牌](../00-总览/环境与令牌.md)。

## 日常怎么用

```bash
guji db migrate -w <工作区> --dry-run   # 一次性：老工作区的数据挪进数据目录
guji db pull    -w <工作区>             # 中心库 → 本机数据目录；字形库有新内容才重建 glyph.db
guji db status  -w <工作区>             # 分支、rev、落后几条、哪些文件没推
guji db sync    -w <工作区>             # 拉＋合并＋顺带把人裁落进字形库＋推（日常用这个）
guji db push    -w <工作区> [--dry-run] # 只推
```

- **数据目录**：`$GUJI_DATA_HOME/<分支>/<工作区 id>/`（缺省 `~/.guji-data`）。工作区根只留 `workspace.yaml` 和标记 `.central.json`，原图、products、glyph.db 照旧在工作区。
- **push 先比版本号**：该工作区在你的基准 rev 之后有人写过就整次拒绝，先 pull——同 git 的 non-fast-forward。
- **sync 自动合并**：一边改的直接取；两边都改了的只追加台账按行合，其它文件两边都改就停下（`SyncConflict`），什么都不动。要库里的用 `pull --force`，要本地的手工合。
- **sync 顺带落库**（10-24 起）：对还没落进字形库的人裁跑 `glyphdb_admit`、`glyph_audit`，落了再推一次。`--no-admit` 或 `GUJI_AUTO_ADMIT=0` 关。
- 本地有没推的改动时 pull 会拒绝；`--force` 丢掉本地改动。
- `close-check` 第 8 项查「数据目录有没有没推的改动」。

## 实验分支

只比参数、不写库的 A/B 用 `guji pipeline exp` 或 `--override`（见 [册配置](../参考/册配置.md)），不用开分支。实验要写库（人裁、字形库、字组配置、码位表、语料）时：

```bash
export GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_EXP
B=exp/GUJI-<卡号>-<小写说明>          # 必须带卡号，最多 63 字
guji db branch create $B --ws <工作区 id>  # D1 上开分支＝建新库，按工作区从 main 复制
export GUJI_DATA_BRANCH=$B            # 之后数据目录、glyph.db、products 都换到这个分支自己的目录
guji db pull -w <工作区>
#   …照常跑…
guji db sync -w <工作区>               # 推到实验分支，新图进实验桶
guji db diff -w <工作区>               # 与 main 逐文件比
unset GUJI_DATA_BRANCH
guji db import --from $B -w <工作区> --dry-run   # 裁定事件导回 main，要正式令牌
guji db branch delete $B               # 用完就删：最多同时 20 个实验分支
```

- 进正式库只有显式的路，不整分支合并：裁定事件用 `db import`（按 id 幂等）；册 yaml、配置这类文件拷到 main 的数据目录再 `db sync`。
- 同一台机器可以一边在 main 上整理、一边在实验分支上试，互不覆盖。

## 版本与钉住

- `db pull --rev N` 钉库版本（该工作区 N 之后没变才放行）。
- 跑批的结果不靠 rev 钉，而靠册 yaml 的三样钉版（`cv_version`、`corpus`、`glyph_pin`），见 [产物包与版本钉](../参考/产物包与版本钉.md)。原因：产物在各机本地，同一份内容各机拉到的 rev 不同；本地人裁没推时没有 rev。

## 备份与恢复

> 账本被清空／误删后的恢复做法见 Wiki [中心库字形账本恢复](../../wiki/中心库字形账本恢复.md)。

- 备份：`guji datastore backup` 把全部表分页导出进 R2 正式桶 `backup/<日期>/`，有清单才算完整。首份 D1 备份 11-18（rev 1073950，31 表 180 万行，约 172 MB）。大行（files、imports）要小页起步，否则 Worker 回 500。
- D1 自带时间点恢复（Time Travel，30 天内）：只能恢复成新库再核对，**换正式库要用户点头**。实验分支是独立的 D1 库，开分支时按工作区从 main 复制，不能从过去的 rev 开。

## 常见坑

- D1 单条 SQL 文本 ≤100 KB、单个字符串参数 ≤2 MB、一批 30 秒：大推库自动分段，每段各自原子；中途失败要能重跑（导入是差分写，天然幂等）。
- 册 yaml 带 `corpus_dev: true` 推不上去（`push_problems` 拒），先 `guji start corpus release`。
- 老版 cv 不认 `corpus_files`，pull 不还原整理本；整理前先确认 cv 版本够新（见 [COMPAT](../../COMPAT.md)）。
- **`db push` 缺省不推字形库**（v0.4.42 起）：不导出本机 glyph.db、`output/glyph_store/` 不推；要连账本一起推才加 `--with-glyph`（先 `db pull` 重建 + `--dry-run` 核对没有成批 delete）。缩水闸、删除闸门槛是 5%（11-10 史記 6,465→3,554 事故）。`db sync`、`store commit` 仍处理字形库。
- **推库前看 dry-run**：`guji db push --dry-run` 里出现 `glyph_exported:true` 或成批 delete 就停手（全唐文 rev 423141 把字形账本推空 22,002→0）。核借库账本 `borrowed_instances` 非空；账本被清空只会让待审虚涨，指纹不报警。推库前设 `GUJI_ACTOR`。
- 降人审轮次里推库设 `GUJI_AUTO_ONLINE_LISTS=0`（标 main 后不自动走 `guji land`），收尾交 GM4；一轮中途不推库。
- 大模型裁定（`ctx_ruling`）落 `feedback/rulings/`，进 events 表时 `stream=rulings`，**不算落定**；直接查表的要按 kind 或 stream 过滤。键是前后文窗口内容，不是格号。
- `glyph.db` 只由 `db pull/sync` 和起跑前重建，别手拷别人的 glyph.db：指纹会变、产物判过期。
