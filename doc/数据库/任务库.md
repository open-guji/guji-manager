# 任务库（jobs）

跑批不在自己会话里跑，而是交单进任务库，执行方领单去跑。代码 `guji_manager/jobs/`（`store.py` 读写（Postgres 写法）、`store_d1.py`（D1 写法，`store` 按连接分派）、`schema.sql`／`schema_d1.sql` 建表、`d1.py` D1 连接、`runner.py` 执行方）；用法见 Wiki [任务库与重跑](../../wiki/任务库与重跑.md)。

- **现在**：美国机 170.106.66.156 本机 Postgres 18，库 `jobs`、schema `jobs`，只听 127.0.0.1，经 wss 桥 `relay.open-guji.com/jobsdb` 访问。11-03 从 Neon 搬来；没有 R2 备份（用户定数据可弃）。11-23 约 165 MB。
- **搬 D1**（用户 11-22 定）：Cloudflare D1 独立库 `guji-jobs`（id `18f1da0f-b053-4601-9b41-b3af6b8fef24`），经 guji-data Worker `POST /v1/sql?db=jobs`。代码两边都支持，按 `databases.toml` 的 `[jobs].driver` 选；切换步骤见下「搬家」。

## 连法与令牌

`databases.toml` 的 `[jobs]`，缺省 `driver = "pg-tunnel"`：

| 键 | 缺省 | 说明 |
|---|---|---|
| `url` | `wss://relay.open-guji.com/jobsdb` | 桥地址；环境变量 `JOBSDB_URL` 能盖 |
| `token` | `JOBSDB_TOKEN` | 桥的 Bearer 令牌（rw 或 ro 两把：`JOBSDB_TOKEN_RW`／`_RO`） |
| `password` | `JOBSDB_PASSWORD` | Postgres 口令（`jobs_rw`／`jobs_ro`，与令牌不是同一个） |
| `user` | `jobs_rw` | ro 令牌要配 `jobs_ro`；`JOBSDB_USER` 能盖 |

裸 IP 自签证书时按指纹固定（`JOBSDB_CERT_SHA256`）；走域名时用系统 CA。

D1 的写法（`driver = "d1-worker"`）：

```toml
[jobs]
driver = "d1-worker"
url = "https://data.open-guji.com"   # guji-data Worker；请求发到 <url>/v1/sql?db=jobs
token = ["JOBSDB_TOKEN"]             # 同一把令牌：Worker 认 JOBSDB_TOKEN_RW 的指纹为 jobs 角色（读写）、_RO 为 jobsread（只读）
env_url = "GUJI_JOBS_URL"            # 别再用 JOBSDB_URL（执行机上多半还设着 wss 桥地址）
```

`driver = "sqlite"`＋`path = "…/jobs.db"` 连本机 SQLite 文件（测试、核对用），首次自动按 `schema_d1.sql` 建表。

Worker 侧：`wrangler.toml` 绑 `JOBS`＝guji-jobs；secret `TOKENS_JOBS_JSON` 存令牌指纹与角色。jobs／jobsread 角色只能 `GET /v1/whoami` 和 `POST /v1/sql?db=jobs`，碰不到中心库；中心库的令牌（main 除外）也碰不到任务库。

## 表

| 表 | 主键 | 一行是什么 | 要点 | 行数（11-23） |
|---|---|---|---|---|
| `job` | `id` | 一条任务 | `kind`、`book`、`book_id`、`spec`（jsonb，提交后不改）、`spec_hash`、`status`、`priority`（小的先）、`depends_on`（bigint[]）、`duplicate_of`、`submitted_by`、`why`、`stage`、`progress`、`attempts`／`max_attempts`（缺省 3）、`cancel_requested`、`error`、`run_after`、`notified_at`、四个时间 | 6,509 |
| `attempt` | `id`；唯一 (job_id, n) | 每领一次单一行 | `worker`、`session`、`host`、`cv_commit`、`lease_until`、`heartbeat_at`、`outcome`、`exit_code`、`log_tail`（≤8,000 字） | 10,191 |
| `event` | `id` | 进展流水，只追加 | `stage`、`level`（info／warn／error）、`msg`（≤4,000 字）、`secs`、`data` | 150,029 |
| `result` | `id` | 一条产出 | `kind`（pack／diff／check／output／file）、`name`、`location`（R2 前缀等）、`data` | 12,615 |
| `worker` | `name` | 一个执行方（`GUJI_JOBS_WHO`） | `state`（idle／busy／stopped）、`job_id`、`done`、`seen_at`、`runner`、`note` | 48 |
| `perf_run` | `run_id` | 一次整册跑 | 书、管线、步骤、页数、并发、cv 版本、机器、起止、`wall_s`、`job_id`；建表在 `perf_push.py` | 32,160 |
| `perf_step` | (run_id, step) | 一次跑里的一步 | 页数、成功／跳过／失败、`wall_s`、`compute_s`、p50／p90／max、CPU、峰值内存、`spans`、`slowest`（最慢 20 页） | 39,491 |
| `meta` | `key` | 键值 | `schema_version`（Postgres 记 3，v4 加的 `notified_at` 没升这个号；D1 记 `d1-1`）；D1 另有 `migrated_from_pg`（搬家时间） | 1 |

D1 版（`schema_d1.sql`）同表同列，差别：时间是 UTC 毫秒 `…Z` 文本（字符串比较即先后），`spec`／`data`／`depends_on` 等是 JSON 文本，布尔是 0/1；`job`、`attempt` 多一列 `mark`（见下）；`perf_step` 不设外键。读出来由 `d1.decode` 按列名还原成 datetime／dict／bool，调用方不用管。

## 状态与规则

- `status`：queued → running → succeeded／failed／blocked／cancelled；同 `spec_hash` 已有排队、在跑或成功的，新交的记 duplicate 并指向它。
- **同册同时只跑一条**：部分唯一索引 `job_one_running_per_book` on (coalesce(book_id,''), book) where status='running'。
- **领单**：挑 queued 且依赖全成功、同册无在跑、`run_after` 已到的；排序按优先级 → 失联被收回的先 → 本执行方失败过的后 → 与上一单同册的先 → 先交的先。
- **租约**：领到开一条 attempt，租约 10 分钟（`GUJI_JOBS_LEASE_MIN`），执行方每 60 秒心跳续租。过期由任何执行方 `reap` 收回：记 lost、退回排队；前 5 次失联不占重试额度（`GUJI_JOBS_LOST_FREE`）。
- **失败重排**：错误以「环境：」开头的退回排队，隔 5×已领次数 分钟；「环境（瞬时）：」随机隔 2–10 分钟；其余失败是终态。
- **依赖失败**：依赖的单失败／拦下／取消，排队单记 blocked。
- **通知**：某提交人名下没有排队和在跑的单时，把其终态单一次通知（`notified_at` 认领，发不出去退回）。
- 空闲执行方轮询：Postgres 每 30 秒一次（收回过期、领单＋报到、通知）；D1 每 60 秒**一次请求**（领单＋报到并成一批），收回过期与通知每 5 轮一次（`GUJI_JOBS_IDLE_EVERY`）。在跑的执行方每 60 秒一次续租＋报到（D1 上同一批），每 5 拍顺手收回一次。

## D1 写法要点

D1 没有交互式事务、没有 `SELECT … FOR UPDATE`。`store_d1` 每个操作是一次请求、一批语句（Worker 一批一个事务，D1 单库串行，不会两人领到同一条）：

- 「刚改的那几行」靠本次随机标记 `mark`：如领单＝`UPDATE job … WHERE id = (挑一条) RETURNING *` → `INSERT INTO attempt … FROM job WHERE mark = ?` → 记事件；
- 有条件的分支写成 `UPDATE … WHERE <条件> RETURNING`（取消、改优先级、重排、收尾、被收回后旧会话醒来只记事件）；
- 领单、收回、通知都走部分索引（`job_queued`、`attempt_live`、`job_unnotified`、`job_active_by`、`job_waiting_deps`），按读行计费不扫全表；
- 看板（`board.py`）、统计（`stats.py`）、耗时（`perf_push.py`）等零散查询照写 Postgres 语法，由 `d1.translate` 翻（`%s`、`= ANY`、`now()`、去 `jobs.` 前缀）；翻不了的（`LATERAL`、`extract(epoch …)`、`make_interval`）各自有 D1 分支。

用量估计（11-22）：40 个执行方空闲时每天约 6 万次请求，加上在跑时的续租与事件，合计约每天 8 万次，在 Workers 付费档含量内。

## 搬家（Postgres → D1）

1. Worker 部署 `JOBS` 绑定与 `TOKENS_JOBS_JSON`；manager 发支持两边的版本（缺省仍 Postgres）。
2. 选队列将空时，先告诉 A30；Ops 把美国机 `jobs` 设只读。
3. `npx wrangler d1 execute guji-jobs --remote --file guji_manager/jobs/schema_d1.sql` 建表；`python scripts/jobs_pg_to_d1.py dump --out jobs.sql`（一个只读快照里导，约 180 MB、半分钟）后 `wrangler d1 execute … --file jobs.sql` 导入；`python scripts/jobs_pg_to_d1.py check` 逐表核行数与最大号。
4. 发 PATCH 把包内 `[jobs]` 缺省改成 D1；执行方下次空闲自更新后就连 D1。
5. 旧 Postgres 留只读两周，再问用户删。
