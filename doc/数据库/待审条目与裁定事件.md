# 待审条目与裁定事件：现行结构（基准）

> 2026-11-27 定稿（A-BAK 清理计划第一、二阶段之后）。**本页是现行口径的基准**：别处文档与本页冲突时以本页为准，并改别处。
> 历史设计（整张换单、rev、批号、人裁事件）只在 archive 里留档，不再描述现状。

## 一、三样东西

| 东西 | 是什么 | 存在哪 | 谁写 | 只追加？ |
|---|---|---|---|---|
| **格子** | 一格现行的字 | book-text 仓（`<章>.char.json` 等） | `guji collect`、`guji land --text-apply` | 否（git 版本） |
| **待审条目** | 「这格要人看」——问题 | 数据目录 `feedback/lists/pending/<书>/<章>.items.jsonl` → 中心库 `pending_items` | `guji land`（开／改／关）、`guji pending-settle`（标 resolved）、人工撤下 | 是 |
| **裁定事件** | 「这格是什么」——答案 | 数据目录 `feedback/events/*.jsonl` 等 → 中心库 `events` | 控制台、`guji cellvotes write`、`guji collect`、意见采纳、各脚本 | 是 |

另有两样辅助：读者的票（`web_inbox`，`kind=cellreview`，键 `cr:i:<书>:<条目 id>:<投票人>`）和 AI 分析摘要（`ai_notes`，只提示、不是裁定）。

**没有 rev、没有批次。** 每格独立：条目随时开、改、关，网站按条目现算显示，不按批号。

## 二、身份：（书, 册, u）

- `u` 是字格永久编号，**只在册内唯一**。配条目、配事件、配票，一律用（书, 册, u）；不能只用 u，也不能用格号（重切后格号会变）。
- 册号写法尚在统一（`01`／`001`／`vol01` 并存）：比较前先归一（纯数字去前导零；Worker `normVol`、manager `progress_sync.vol_key` 同口径）。
- 没有 u 的旧条目／旧事件：按 uid 账补（条目追加新版本；事件写 `~u` 抄件批），不改原行。

## 三、待审条目（`pending_items`）

每次改动追加一行完整新版本；当前状态＝每个 `item_id` 的最后一行，视图 `pending_current`。

| 列 | 含义 |
|---|---|
| `item_id` | `pi_` + 12 位十六进制，开条目时定，不变 |
| `ver`／`op`／`actor`／`at`／`why` | 版本号与这次改动（`op`：open、add、note、resolve、withdraw、restore、u-fill…；`why`＝这一版为什么改，**不是**待审原因） |
| `book`／`vol`／`cell` | 书、册、当前格号 `页:列:格[a|b]`（可变） |
| `state` | `open` 待审／`withdrawn` 人工撤下／`resolved` 已落定（记 `event`）／`closed` 机器不再判待审 |
| `recheck` | 复审格：只有**晚于复审开出**的裁定才关它 |
| `src` | 谁开的：`pipeline`／`human:<谁>`／`script:<名>`（历史行有 `rev:…`、`land:…`，读时一律当机器出的） |
| `raw` | 整行 JSON；`raw.doc` 是网站卡片字段（见第六节） |
| `u`（现算） | `raw.u` |
| `reason`（现算） | 待审原因码 `raw.doc.pending_reason`（ref_gap、hard_pair、recheck…） |

## 四、裁定事件（`events`）

| 列 | 含义 |
|---|---|
| `stream` | `events`（人与脚本的裁定）／`rulings`（大模型裁定）／`vision`／`uid`（字格身份账）／`pin_state`（钉的删除与过期） |
| `book` | 册（11-27 起写入口必填；存量已按 `target.key` 第一段回填） |
| `batch`、`kind`、`actor`、`reviewer`、`ts` | 批次名（只作来源记录，不作显示与分组）、种类（`confirm` 等）、写入方 |
| `payload`、`target`（现算） | `raw.payload`、`raw.target`（格事件 `target.unit=cell`，`target.anchor.u`） |
| `u`（现算） | `target.anchor.u` 或 `payload.u` |
| `level`（现算） | 见下 |

**来源三字段**（`payload` 里，新写入必填，`write_events` 兜底补）：

| 字段 | 取值 |
|---|---|
| `level` | `human`（人定，**含「AI 判、人点按钮确认」**）／`ai`（AI 定、无人点）／`machine`（规则、回填） |
| `by` | 人的账号，或脚本／模型名 |
| `channel` | `console`／`web_vote`／`opinion`／`script`／`llm`／`vision` |

**落定口径只有一处**：manager `guji_manager/feedback/levels.py`（`event_level`、`settles_cell`、`SETTLED_VS`）。
一格算落定＝有 `kind=confirm`、`target.unit=cell`、`payload.v ∈ SETTLED_VS`（confirm、seg_defect、not_a_char、damaged、figure）、级别为 `human` 或 `ai` 的事件。
中心库 `events.level` 虚拟列与 Worker 都是它的镜像（`tests/test_event_levels.py` 逐条比对）；`level=model`（大模型判断、未经人点）与 `machine` **不算落定**。

## 五、主流程

1. cv 出包，标 ★main。
2. `guji land <册> --apply`：用 main 包对账条目——没变不动、变了就地改、新的开、机器不再判的关；已有人裁的格扣掉不开。标 main 钩子与 `guji swap run` 都走它。
3. 网站经 Worker 现拼出单：精校页按章取 `/v1/web/pending-doc?book=&vol=`（每个 open 且未落定的条目一格，带 `id`／`ver`／`u`，无 rev、无整张单）、`/v1/web/pending-live-index?book=`（各章剩几格）；网站 `/api/pending`、`/api/pending-index` 转它们。`/v1/web/pending-chapters` 只给 `proofing-sync` 用（各章 open 条目数＋单格图登记，发图到 COS、写 `proof/index.json`）。
4. 读者投票按条目记 `cr:i:<书>:<条目>:<投票人>`（带 `item`、`ver`、`u`，不带 rev；旧 `cr:<rev>:…` 票已一次性迁到新键）。
5. `guji cellvotes write`／`guji collect`：票写成裁定事件（`channel=web_vote`），落 book-text。
6. `guji pending-settle`：格已落定的条目标 `resolved`（记 event id）；执行方用 `GUJI_PENDING_SETTLE_S` 定时跑，跑完顺手 `progress-sync --fix --pending-only`。
7. 后台看板：`pending_review`＝该册 open 条目数，`pending_at`＝最后一次条目变更时间。

**已退役**：cv `scripts/zhengli/republish.py`、`proof_cycle.py`、`auto_cycle.py` 等整张换单脚本；网站按 rev 存票（旧 `cr:<rev>:…` 键保留只读）。
**过渡中**：land 仍导出整张 `<章>.pending.json`，因为网站 `proofing-sync` 还靠它搬单格图；proofing-sync 改按条目后停导。

## 六、卡片字段（`raw.doc`）

**候选字以 `cands`（`cands/1`，候选字线 CV3）为准**：一格只留一份候选列表，序号即名次，卡片按钮就是前 `top` 个。规格见 manager `guji_manager/review/cands_field.py` 模块头。

| 键 | 含义 |
|---|---|
| `v`／`by` | 格式版本 `cands/1`／出表算法版本 |
| `top` | 卡上直接显示几个（缺省 3），其余折进「更多」 |
| `list[]` | `{c 字, p 校准概率（多数为 null，只按名次显示）, fam 异体族键, src 各来源原始分}`；`src`：`a` 库相似、`c` 图像余弦、`b` 形近组方法分、`ctx` 填空 logp、`ref`＝1 整理本字（排第一） |
| `p_other` | 「都不对」的概率，现恒 null |
| `p_map` | 图像毛病的概率（cut／border／residue／stain…），有才写 |

投票时随票带 `pick_src`／`pick_rank`／`pick_shown`（`cands_field.pick_fields`），用来量候选命中率。
产线出包时由 cv 3c／4b 写；已开着的条目用 `guji pending cands <册> -w <工作区> --text-id <书> --chapter <条目章>` 现算（追加 op=cands 版本，可重跑），再 `guji db push --only <条目文件>`。2026-11-28 已给线上全部开着条目补完（四庫 76 格取不到字块图除外）。`guji audit cands` 是给旧整张单出卡用的，不再用于线上条目。

**旧候选字段**（`alt[]`、`lib`／`lib_top`、`ref`／`refc`／`ref_suspect`）照出，只作过渡：网站先读 `cands`，没有才退回旧字段；新代码不再读写它们。
其余卡片字段：`why`、`note`、`detail`、`pending_reason`（及 `_detail`／`_cause`／`_cause_detail`）、`conf`、`margin`、`img`（单格图）、`ctx`（上下文）、`grp`、`prior`（旧人裁）、`recheck`、`audience`；Worker 另挂 `ai`（AI 摘要）。覆盖随出单来源不齐，统一与网站格子的重新设计另见计划（2026-11-27 起草）。
