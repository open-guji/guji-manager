# 5a 分段与形近字组表：配置、开关、原理

> [N01 总览](README.md) · [N01 全流程](流程.md) · 写于 2026-11-16（OCR 研究方向 1，Sheldon 定方向）。代码在 cv（open-guji-cv#1589）：`steps/glyph_stages.py`、`clustering/near_route.py`、`groups/shape_stage.py`、`config/near_groups.json`。设计与实测细节见 cv `doc/design/形近字组-5a分流与第7步对接.md`。

## 一、为什么要有这个

5a 换成相似度 CNN 以后，「见过的字」认得很准，但统一的字形比对分不开极近的字（天夭、尸戸、延廷、侯𠋫）。这类错分数很高，靠提门槛拦不住。所以定了两条：

1. 维护一张较大的**形近字组表**，落表的格不让字形单独放行，交给专门的判法。
2. 5a 分成几段。只看字形就能判的在第 5 步判，要整理本、上下文的照旧留第 7 步。

| 段 | 做什么 |
|---|---|
| 5a.1 | CNN 匹配后分流：首位字落表（或属于已注册字组）的格、近邻一致度不满的格，从 same 降成 unsure |
| 5a.2 | 落在已注册字组的格，跑该组登记的只吃字块图的方法；本书终判名单里的组给了字就在这一步定字 |
| 5a.3… | 以后的字形方法往后排 |
| 5b | 不变 |
| 第 7 步 | 要整理本、文意的判法，以及 5a.2 判不出的格 |

## 二、怎么开

书的 yaml（或 `book_defaults`），要先开着 `sim_model`：

```yaml
params:
  glyph_match:
    sim_model: {path: models/glyph_sim_qtw/model.pt, fuse: mean}
    stages:
      route:
        level: core        # core＝核心表（缺省）；all＝全表，多拦很多
        knn_min: 1.0       # 近邻一致度低于它算证据弱；1.0＝前 10 名里混进一个别的字就算
        registry: true     # 首位字属于已注册字组也算落表
        book: null         # 只用哪本书字形库挖出的对；null＝三本书的表并着用
      final: []            # 本书实测够准、5a.2 可以直接定字的字组 id；缺省空＝全部待审
      shape: true          # false＝只分流，不跑 5a.2
```

最省事的写法是 `stages: true`，全用缺省值：所有落表的格都交后面的步骤，第 5 步不替任何字组定字。

试跑不用改 yaml：`guji step glyph_match <册> --override '{"params":{"glyph_match":{"stages":true}}}'`。

关着时参数不进 dump，产物逐字节不变。开着时相关模块代码、表、终判组的模板库都进硬参数 `stages_sha`，任何一样变了这本书的第 5 步判过期。

## 三、开了以后一格怎么走

只管判决层判成 **same** 的格（unsure、diff 本来就交后面）。

| 情形 | 第 5 步产物 | 后面怎么接 |
|---|---|---|
| 首位字落表或属于注册组 | `verdict=unsure`、`guard=never_match`，表里的对家补进候选（分 0）；`stage.route=near_group` | 和匹配器自己判的形近护栏格完全一样：纯字形通道不放，整理本与库首位一致的 `match_ref` 照放，`group_flow`、`near_knn` 等形近判法接手，上下文在候选里重排；放不出来的落 N01 |
| 近邻一致度不满 | `verdict=unsure`、`guard=conflict`，前 10 名里最像的别的字补进候选；`stage.route=weak_knn` | 同匹配器的冲突护栏格 |
| 落在终判名单里的字组，字形方法给了字 | `verdict=same`、字取字形方法判的字、`via=shape:<组>`；`stage.final=5a.2` | 当普通 same 格；第 7 步字组复核照常再看一遍 |
| 其余 | 不动 | 不动 |

分流故意**不另起护栏名**。`never_match` 和 `conflict` 是匹配器早就有的两种护栏，第 7 步的通道、待审原因 N01、审阅页都认识。新的只是「谁来判定这格属于形近」：原来靠三张小表（手工 20 对、字体表、人裁表），现在加上从字形库挖出来的大表和字组注册表。要把两种来源分开统计，看 `MatchRec.stage.route`。

`stage` 里还有：`top`（整库 CNN 首位字）、`knn`（近邻一致度）、`partners`（表里的对家）、`groups`（所属注册组）、`shape`（5a.2 每组每个方法给的字与理由）。

## 四、形近字组表

`config/near_groups.json`，572 对、920 字，核心 369 对。每对记来源：

| 来源 | 说明 |
|---|---|
| `lib:<书>` | 这本书字形库里挖的：每个刻例找 CNN 最像的别的字，一对字的近度取各刻例分数的第二高；≥0.985 算核心，≥0.975 进全表 |
| `variant` | 库里两个字都有的异体、同形异码对，库里量出来近度 ≥0.95 |
| `hand`、`human` | 原有的手工表、人裁表 |
| `font` | 字体渲染表；只有它一个来源的不算核心 |

重建：`python scripts/build_near_groups.py mine --book <书> --db <glyph.db> --model <权重> [--trusted] --out near_<书>.json`，再 `merge` 合表。殿本、史記要加 `--trusted`（只用可信刻例，不然错标刻例会造出假对）；全唐文不加（人裁刻例太少，加了表缩到五分之一）。`config/near_groups_drop.tsv` 是剔除名单。

表只知道库里两个字都有的对。一个字真不在库里时，只能靠别的书的表、手工表、近邻一致度和分数门槛。

## 五、终判名单 `final` 怎么定

字形方法不看整理本单独用，多数字组还不够准。2026-11-16 拿三本书人裁刻例量过 80 个有字形方法的组：给字 30 格以上 0 错的只有 9 组（心必 `xb`、扺抵 `di`、禽俞會舍命 `qin`、圓圖 `yt`、甲申 `js`、㫖旨 `zhi`、敎教 `jiao`、厯歴 `lih`、囗部 `kou`），37 组有错，跨书最差（人入八的分类器是殿本练的，在史記 57 格错 44）。

所以名单**按书、按实测**给：

1. 需要的话先给这本书建自己的模板库：工作区 `config/groups/ids/<组>.json` 优先于 cv 仓里的殿本库。
2. 在本书人裁刻例上量这一组不看整理本的准确率（脚本 ai-team `domain/CV/字形领域/5a相似度CNN深化-2026-11-15/code/shape_eval.py`）。
3. 够准再把组 id 写进 `final`。

## 六、加新的字形方法

- 针对某个字组的：在 cv `groups/methods.py` 写成一个方法（`needs_patch=True`），挂到 `groups/registry.py` 那一组上。5a.2 和第 7 步的 `group_flow` 都会用到，不用动第 5 步。
- 不按字组的新一段：写一个函数排进 `steps/glyph_stages.py` 的 `STAGES`。

## 七、已知的数和限制

- 全唐文整库基准（2762 格，库外模拟最多误放 2 格）：只加近邻一致度规则，放行率 73.2%→91.4%；核心表会拦走约 23% 的格，其中多数有整理本作证仍能放。
- 库外形近字对抗集（1765 格）：同一门槛误放 13 格，加核心表剩 2 格，加全表 0 格。近邻一致度规则在这类上一格也拦不住，两条都要。
- 全唐文 020 八页从第 5 步跑到第 7 步的开关前后对比见 cv 设计文档第六节。
- 史記、殿本的 5a 权重还不够好，先不要在这两本书上开。
- 表里有些对没看图核过。
