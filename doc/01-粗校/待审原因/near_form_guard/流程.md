# N01 形近字：从一格进来到判成 N01 的全流程

> [N01 总览](README.md) · 写于 2026-11-06（A24，sheldon 要求「理一遍整个流程、哪些字进来、有什么标准和参数」）。代码以 cv `0ad3b53`、guji-manager dev `a43a3e8`＋#256 为准。

一格要先过**三关**才会停在 N01：① 字形匹配没给出可信的字；② 进库准入的所有放行通道都没放；③ 出单时按优先级，前面的原因都没命中，而形近条件命中。下面按这个顺序讲，最后一节是新书怎么做。

```
原图字块 ──▶ ① glyph_match（cv 步骤 5-a）
              库里刻例做近邻 → 逐个验证 → verdict: same / unsure / diff ＋ 候选（字,cov）＋ guard
        ──▶ ② seed_admit（cv 步骤 5/6 之后的进库准入）
              疑问码 doubts（含 near_form）→ 主循环通道 → 后处理各遍（升/降）→ admit=true/false
        ──▶ ③ manager reasons.classify（出单时，按 priority 取第一个命中的原因）
              … H01 → Z01–Z06 → R01 → L01 → L05 → R02 → V01 → **N01(56)** → L03 → L02 → P01 → L04 → P02
```

## 一、字形匹配：形近表在这里第一次起作用

- 验证判据 elastic，**same 闸 0.992**（`verify.py` `COV_HIGH`；放到 0.988 实测会漏朱/宋、匕/七）。覆盖率 <0.85 判 `diff`（这样的格落 L01）。
- 判 same 之后还有两道护栏（`clustering/match.py` `_match`）：
  - **conflict**：判 same 的刻例里有两个不同字 → 降成 `unsure`，两字都进候选；
  - **never_match**：判 same 的字在形近表里有伙伴（`_PARTNER`）→ 降成 `unsure`，把伙伴也补进候选（分 0）。
- 所以「候选里有形近字」有一部分是**匹配层自己补进去的**，不是图像真的像。

### 三张形近表（`clustering/confusable.py`，别混）

| 表 | 规模 | 谁来用 | 为什么 |
|---|---|---|---|
| `NEVER_MATCH_FAMILIES` 手工表 | 20 对，每对有实审案底 | `seeding.NEAR_FORM_CHARS`（`near_form` 疑问）、manager N01 判定 | 命中就拦采信通道，代价高，只放核过的 |
| `FONT_TABLE` 字体渲染自动表（τ=0.988） | 约 200 字有伙伴 | 只用于匹配层 `_PARTNER` 降档 | 命中只是 same→unsure，还有候选＋上下文兜底，宁可多拦 |
| `HUMAN_TABLE` 人裁确认表 | 27 对（`config/confusable_human.json`） | 同上 | 本书上真会混的对 |

手工 20 对：人入、候侯、匕七、圓圖、大太、夬夫、己已、己巳、已巳、廣贋、彖象、揀棟、日曰、曾會、未末、諭論、選過、遺還、間問、面而。

### 三处同名，不是一回事

| 叫法 | 在哪 | 口径 | 谁改它会影响什么 |
|---|---|---|---|
| 匹配层护栏 `guard=never_match／conflict` | `match.py` | 三张表的并集（`_PARTNER`）；conflict 只看刻例里字不同 | 影响候选里多不多伙伴、verdict 降不降档 |
| `near_form` 疑问 | `seed_admit.py:1554`（`cand_chars & NEAR_FORM_CHARS`） | **只认手工 20 对**；候选前三＋机器字里**任一**成员就记，不要求是真字、不要求与参校字成对 | 拦一批放行通道（见第三节） |
| 待审原因 N01 | manager `reasons.py` `_near_form` | #256 后：护栏 conflict／never_match，**或**参校字与（机器字、候选前三）成手工表一对 | 只改分类，不放行 |

三者都被叫「形近护栏」，但判法不同，所以会出现「`near_form` 疑问很多、N01 很少」。看数据时先问清说的是哪一个。

## 二、进库准入 seed_admit：一格怎么被放行或留下

### 2.1 疑问码里和形近相关的

| 疑问码 | 来源 | 意思 |
|---|---|---|
| `near_form` | 候选前三或机器字含手工表字 | 形近家族在场 |
| `护栏:never_match`／`护栏:conflict` | 匹配层 | 见上 |
| `iron_confusable_ref` | 铁证闸 | 铁证定的字与证人（整理本）是已知形近对且字不同 |
| `iron_vs_ref`／`iron_vs_coord`／`iron_vs_ctx` | 铁证闸 | 铁证与现役对位／坐标对位／上下文不一致 |
| `ctx_guard_ref`／`ctx_guard_diff`／`ctx_guard_ref_blank` | context 通道最后一道闸 | 上下文字与整理本不同且库不是 same、库 diff 且 cov<0.8、整理本说是空格 |
| `replace_align` | 对位 | 整理本这位来自改字层 |
| `库 unsure(cov=…)`、`上下文 margin 不足(…)` | 库、Step6 | 证据不够 |

### 2.2 放行通道（能放「形近处境」格的）

顺序＝`_run_page` 里的执行顺序（**改次序＝改产物**，别动）。「缺省」是代码缺省，书级覆盖用 `guji book show --effective` 看；N01 型格大部分最后还是被其中一条放走，没放走的才留下。

### 2.3 出口

通道放了＝`admit=true`、`channel=…`；都没放＝`admit=false`，`doubts` 里留着上面这些疑问码，`evidence` 里留着 `verdict`、`cov`、`guard`、`ctx_margin`。后处理里「降」的遍把已放行格挪回待审，并在 `evidence.demoted_from` 记通道。

## 三、出单分类：为什么一格是 N01

`guji_manager/review/reasons.py`，按 `pending_reasons.yaml` 的 priority 依次试，第一个命中的就是主原因：

```
5 X01 → 6 X02 → 7 X03 → 8 X04 → 10 S04 → 11 D01 → 12 D02 → 20 S01 → 21 S02 → 22 S03
→ 30 H01(己已巳日曰) → 40–45 Z01–Z06(字组) → 49 R03 → 50 R01 → 51 L01(库无像样刻例) → 52 L05
→ 53 R02(整理本无字) → 55 V01(组外异体对) → 56 N01 → 57 L03 → 58 L02 → 60 P01 → 61 L04 → 62 P02
```

N01 判据（#256 后）：`evidence.guard ∈ {conflict, never_match}`，或 有参校字且（机器字、库候选前三）里有一个字与参校字**在手工表里成对**。不要求疑问码里有 `near_form`。

N01 的去向（yaml）：`route: llm`，`reviewer: llm_then_human`，`ui: pick`，owner A24。

## 六、新书怎么做 N01（照 S0–S4 的节奏）

1. **体检（S0）**：首跑后跑 `guji-manager pending-stats`，看 N01、L02、P01、P02 的数字；再跑 `benchmark/funnel.py <书>` 得到「形近处境」格的漏斗（占比、放行率、各通道占比）。
   - 判读：N01 本身不会多（现行口径只含真形近）；L02／P02 多说明库刻例不足或整理本分歧多，那是别的线的事。
2. **查整理本可信度（决定要不要开按参校字的通道）**：对人裁过的形近处境格算「真字＝参校字」比率，按类 A／B／C／E 看（`benchmark/gold_human.tsv` 的算法，见 [benchmark.md](benchmark.md)）。
   - 史記 B 类 38/38、全唐文 21/23、殿本 99/130（其中 11 格〓缺字、17 格同词异形，真错 3 格）。**按书不同，不能继承别的书**。
3. **能配的先配（L0）**：`follow_ref_seen`（看图核实过的字对）、`ref_lib_coord`（整理本可靠的书）、`ref_topk_follow`、`rare_ref_sparse`（A23 L02）。每开一个，用金标打分，0 错才开。
4. **刻形近邻（L1）**：书里已放行的格多（万级以上）、刻本干净的才试 `near_knn`：`research/char_groups/near_knn_train.py collect/train`，按册留出，门槛 votes 7、ratio<0.6、全库票≥4。殿本 13 册小库试验 0 放行，别在刻本淡印粘连的书上抱太大期望。
5. **文意（L2）**：真形近格交 L2 只读文意（干净会话，不调 API），只收 high。
6. **余下人审（L4）**：用 `review-pages build pair_whitelist`／`gold_sample` 成批页，字对看图。每个字对 30 格定白名单，不继承别的书。
7. **验收**：新放行通道按[准确率守则](../../迭代框架/准确率守则.md)——金标放行子集 0 错、盲读抽样 0 错；放行后每轮抽 30 格。
