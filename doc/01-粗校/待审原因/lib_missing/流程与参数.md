# L01 `lib_missing` 流程与参数

> [README](README.md)（介绍与配图）· [benchmark](benchmark.md)（怎么量好坏）

本文回答：**什么样的格会进 L01、判据和参数各是什么、怎么放行、新书上手怎么做。** 代码事实来自 guji-manager `review/reasons.py`、cv `steps/glyph_match.py`、`steps/seed_admit.py`（2026-11-06，manager #258 之后）。

## 一、两个入口

L01 有两个入口，进来的格性质完全不同。

| 入口 | 判法 | 典型格 | 殿本／史記／全唐文（★main 现算） |
|---|---|---|---|
| ① 库认不出（老口径） | 格上有 `lib_miss` 疑问码，或某条疑问以「库里没有」开头（`reasons.RULES[LIB_MISSING] = c.lib_miss`，priority 51） | 格图糊、残、并格、无对位；真缺字 | 354／89／5（共 448） |
| ② 首次入库（#258 新增） | 本来判成 L02（`lib_sparse_dissent`）的格，若整理本字在**本书库里 0 刻例**（`_first_entry`：`ctx.lib_n(ref)==0` 且有对位字），改判 L01，细分写 `all_zero:<字>` | 印得清楚的生僻字，坐标对位，库判 unsure（cov 约 0.93–0.96），上下文 `source=prior` | 366／36／1（共 403） |

合计殿本 720、史記 125、全唐文 6＝**851 格**。②的特殊分支写在 `classify()` 里、不在 `RULES` 表中（后续清理项，见第六节）。

## 二、①入口的判据链（cv 一侧）

```
cell_shrink ─ glyph_match ─ rare_candidates(5b) ─ align_ref ─ context_decide ─ seed_admit
```

1. **glyph_match**：格图与库刻例逐对比，取覆盖率 cov。
   - `same`：弹性 cov ≥ 0.996（`ELASTIC_COV_HIGH`）；
   - `unsure`：0.85 ≤ cov < 0.996，带候选交上下文；
   - `diff`：所有候选 cov < **0.85（`COV_LOW`）** → `_doubts()` 记 `库里没有这个字`/`lib_miss`，即 L01 ①入口。
   - 另：`timeout`→diff；`knn_k=10`、`max_candidates=5`、`MISS_WMAX=12`，`near_shape` 缺省关。
2. **rare_candidates（5b）**：字体特征嵌入，对整格取 top10，**不依赖字形库**，对库里没有的字是唯一的候选来源。
3. **context_decide**：只在库候选里排序。diff 格候选只剩库首位一个，整理本字几乎不进候选（旧批 4/322），所以上下文对 L01 基本无用。
4. **seed_admit** 放行通道里与 L01 有关的：
   - `rare_ref`（缺省开）：整理本字 ＝ 5b 首位，且无硬疑问（`_RARE_REF_HARD`：occluded、excluded、near_form、context_blank_cell、context_tall_cell、form_open、approx_exemplar），库首位不是整理本字的异体 → 放行为整理本字。
   - `rare_ref_coord`（缺省开）：同上，但用**坐标对位**字当整理本字（现役对位没有的格）；多一道 **库首位 cov ≥ 0.90（`_RARE_REF_COORD_MIN_COV`）**，不在字组、不带 group_flow/shadow_veto 疑问、前三候选里没有整理本字的异体。
   - `rare_ref_nf`（缺省开）：坐标对位那支放宽 `near_form`，条件 BMP 字、库刻例 ≤ 2（`rare_ref_nf_max_n`）、无强对手（cov ≥ 0.96，`rare_ref_nf_cov`）、不在册 codepoints。
   - `ctx_garble_shape`（`context_garble_cov` 0.90）：格图糊的拦截，**优先于**放行，使没有 `lib_miss` 时这些格成 L05。

## 三、②入口（#258）的判据

- 前提：格先被分到 L02（库样本 ≤ 2 或库与整理本不同意），整理本字在**本书库 `lib_n(ref)==0`**。
- 这些格的特点（殿本 366 格，见 benchmark 基线）：
  - 坐标对位 355/366，现役对位仅 11；
  - 机器字（库首位或上下文选的）与整理本字**从不相同**（面↔囟、狀↔从 这类形近字）；
  - 5b：整理本字在 top1 的 94、top3 的 214、top5 的 247；史記 36 格里 top1 仅 1、top5 17；
  - 看图（殿本抽看 a/b 两组）：格图确实是整理本字，是**印得清楚的生僻字，因为库里第一次出现而没被认出来**；c 组（5b 前十都没有，119 格）多是整理本字体渲染不出的罕见字形。
- 性质：这是「首次入库」问题而不是「认不出」问题，**按 sheldon 11-03 规矩，字第一次进库要人裁**；放行需另有金标支持。

## 四、细分（detail）

`lib_missing_kind` 给 `pending_reason_detail = <细分>:<整理本字>`：

| 细分 | 入口 | 意思 |
|---|---|---|
| `own_has` | ① | 本书库有该字刻例，这格仍不像 |
| `all_zero` | ① 和 ② | 本书与借来的库都没有该字（②入口全部是这类） |
| `own_zero_borrow_has` | ① | 本书没有、借来的库有 |
| `ref_blank` | ① | 整理本这一位没字（无对位） |

注意：库刻例数有两个口径，`lib_counts` 用 `glyphs.n_confirmed` 求和，`lib_split_counts` 用 exemplars 加借库表，数字可能不同，写报告要注明用哪个。

## 五、参数一览（改动前先看谁会过期）

| 参数 | 位置 | 缺省 | 作用 |
|---|---|---|---|
| `COV_LOW` | glyph_match | 0.85 | 低于它判 diff＝①入口 |
| `ELASTIC_COV_HIGH` | glyph_match | 0.996 | same 门槛 |
| `rare_ref`／`rare_ref_coord`／`rare_ref_nf` | seed_admit | 开 | 5b×整理本放行三支 |
| `_RARE_REF_COORD_MIN_COV` | seed_admit | 0.90 | 坐标对位那支库首位 cov 下限（模块常量，非书参数） |
| `rare_ref_nf_max_n`／`rare_ref_nf_cov` | seed_admit | 2／0.96 | nf 放宽条件 |
| `context_garble_cov` | seed_admit | 0.90 | 糊格闸 |
| L01 priority | reasons.py | 51 | 在 L05 52、R02 53、V01 55、N01 56、L03 57、L02 58、P01 60 之前 |

改 cv 的 Step 与其 `code_deps` 会让各书产物过期，改 manager 不用。

## 六、清理清单（尚未动，改原因码分法先经协调者通知 A31–A34）

1. `_first_entry` 特殊分支搬进 `RULES` 表，或表里给它一条显式规则，别藏在 `classify()` 里。
2. 老口径 README 里「库里没有」与 L01 名称不符：名称与 yaml label/hint 要改成「首次入库／库认不出」两半（看 sheldon 要不要改名）。
3. `_RARE_REF_COORD_MIN_COV` 改为书级参数（框架参数化原则，sheldon 11-06）。
4. 两个库刻例口径统一。

## 七、新书上手清单

1. 建书、跑到 ★main 包后：`python tools/l01_profile.py --ws <工作区> --text <书 id> --out <目录> [--vols …] [--jobs 4] [--crops]`，得 `cells.tsv`、`summary.json`、`report.md`。
2. 对照 benchmark 基线看三项体检指标：L01 占待审比例、入口②占比、5b 召回。
3. ②入口先按字出人审卡（同字头一张），人裁入库；①入口看 `ref_blank` 与形状类，框角、并格先归切分问题。
4. 要开放行前先做金标（每书 30 格、留出 0 错），再改书级参数，不动全局阈值。
