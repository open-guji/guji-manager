## 一、判定条件

代码：`guji_manager/review/reasons.py`，优先级 12，紧跟 D01：

```
D02 = 遮挡 ∧ 不是「遮挡格而整理本字在 日曰己已巳」      （前一条不中，即整理本这位没有字：空，或〓／私用码）
```

## 六、benchmark 与怎么继续提高

金标同 D01 页（我看图定，非人审真值）。可估量的提高，按收益排：

| 路 | 能降多少 | 风险 | 状态 |
|---|---:|---|---|
| **列级「整列阙」人审卡**：整列都被盖死的列，一键标阙 | 18（vol43 p1 c6、c9）＋ vol93 题列 3 | 低（人点头）；是人审页的事，不是算法 | 提议，交 A31／人审页 |
| **P 类遮挡格用 `pua_rules`**：整理本〓、库首位在表里且 cov≥0.95、图清楚 | ≤2（直 vol80／vol89，cov .993／.992）；鉉 3 格库首位在印泥下乱（鉉.935／鍵.882／摯.883），不能靠库首位 | 中：遮挡下库首位不可靠，只能收极高 cov；要新参数 `pua_rule_occluded_cov`（未做） | 估量；量太小，**不建议单独做** |
| **T 类题列补全**：整列坐标字里非〓的字与套语位置一致 ≥3 处 → 其余位置按套语补 | 5（vol53）；殿本别的册首页整理本都有这行，用不上 | 中：套语补全是推断，不是对位；数字位（卷数）补不了 | 估量；量太小，不做 |
| Q 类：库首位对 3、错 2，不能自动 | 0 | — | 人审 |
| 低密度遮挡不当遮挡（C 类） | ≤2 | — | 不做 |
