# S2 配置爬降（1% → 约 0.4%）

> **流程以 [粗校迭代流程](../粗校迭代流程.md) 为准**（2026-11-14：前提→五层→回溯→10 册一批→v0.x 后对比）。本文保留为细节（开关与配置散在第 1–3 层），与之冲突处以粗校迭代流程为准。

> [总览](../降人审迭代框架.md) · 上一步 [S1](S1-冷启动.md) · 下一步 [S3](S3-决策层漏斗.md)

**目的**：把开关、参数、小修吃完。

## 做什么

1. 每轮跑 `pending-stats`，看诊断信号；`guji-manager suggest` 把信号对到 A 档开关建议，用户点头后 `--apply` 写册 yaml（见 [终审判读与开关建议](../终审判读与开关建议.md)）。
2. 常用开关：`symbol_ref_blank`、`follow_ref_variants`／`follow_ref_seen`、`stain_pages`、`vline_overrides`、`row_pitch`、book_knn、码位对照。开关写法见 [书级开关与跑批分支](../书级开关与跑批分支.md)。
3. 待审按成因码派给各组；各组修好自己通知，攒成一轮统一重跑（[两档轮](两档轮与交单检查.md)）。
4. 同字对照自检（`seg_defect --gate`，缺省关）：用本书别处同一个字的切法，找被切掉一截或带框线的格；哪本书哪一轮开由用户定。

## 出口

连续两轮收益 <5%（拐点），且 Z/N/L/R/V 类合计占待审一半以上（配置已清不掉）。

## R2 每轮开跑（用户点头）

一页轮单：本轮修复清单、起跑步、预计收益、风险、要不要发 cv 新版。约 5 分钟。
