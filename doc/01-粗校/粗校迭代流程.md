# 粗校迭代流程：前提 → 五层 → 反复回溯 → 出 v0.x

> 现行：2026-11-14（A31，sheldon 定口径）。**粗校从开书到 v0.x 怎么一轮一轮压人审率，以本文为准。**
> 旧文档（[降人审迭代框架](降人审迭代框架.md) 与 `迭代框架/S0–S4`、[四层工作法](四层工作法.md)、[逐轮降人审节奏](逐轮降人审节奏.md)、[步骤](步骤.md)）保留为各层细节、经验和历史，流程上与本文冲突的以本文为准。
> 范围：粗校（到 v0.x 文本线）。精校、反馈迭代只列交接项；点校里「靠文意比较确定的字」并进第 4 层。

## 〇、一页看全

```
前提（先行册 2–3 册，一次性）
  P1 资源准备 → P2 先跑切分 → P3 试验 → P4 集中审新字形库 → P5 定目标人审率
        │
        ▼
以 10 册为一批，批内一轮一轮转（每轮同一套固定动作，见第三节）
  ┌────────────────────────────────────────────────────────────┐
  │ 第1层 切分（含对位、页钉位）                                     │
  │ 第2层 少见字入库（字形库无例/少例）                               │
  │ 第3层 形近字自动处理（字组、刻形、码位、白名单）                   │
  │ 第4层 AI 处理文意、点校（对话审写裁定缓存，不调 API）             │
  │ 第5层 剩下的人审（攒大批，结果回流成刻例/白名单/金标）             │
  └──── 后层发现前层的问题 → 回到那一层（第五节回溯表）──────────────┘
        │  本批判停（第六节）
        ▼
出 v0.x（book-text 文本线）→ 下一批 10 册沿用本批配置
        │
        ▼
v0.x 之后：参校本 / 维基文库对比（脚本已有，差异怎么处理**待定**，总目在试，第八节）
```

**三条总规矩**
1. **前层没稳不进后层**：后层的结果依赖前层的格切得对不对、库里有没有样本；在前层没稳时做后层，切分一动全要返工。
2. **一批一批做，前一批做好再做下一批**：一般 10 册一批；先行批把配置、书级代码、字形库磨好，后面的批沿用，减少返工（第二节）。
3. **绝大部分是自动的**：本文每一步都标了【自动】或【人】。【自动】＝会话直接做，不问用户、做完在本书线程里记一笔即可（依据：10-24 用户授权冻结、推库、发包、合并、上线默认直接做；PR 自审自合）。【人】＝必须等用户（或用户本人点页面）。用户的时间只花在第七节列的几处。

## 一、前提（先行册，一次性做完）

先行册取 2–3 册：一册正文最典型、一册特殊页型最多、可选一册另一种体裁（理由与挑法见 [开书全流程](开书/开书全流程.md) 一节「先行册」）。

**前提完成的标志（关口 A，会话自判，不问人）**：先行册无整页／整列成片切分错；放行 ≥90%、正文 ≥95%；常用字有 15–20 个本书刻例。之后进入「10 册一批」的五层迭代。

## 二、10 册一批的节奏

- **第一批**＝先行册＋凑够约 10 册。批内按第三、四节一轮一轮转，直到本批判停（第六节）。
- **开下一批的门槛**：本批第 1–3 层已稳——`guji seg gate` 无回退、`切分未定.tsv` 只剩已登记根因的少数列；无例／少例字已集中审过入库；主要形近组有定判法。第 4、5 层的尾巴可以与下一批首跑并行。
- **下一批沿用**：册配置模板、书级代码 `k`、字形库 `g`、格位表脚本、页型声明全部沿用；首跑后的重点通常是第 2 层（新册带来新字头），切分只处理新出现的版式。
- **回补**：后来全书统一上的修法（某个钉子规则、卷名栏表行、勘误），出 v0.x 前要对已做的各批按统一配置对一遍（先行册最容易漏）。
- 节奏由各书线自己掌握（殿本 ZM、全唐文 QTW、史記 SJ；11-09 定）；A31 只管本文、工具和规范。

## 三、一轮的固定动作（每轮都一样）

一轮只做一次统一重跑：各层的修复先攒着，收齐后冻结、发版、重跑一次，再一起看结果（10-31 定，11-04 补「先发 cv 新版」）。

## 四、五层：每层做什么

待审原因码（`pending_reason`，真源 `guji_manager/review/pending_reasons.yaml`）按下表归层；每个码的具体处理见 [待审原因](待审原因/README.md) 与 [待审原因各步骤处理标准](../00-总览/待审原因各步骤处理标准.md)。

| 层 | 收哪些码 | 判停 |
|---|---|---|
| 1 切分 | S01–S04；对位、钉位类的 R01、P01；字形差别大的错（駱/路）先查这里 | seg gate 不挡；切坏格、格号不符只剩根因台账里已登记的列 |
| 2 少见字入库 | L01、L03、L04、L05、R03；L02 先查是不是缺样本 | 参校字已知却因样本少被拦的格清到可忽略；本书可信 ≥3 例字头覆盖全书格 ≥99% |
| 3 形近字自动处理 | Z01–Z07、N01、V02；V01 先看能否按刻形定 | 主要组都有定判法、金标盲读 0 错；轮收益 <3% |
| 4 AI 文意、点校 | 第 3 层放不掉的 Z／N；L02、R02、P02；D01；H01（日曰、己已巳） | 待裁问已全部判过、缓存已入库重放；新类别金标 0 错 |
| 5 人审 | S04、D02、V01、X01–X04；前四层都放不掉的 | 人审总清单清完或交接；X99（unknown）必须为 0 |

### 第 1 层　切分（含对位、页钉位）

**目标**：格框对、格号对、配上整理本。切分一动，格号、刻例、人裁锚都要迁，所以最先清。
**做法**
1. 每轮第 6 步的 seg check／gate 给出结构列清单；逐列看缩略图（管线的 column_image＋bbox_col，坐标原点在右上）。
2. 报问题**先查根因台账** ai-team `domain/CV/A22/切分根因台账.tsv`：已有根因只加例子；新根因开一行，用 `send.py` 发给归属方（本书切分线或 A22），写 `册:页:列:格`、包标签与 cv 版本、已查到哪一层。没包标签的单退回。
3. 修法分级，由便宜到贵：公用算法（A22，cv PR）→ 本书书级代码（书仓 `code/`，出新 `k`；**单书开关不再往 cv 共用 Step 加**，cv 里已有的「改到哪个搬哪个」）→ 本书配置数值（书仓 `code/defaults.yaml`、册 yaml）→ 单页／单列钉子（`manual-cells`、格位表 override）。
4. 首跑后第一件事扫失锚页（一段连续页「参校本＝库首位、cov 高却 unsure」多是钉位错）；目录页建 TOC 参照段；装饰类（邻字残笔、框线进框）用发前清格，不挪框。
5. 下游任何一层发现切分真错而本轮 seg check 没报：登进台账、加进本书尺子（漏检即进尺子）。

**脚本**：`guji seg check／gate／pin／ruler`、`tools/seg_check/seg_check.py`、cv `scripts/seg_pins_check.py`（推钉子前必跑）、`guji code release／verify`、`code_equiv`。
**自动**：全部【自动】。看图判切分由会话做，不交用户（人裁切线页型不做，11-08 定）。
**细节**：[切分快筛](切分快筛.md)（十二节不回退闸）、[四层工作法](四层工作法.md) 第一节、cv `doc/design/书级代码.md`、ai-team `domain/CV/A22/切分返工复盘-2026-11-13.md`。

### 第 2 层　少见字入库

**目标**：库里缺例、样本少的字头补上本书刻例，让库自己能放。
**做法**
1. 先量：待审里到底多少是字库的事（同字已补过刻例仍待审 → 查开关，不是再补）。
2. `scan` 统计自有样本 =0／<4／<8 分档，先补 =0、<4 的字头；每字头只取约 3 个代表格。
3. 走四层页（char_grid 快审 → 高置信 → 低置信 → 难认字）；形近组字头、日曰己已巳、印章遮挡格、小注 a/b 格不上快速页。
4. 入库：`db pull`（不加 `--no-rebuild`）→ `push --dry-run` 只增不删 → `push --with-glyph` → `glyph-db snapshot --pin N` → `snapshot-upload --execute` → `pin-verify` → 册 yaml 钉新 `g`，下一轮从 `glyph_match` 起跑。私用码注明最相近异体字（11-06 定）。
5. 自动入库闸（三方一致选格自动入库）目前**不开**：分层盲读 ≥100 格 0 错才写 `gate.ok`。

**脚本**：`tools/开书/字形快速入库_自动.py scan/ocr/crop/sample/gate/admit`、`guji-manager review-pages build char_grid`、`scripts/build_newchar_review.py apply … --execute --admit`、`guji events route`、`guji glyph-db snapshot/snapshot-upload/pin-list/pin-verify`。
**自动**：选格、出页、入库、快照、钉版本【自动】；**第一次进库的字点页【人】**（每批新册集中出一次，不零碎出）。
**细节**：[字形快速入库](开书/字形快速入库.md)（真源）、[四层工作法](四层工作法.md) 第二节。

### 第 3 层　形近字自动处理

**目标**：同组字（日曰、己已巳、末未木、入人八…）和异体、码位，能靠字形和规则定的由机器定。
**做法**
1. 定组：只把实际错放、人裁改字、金标盲读错例里反复出现的字对入组；字形差别大的错不是形近，回第 1／2 层。
2. 判法三类：整格靠字形（训本书刻形模板 `config/groups/pair_shape_*.json`、IDS 模板，模板刻例 <8 宁可弃权）；靠上下文的交第 4 层；都拿不准的留第 5 层。
3. 码位口径（归一还是分开）先改码位表、再改库标签、两边一起推；库分不开的码位对不靠降门槛放。
4. 新放行规则上线：金标里放行子集 0 错，独立盲读抽样也 0 错（<100 格抽 30、>300 抽 100、>1000 抽 200）；有错先收紧。放行后每轮滚动抽 30 格。
5. 错放先归因：缺样本（第 2 层）、切分／对位（第 1 层）、组内判别（本层）、整理本错——分别回对应层，不混着调参数。

**脚本**：`guji-manager pending-stats`（看哪些组占大头）、`guji groups status`、`guji promote mine`、`guji-manager iterate gold／audit`、`guji-manager suggest`（诊断信号对开关建议）、`review-pages build gold_sample／pair_whitelist／codepoint`。
**自动**：定组、模板、规则、回放、抽检【自动】；**金标标注、码位口径（归一还是分开）、新放行类别上线【人】**（每类 15–30 分钟）。
**细节**：[四层工作法](四层工作法.md) 第三节、[形近字迁移框架](开书/形近字迁移框架.md)、[准确率守则](迭代框架/准确率守则.md)、[S3 决策层漏斗](迭代框架/S3-决策层漏斗.md)。

### 第 4 层　AI 处理文意、点校

**目标**：靠文意能定的字，由对话会话统一判，结果写裁定缓存，管线只读缓存。**管线不调 Anthropic API**；尽量只用 Sonnet。
**做法**
1. 每轮第 9 步后导出待裁问 → 干净会话逐行判 → 导入裁定库 → 推库后下一轮从 `seed_admit` 重放（D 轮）。裁定键按前后文哈希，不含格号，重切后仍能命中；前后文一变会重出问。
2. 放行条件：两路（候选正／反序）都 high 且同字、字在候选内；日曰、己已巳等整格形近要**两轮**（两次独立会话）一致才写人裁，不参考整理本。
3. 上下文不足的格要跨列／跨页补足（小注 b 列接下一列开头，a 列接上一列末尾），补足后仍不一致就撤回不硬判。撤回已写的人裁用 `feedback/lists/stale_verdicts.tsv`（`confirm`＋`skip` 撤不掉）。
4. 点校里靠文意比较确定的字可放行（11-08 定）：须是待审格、字在候选内、两路 high 同字并有文意依据、金标 0 错；推翻机器已确认字、候选外的字只作提示（`dian`），交精校人裁。
5. 大模型不看图放行：字形一致由算法作证，大模型看图只给人审页做预标注。

**脚本**：`llm_queue export／import --model session`、`guji review-pages ctx2-export／ctx2-import`（`review_pages/ctx2.py`）、`guji-manager final-review`。
**自动**：全部【自动】（判由会话做）；新放行类别第一次上线前的金标抽样【人】（同第 3 层）。
**细节**：[S3 决策层漏斗](迭代框架/S3-决策层漏斗.md)「AI 统一审」、[人审页模板](人审页模板.md) 第九节、[03 点校／点校先于精校](../03-点校/点校先于精校.md)。

### 第 5 层　剩下的人审

**目标**：机器原理上定不了的格，一次性攒大批给人，结果回流让下一轮少审。
**做法**
1. 机器已能判的格不进人审页；未定格进「人审总清单」累积，重跑后一次性出页，不拆小批；台账写清为什么要人裁、裁了多少格。
2. 页一律从模板库出（`review-pages build …`），页上显示库里首选字、带原页图裁格和前后文，不默认全对；预选好答案，按杠杆排序（同字全书格数多、第一次进库、影响多册的先上）。
3. 人裁落库后回流：刻例（第 2 层）、白名单与码位（第 3 层）、金标（第 3、4 层）。
4. 收口时每类剩余格只有三种去向：放行／留人审（交精校）／算法再处理（还有一格就不出 v0.x）。

**脚本**：`guji-manager review-pages build <页型>`、`guji cellvotes write`、`guji events route`、`guji-manager iterate leverage`、`tools/开书/出v01.py`。
**自动**：出页、落库、回流【自动】；**点页【人】**。
**细节**：[人审页模板](人审页模板.md)、[S4 收口出 v0.1](迭代框架/S4-收口出v0.1.md)。

## 五、回溯：后层发现前层的问题怎么办

五层之间会反复回溯，这是正常的。规矩是**发现了就登记、回到那一层修、跟下一轮统一重跑**，不在后层就地补字掩盖。

| 在哪层发现 | 现象 | 回到 | 怎么做 |
|---|---|---|---|
| 2–5 任一层，或 v0.x 后对比 | 半字、两字一格、框线进格、列错位 | 第 1 层 | 登根因台账（漏检加尺子）；本轮这几列进 `切分未定.tsv` 先跳过；切分修复攒进下一个 S 轮 |
| 3、4 层 | 一组字成批「刻的≠参校本」 | 第 1 层 | 先查参照段、钉位，不先疑字形库 |
| 3、4、5 层 | 错放其实是库里没样本、○邻误读 | 第 2 层 | 补本书「别的」刻例（不拿待审格自己当刻例），出新 `g` |
| 4、5 层 | 同组字反复要人判、会话两路常不一致 | 第 3 层 | 改判法（刻形模板、白名单、码位），金标 0 错再放 |
| 5 层 | 人裁结果 | 第 2、3、4 层 | 回流成刻例、白名单、码位、金标 |
| 任一层 | 写错的人裁 | — | `stale_verdicts.tsv` 撤回，再写更晚的 `confirm` |

**回溯的代价**：回到第 1 层的修复会让格号变，触发收尾里的 IoU 对照表、人裁锚、钉子、字形库键的迁移，所以切分修复一定攒批，一轮最多一次；只动第 3、4 层的轮（D 轮，从 `seed_admit` 起）便宜，可以多转几轮。
