# 四层工作法：切分 → 字形库 → 形近字 → 人审（史记实战，2026-11-09 起）

> 来源：史记文渊阁 r20–r43 的逐轮降人审。Sheldon 11-09 定：**第一层解决再进下一层**。本篇是各层的新经验、可复用脚本与「开新书照做」清单；各层原始材料在 [案例/史记-四层材料](../案例/史记-四层材料/)。总框架见[降人审迭代框架](降人审迭代框架.md)，轮次节奏见[逐轮降人审节奏](逐轮降人审节奏.md)。

## 0. 总纲（各层共用）

| 层 | 问题 | 判停 |
|---|---|---|
| 1 切分 | 格框对不对、格号对不对 | 切坏格 0、格号不符 0 |
| 2 字形库 | 字头无/少样本，认不出 | 参校字已知却因样本<8 被拦的格清到可忽略 |
| 3 形近字 | 同组字（日曰、己已巳、末未木…）分不清 | 每组有定判法、金标盲读 0 错 |
| 4 余下 | AI 判不了的，攒大批给人 | 一批一批清，不拆小批 |

四条通用规矩：
1. **切分问题必须最先清零**：切分一动，格号、刻例、人裁锚都要迁，晚改代价最大。
2. **修法分级**：公用算法 → 本书/本类页设置 → 单页/单列参数 → 最后直接标特殊格坐标（hard code，防下次重跑再错）。不为个别格改算法参数，免得把别处改乱。
3. **新放行规则要有金标证据**：按组/字头分层抽样盲读（读原页图），**0 错**才开；有错先修判法，不放行。盲读判对错依据是原页图，不是 main 的字、也不是整理本的字。
4. **人审攒大批**：机器已能判的格不放进人审页；未定的进「人审总清单」，重跑后一次性给；记清为什么需要人裁、裁了多少格。

## 1. 第一层：切分

**新经验**
- 毛病分两类：结构类（漏切、并格、拦腰切、格数不对）动格号，必须第一层清零；装饰类（邻字残笔、界行、版框进框）不动格号，靠**发前清格**抹墨，不挪框。
- **整列钉坐标 / 一格两字强拆**：算法切不开的少数列（如职名页「原任」「三等」挤一格），在 manual-cells 里把整列格坐标写死。人裁按墨框锚绑定，格号顺延后自动跟过去，不用手迁。
- **发前清格**（书仓 `patch_clean`）：只抹字块里别格的墨，框和格号不动；加「伸入深度 ≤框高 30%」闸，免得把本字相连的笔画抹掉。
- 墨账前先剥长直线（竖开运算、横 0.85 列宽）；漏切块（orphan）要滤粗框横带与外圈稀疏框角（cv `scripts/seg_screen.py`，#1422）。
- **○ 不是切分问题**：○ 列切分框全对，待审是对位/字形库的事（A9）。版式编号习惯差（题署列不留空位号、只左行小注标 b）不算错。
- **坐标原点在右上**：`cell_shrink.bbox_page` 是 `raw_page_px@top-right`，x 从右往左；裁图用 `open_guji_cv.core.anchor.crop_patch(img, bbox)`，或 `x0'=(W-1)-x1, x1'=(W-1)-x0`。按左上原点裁会落到空白或邻字。

**可复用脚本**
- `tools/seg_check/seg_check.py`：一轮出包一条命令，几何快筛、漏切、钉子格号核对、版式对格号、待审原因码归类；输出 `列清单.tsv`（处置）、`需看图_*.png`、`report.md`；十册约 6 分钟。
- cv `scripts/seg_pins_check.py`：推钉子前必跑。
- 数据准备：`guji products pack fetch NN --label <带 job 号> --root <目录>`、`guji cache warm --book NN --jobs 4`。
- 判据、金标、能钉 vs 须改公用算法的划分：[切分快筛](切分快筛.md)。

**开新书第一层清单**
1. 书仓建 `code/`（k1），点名跳过页（年表、卷首、整页印）。
2. 跑一轮 → `cache warm` → `seg_check`。
3. 先看格号不符 / 版式不符 / 需钉子，逐列看缩略图，按修法分级归位。
4. 原因码「看图」框对就转字形/对位线，不在本层动。
5. 装饰类计数高 → 上书级 `patch_clean`，从 cell_shrink 起重跑。
6. 钉子推中心库：写 items.jsonl → `seg_pins_check` 全过 → pull、dry-run（`glyph_exported=false`）→ push。
7. 重跑后再 `seg_check`，**切坏格 0、格号不符 0** 才进第二层。

**坑**：钉子推前不 pull 会互相覆盖；改定框后旧人裁要迁，不能默认丢；换 cv 检出后 unet 模型软链会断，要拷 `models/partition_unet_v2/model.pt`；`code_equiv.py` 只给要测的那一册缓存。

## 2. 第二层：字形库

**新经验**
- **字形库是真源，快照必须对得上中心库某 rev**：改库 → `db push --with-glyph` → `glyph-db snapshot --pin N` → `snapshot-upload --execute` → `pin-verify` → `db push`（带 manifest）。每轮只钉一个 g。
- **撤借库**：借来的刻例带进别书写法、掩盖本书缺样本；撤后缺样本字头才暴露，补完再出快照。
- **字形库缩水事故（11-10）**：`pull --no-rebuild` 之后 push，把旧 glyph.db 导出覆盖了中心库。规矩：pull 不加 `--no-rebuild`；推前 `push --dry-run` 看 `glyph_exported` 与各表 insert/delete（只增不删）；设 `GUJI_ACTOR`、带 `--with-glyph`；不开 allow-delete/shrink。
- **点审不默认全对**：形近格被默认 OK 入库放错过字。没点的格 ≠ 审过；形近格逐格对图。
- **○邻字系统误读**：○ 后书名人名字被库误读（令≠今、駱≠路…），按整理本唯一定位 + 原页图补刻例（g18 补 39 条）。
- **自动入库闸（本轮结论：先不放）**：三方一致（库首位＝参校＝对位，cov≥.975，gap≥.025）选格 → 分层盲读 ≥100 格或 5% **0 错**才写 `gate.ok`；`admit` 无 `gate.ok` 拒绝。首轮 168 格 ≥8 真错，全在字头自有样本 ≤3（own≥4 的 64 格 0 真错）；rapidocr 紧框首位字＝参校字能拦 14 个真错/疑似里的 12 个；字体渲染相似度无效。收窄后抽 120 格仍有 2 格无法证明对，闸不过。错一条刻例会污染后面所有轮，宁可不放。反例集见案例材料。

**可复用脚本**
- `tools/开书/字形快速入库_自动.py`：`scan`（`--exclude-file` 排形近组、`--min-own`、`--ocr`）→ `ocr` → `crop`（原页图裁格）→ `sample`（分层抽样）→ 读图写 reads.tsv → `gate` → `admit`。
- 人审路径：`guji_manager review-pages build char_grid` + `scripts/build_newchar_review.py apply … --execute --admit`；快照：`guji glyph-db snapshot / snapshot-upload / pin-list / pin-verify`；同步：`guji db pull/push/status`。
- 详见[字形快速入库](开书/字形快速入库.md)第八节。

**开新书第二层清单**：① `db pull` 确认 behind=0、备份本机 glyph_store；② 第一层清零后 `scan` 统计缺样本（自有样本 <8、<4、=0 分档）；③ 先补 =0 / <4 的字头，走四层页（char_grid 快审→高→低→难认字），形近格逐格对图；④ 自动链只作统计与待批台账，放行须先对新书重测 own 阈值与盲读 0 错；⑤ 入库后 dry-run → push → snapshot → upload → pin-verify → push manifest；⑥ spec 钉新 g 跑一轮，核缺样本字头是否被纠正。

**坑**：`export_store` 默认写工作区 output，不是数据目录 store；`guji db sync` 会重放未消费事件，要核；缺 `GUJI_ACTOR` 推不了；旧包的 cell_shrink 要与当前格号一致才能裁图。

## 3. 第三层：形近字

**新经验**
- **定组**：先看实际错放（待审、人裁改字、金标盲读错例）里反复出现的字对再入组；同组字不能凭单字相似度自动入库，自动入库脚本要排除全部组字头。字形差别大的错（駱/路、清/瀆）不是形近，是○邻对位或切分错，归第一/二层。
- **判法三类**：① 整格靠字形（看图与字形库样本）；② 靠上下文（日曰、己已巳、令今…），用「文意两路」；③ 都拿不准的留人审。**日曰、己已巳不参考整理本**（整理本可能就是错的），按文意定。
- **文意两路双轮规则**：两个干净会话只读 ±5 字上下文，候选顺序正/反各一路；一格至少**两轮**（两次独立会话）、两路全一致且都 high 才写人裁，source 标「文意两路 rN 双轮」。单轮读法有随机波动（r39 的 low 到 r41 变 high）。r41：整格日曰/己已巳 16 格，首轮一致 7 格，双轮通过 3 格。这个办法只对日曰、己已巳有量，末未/還環/子于/春泰靠文意分不开，仍留人审。
- **错放归因**：每个错放先判是字形库缺样本、切分/对位、组内判别、还是整理本错，分别回给对应层，不混着调参数。

**可复用脚本**：`guji review-pages ctx2-export`（出 cells.json 与正反 prompt）/ `ctx2-import`（出判定.tsv 与 import 草案.jsonl），代码 `guji_manager/review_pages/ctx2.py`，用法见[人审页模板](人审页模板.md)第九节；入人八自建 HOG 模板 `config/groups/ids/rr.json`。

**开新书第三层清单**：跑 `pending-stats` 看哪些组占待审大头 → 定组 → 金标盲读 → 文意两路 → 人裁入库（写事件前 pull、dry-run 确认 `glyph_exported=false`、无删除）→ 重跑核对放行与逐格一致。

## 4. 第四层：余下留 AI / 人审

- 一律用模板库出页（`review-pages build gold_sample` 等），不手写 HTML；用户意见改模板，不改已发页。
- 页上显示库里的**首选字**，不显示「待选一串」；格图从原页图裁格并带前后文；不默认全对，要人明确点；机器已预判的格不放进页。
- **攒大批**：未定格进「人审总清单」累积，重跑后一次性给；台账写清为什么需要人裁、裁多少格。

## 5. 跑批与标 main（贯穿四层）

- **自己直接交单**：`python -m guji_manager.jobs submit <spec.json> [--dry-run]`，spec 放书仓 `jobs/rN/<册>.json`，`why` 写全 cv / k / g 版本、中心库 rev 下限、base 包、起跑步骤、出包后要核什么。
- **版本钉法**：cv 钉发版 tag；书级代码 k 写 book_defaults 的 `code:`；字形库 g 写各册 yaml 的 `glyph_pin`；新开关放在它原有的位置，不另加单书开关。
- **起跑步骤取受影响的最早一步**：改字形库/对位参数/人裁 → `glyph_match`；改切分钉子/行切 → `row_segment` 且整册重跑；改清格 → `cell_shrink`。
- **base 写带 job 号的包标签**，防止基线漂移。
- **缓存**：升 cv、换 k 都要清 `cache/<册>/{column_image,column_raw,char_patch}`（cv <0.7.7 的 #1414 会让再生字块丢偏旁）；用缓存字块出的图只当参考，改字盲读用原图按 `bbox_page` 裁。
- **比对口径（图为准）**：逐格对 main 分改字/新放行/新退回，另看格数、人裁有无丢、绑定丢失数；盲读拼图只标格号不给字；抽清格固定种子 30 格看有无伤字。
- **标 main 条件**：改错 ≤ 改对；没有新「原对现错」；清格无伤字。与 main 逐格一致的册不重标（对位等中间产物变了则十册都标，好让版本统一）。标完通知 Console（标签、cv、书仓检出、是否清缓存）、Jira、台账。
- **通知与兜底**：任务库收尾通知按 `GUJI_JOBS_WHO` 去花名册找人，名字不在花名册会 404 并静默放弃（史记 r33–r41 就是如此）。花名册名字须英文开头，用 `process/register.py` 登记；并且**每次交单后用 `send_later` 定 60–90 分钟兜底检查**，到点或收到通知就接着取包、比对、标 main、交下一轮，不空等。
- **执行机失联**（日志「worker 失联，次数用完」）与产物无关，用同一份 spec 重交。
