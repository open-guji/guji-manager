# 换线上人审单（首发、换单、落票）

> 现行：2026-11-18（A31，接手 ZM 换单提速六项）。[粗校迭代流程](粗校迭代流程.md) 第三节第 8 步「换线上人审单」的细则，**换单怎么做以本文为准**。
> 来源：全唐文 QTW 11-16～17（005–015 重出带备选字、001–003 首发、一天随 y2／a3／b1 三换）、殿本 ZM 11-14～17（第 1–20 册 g24 换单）、史記 SJ r70–r78 跑批。原始记录在 ai-team（见末节），只作历史，不再在那里加规矩；新坑写到本文第五节。

> 精校阶段的落票细节见 [02 精校／步骤](../02-精校/步骤.md)；格号变了落 book-text 见 [换包落book-text-增删格](../02-精校/换包落book-text-增删格.md)。

## 一、先分清三件事

| 事 | 什么时候 | 怎么做 |
|---|---|---|
| **首发** | 书（或新册）第一次上网站 | book-text **main** 上有该章 cord、书影 IIIF、待审单三样齐全（第三节清单） |
| **换单** | 主包变了（标了新 main），线上单要跟上 | 有票的册：`proof_cycle plan/apply`（落票 → 推库 → `seed_admit` 重放 → 出单）；没票的册：`republish.py issue`；批量：`guji swap run --books …` |
| **落票** | 每次换单之前 | 网站票落成人裁事件；落不了的票换单闸会拦（第四节） |
| **收单（不换包）** | 用户投完一张单、主包没变 | `guji collect --books <册>`：人裁直接落 book-text、条目结案、只发这一章，不重放不重出单（见 [收单](收单.md) 第二节） |

## 二、三条总规矩

1. **网站只发 book-text main。** dev 上的新章、新 cord 网站看不到：首发后「校对页没有整页图、阅读页没有这一册」多半是只到了 dev。合 main（`scripts/daily_merge.py` 或单开 PR）后触发 kaiyuanguji-web `data.yml`（flow=text，约 40 分钟）。想先看 dev 效果：同一工作流选 target=staging、text_ref=dev，看测试站。
2. **`republish push` 不带备选字（alt），也不默认推库。** 首发或手工 push 后要补 `guji audit alt <册> -w <工作区>`＋`republish.py add-alt --yes --sync`；push 一律加 `--sync`（或推完看 `guji db status` 的 unpushed 为空）再触发发站，否则新单只在本机，proofing-sync 照样 success（殿本 019-r10）。批量换单用 `guji swap run`，它自己同步、发布并逐册核线上 rev。
3. **主包一天换几次，别每次都追。** 全唐文 11-17 一天 y2→a3→b1 三换，前两次换单全作废。做法：有票的先落票（落票不依赖哪个主包）；换单等本书总览说「这一批稳了」再做一次；标 main 后的自动重出（`online_lists`）照常，失败了由每日 `--audit` 补。

## 三、首发清单（逐项勾）

- [ ] book-text 已合进 **main**，网站数据已重发（规矩 1）。
- [ ] `ops/iiif/pages-books.json` 有这本书各册，iiif 工作流跑完。
- [ ] 待审单每格都有 alt（规矩 2）。
- [ ] 手动触发 proofing-sync（不等每日定时；target=production、parts=publish、`only=<书ID>/<册>`），逐册读线上 `pending.json` 核格数、rev 和 alt。workflow 显示 success 不算数。
- [ ] 打开校对页、阅读页各看一眼（Playwright 打开即可）。校对页写「这一格没有整页坐标」＝cord 没上线。
- [ ] 冒烟对刚上传的图报 403：CDN 延迟几分钟，等一会儿再核，不是失败。

## 四、换单：标准顺序（每册）

| # | 做什么 | 命令 | 备注 |
|---|---|---|---|
| 1 | **看主包到底标了谁** | `python -m guji_manager.online_lists --audit <册段> -w <工作区>` | 线上单出自的包不是 ★ main，或有格 alt 空，退出码 1；`--fix` 顺带重出。交 seed_admit 重放前也要确认 base 是想要的 main（殿本吃过「重放落在旧包上」的亏） |
| 2 | **标 main 前硬检查** | `guji seg premain`、补锚档扫描（殿本 `/mnt/project-files/zm-pua/scan_migrated_anchor_shift.py <册>`）、逐格比旧 main | 见流程第 6、6b 步；补锚档错一格 cv #1627 已加闸 |
| 3 | **标 main** | `GUJI_AUTO_ONLINE_LISTS=0 guji products pack promote volNN --label L` | 打算手工换单时关掉自动重出，免得两路并发 |
| 4 | **落网站票** | `guji cellvotes draft … --from-kv --items` → `write` → `guji db sync --no-glyph` | 重切过的册见第五节「重切后旧票锚不上」 |
| 5 | **重放 `seed_admit`** | 任务库从 `seed_admit` 起跑，`--compare-to main` | 人裁只有重放后才进产物和 book-text；只落事件不重放，文本不变。`proof_cycle apply` 自带这一步 |
| 6 | **换单** | 批量 `guji swap run --books … -w <工作区> --book-text <检出>`（非殿本加 `--text-id <书ID>`）；单册 `republish.py issue`（`GUJI_PRODUCTS_DIR` 指向放现行 main 包的沙箱） | 引擎要用该包的 cv 版本：`proof_cycle plan --engine <worktree>`（`git worktree add cv-xx vX.Y.Z`，再 `fetch_registry('model')`）。册 yaml 的 `code: N` 变了，书仓要 `git pull` 到有 `code/releases/kN.json` |
| 7 | **发站并核对** | proofing-sync（只发本批 `only=`），再 `curl https://www.openguji.com/api/pending?book=<书>&vol=NNN` 核 rev | `swap run` 已逐批做；手工单册要自己核 |

### 殿本批量换单（auto_cycle，11-18 起）

开新容器先自检，再一条命令跑；被 2 小时上限杀掉就原样再跑一次：

```
eval "$(python3 <guji-dev-secret>/gsecrets.py export)"; export GUJI_ACTOR=<名字>
guji swap doctor -w <工作区路径> --book-text <检出> --cv <cv dev 检出> --books vol21-vol99 --fix --env   # 有 ✗ 先处理；--env 打印 export 行
python scripts/zhengli/auto_cycle.py --books vol21-vol99 -w <工作区路径> --book-text <检出> --land-votes --max-minutes 100
```

- `guji swap doctor` 是 manager #687（dev），随下一版 manager 发；发版前要用就 `uv pip install -e <guji-manager dev 检出>`。
- **编排脚本从 cv dev 检出跑**（auto_cycle／proof_cycle／republish 不进 Step code_deps，不用等发版）；重放 seed_admit 的引擎按 ★main 包 manifest 的 `cv_commit` 另起 worktree（`~/.guji-engines/`），产物口径跟包走。
- **断点续跑**：状态在 `reports/_auto_cycle/state.json`。done 跳过；guard-stop／blocked 缺省跳过（`--retry-blocked` 重试）；上次跑到一半被杀的册先清 book-text 改动和本册沙箱再重做；`--fresh` 从头判。
- **沙箱只清本册**（`_packs/<标签>/<册>`；同标签各册共用目录，cv #1695 前会互删，vol43 吃过亏）；开跑每册前查盘（`GUJI_CYCLE_MIN_FREE_GB` 缺省 8）、半截沙箱不用；同一工作区只许一个 auto_cycle（`reports/_auto_cycle/.lock`）。
- **发站一次**：这次给的册都有结论了才统一发一次网站并逐册读者侧冒烟，发的是历次 done 而还没冒烟成功的册（`--publish-now` 不等）。
- **页表 rev 不符不一定是换源**：殿本各册 r003→r004（vol84 是 r004→r005）只把 staged 转 final，像素、页号都没变；cv #1698 起换单门读 R2 页表链，只换 rev 的按同一套格号比，不要再给 `--cells`（siku-qiefen-v2 对照表是 r1→r2 的旧页号，拿来对 r3 的单会把票全判「无法对位」）。
- **旧单真出在换图源之前**：`--cells` 不给也会自己找 `GUJI_OLD_NEW_CELLS` 或 `~/ai-team/domain/CV/图源迁移/siku-qiefen-v2/results/old_new_cells`（有本册表才用，cv #1697）；对不上新格的票不拦，进「旧单票无法对位」清单交复审。
- **守卫拦下**：自动出 `reports/<册>/_cycle/<rev>/待重挂锚点.tsv` 和汇总 `reports/_auto_cycle/待重挂-<日期>.md`（问题原文、交切分线还是 A33、对照表、补落命令），book-text 里未跟踪的 punct-stale 先留底到 `_cycle/<rev>/book-text-未提交/`。修好后同一条命令加 `--resume-guard`（即 `guji swap book-text --push --sheet`），成了算 done，随下一次统一发站。
- `guji swap run` 仍可用（按批发布、核线上 rev）；它不透传 `--land-votes`／`--cells`，有票没投完或换过图源的册用上面的 auto_cycle。

**票的闸**：「还有 N 格的票没落成人裁」——确认票都已落成人裁（如图形票、`~r` 迁移后已是人裁）才用 `--ack-unlanded-votes "<原因>"` 放行。切坏票、看不清票这类真落不了的，要用户点头才放；脚本里不要预设放行。

## 五、慢和失败：现象与做法

已修的注 PR 号；没注的仍开着，照「做法」绕。

| 坑 | 现象 | 做法／修复 |
|---|---|---|
| 推库慢 | 每次 `guji db pull/sync` 全量重建中心库约 90 秒，一册要 3–4 次；一册换单 10–25 分钟，真计算约 5 分钟 | manager v0.4.55 增量推、v0.4.58 增量拉（殿本 sync 64 s→8 s、有远端改动 97 s→20 s，见 [收单](收单.md) 第三节）；批量仍走 `swap run`（按批同步） |
| push 没 `--sync` | 新单只在本机，网站还是旧单 | 规矩 2；cv #1588 会醒目警告 |
| 读票接口断连 | `/api/cellreview` 偶发 500／ConnectionResetError，出单中断 | cv #1588、`republish._fetch_votes` 已加退避重试；中断后先看 `guji db status` unpushed 再补推 |
| 磁盘满 | 每册 `_cycle` 产物包约 150MB、沙箱 0.3–5.6GB，`No space left on device`，db sync 半途失败 | 用完即删；`swap run` 核过线上的册自动清盘；auto_cycle 每册前查盘（cv #1695） |
| 别的册的沙箱被清掉 | auto_cycle 清 `_packs/<标签>` 整目录，同标签别的册产物没了（vol43） | cv #1695 只清本册、半截沙箱不用、工作区加锁 |
| 后台命令 2 小时被杀 | 跑到一半的册 book-text 留改动，再跑从头判 | cv #1695 状态文件：`--max-minutes 100`，原命令再跑接着做 |
| 新容器缺件 | PATH/PYTHONPATH 指错 cv、少令牌、`-w` 写成 id、book-text 稀疏检出没本书、引擎没 CNN 权重 | `guji swap doctor --fix --env`（manager #687） |
| 守卫拦下要人转发 `_cycle` | 切分线／A33 拿不到清单 | cv #1695 自动出 待重挂锚点清单，修好后 `--resume-guard` |
| `db pull` 报本地有改动未推 | 拒绝 pull | 先 `guji db sync --no-glyph`；缺文件被拒（FileDeleteRefused）不要 `--allow-delete`：备份未推文件 → `db pull --force` → 只恢复自己的文件（别动 books/、config/、output/ 里别人会改的） |
| 网站发布并发互相取消 | 补触发的 run 被 concurrency 取消 | 补触发时加 `only=<书ID>/<册>` |
| 图形票落了事件，格子又回单上 | `cellvotes write --no-consume` 跳过排除名单 | manager #604 已修；旧批次补跑 `guji events route <批次>` |
| 单里有图片格，book-text 拒推 | 校验 F-OV-13：有图没声明 fig_file | cv #1588：出单自动拷 `NNN.fig.json`、裁图、声明 fig_file |
| 重切后旧票锚不上 | 绑定 status=review，人裁不生效，机器字顶上 | 用新包做 products_root 重写同票：草稿 id 带册前缀（`vol15:25:4:11a`）；**先按新包重建本地字块缓存**（`guji cache verify --book <册> --pages <页> --fix`，或跑一次 human_chars），否则锚指纹不符；写完用 `book_bindings` 核 status=valid 再重放 |
| 补锚档错一格 | backfill:migrated 旧人裁 IoU 1.0 落到邻格 | cv #1627 加闸（两框落格不同 → review）；扫描脚本 `--fix` 改用上一版锚框 |
| 册 yaml 改钉后用旧 cv 交任务 | CorpusDrift／BookCodeError 拒跑 | 交单 `--cv` 与册 yaml 一致；逐册 `guji book show` 核生效的 cv／code |
| 空单 | book-text 不更新 | `republish.py issue --allow-empty` |
| book-text 工作区不干净 | push 拒绝 | `git checkout -- . && git clean -qfd Book && git pull --rebase origin dev` |
| 用户在票的备注里说「要改的是前后格」 | 票落到被投的那格 | 按备注改写目标格的人裁再重放，备注原话写进 `payload.note` |
| 任务完成通知投错线 | 通知落到别的线程 | 自己 `guji job wait`／`job show --log`，不等通知 |
| follow_main 自动重出失败没报警 | 线上单停在旧包（全唐文 005–015 停在 11-08 单） | manager #591、#601、#602 已修钩子；每日 `online_lists --audit` 定时核对 |
| 线程之间转来的批量换单请求 | 自动权限拦下 | 在本线程请用户写一句「动作＋范围」 |

## 六、标点锚点

格号变了旧标点锚点要迁：□→字、旧格劈成 NNa/NNb 自动迁（manager #600）。「旧格被删」的锚点迁不了，`bump punct` 会拒绝：手工把标点挪到新文本里对应的格，不要硬删。迁不了的锚点在换单时按 A01–A03 留给点校（见 [标main后收尾](../02-精校/标main后收尾.md)）。
