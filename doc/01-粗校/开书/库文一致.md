# 库文一致：字形库的字和文本的字逐格核对

> 2026-11-18 Sheldon 定：「我们的字形库和实际的文本应该要是一致的」，整个过程要自动。
> 代码 `guji_manager/ops/lib_text_check.py`，命令 `guji glyph-db text-check`。

## 一、要解决的问题

字形库和文本是同一格的两份记录。库里记「这块图是什么字」，文本记「这一格显示什么字」
（`seed_admit` 产物，换包后进 book-text）。两边各改各的：

- 体检撤库、改标（`glyph_audit`）只动库。文本要等那一册下次重跑第 7 步、换包才跟着变。
- 人裁、重跑只动文本。库里那一格早先入的机器刻例不会自己改。

中间原先没有任何一步核对两边。全唐文 11-17 夜改标 138 例后实测，b2 产物 001–045 册 36,044 个刻例里
158 格两边不一样：75 格是当晚改标后文本还没重算，其余 83 格是早就不一致、一直没人发现的。

## 二、怎么比

一册一册比。库里 `v2:<册>:…` 的每个刻例，对本机 `seed_admit` 产物里同一格的字。两边先按书级码位归一
（`config/codepoints.yaml`，陝／陜、寛／寬 这类不算不一致）再比。不一样的分类处理：

| 类 | 判据 | 加 `--apply` 时怎么办 |
|---|---|---|
| 文本过期 `text_stale` | 库例入库时刻晚于这一页的计算时刻（`_manifest.jsonl` 的 `ts`；取包会刷新文件时刻，不能用） | 这一页 `seed_admit` 标失效；`guji rerun --stale <册>` 重算后文本跟上 |
| 库图错位 `shifted` | 库标正是同一列上下邻格的字 | 库图是旧切分的字块、格号整体挪过。机器来路的撤库例（文本不动），人裁来路的只报 |
| 文本是人裁 `follow_human` | 文本通道是人裁，库例是机器来路或更早的人裁 | 库例改成文本的字 |
| 两边都是机器 `machine` | 文本机器放行，库例机器来路 | 库图过字体模板（十万字选一）重新识别，见下 |
| 库是人裁、文本没采信 `human_unapplied` | 库例人裁来路，文本机器放行了别的字 | 这一格加进待审单当复审格，库不动 |
| 格没了 `orphan` | 库例的格在产物里不存在 | 机器来路的撤库例；人裁来路的只报 |
| 格在待审 `pending` | 文本这一格没放行 | 不处理 |

两边都是机器时，按字体模板首位分三种：

- 认成文本的字，且模板首位领先次位不少于 0.03：库标错了，库例改标，仍是机器来路（`glyph_audit relabel` 带 `provenance: auto`）。领先不到 0.03 的不凭它改库，进待审复审。
- 认成库标：文本可疑。**不直接改文本**，这一格加进待审单当复审格，说明里写两边各是什么字。
- 都不是：库标和文本都没有佐证，撤库例，并让这一格回人审（撤库事件带 `review`，下一轮 `seed_admit` 退回待审）。

「库是人裁、文本没采信」多半是切分变过，人裁落到了别的格上（全唐文实测 輪／上、相／王、寧／及），所以送人看，不拿人裁去改文本。

## 三、怎么跑

```bash
guji glyph-db text-check --books 001,002 -w <工作区>                    # 只报告
guji glyph-db text-check --books 001,002 -w <工作区> --report r.json    # 逐格报告
guji glyph-db text-check --books 001,002 -w <工作区> --apply            # 处理
guji rerun --stale 001 -w <工作区>                                      # 标失效的页重算，文本跟上
guji db sync -w <工作区>                                                # 库、事件、待审单推上中心库
```

要求本机有这些册的 `seed_admit` 产物（没有的册会列出来，先 `guji products pack fetch`）。`--apply` 前有同
放行格回库一样的护栏（借库跑批、部分副本、本机库比账本旧时拒绝）。

自动：`guji pipeline` 整册跑完，在放行格回库之后对这一册比一遍。`workspace.yaml`：

```yaml
glyph_lib:
  text_check: report    # 缺省。只报告，有不一致打一行提醒
  # text_check: apply   # 跑完自动处理
  # text_check: false   # 关
```

`GUJI_LIB_TEXT_CHECK=0` 临时关。

## 四、改库之后的规矩

对中心库撤库、改标之后（体检、重分卡、清边换图等），**当场**对受影响的册跑一遍 `text-check`，
把「文本过期」的页重算、换包，不要等下一轮。每轮收尾时各册的不一致数应当是 0，或者只剩已经进了待审单的格。

| 格在待审 | 45 | |

## 六、边界

- 只比库里有刻例的格。库里没有刻例的格，文本对不对不归这里管。
- 字体模板对形近字会错，所以「认成库标」时只送人审，不改文本；「认成文本的字」是模板和管线两路独立证据一致才改库。
- 进待审单的复审格用 `script:lib_text_check` 作来源，下一轮出单按条目规矩留着。
- 只改本机的库和数据目录，随 `guji db sync` 推上去；跑批机若不推库，要在有全量库的机器上跑。
