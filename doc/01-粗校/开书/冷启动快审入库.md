# 冷启动快审入库：每册「库里没有或很少的字」

> 用户 2026-11-09 定（全唐文 001–003 起）：每册里**本书字形库没有、或刻例很少的字**，都走一次快审，每个字头由人确认 3 个代表格，再收进本书字形库，作为这一册的冷启动。之后从 `glyph_match` 起重跑。
> 第一次实例：全唐文 995ejelvk0 册 001–003 的 front10 包，735 个字头。

## 分工

| 环节 | 谁做 | 产出 |
|---|---|---|
| 1. 挑字头、出页 | 人审页线 | char_card 页（Artifact，带 db 能力） |
| 2. 人点 | 用户 | 页面后台 `review` 集合 |
| 3. 收成人裁事件、推库 | 人审页线 | 事件批次 `H-cold-<册段>-<MMDD>`，推中心库 |
| 4. 确认格收进字形库、推库 | 字形线 | 中心库 rev，报给总览 |
| 5. 重跑 | 总览 | 从 `glyph_match` 起 |

## 1. 挑字头、出页（人审页线）

- **选格**：取这一册包里 `seed_admit` 未放行的格，按 `glyph_match` 首位字和整理本字归组。字头满足下面任一条就上页：
  - 库里没有这个字（doubts 有「库里没有这个字」，或首位字在 `glyph_store/exemplars.jsonl` 里是 0 例）；
  - 首位字的本书刻例少于 5 例。
- **先撤掉**：
  - 印章、遮挡格；
  - 切分线的格（双行小字数字被并成一格、半字、边框、碎片）。这类格交切分线，**不要上快审页**。全唐文 001–003 里「库里没有这个字」的格几乎全是这类。
- **出页**：
  ```bash
  guji-manager review-pages build char_card --items page.jsonl --book <书ID> --per-card 3 --out card.html
  ```
  用 Artifact 发布，要有 db 能力。每个字头放 3 个代表格，按 glyph_match 首位 cov 从高往低取，污渍、残块自然排在后面。

## 2. 人点（用户）

逐格点选（char_card ≥1.1.0）：

- 不点＝对；
- 点 1 下＝切分有问题；
- 点 2 下＝改字；
- 点 3 下＝看不清。

卡头可以整卡改字。

## 3. 收成人裁事件（人审页线）

```bash
ArtifactData list review  →  res/
guji-manager review-pages expand --cards card.cards.json --results res/ --out decisions.jsonl
```

把 decisions 写成事件，规则如下：

- **只写人点过的代表格**，跟随格不写。
- 一格一条，`kind=confirm`、`actor=user`、`reviewer=<点的人>`。
- payload：`{"v":"confirm","shape":<字>,"source":"cold_start_char_card","via":"char_card"}`。
  - 字取卡头字。改字的格取人填的字。
  - `source` 不能写 `vision`、`llm`、`knn_infer`、`auto`。写了这几种，cv 的 `counts_as_human` 不当人裁，就进不了 human。
- 切分有问题、看不清的格不写 confirm，另列清单交切分线。
- **批次名**：`H-cold-<册段>-<MMDD>`，例如 `H-cold-001-003-1109`。分波收的就加后缀：`H-cold-001-003-1109a`、`…b`。
- 带锚（`target.anchor`，和其它 H- 批次一样），重切以后才能重绑。
- 写完先 `guji events lint`，再 `guji db pull`、dry-run、推中心库。把**批次名**和 rev 告诉字形线。

## 4. 确认格收进字形库（字形线）

人裁事件推上中心库，**不会自动进字形库**：各线同步都用 `--no-admit`。所以这一步要单独做：

```bash
cd <工作区>                       # 如 guji-workspace/995ejelvk0-quan-tang-wen
export GUJI_WORKSPACE=$PWD GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD GUJI_ACTOR=<线名>
export GUJI_PRODUCTS_DIR=<出页用的那版包目录>   # glyphdb_admit 要从包里取字块图
guji db pull -w .
guji events route H-cold-001-003-1109 --dry-run -w .   # 看 glyphdb_admit：added≈确认格数，unbound/errors 应为 0
guji events route H-cold-001-003-1109 -w .             # 落库：provenance=human（写 glyph.db＋consumed 记账）
guji db sync --no-admit --dry-run -w .                 # glyph_exported 要是 true；glyph_admissions/instances insert≈新格、update＝原 auto 改成人裁的格；exemplars 的 delete＝被换掉的旧标签行；0 成批 delete
guji db sync --no-admit -w .                           # 记下 rev_to
```

要点：

- **route 之后不要跑 `guji glyph-db rebuild --no-replay`**：它按 glyph_store 重建 glyph.db，会把刚落进去的人裁冲掉，consumed 记账却还留着（全唐文 11-09 踩过：dry-run 出现 consumed insert，但 glyph_exported 是 false）。踩了就 `guji db pull --force` 丢掉本机改动，再 route 一遍。直接 sync 就行，它会把 glyph.db 导出到 glyph_store。
- **provenance 是 human**：`glyphdb_admit` 消费 `actor=user` 且 `counts_as_human` 的 confirm 事件，写的就是 `provenance="human"`。不用另写脚本，不要用 `admit_instance(provenance='auto')` 那套。
- **unbound 不为 0**：说明这一格在当前包里已经重切了，事件对不上。把格号报给人审页线，按锚重绑或者撤掉。不要硬收。
- **改字（shape≠首位字）的格**：照收，标签就用人填的字。字头原先 0 例的，会新建这个字的条目。
- **库里同一格原来是 auto 刻例**：
  - 字不同：消费者会撤掉旧的，换成人裁（「改判撤旧进新」）。
  - **字相同**：guji-manager ≥0.4.30（PR #416，GUJI-764）会撤掉 auto、升成 human，计入 updated。更早的版本会走幂等闸记 skipped，库里留着 auto。所以落库要用 ≥0.4.30，route 之后查一下这一批的格在 admissions 里是不是全是 human。
- 推完把 rev 报给总览，总览从 `glyph_match` 起重跑。轮中（交单到出包）不推。

## 高把握／低把握两张页（全唐文 001–003 c35 第二层，2026-11-09 起；以后每册照做）

> 用户（Sheldon）11-09 看过实例，原话：「这个高低把握卡设计得很好」，要求写成经验和流程、模板固化。头一版「每字头 3 代表格」页对大批单格字头太慢（735 张卡 92 页），改成按把握分页。

**何时用：** 新书、新册冷启动，**切分清零之后**（切分线的格先撤掉），待审里「库缺样本」那一层（参校本字或 5b 首位在本书库里 <5 例）。先出这一层；形近字组、其余层不走这页。

**怎么分档**（依据 `qtw-tools/冷启动加速/对照.md`：456 个人点代表格，5a＝5b 且 cov .90–.95 对率 97.5%，5b 领先≥.03 对率 98.8%，库 0 例的格 5a 全错、5b 对 83%）：

| 页 | 条件 | 页型与参数 | 点法 |
|---|---|---|---|
| 高把握 | （库首位＝5b 首位，或 5b 领先第二名≥.03）**且** cov≥.90 **且** 库里该字有例 | `char_card` 1.5.4，`--per-card 3`，带「本页其余都对」 | 认得对的不点，页尾点一下整页确认；不对的格改字或标切分有问题 |
| 低把握 | 其余：库与 5b 不一致且领先小、库 0 例、cov<.90 | `char_card` 1.5.4，`--per-card 1 --no-rest-ok`（一格一卡） | 逐格点；没点不算对；认不出点「认不出」 |

5b 领先量＝包里 `rare_candidates` 的 emb 候选，同一格按分排序后首位减次位。不上页的格：木入八己已巳（看图分不开，走文意／形近字组）、字组成员、切分线的格、001 职名页等切分线另在做的列、已点过的格。

**一条命令出页**（全部已固化，在 `review_pages/cold_start.py`）：

```bash
# 0. 每册先拉包（guji products pack fetch），再按 cell_shrink 字框裁图
guji-manager review-pages crop --cells ids.txt --shrink-dir '<包>/{vol}/cell_shrink' \
    --pages-dir '<工作区>/data_full/{vol}' --page-name '{page}.png' --out crops/
# 1. 分档 → hi.jsonl / lo.jsonl（--where 层=2 只取库缺样本层；--skip 已点格；--skip-chars 木入八己已巳）
guji-manager review-pages cold-items --cells 待审四层.tsv --where 层=2 \
    --pack-dir '<包>/{vol}' --crops-dir 'crops/{cell}.png' --out-dir out/ \
    --skip 已点格号.txt --skip-chars 木入八己已巳
# 2. 出两张页 out/hi.html、out/lo.html
guji-manager review-pages cold-pages --out-dir out/ --book <书ID> --tag " 册001-003"
```

待审 tsv 要有列：`cell、参校本、库首位、cov、5b前三、库例数、疑问`（总览 `待审四层.tsv` 就是）。两张页都要用 Artifact 发布并带 `capabilities {"db":{}}`。

**收：** 和上面第 3、4 步一样。高把握页「本页其余都对」点过的页，所有格按确认算；低把握页只算点过的格。批次名 `H-cold-<册段>-<MMDD>b`（高）、`…c`（低），`source=cold_start_char_card`，字形线 `route`＋`glyphdb_admit` 入库，**不要**跑 `rebuild --no-replay`。认不出、切分有问题、看不清的格不写 confirm，另列清单（`qtw-tools/冷启动加速/…-未写事件.tsv`）。

**已知问题（实例 11-09，c35 第二层 334 格）：** 低把握页里「认不出」多半是候选里没有对的字（候选只有 5b 前三＋库首位＋参校本）。这些格要另出一张难认字页，给更多候选：IDS 部件、扩展 B 以后的字、整理本、字体模板（做法同全唐文难认异体页，A23 候选）。高把握格偏少，是因为这一层多是单格字头。

**实例数字：** 低把握页 279 格，Sheldon 点了 233 格（对 130、改字 80、认不出 6、不是字 2、切分有问题 12、看不清 3）；高把握页 55 格，7 页「本页其余都对」，改字 10、切分有问题 1。

## 5. 重跑后看什么

- 这一册「刻例不足」「库里没有」两类待审应该明显下降。
- 还剩下的，多半是：
  - 这一册里只出现 1–2 次的字，补不到；
  - 切分问题。
- 3 个代表格进库以后，同字其余格靠 5a 自动验。验不过的才回到人。不要为了凑例数再出页。

## 全唐文经验（2026-11-08，front3／front8，机器看图补的 auto 刻例）

- 首位候选 cov 在 0.95–0.98、刻例不足 5 的格，看图后大约一半的首位字是错的。错的是因为真字库里没有，候选落在形近字上：如 馮 落成 馬，吳 落成 英／具／晏，鉉 落成 銓，詠 落成 誅，逢 落成 達／連。所以这一步必须由人确认（或改字），不能按首位字直接收。
- 「库里没有这个字」的格基本都是切分碎片，要交切分线，不进快审页。
