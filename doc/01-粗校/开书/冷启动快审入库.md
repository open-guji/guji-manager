# 冷启动快审入库：人裁事件进本书字形库

> **选字、分层、页模板、批号后缀、验收**一律看 [字形快速入库：四层页](字形快速入库.md)（Sheldon 2026-11-10 定）。本文只留它第四节引用的两步细命令：第 3 节「收成人裁事件」和第 4 节「确认格收进字形库」。

> 用户 2026-11-09 定（全唐文 001–003 起）：每册里**本书字形库没有、或刻例很少的字**，都走一次快审，每个字头由人确认 3 个代表格，再收进本书字形库，作为这一册的冷启动。之后从 `glyph_match` 起重跑。
> 第一次实例：全唐文 995ejelvk0 册 001–003 的 front10 包，735 个字头。

## 分工

| 环节 | 谁做 | 产出 |
|---|---|---|
| 1. 挑字头、出页 | 人审页线 | char_card 页（Artifact，带 db 能力） |
| 2. 人点 | 用户 | 页面后台 `review` 集合 |
| 3. 收成人裁事件、推库 | 人审页线 | 事件批次 `H-cold-<册段>-<MMDD>`，推中心库 |
| 4. 确认格收进字形库、推库 | 字形线 | 中心库 rev，报给总览 |
| 5. 重跑 | 总览 | 从 `glyph_match` 起 |

## 1–2. 挑字、出页、人点

见[字形快速入库](字形快速入库.md)第一～三节。

## 3. 收成人裁事件（人审页线）

```bash
ArtifactData list review  →  res/
guji-manager review-pages expand --cards card.cards.json --results res/ --out decisions.jsonl
```

把 decisions 写成事件，规则如下：

- **只写人点过的代表格**，跟随格不写。
- 一格一条，`kind=confirm`、`actor=user`、`reviewer=<点的人>`。
- payload：`{"v":"confirm","shape":<字>,"source":"cold_start_char_card","via":"char_card"}`。
  - 字取卡头字。改字的格取人填的字。
  - `source` 不能写 `vision`、`llm`、`knn_infer`、`auto`。写了这几种，cv 的 `counts_as_human` 不当人裁，就进不了 human。
- 切分有问题、看不清的格不写 confirm，另列清单交切分线。
- **批次名**：`H-cold-<册段>-<MMDD>` 加层后缀（快审单 `q`、高置信度 `b`、低置信度 `c`、难认字 `d`，分波再加数字），见[字形快速入库](字形快速入库.md)第四节。全唐文 11-09 首批用的是旧写法 `H-cold-001-003-1109a/b/c`（a/b/c 是波次）。
- **不入库**：勾了「不入库」的格写 `no_glyph_lib: true`（char_card ≥1.6.0）。glyphdb_admit 照常算人裁，不建库，计入 no_lib。
- 带锚（`target.anchor`，和其它 H- 批次一样），重切以后才能重绑。
- 写完先 `guji events lint`，再 `guji db pull`、dry-run、推中心库。把**批次名**和 rev 告诉字形线。

## 4. 确认格收进字形库（字形线）

人裁事件推上中心库，**不会自动进字形库**：各线同步都用 `--no-admit`。所以这一步要单独做：

```bash
cd <工作区>                       # 如 guji-workspace/995ejelvk0-quan-tang-wen
export GUJI_WORKSPACE=$PWD GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD GUJI_ACTOR=<线名>
export GUJI_PRODUCTS_DIR=<出页用的那版包目录>   # glyphdb_admit 要从包里取字块图
guji db pull -w .
guji events route H-cold-001-003-1109 --dry-run -w .   # 看 glyphdb_admit：added≈确认格数，unbound/errors 应为 0
guji events route H-cold-001-003-1109 -w .             # 落库：provenance=human（写 glyph.db＋consumed 记账）
guji db sync --no-admit --dry-run -w .                 # glyph_exported 要是 true；glyph_admissions/instances insert≈新格、update＝原 auto 改成人裁的格；exemplars 的 delete＝被换掉的旧标签行；0 成批 delete
guji db sync --no-admit -w .                           # 记下 rev_to
```

要点：

- **route 之后不要跑 `guji glyph-db rebuild --no-replay`**：它按 glyph_store 重建 glyph.db，会把刚落进去的人裁冲掉，consumed 记账却还留着（全唐文 11-09 踩过：dry-run 出现 consumed insert，但 glyph_exported 是 false）。踩了就 `guji db pull --force` 丢掉本机改动，再 route 一遍。直接 sync 就行，它会把 glyph.db 导出到 glyph_store。
- **provenance 是 human**：`glyphdb_admit` 消费 `actor=user` 且 `counts_as_human` 的 confirm 事件，写的就是 `provenance="human"`。不用另写脚本，不要用 `admit_instance(provenance='auto')` 那套。
- **unbound 不为 0**：说明这一格在当前包里已经重切了，事件对不上。把格号报给人审页线，按锚重绑或者撤掉。不要硬收。
- **改字（shape≠首位字）的格**：照收，标签就用人填的字。字头原先 0 例的，会新建这个字的条目。
- **库里同一格原来是 auto 刻例**：
  - 字不同：消费者会撤掉旧的，换成人裁（「改判撤旧进新」）。
  - **字相同**：guji-manager ≥0.4.30（PR #416，GUJI-764）会撤掉 auto、升成 human，计入 updated。更早的版本会走幂等闸记 skipped，库里留着 auto。所以落库要用 ≥0.4.30，route 之后查一下这一批的格在 admissions 里是不是全是 human。
- 推完把 rev 报给总览，总览从 `glyph_match` 起重跑。轮中（交单到出包）不推。

## 5. 重跑后看什么

- 这一册「刻例不足」「库里没有」两类待审应该明显下降。
- 还剩下的，多半是：
  - 这一册里只出现 1–2 次的字，补不到；
  - 切分问题。
- 3 个代表格进库以后，同字其余格靠 5a 自动验。验不过的才回到人。不要为了凑例数再出页。

## 全唐文经验（2026-11-08，front3／front8，机器看图补的 auto 刻例）

- 首位候选 cov 在 0.95–0.98、刻例不足 5 的格，看图后大约一半的首位字是错的。错的是因为真字库里没有，候选落在形近字上：如 馮 落成 馬，吳 落成 英／具／晏，鉉 落成 銓，詠 落成 誅，逢 落成 達／連。所以这一步必须由人确认（或改字），不能按首位字直接收。
- 「库里没有这个字」的格基本都是切分碎片，要交切分线，不进快审页。
