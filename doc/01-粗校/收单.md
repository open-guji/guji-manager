> 现行：2026-11-18（A31）。[粗校迭代流程](粗校迭代流程.md) 第 8 步里「收单」这一段的细则，**收单怎么做以本文为准**。
> 换单的总规矩（首发、主包变了跟单、三条总规矩、坑表）见 [换线上人审单](换线上人审单.md)，本文不重复。

## 一、收单是哪一段

用户在网站投完票 → **落票**成人裁 → **推库** → **seed_admit 重放** → **出新单** → **book-text 升版** → **中心库同步** → **发站并核线上 rev**。

两条硬规矩（用户定，不随本文改）：
- book-text 只录首选字；待审原因、候选、人裁事件都在 KV／中心库。
- 线上人审单以最新一轮为准，机器结果不覆盖人裁。

## 二、用哪条路

| 情形 | 走法 | 一册耗时（11-17 实测，提速前） |
|---|---|---|
| 一批册、主包已稳 | `guji swap run --books <段> -w <工作区> --book-text <检出>`（非殿本加 `--text-id <书ID>`；册名可写 `001-015`、`01-42`） | 殿本 20 册 3.4 h，每册中位 6 分 |
| 单册、有票 | `proof_cycle.py plan` → `apply`（落票、推库、重放、出单、book-text 一条龙） | 全唐文约 23 分 |
| 单册、没票 | `republish.py issue` | 全唐文 8–10 分 |
| 只落票不改文本 | `guji cellvotes draft --from-kv --items` → `write` → `guji db sync` | 殿本第一册 10–20 分 |

史記到 11-17 还没上过线上单，没有收单实测。它的人裁走卡片审阅页回流（写裁定 → 推库 → 页级重放），见汇总文档。

`swap run` 每 6 册一批：逐册 auto_cycle（plan/apply）→ 批末一次 `db sync` → 这批章一次 proofing-sync（`only=` 多章）→ 逐册核线上 rev，核过的册续跑时跳过。云端会话一个后台命令最多 2 小时，一次交不超过 12 册，被停了照原命令续跑。

## 三、已做的提速（都在现行版本里）

| 改动 | 版本 | 效果 |
|---|---|---|
| `db sync／push` 增量推：只扫只比改了的文件，清单 sha 按 mtime 缓存 | manager v0.4.55（#628） | 殿本有本地改动的 sync 64 s → 8 s |
| `db pull／sync` 增量拉：按 `changes` 表只取库里改了的文件；字形库 instances 这类大台账只补改了的行，整文件 sha 对上才用 | manager v0.4.58（#640） | 殿本 4 个文件远端改动的 sync 97 s → 20 s；结果与整拉逐字节同 |
| 放行格自动回库，对所有书缺省开 | manager v0.4.55（#624） | 不再每册手工回库 |
| book-text 只差码位归一的格留现行字 | manager v0.4.56（#634） | 1.x 不再把 宮→宫 之类改反 |
| `swap run／book-text／finish-merged` 支持非殿本 | manager v0.4.57（#637） | 全唐文、史記可走批量 |
| 落完票新单 0 格也换成空单、升 book-text；auto_cycle 停下的原因取最后一条 ✗ 行 | cv #1643（dev，随下一版 cv） | 殿本 vol08 这类空单不用手工补推；state.json 的 why 写真原因 |
| 读票接口退避重试；push 缺省就 sync 并发站 | cv #1588、#1641 | 不再漏推、少断连重跑 |

增量拉退回整拉的情形：整批导入、变更超过 2 万条或文件超过 400 个、旧数据源、`pull --force／--exclude／--repair-gaps`、新机器。`GUJI_DB_FULL_PULL=1` 强制整拉，`GUJI_DB_FULL_SCAN=1` 强制整扫推。输出里 `scan` 写着这次走的是 incremental 还是 full。

## 四、收单前后要核的

1. **先问用户有没有正在投的册**。`swap run` 遇到正在投的册会判 waiting、不换，这是对的。
2. **看主包标的是谁**：`python -m guji_manager.online_lists --audit <册段> -w <工作区>`。
3. **票的闸**（「还有 N 格的票没落成人裁」）：确认票都已落成人裁才用 `--ack-unlanded-votes "<原因>"`。全唐文 QTW 报 Sheldon 11-17 定这三类（切坏票、看不清票、已有同样人裁）以后一律放行；别的书、别的类型仍要用户点头。
4. **重切过的册**先按新包重建字块缓存，再落票（见换单文档坑表「重切后旧票锚不上」）。
5. **收完核线上 rev**：`curl https://www.openguji.com/api/pending?book=<书ID>&vol=<章>`。proofing-sync 显示 success 不算数。
