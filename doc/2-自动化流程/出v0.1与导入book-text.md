# 出 v0.1、导入 book-text

> 第二步「迭代」本批收尾。判停三问与用户参与见[迭代流程](../../wiki/自动化流程/迭代流程.md)第六节。出 v0.1 只要求 2b–2d 判停，不等第三步。

## 做什么

1. 过[判停三问](../../wiki/自动化流程/降人审迭代框架.md#判停三问)。
2. 出收口单（`closeout` 页）：每类剩余格的去向只有三个（Sheldon 11-06 定）：
   - 放行：就这样出 v0.1，放行之后精校不再看这类格；
   - 留人审：机器判不了、终须人看书影的格（D02、真异文、断烂图源、参照缺字、闕文、遮挡、H01 极难字）；
   - 算法再处理：还能让算法压下去的，出 v0.1 前再跑一轮。
   **还有任何一格是「算法再处理」，就不出 v0.1。**
3. 三类里没有「算法再处理」，最后一轮标 main，出 v0.1（book-text 文本线 0.1.0）。
4. 交接单随 v0.1 交出：「留人审」的格交给精校（A32），H01 极难字清单写进交接单，不另行通知；「放行」的格精校不再看。

## 一条命令

`tools/开书/出v01.py`（2026-11-08，全唐文 004 首用）：取 main 包 → 第 1 步的机器部分 → 第五步产物（`guji output export md`＋`guji pipeline collate`，close-check 第 12 项要，见下文 R5）（待审格按 pending_reason 分，切分类＝算法再处理就停、按页列出）→ 交接单（剩余格默认全留人审）→ 导出＋出待审单（`guji land` 的 `land_text.export_cmd`，GM2 #1193；原 `republish.py from-pack`）→ book-text 加章 → `local_check.py --dev`。推库、推 book-text、网站不做，末尾打印命令。`--gate-only` 只判停。

| # | 条件 | 判 |

### R5 第 12 项「第五步产物（原 Step9）」从哪来（2026-11-16 A31 定，史記预演提出）

rough 档只放宽第 2 项（待审只报数），**第 12 项照计**：出 0.1.0 必须有 `reports/<册>/<册>.md` 与 `collation_*.html`。
任务库产物包里**不带**这些产物（原 Step9，现第五步排版输出）（它跨页，不进 `products/`），所以在取 main 包的那台机器上本地补出，两条都只读产物：

```bash
# GUJI_PRODUCTS_DIR 指向取包的沙箱；包已用 guji pipeline products pack fetch <册> --label <main 包标签> --to $GUJI_PRODUCTS_DIR 取下
guji output export md <册> -w <工作区>              # → reports/<册>/<册>.md（9.1 逐列文本）＋ .approx.tsv
guji pipeline collate <册> --console "" -w <工作区>    # → reports/<册>/collation_<时间>.json/.html（与书配置 references 对勘）
guji pipeline close-check <册> --tier rough -w <工作区>
```

`tools/开书/出v01.py` 取包后自动跑前两条。用途：`<册>.md` 是 9.1 逐列文本（维基文库导出、分段的输入），对勘 html 是与整理本／参校本的差异总表，粗校出口留一份作 v0.1 的对勘底账。不要为过这一项去改 rough 档。

## 每轮重落的验收（对比 A→B），顺序固定

1. 放行字变 = 0，或逐格看图确认全是改对；
2. 人裁没带过来 = 0；
3. 人审率下降且不靠松阈值；
4. 切没了／新切出的列有交代；
5. 新出现的送审类别有解释。

放行错必须为 0 是目标；字形判法上线门槛是按册留出 0 错。重跑完默认标 main 推库，只有程序级严重 bug 才拦，少数错放是预期内的，不要求零回退。

## 本步骤完成标准
每册都有统一格式的粗校报告＋异常表；R3 超标的册写出分类原因；待审分类报告每轮更新；没有「只在某会话里知道」的结论（全部落进文档或 Jira）。
