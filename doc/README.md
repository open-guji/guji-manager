## 整理全流程

```
粗校（开书→v0.1） ──▶ 精校 ──▶ 点校 ──▶（版本达 1.0 之后）反馈迭代
       01              02       03              04
```

- **11-08 起试行：粗校 v0.1 之后先点校、再精校**（点校时 AI 读文意顺带判字），见 [点校先于精校](03-点校/点校先于精校.md)；下图目录序号暂不改。
- 原「开新书」一步 11-05 并进 01 粗校：开书到 v0.1 是一个完整流程，序号随之前移。
- 第 1–3 步在做的过程中都会把结果发布、推送到 book-text，**发布不是单独一步**，各步文档里自己写清推送的命令和检查。
- 第 4 步专指：版本达到 1.0 之后，如何迭代网站上用户的报错和反馈，以及算法提高后机器给出的反馈。它与第 1–3 步相互独立，排在它们后面。

## 每个步骤目录的统一模板

目标 → 入口条件 → 步骤（命令、仓、令牌）→ 验收标准 → 产出（含推送到哪） → 谁做 → 常见坑 → 相关案例。

## 写文档的规矩

- 公开仓：不写令牌、密码、内部地址。
- 迁自 ai-team 的文档，迁完在 ai-team 原位置留一行指向这里；ai-team 另有索引（`通用/整理流程文档索引.md`）。
- 新踩的坑先写进对应步骤文档的「常见坑」，跨步骤的进 [经验](经验/)。
- 本目录是操作手册；「看图懂系统」的入门在 [Wiki](https://github.com/open-guji/guji-manager/wiki)（源文件 `../wiki/`）。Wiki 不随 PATCH 改，每升一次 MINOR 版整体重改一遍。
