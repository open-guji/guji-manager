# guji-manager 文档

怎么把一套书（一个 book ID）文本化：每一步做什么、调哪个命令、怎么与中心库／R2／book-text 配合、验收标准、踩过的坑。
识别算法本身（切分、识别、定字）的文档在 [open-guji-cv](https://github.com/open-guji/open-guji-cv)；团队怎么协作（通信、红线、分工）在 ai-team 仓。「看图懂系统」的入门在 [Wiki](https://github.com/open-guji/guji-manager/wiki)（源文件 `../wiki/`）。

## 四大步

```
第一步 新书启动          第二步 迭代（多册分批）            第三步 AI 文意判字、    第四步 网站人审、
 a 元数据与资源          a 跑 CV 管线                      标点、专名             更新 book-text、
 b 页面分析与参数   ──▶  b 切分检查与优化            ──▶                    ──▶  版本迭代
 c 选页试运行            c 少见字入库、OCR 候选                                  （0.x → 1.0 → 1.x）
                         d 形近字处理
   关口 A：先行册达标        完成一批标 v0.1、导入 book-text
```

| 步 | 做什么 | 出口 | 文档 |
|---|---|---|---|
| **1 新书启动** | 书目、原图、整理本、工作区；量版式、定参数；先行册选页试跑、首批字形入库 | 关口 A：先行册无成片切分错、放行 ≥90%、常用字有本书刻例 | [1-新书启动](1-新书启动/) |
| **2 迭代** | 10 册一批，一轮一轮跑管线、修切分、补少见字、处理形近字；初期人参与多，数据多了逐步减少 | 本批 b–d 判停，标 v0.1，导入 book-text、上网站 | [2-迭代](2-迭代/)（主文 [迭代流程](2-迭代/迭代流程.md)） |
| **3 AI 文意判字、标点、专名** | AI 读文意一遍判靠文意的形近字、标点、专名 | 待裁问全判过、裁定入库重放；punct、entity 线 0.1.0 | [3-AI文意判字标点专名](3-AI文意判字标点专名/) |
| **4 网站人审与版本迭代** | 出单上线、收单落票、更新 book-text、升 1.0 冻结；1.0 之后收网站反馈发 1.x | 1.0 发布标准；1.x 每批一个 PR | [4-网站人审与版本迭代](4-网站人审与版本迭代/) |

每步一个目录：`README.md` 写目标、入口、小步、出口、用户参与点和谁做；每个小步一个子目录，`README.md` 写输入、输出、命令，下面放细节文档。

## 写文档的规矩

- 公开仓：不写令牌、密码、内部地址。
- 新文档放进它所属的那一步、那一小步；跨步骤的查表资料进 [参考](参考/)，各书的数字和历史进 [案例](案例/)。
- 新踩的坑先写进对应步骤的「常见坑」，跨步骤的进 [经验](经验/)。
- 同一件事只写一处，别处链过去；流程主文（如[迭代流程](2-迭代/迭代流程.md)）与细节文档冲突时以主文为准，并顺手把细节改掉。
- Wiki 不随 PATCH 改，每升一次 MINOR 版对照四步结构整体重改一遍。
