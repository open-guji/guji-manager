# 册配置

> **配置的权威说明只有这一份**（四大步整改 X6，CV0 2026-11-28）。cv `doc/design/册配置分层与运行覆盖.md`、`doc/design/配置组层.md` 是设计稿，现行以本文为准；Wiki 只链过来。
> 代码在 cv `open_guji_cv/core/book_config.py`（分层合并、组层）、`core/config_keys.py`（键归层登记）、`core/book.py`（字段定义与注释）。单个字段的含义以 `book.py` 注释为准。

## 一句话

配置分六层：**全局、组、书、册、页、运行**。生效顺序从低到高：**代码缺省 → 组 → 书（基础配置）→ 册 yaml → 运行覆盖**，上层盖下层。页层只放人裁和页型，不放开关。正式配置只存在中心库，不进 git；运行覆盖只叠在内存里，不改文件、不推库，生效值记进产物 manifest。

## 六层

| 层 | 在哪 | 谁改 | 进中心库？ |
|---|---|---|---|
| ① 全局（代码缺省） | cv 各 Step 的 Params 类、`pipelines/*.yaml` 的 `params:`、套书或书仓 `code/defaults.yaml`、cv `config/`（文件登记见 cv `config/registry.yaml`） | cv 开发（PR）；书仓 code 归该书 | 否 |
| ② 组 | 中心库只读工作区 `group-<组>` 的 `config/group/v<N>.yaml` | 组负责线，用 `guji config-group publish` 出新版本 | 是（只增不改） |
| ③ 书（基础配置） | 中心库 `config/book_defaults.yaml` | 定版本、定开关的人，改了就推库 | 是 |
| ④ 册 yaml | 中心库 `books/<册>.yaml` | 立档人；册特有的调参 | 是 |
| 页 | 人裁事件、页型表（`page_kinds`）、页钉文件 | 人审、页型工具 | 是（不是开关层） |
| ⑤ 运行 | `--override`、任务单、`guji pipeline exp` 变体 | 跑的人 | 否，只记进产物 manifest |

- 一个工作区＝一部书，所以 ③ 就是「这部书各册共用的配置」，不同书互不影响。
- 本机副本在数据目录 `$GUJI_DATA_HOME/main/<工作区>/books/`、`config/`，由 `guji db pull` 落、`guji db sync/push` 推（见 [中心库](../数据库/中心库.md)）。
- 没有 ②、③、⑤ 时，生效配置就是册 yaml 本身，与分层前逐位相同。

## 合并规则

- 映射按键深合并（`params`、`codepoints`、`font`、`jiazhu` 等）。
- 标量和列表整体替换（如 `group_flow`、`references`、`dev_set`），没有「列表追加」语法。
- 普通字段写 `null` 就是 null（`expected_cols: null` 本身有意义）；只有 `params:` 里的字段写 `null` 表示去掉下层的值、回到 Step 默认。
- 按「写没写」判断，不按「是否等于默认值」判断：`--override` 里的 `params` 当调用方显式参数，能把册 yaml 打开的开关关掉。
- Step 参数逐字段的优先级：Step 默认 < 管线 yaml `params:` < 套书／书仓 `code/defaults.yaml` < 组 < 基础配置 < 册 yaml < 运行覆盖（`--params` 等同运行覆盖里的 `params`）。cv 0.5.x 11-03（PR #903）以前管线 yaml 写过的字段册配置盖不住，只涉及现代链 `modern_body`。

## 哪些字段能写在哪一层

| 类别 | 字段 | ② 组 | ③ 基础配置 | ④ 册 yaml | ⑤ 运行覆盖 |
|---|---|---|---|---|---|
| 身份与图源 | `id`、`title`、`raw_dir`、`raw_pattern`、`pages`、`sets` | 禁止 | 禁止 | 必填／可写 | 禁止 |
| 书身份 | `book_id`、`book_title`、`book_edition`、`volume_width`、`chapter_width`、`seg_set` | 禁止 | 写这里 | 可写 | 身份类禁止 |
| 归组 | `groups` | 禁止 | **只许写这里** | 禁止 | 禁止 |
| 冻结、缺页 | `freeze`、`gaps` | 禁止 | 禁止 | 写这里 | 禁止 |
| 实测版式先验 | `bottom_gap`、`period_prior`、`frame_height`、`col_pitch`、`outer_shift`、`outer_gap`、`preclean`、`page_split`、`dev_set`、`layout_hints`、`page_kinds` | 禁止 | 禁止（换书必须重标） | 写这里 | 可写（实验用） |
| 钉子 | `cv_version`、`glyph_pin`、`model`、`code`、`pua_table_pin`、`pin` | 禁止 | 推荐写这里 | 可写（个别册另钉） | 可写 |
| 语料总号 | `corpus` | 禁止 | **别写这里**（总号每册各编） | 写这里 | 可写 |
| 参校本、码位 | `references`、`codepoints`（书级写 `config/codepoints.yaml`） | 禁止 | 推荐写这里 | 可写 | 可写 |
| 书影 | `src_w`、`cos_iou_min` | 禁止 | 写这里 | 可写 | — |
| 版式 | `expected_cols`、`chars_per_line`、`side_frame`、`frame_layers` | 推荐（同版式的书） | 推荐 | 可写 | 可写 |
| Step 参数 | `params:`（`{step_id: {字段: 值}}`） | 对位、5a、版式与切分开关推荐进组；字对（`follow_ref*`、`pua_rules`）、`page_pins`、`coord_title_formula`、`layout_prior`、`roster_ref_*`、`group_decision.handling.*.methods` 禁止 | 推荐写这里 | 可写 | 可写 |

- **写错层直接报错**：基础配置里写了禁止字段、`--override` 里改身份与图源、组里写了禁写键、册 yaml 写 `groups:`，命令都会拒绝并说明原因。
- **写在不推荐的层只提示**：每个键允许哪几层、推荐哪层登在 cv `core/config_keys.py`。`guji pipeline book show <册> --effective` 末尾有「归层提示」一节：写在不推荐的层、配套键不同层（`glyph_match.sim_model` 与 `pair_clf` 必须同层），以及「同一键同一值写在 90% 以上的册里，可收进书或组」。一期只提示不拦。

### 归层准则：一个键该写哪层

1. 换一部书就要重标的（实测先验、图源、身份）写册。
2. 只属于这部书的（钉子、参校本、码位、字对、书名行公式、页钉）写书。
3. 同一刻本或写本的书都一样的（版式、对位、5a、切分开关）写组。
4. 所有书都一样的改代码缺省（cv PR），不写进任何书。
5. 个别册不同的才写册，和书相同的别抄到册里。
6. 做实验只用运行覆盖。
7. 拿不准先写书，等第二部书来了再提到组。

## 组

一组＝一套丛书或同一种版式的书，例如 `wyg`（文渊阁四库全书写本：史記、汉书）、`wyd`（武英殿刻本：殿本）。字形、语料、模型三个系统也各有自己的组，一期只有配置组真生效。

- **声明**：书的 `config/book_defaults.yaml` 写
  ```yaml
  groups: {config: wyg@1, glyph: [wyg]}    # 配置组只认一个、要带版本；glyph/corpus/model 是列表
  ```
- **存放**：中心库只读工作区 `group-<组>`，`config/group/v<N>.yaml` 只增不改。出新版本用 `guji config-group publish <组> --from <yaml> [--note …] [--dry-run]`，发布前查禁写键。
- **拉取**：`guji db pull`／`sync` 会按书的 `groups.config` 自动拉组配置的只读副本；组或版本不存在直接报错。
- **版本号**：`wyg@1` 是配置组的版本，和字形库 `glyphlib-wyg-v1` 的版本互不对应。`groups.glyph: [wyg]` 对应 glyphlib-wyg-vN，实际用哪版跟 `workspace.yaml` 的 borrow。
- **指纹**：只认生效值，组名、组版本不进指纹。键从书挪到组、值不变，产物不过期。
- **老 cv 兼容**：cv 0.7.x 读到 `groups:` 静默忽略。书钉的 cv 升到含组层的版本之前，只加 `groups:`，书层、册层与组同值的键一个不删。
- **执行方要求**：书写 `groups:` 之前，它的执行方 manager 要 ≥ v0.7.7，否则拉不到组、新 cv 拒跑。
- **代码**：书级代码仍只分全局、书仓两级，没有组代码仓。
- 现有的组：

| 组 | 成员 | 当前版本 | 内容 |
|---|---|---|---|
| wyg | 史記（入组待推）、汉书（待入组） | v1（2026-11-28） | 版式、对位 10 键、5a 六键、`context_decide.consensus_as_unsure`、判定 3 键 |
| wyd | 殿本（入组待推） | v1（2026-11-28） | 版式、切分开关、5a 六键 |

读配置的程序口子（manager 经 `guji_manager._cv` 取）：`effective_book_dict`（某册完整生效值）、`effective_defaults`（书级＝组∪基础配置）、`book_groups`（解析 `groups:`）、`check_group_layer`（组配置禁写检查）。别直接读原始 yaml。

### 字段速查

完整字段与每个字段的标定方法见 cv `core/book.py` 的 `BookSpec`。常碰到的：

| 字段 | 管什么 |
|---|---|
| `id`、`title` | 册名、本册标题 |
| `book_id`、`book_title`、`book_edition`、`volume`、`volume_width`、`chapter_width` | 书 id、书名、版本、册序、册号位数、章号位数（见下「册号」） |
| `raw_dir`、`raw_pattern`、`pages`、`sets` | 原图在哪、文件名模式、页范围、页集合 |
| `expected_cols`、`chars_per_line` | 每页列数、每列字数先验 |
| `bottom_gap`、`period_prior`、`frame_height`、`col_pitch`、`outer_shift`、`outer_gap`、`frame_layers` | 版框与界行的实测先验，换书重标，别抄 |
| `column_grid`、`binarized_input`、`vline_polyline`、`frame_bar_strategy` | Step1 几何链路的开关，逐册验过才改 |
| `ink` | 墨层＋二值化（cv 11-18，用户 11-17 定）：`{}`＝彩图压掉朱印朱批再 Otsu 二值、去小斑；`{binarize: none}` 回退灰度；`{binarize: sauvola, window: auto}` 给淡界行的书。**开新书缺省在书的 `config/book_defaults.yaml` 写 `ink: {}`**，切分有问题再改。没写的册读灰度、指纹不变。写了 `binarized_input` 失效。详见 cv `doc/design/彩图墨层与二值体检.md` |
| `codepoints` | 本书统一用哪个码位（别/別 这类）；只写在工作区级 `config/codepoints.yaml`，册里逐条覆盖；基础配置里别再写 |
| `edition` | 版式大类 `keben`／`modern`，选缺省管线。**不是**书 ID，也不是版本名 |
| `references` | 对勘用的参考文本 |
| `iron_gate` | 放行判别开关 |
| `params` | 任意 Step 的参数覆盖 |
| `cv_version` | 本册钉的 cv 版本；只是护栏，不进指纹 |
| `corpus`、`corpus_dev` | 语料钉子账总号；开发中标记（不许推库） |
| `glyph_pin` | 字形库快照号 g<N> |
| `freeze` | 冻结基线登记（`at`、`pack` 等），由命令写，别手填 |
| `gaps` | 缺页（cv 11-18，用户定**只按图片页号记**）：一段连续缺的写一条 `{after_page, what, kind, est_chars, evidence}`，`after_page` 是缺在哪张图之后，`kind` 写 `原书缺` 或 `未拍`。不挪页号、不进指纹；`guji pipeline collate` 报告带上、`guji output export format` 出 `NNN.gaps.json`、网站据此画缺页卡。详见 cv `doc/formats/缺页.md` |

钉版三字段的含义与用法见 [产物包与版本钉](产物包与版本钉.md)。

印章相关的书级 `params`（换书时先查，详见 [印章遮挡格-校对处理](../../wiki/自动化流程/印章遮挡格-校对处理.md) 第四节）：
- `seal_detect.stain_pages: [页号…]`：大印只认这些页。适用于纸面底纹重、没印的页也被认成大印的书，例如史記写 `[2]`。不写＝每页都找。
- `seed_admit.lane_seal_title_formula: "<正则>"`：首叶题列的套语，整列与它对上就按坐标字放行。殿本用缺省值，史記写 `"^欽定四庫全書$"`。

## 册号（2026-11-02 统一）

> 本节由「统一册号位数」线程维护（11-27 新规：位数按全书册数统一）。

同一册在各处要写成同一个号。以前各处从册名字符串现推，只认殿本的 `volNN`，北行 `bxgb` 被推成章号 `000`。现在规定：

- **书 id 与册序写进配置**：基础配置写 `book_id`（10 位书 id）、`book_title`、`book_edition`（导出用）；册 yaml 写 `volume:`（册序，从 1 起的整数）。册名本身就是纯数字的（`01`、`42`）可以不写 `volume`。
- **位数按全书册数定、全书统一、最少 2 位**：基础配置写 `volume_width`。99 册以内 2 位，100–999 册 3 位。补零是为了排序。
- 各层都从这几个字段生成，代码不再从册名推（cv `open_guji_cv/core/volume_id.py`）：
  - 新书的 cv 册名、R2 页表与 IIIF 册号：册序补到 `volume_width` 位（`01`、`001`）
  - book-text 章号、进度表 `progress.volume.vol`、待审条目 `feedback/lists/pending/<书id>/<章>.items.jsonl` 与 land 导出的 `proofing/<书id>/<章>.pending.json`：补到 `chapter_width` 位，不写就等于 `volume_width`
- 已上线的书章号不改：殿本册名 `vol01`–`vol99`、R2 `01`–`99`、章号 `001`–`099`；北行册名 `bxgb`、R2 `01`、章号 `001`。这两部书的基础配置写 `chapter_width: 3`。
- 认不出书 id 或章号的册，land、记进度、标 main 自动收尾都会停下或跳过，不再写错号。补上配置字段即可。

## 运行覆盖：`--override`

```bash
guji pipeline keben_body_v2 vol51 -w $WS --override '{"corpus":23,"params":{"seed_admit":{"shadow_veto":false}}}'
guji pipeline book show vol51 -w $WS --effective      # 看合并后的完整配置，每个字段标出来自哪一层
```

- 内容是一段 JSON「册配置片段」，叠在册 yaml 之上；不改任何文件、不推库。
- 实现上设环境变量 `GUJI_BOOK_OVERRIDE`，分步子进程自动继承。
- `--params '<JSON>'` 保留，等价于 `--override '{"params": …}'`。
- 产物 manifest 记覆盖原文和生效值；覆盖改了参与指纹的值，对应步骤判过期重算，没改就不重算。
- 任务库交单：`guji_jobs submit … --override '<JSON>'`（`--corpus`、`--glyph-pin` 是它的简写），写进单子的 `book_overrides`，执行方照样传 `--override`，不再改本机 yaml。

## 什么时候改哪层、进不进库

| 情况 | 动作 |
|---|---|
| 新立一册 | 写 ④ 册 yaml（几行），推中心库 |
| 全书升版本、换语料、换字形库、开关转正 | 改 ③ 一处，推中心库，再交整批任务 |
| 同组各书一起改开关 | 出组的新版本 `v<N+1>`，各书把 `groups.config` 改指新版本，各自推库、交单 |
| 某一册单独调参，结论要留下 | 改该册 ④，推中心库 |
| 实验、A/B、试新参数 | 只用 ⑤，不推库、不改文件 |
| 实验还要写库 | 开中心库实验分支（见 [中心库](../数据库/中心库.md)） |
| 改 Step 默认值、管线结构 | cv 仓 PR |
| 册 yaml、基础配置 | 永远不进 git |

## 把一组册的共同部分抽成基础配置

```bash
guji pipeline book split -w $WS --books vol51-vol99           # 干跑：列出共同部分和每册剩下的
guji pipeline book split -w $WS --books vol51-vol99 --apply   # 真写：写 config/book_defaults.yaml、瘦身各册 yaml
guji db sync -w $WS
```

工具逐册校验「合并结果与拆前相等」，不等就不写。迁完用 `guji pipeline status` 对账，应无新增过期。用户定的顺序：先迁 vol51–99，稳定后迁 vol21–50，vol01–20（含冻结册、各有手调）不迁。

## 指纹与重跑

- 指纹看生效值，不看值来自哪一层（含组层）。合并结果不变，拆分、入组就不会让任何册判过期。
- `cv_version` 只是护栏，不进指纹；`corpus`、`glyph_pin` 进指纹（换号即重算对应步）。
- 改基础配置会影响这部书全部册：推之前 `guji db diff` 看清，改完用 `guji pipeline status` 看哪些册过期；冻结册按冻结基线比，不受影响。

## 常见坑

- 以前 `--params` 关不掉册 yaml 打开的开关（只替换「仍等于默认值」的字段），现已修；用老版 cv 时仍有这个坑。
- **册配置改在中心库数据目录**（`$GUJI_DATA_HOME/<分支>/<工作区 id>/books/`、`config/book_defaults.yaml`），不是工作区 git 仓里的 `config/`：改了后者不生效（QTW #1848–1858 白交了一批）。
- 改册 yaml 用文本追加或手改那几行，别用 ruamel 整份读写重排；推前用 `guji pipeline book show --effective` 或 manifest 核 `params_hash` 没有意外变化。
- 越过参校本放行的白名单是**按书**的（11-05 定，每书每组抽 30 格金标定），别从殿本册配置抄到别的书。
- 别从别的书抄实测先验（`frame_height`、`outer_shift` 等）：不给只是静默退化，抄错了是整册漏框。
- 还有少数代码绕过合并入口直接读册 yaml（见设计稿风险一节）；发现字段「改了没生效」先用 `guji pipeline book show --effective` 查。
