# 册配置

> 迁自 open-guji-cv `doc/design/册配置分层与运行覆盖.md`（A31 设计，2026-10-26 用户同意）；A20 2026-10-30 按 cv dev 代码核对改写。
> 代码在 cv `open_guji_cv/core/book_config.py`（分层合并）、`core/book.py`（字段定义与注释）。字段的权威说明以 `book.py` 里的注释为准。

## 一句话

一册书的配置分五层，从低到高：**代码默认 → 管线 yaml → 工作区基础配置 → 册 yaml → 本次运行覆盖**。上层盖下层；正式配置只存在中心库，不进 git；实验覆盖只叠在内存里，不改文件、不推库，生效值记进产物 manifest。

## 五层

| 层 | 在哪 | 谁改 | 进中心库？ |
|---|---|---|---|
| ① 代码默认 | cv 各 Step 的 Params 类 | cv 开发（PR） | 否（cv 仓） |
| ② 管线 yaml | cv `pipelines/*.yaml` 的 `params:` | cv 开发（PR） | 否（cv 仓） |
| ③ 工作区基础配置 | 中心库 `config/book_defaults.yaml` | 定版本、定开关的人，改了就推库 | 是 |
| ④ 册 yaml | 中心库 `books/<册>.yaml` | 立档人；册特有的调参 | 是 |
| ⑤ 运行覆盖 | `--override`、任务单、`guji exp` 变体 | 跑的人 | 否，只记进产物 manifest |

- 一个工作区＝一部书，所以 ③ 就是「这部书各册共用的配置」，不同书互不影响。
- 本机副本在数据目录 `$GUJI_DATA_HOME/main/<工作区>/books/`、`config/`，由 `guji db pull` 落、`guji db sync/push` 推（见 [中心库](中心库.md)）。
- 没有 ③、没有 ⑤ 时，生效配置就是册 yaml 本身，与分层前逐位相同。

## 合并规则

- 映射按键深合并（`params`、`codepoints`、`font`、`jiazhu` 等）。
- 标量和列表整体替换（如 `group_flow`、`references`、`dev_set`），没有「列表追加」语法。
- 普通字段写 `null` 就是 null（`expected_cols: null` 本身有意义）；只有 `params:` 里的字段写 `null` 表示去掉下层的值、回到 Step 默认。
- 按「写没写」判断，不按「是否等于默认值」判断：`--override` 里的 `params` 当调用方显式参数，能把册 yaml 打开的开关关掉。

## 哪些字段能写在哪一层

| 类别 | 字段 | ③ 基础配置 | ④ 册 yaml | ⑤ 运行覆盖 |
|---|---|---|---|---|
| 身份与图源 | `id`、`title`、`raw_dir`、`raw_pattern`、`pages`、`sets` | 禁止 | 必填／可写 | 禁止 |
| 冻结 | `freeze` | 禁止 | 由 `guji freeze register` 写 | 禁止 |
| 实测版式先验 | `bottom_gap`、`period_prior`、`frame_height`、`col_pitch`、`outer_shift`、`outer_gap`、`preclean`、`page_split`、`dev_set`、`layout_hints` | 禁止（换书必须重标） | 可写 | 可写（实验用） |
| 钉版 | `cv_version`、`corpus`、`glyph_pin` | 推荐写这里 | 可写（个别册钉旧版） | 可写 |
| 书级共性 | `expected_cols`、`chars_per_line`、`edition`、`references`、`codepoints`、`font`、`iron_gate`、`frame` 等 | 推荐写这里 | 可写 | 可写 |
| Step 参数 | `params:`（`{step_id: {字段: 值}}`，含 `group_flow`、`page_map`、`layout_prior` 等） | 推荐写这里 | 可写 | 可写 |

写错层直接报错：基础配置里写了禁止字段、`--override` 里改身份与图源，命令都会拒绝并说明原因。

### 字段速查

完整字段与每个字段的标定方法见 cv `core/book.py` 的 `BookSpec`。常碰到的：

| 字段 | 管什么 |
|---|---|
| `id`、`title` | 册号、书名 |
| `raw_dir`、`raw_pattern`、`pages`、`sets` | 原图在哪、文件名模式、页范围、页集合 |
| `expected_cols`、`chars_per_line` | 每页列数、每列字数先验 |
| `bottom_gap`、`period_prior`、`frame_height`、`col_pitch`、`outer_shift`、`outer_gap`、`frame_layers` | 版框与界行的实测先验，换书重标，别抄 |
| `column_grid`、`binarized_input`、`vline_polyline`、`frame_bar_strategy` | Step1 几何链路的开关，逐册验过才改 |
| `codepoints` | 本书统一用哪个码位（别/別 这类）；工作区级 `config/codepoints.yaml` 先取，册里逐条覆盖 |
| `references` | 对勘用的参考文本 |
| `iron_gate` | 放行判别开关 |
| `params` | 任意 Step 的参数覆盖 |
| `cv_version` | 本册钉的 cv 版本；只是护栏，不进指纹 |
| `corpus`、`corpus_dev` | 语料钉子账总号；开发中标记（不许推库） |
| `glyph_pin` | 字形库快照号 g<N> |
| `freeze` | 冻结基线登记（`at`、`pack` 等），由命令写，别手填 |

钉版三字段的含义与用法见 [产物包与版本钉](产物包与版本钉.md)。

## 运行覆盖：`--override`

```bash
guji pipeline keben_body_v2 vol51 -w $WS --override '{"corpus":23,"params":{"seed_admit":{"shadow_veto":false}}}'
guji book show vol51 -w $WS --effective      # 看合并后的完整配置，每个字段标出来自哪一层
```

- 内容是一段 JSON「册配置片段」，叠在册 yaml 之上；不改任何文件、不推库。
- 实现上设环境变量 `GUJI_BOOK_OVERRIDE`，分步子进程自动继承。
- `--params '<JSON>'` 保留，等价于 `--override '{"params": …}'`。
- 产物 manifest 记覆盖原文和生效值；覆盖改了参与指纹的值，对应步骤判过期重算，没改就不重算。
- 任务库交单：`guji_jobs submit … --override '<JSON>'`（`--corpus`、`--glyph-pin` 是它的简写），写进单子的 `book_overrides`，执行方照样传 `--override`，不再改本机 yaml。

## 什么时候改哪层、进不进库

| 情况 | 动作 |
|---|---|
| 新立一册 | 写 ④ 册 yaml（几行），推中心库 |
| 全书升版本、换语料、换字形库、开关转正 | 改 ③ 一处，推中心库，再交整批任务 |
| 某一册单独调参，结论要留下 | 改该册 ④，推中心库 |
| 实验、A/B、试新参数 | 只用 ⑤，不推库、不改文件 |
| 实验还要写库 | 开中心库实验分支（见 [中心库](中心库.md)） |
| 改 Step 默认值、管线结构 | cv 仓 PR |
| 册 yaml、基础配置 | 永远不进 git |

## 把一组册的共同部分抽成基础配置

```bash
guji book split -w $WS --books vol51-vol99           # 干跑：列出共同部分和每册剩下的
guji book split -w $WS --books vol51-vol99 --apply   # 真写：写 config/book_defaults.yaml、瘦身各册 yaml
guji db sync -w $WS
```

工具逐册校验「合并结果与拆前相等」，不等就不写。迁完用 `guji status` 对账，应无新增过期。用户定的顺序：先迁 vol51–99，稳定后迁 vol21–50，vol01–20（含冻结册、各有手调）不迁。

## 指纹与重跑

- 指纹看生效值，不看值来自哪一层。合并结果不变，拆分就不会让任何册判过期。
- `cv_version` 只是护栏，不进指纹；`corpus`、`glyph_pin` 进指纹（换号即重算对应步）。
- 改基础配置会影响这部书全部册：推之前 `guji db diff` 看清，改完用 `guji status` 看哪些册过期；冻结册按冻结基线比，不受影响。

## 常见坑

- 以前 `--params` 关不掉册 yaml 打开的开关（只替换「仍等于默认值」的字段），现已修；用老版 cv 时仍有这个坑。
- 别从别的书抄实测先验（`frame_height`、`outer_shift` 等）：不给只是静默退化，抄错了是整册漏框。
- 还有少数代码绕过合并入口直接读册 yaml（见设计稿风险一节）；发现字段「改了没生效」先用 `guji book show --effective` 查。
