> 本文是这张表的格式与校验。代码 `guji_manager/pair_attribution.py`。**现在还没有任何一步读这张表**，接进第 5／7 步在后面做。

## 为什么要有

一对字「归谁判」原先散在四处，改一处不带动另三处：

| 在哪 | 说的是什么 |
|---|---|
| `config/groups/pair_clf.json` 的 `context` | 按对分类器不训、归文意的对（己已巳、日曰、千干、天夭） |
| 第 7 步注册组（cv `groups/registry.py`）＋书配置 `seed_admit.group_flow` | 哪些组在用、挂的是字形解法还是只有文意 |
| `config/codepoints.yaml` | 两个码位统一记一个 |
| 书配置 `seed_admit.group_flow_provisional_to` | 某组分不出来时兜底记哪个字 |

全唐文 11-18 按刻形回库时就撞上：簡𥳑、候𠋫 聚类定名有两形，码位表早已定统一记 𥳑、𠋫（59 格，回库时剔掉）。

## 格式

数据目录 `config/groups/pair_attribution.yaml`，随中心库走：

```yaml
schema: pair_attribution/1
pairs:
  日曰: {attr: context, by: Sheldon, date: 2026-11-18, note: 刻本混用}
  簡𥳑: {attr: merge, to: 𥳑}
  淸清: {attr: shape, variant: true}
```

| attr | 含义 | 要写的 |
|---|---|---|
| `shape` 刻形 | 刻本上分得开，照刻的形录。**没列的对缺省就是刻形** | 一般不用列；想留个说明才列 |
| `context` 文意 | 刻本混用或字形分不开，按文意定 | |
| `merge` 暂归一 | 目前分不开，统一记一个字，留待将来再分 | `to`：这一对里的一个字 |

`variant: true`（可选）标这一对是**同字异形**（淸清、靑青），不是两个不同的字。cv 第 7 步 `pair_form` 只对标了 variant 的对自动改字；异字对（壞壤）字形与整理本相反时只记证据进复审，不自动改。

键是两个字连写，先后不拘（内部按码位排序）。`by`、`date`、`note` 随意。别的字段不认，写错了读的时候就报。

## 命令

```
guji-manager pair-attr show 淸清 -w <工作区>     # 这一对的归属（没列的回 shape）
guji-manager pair-attr check -w <工作区>          # 与另四处对一遍，列不一致；有不一致退出码 1
```

`check` 查的：

- 码位表归一的对，表里必须是 `merge` 且 `to` 相同；表里 `merge` 的对，码位表必须有这一条。
- 分类器文件的人定归文意名单，表里必须是 `context`；表里 `context`／`merge` 的对分类器却够终判（档 3）的报出来（刻形其实分得开？）；
  分类器机器判分不开、表里没列的报出来（要人定）。
- 第 7 步现役组里只挂文意解法的两字组，表里还是刻形（缺省）的报出来。要装着 pipeline 才查这一条。
- 暂归一兜底的两字组，表里要是 `merge` 到同一个字。

`check` 只报不改。归属是人定的事：机器（分类器重建）只提议，改表要人点头。
