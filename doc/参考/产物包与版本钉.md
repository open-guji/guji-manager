## 一句话

一册书的结果由四样东西决定：**cv 代码版本、语料库号（c）、字形库号（g）、中心库里的人裁与册配置**。前三样写在册配置里钉住；结果（products）打成**产物包**存 R2，标签就写着这三样。产物不进中心库、不进 git。

## 版本钉

三个字段都写在册配置里，推荐写在基础配置 `config/book_defaults.yaml`，个别册钉旧版时写在册 yaml（见 [册配置](册配置.md)）。

| 字段 | 钉什么 | 进指纹？ | 不钉会怎样 |
|---|---|---|---|
| `cv_version: "0.5.30"` | cv 正式版本（不带 `v`） | 否，只是护栏 | 不设防：装什么版本都能跑 |
| `corpus: N` | 本册钉子账里的语料总号 | 是（换号即重算读语料的步） | 指纹按语料文件内容算，改了文件就过期 |
| `glyph_pin: N` | 字形库快照 g<N> | 是（换号即重算读字形库的步） | 别的会话推一条人裁，本册 `seed_admit` 就过期 |

**每波开工前的规矩**（`版本号规矩.md`）：先发一个正式 tag，这一波每册都钉它，同时钉语料和字形库。不用 rc 分支、不用 dev 版本跑正式册。

### cv_version：护栏

- 装的 cv 与册里钉的不同，`guji step`／`pipeline`／`rerun` 拒跑（退出码 2）；`guji status` 只提醒。
- 产物 manifest 记 `cv_version`：正式 tag 写三段数字 `0.5.30`；dev 写 `0.5.31.dev12+g<12 位 hash>`；有没提交的改动再加 `dirty`。
- 确要用别的版本跑：`--allow-cv-mismatch --why "<理由>"`，理由记进 manifest 的 `cv_override`。
- 在中心库实验分支上跑时护栏自动放行、只提醒。dev 上跑出的结果要转正：发正式 tag，在 tag 上重跑再存包标 main。

### corpus：语料钉子账

- 语料分三层：全局底库 `b<M>`（引擎仓文件，登记在只读工作区 `corpus-base`）、书库 `v<N>`（工作区文件：整理本、字频、L2、异体表）、册层（初期为空）。
- 册 yaml 的 `corpus: N` 是**这一册钉子账** `config/corpus-pack/pins/<册>.json` 里的**总号**，每册各编各的，不等于书库号。总号对应一行三层组合，任何一层变了总号必升。
- 指纹取总号三层清单条目的内容哈希，不取号本身：号升了但这册用到的文件没变，不白重算。
- 起跑前硬校验：读语料的步开跑前按清单核文件，有改动或缺失就拒绝（`CorpusDrift`）；临时绕过设 `GUJI_CORPUS_DRIFT=warn`。

```bash
guji corpus pin -w $WS --vol vol04 --global-ver 8 --book-ver 18 --note "…"   # 只写账，打印新总号
# 改册配置 corpus: <新总号>，再 guji db sync
guji corpus verify -w $WS --vol vol04
```

- `pin` 不认 `--version`，要给 `--global-ver`／`--book-ver`；不给就沿用最新一行，组合相同拒绝（不空升）。
- 开发中：`guji corpus pin --dev` 升号，册 yaml 加 `corpus_dev: true`（不核清单、不许推库）；改定后各层出新版，`guji corpus release` 去掉 dev 标记。
- 出新版：`guji corpus build-base`（底库，要写库权限）、`guji corpus build -w $WS --base latest`（书库）、新书 `guji corpus init`。

### glyph_pin：字形库快照

```bash
guji db sync -w $WS                         # 先推干净，快照才对得上中心库
guji glyph-db snapshot -w $WS --note "…"    # 出 config/glyph-pack/g<N>/manifest.json，内容与上一版相同拒绝
guji db push -w $WS                         # 清单进中心库，登记的文本按 sha 进 R2
# 改册配置 glyph_pin: <N>，再 guji db sync
guji glyph-db pin-verify -w $WS --pin N     # 只从 R2 拼一遍核对
```

- 已发布的清单不可改。`glyph-g<N>.db` 在工作区本地，`db pull/sync` 和起跑前按各册 `glyph_pin` 自动建。
- 钉了之后，读字形库的步都读 `glyph-g<N>.db`，同一册任何时候跑用的是同一份库。
- **人裁照常写当前库**：本格的裁决立即生效；经字形库传播到别的格的，要等出新号、改钉才进本册。

## 产物包

### 布局

```
R2 pack/products/<工作区>/<册>/<标签>/manifest.json
                                    /part-000.tgz …          每段 ≤ 64 MB
R2 pack/products/<工作区>/<册>/main-ptr/<UTC 时刻>-<标签>.json   main 指针，只增不改，最新一条为准
```

- 每份包按「册＋标签」各存一份，只增不改，不同版本、不同开关的结果并存，任意两份都能取回比。
- 标签缺省 `cv<版本>-c<语料号>-g<字形库号>-<改动名或 UTC 时刻>`，如 `cv0.5.30-c17-g2-layout`。没钉语料写 `c-`；没钉字形库写 `g-` 加人裁指纹前 6 位。标签只许 ASCII 字母、数字、`_.-`。
- 包里不带 `_prev/` 和 `*.tmp`。manifest 记三样版本（`versions`）、`cv_commit`、各步文件数、每段 sha256、整包 sha256。
- 实验分支上存的包进实验桶，与正式桶分开。

### 命令

```bash
guji products pack push    vol04 -w $WS [--change layout] [--note "…"] [--main]
guji products pack list    vol04 -w $WS            # ★ 是 main
guji products pack fetch   vol04 -w $WS [--label <标签>] [--to <产物根>] [--force]
guji products pack promote vol04 -w $WS --label <标签> [--note "…"]
```

- 存、标 main 要正式令牌（实验分支用实验令牌）；取、列读令牌就够。
- `fetch` 不给标签取 main；没标过 main 才退回最新存的那份。目标已有该册产物时不覆盖，除非 `--force`。取回时逐段核 sha256。
- `push` 缺省在工作区 `experiments/<册>/<标签>.md` 写一条实验记录（`--report`、`--summary` 补内容，`--no-record` 不写）。

### main：这册当前的正式结果

- 只有正式版 cv（三段数字）出的包能标 main；dev、rc、带 dirty 的拒绝，确要标加 `--why "<理由>"`，记进指针。实验桶不查。
- **新册首跑**（还没有 main）在正式库、正式版 cv 上存的第一个包自动标 main（用户 10-25 定）。
- 标 main 后会触发钩子自动重出线上单（cv `guji.post_promote` 入口点组），条件和关法见 [环境与令牌](../00-总览/环境与令牌.md)。

### 包拿来做什么

- 新会话取回上游，不用整册从 Step1 重算（殿本一册 1.5–2.5 小时 → 取回几十秒）。
- 当 `guji products diff --a` 的「前」，看改动前后对比；当 `guji exp run --snapshot` 的上游。
- 放进本机 `products/` 接着增量重跑：指纹照常判，代码、参数、库变了的步照样过期。包本身只当缓存，不保证新鲜。

## 冻结登记

文本定版（0.1.0／1.0.0）时用一条命令做齐：

```bash
guji freeze register vol04 -w $WS --version 1.0.0 --text-id <book-text 条目 id> --text-dir <本书目录>            # 只出计划
guji freeze register vol04 -w $WS --version 1.0.0 --text-id … --text-dir … --tag-via /home/user/ai-team --execute
guji db sync -w $WS
```

它做五件事：

1. 产物存 R2 冻结包，标签 `freeze-<文本版本>-<UTC>`，标成该册 main；包旁另存 `baseline.json`（每个产物文件的 sha256）。
2. 数据目录 `feedback/lists/freeze/<册>.jsonl` 追加一行登记（字段同 `freeze_baselines` 表，另带 `pack`、`tag`、`text_commit`），随 `db sync` 进中心库。
3. 册 yaml 的 `freeze:` 换成 `{at, cv_version, cv_commit, pack, tag, registered}`，顶层 `cv_version` 设成同一版本。
4. 打 `freeze/<书>-<册>-<UTC>` tag（给了 `--tag-via` 就经中转站 `process/tag.py` 打）。
5. 提醒 `guji db sync`。

- 前提：cv 检出干净、HEAD 已在远端某分支上；本机有这册产物；版本号形如 X.Y.Z。不满足就拒。
- 冻结后 `close-check` 1a 照 `baseline.json` 逐文件比，不再因 cv 升版、人裁进库报过期。规则见 ai-team `domain/CV/规范/冻结基线与重跑分级.md`。
- 打 1.0 标签与冻结要用户明说。

## 常见坑

- `corpus: N` 是每册钉子账的总号，不是书库号 `v<N>`：两册写同一个数字可能是不同语料。
- 底库换过文件（如 `config/charset/symbols.tsv`），钉旧底库的册用新代码跑会被清单校验拦下——这是该拦的，改钉新底库。
- 包标签带中文会被 Worker 拒（`bad_path`），本地先挡。
- 只打了几步（`--steps`）的包不算整册存过。
- dev 上跑的包标 main 会被拒；别用 `--why` 绕过当常态。
