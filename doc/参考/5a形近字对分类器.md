# 5a 形近字对分类器（5a.3）

> OCR 研究 Project 方向 2，2026-11-18。代码在 cv：`groups/pair_clf.py`、`steps/glyph_stages.py`、`scripts/build_pair_clf.py`；
> 设计与数字的出处在 cv `doc/design/形近字组-按对分类器.md`。本文讲原理、怎么配、怎么建、怎么迭代。
> 现状：代码已进 cv dev，**没有任何书打开**；真册 A/B 和回头重判工具还没做。

## 一、它解决什么

5a 用统一的相似度嵌入拿一格去比字形库里的刻例。形近字对（日曰、未末）和同字异形对（淸清、眞真）上它常错，原因不在嵌入，
在拿去比的刻例：库里同字异形的刻例按放行字标、没跟刻形，少见一形的刻例又太少。全唐文 001–045 册 81 对 34,596 格按册留出，
比现库刻例是 93.0%，换成本书刻例上按对训的逻辑回归是 99.4%。

所以给每本书建一份小文件，每对字一个分类器（一个 128 维向量加一个偏置），吃 5a 已经算好的嵌入，运行时只是一次点积。
嵌入模型跨书共用，分类器不跨书。

## 二、五个档

每对字按本书刻例多少和留出验收结果分档，每次重建重算，能升能降：

| 档 | 条件 | 做什么 |
|---|---|---|
| 0 借 | 本书有一形还没有刻例 | 没有分类器。行为与没开一样 |
| 1 起步 | 两形都有，有一形不到 4 例 | 最近类心，只出证据 |
| 2 可用 | 两形都 ≥4 例 | 逻辑回归，出证据；把握过门槛时证据带字 |
| 3 终判 | 按册留出给字 ≥30 格且零错 | 开了 `final` 时在 5a 直接定字 |
| context 归文意 | 人定名单，或刻例够了（两形都 ≥30）留出准确率仍 <98.5% 且够不上终判 | 不给字，交第 7 步文意 |

己已巳、日曰、千干、天夭 是 Sheldon 定的人定归文意。全唐文第一版机器归文意的是 壞壤、皐臯、祇祗、迥迴。

**规矩（Sheldon 11-18）**：除了己已巳、日曰这类文意不区分的对按文意改，其余一律按刻形走；异体字更是按刻形（刻的是 淸、
放行成了 清，只要认得出就改成 淸）。只有少数分不开的才暂归一，为的是将来还能再分开。

## 三、怎么配

册配置（书级）里，在已经开着的 `glyph_match.stages` 下加一行：

```yaml
params:
  glyph_match:
    sim_model: {path: models/glyph_sim_qtw/model.pt, same: 0.90, low: 0.50}
    stages:
      route: {level: core, knn_min: 1.0}
      pair: {model: config/groups/pair_clf.json, final: false}
```

- `pair` 不写就不跑，产物和指纹与原来逐字节相同。
- `model`：相对路径先找数据目录（随中心库走），再找工作区、cv 仓根；找不到直接报错。
- `final: false`（缺省）：只往 `MatchRec.stage.pair` 写证据，判决一格不变。先这样跑一轮看证据。
- `final: true`：档 3 的对可以在 5a 定字，`via` 记 `pair:<对>`。定的字可以不是 CNN 首位字（淸 的格首位常是 清）。
  条件是含首位字的对里没有归文意的、有分类器的对全都给了字且一致、其中至少一对是档 3。
- 写了 `pair` 以后，分类器文件内容进 `stages_sha`。换文件第 5 步就过期，所以重建放在一轮开头。
- 打开 `pair`、把 `final` 改成 true 都是书配置开关，要先问 Sheldon。

## 四、怎么建

```
python scripts/build_pair_clf.py --labels 刻例.json --emb 嵌入.npz \
    --out <数据目录>/config/groups/pair_clf.json \
    --context 己已 已巳 己巳 日曰 千干 天夭 \
    [--prev 旧版.json] [--keep-prev-on-regress] [--snapshot <刻例快照号>] [--sim-model <嵌入模型>]
```

- `刻例.json`：`{"淸清": {"<格 id>": "<这格刻的字>", …}, …}`。只收独立证据定下的格：人裁、文意与整理本两路一致、聚类后人定名的类。
  **由本分类器定字的格（`via` 以 `pair:` 开头）不要收**，那是拿自己的输出当标签。
- `嵌入.npz`：`ids`、`E`，必须和书配置 `sim_model` 是同一个模型、同一种字块（管线的 `char_patch` 归一后）。
- 折按册分（格 id 第一段是册号）。输出各档对数、机器归文意的对；给了 `--prev` 再列档位变化。
- 训练几秒。全唐文第一版的输入是从基准包导的（ai-team 基准目录 `code/export_clf_inputs.py`），嵌入来自原图直接裁的字块，
  上线前要用管线字块重导。从工作区产物直接导刻例和嵌入的命令还没有。

## 五、怎么迭代

1. 新书头几册：所有对在档 0～1，等于没开。可以先借通用底座的嵌入模型，分类器不借。
2. 每跑完一批册重建一次，看档位变化。同字异形的对要先有按刻形定的刻例，办法是聚类后人给类定名（每对看十来行），再让机器重判混类。
3. 一对升到档 3 以后，拿新版把前面册的放行格回头重判一遍，不一致且把握过门槛的自动改（Sheldon 11-18 定）。工具还没做。
4. 退档的对会在重建输出里列出来；退到归文意就不再试字形。

## 六、数字从哪来

门槛（`LR_C=8`、`P_MIN=0.98`、`P_MARGIN=1.0`、终判给字 ≥30）在全唐文 001–045 册上定：66 对够终判，嵌套验证（门槛用两折定、
第三折数错）给字 21,535 格错 2 格，都在 三二。除同字异形的 80 对以外，标签是放行字、没有逐格看图，这 2 格可能是标签错。
刻例少的对（戊戌、搏摶）概率过不了 0.98，留在档 2，这是现在的保守之处。
