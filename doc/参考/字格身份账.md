# 字格身份账（字格永久编号 u）

> 状态：v2，按 guji-manager **v0.6.24**（2026-11-26）现状重写。v1 是 2026-11-24 CV0 定的（Sheldon 同意用 `u`）。
> 代码在 `guji_manager/uid/`（账、对照、入账、自检）、`guji_manager/u_stamp.py`（写入盖 u、导出取 u）、`guji_manager/cell_ref.py`（格的引用出口），命令是 `guji uid …`。
> 对外格式（book-text char 的 `u`、`u_max`、`u_retired`）见 guji-format `spec/02-guji-char.md` §4.10。本账**不是**对外格式，不进 guji-format。
> 改挂清单见 [设计-字格u改挂](../4-反馈迭代/设计-字格u改挂.md)，给人看的入门见 Wiki「字格永久编号 u 与身份账」。

## 一、一句话

格号 `册:页:列:格` 是**位置**：补一个字，后面整列格号都会变；重切一次，整页都可能变。`u` 是**身份**：册内唯一的正整数，一经发出就不改、不复用。
裁定、人裁、待审条目、网站票、标点、专名都挂在 `u` 上，格号怎么挪，它们都跟着字走。

- **谁发号**：manager 在**切字之后**入账时发号（本账），book-text 的改字工具改字时也会发号（`u_max + 1`）。cv 产物里**没有** u，因此 u 不进指纹，也不会让产物过期。
- **真源**：book-text 的 char.json 是对外真源（每格有 `u`，顶层有 `u_max`、`u_retired`）。本账记的是「每份切分 → u」，供入账对照、cv 认裁定和 manager 改挂使用。
- **覆盖面**（11-26）：中心库 263 册有账（殿本 99、全唐文、史記 42、脈經、北行）；book-text 174 册已全上 u；cv 三条 patch 线与 dev 都已开 `ruling_by_u`。

## 二、日常谁要做什么

| 你在做 | 要做的事 | 不用做的事 |
|---|---|---|
| 跑管线、标 main | 照常 `products pack push --main`／`promote`，标 main 的机器 manager 要 ≥0.6.16 | 不用手动入账：标 main 钩子会自动入账、推库 |
| 执行机跑单 | 无（rerun／ab 铺 main 底后自动 `uid sync --local`） | 不入本机跑出的试跑包 |
| 写人裁、裁定、待审条目 | 照常写。`EventLog`／`RulingLog` 追加前会自动盖 u | 不用自己查 u。盖不上会整批报错，见第九节 |
| 换包落 book-text | cv 用 v0.7.110／111／112 或 dev（导出走 manager），manager 用 ≥0.6.23 | 不要用 cv 自带的 `export_guji_format.py`，它不写 u |
| 收网站票 | 照常 `guji feedback collect`／`cellvotes` | 票按 u 合到现格。u 已作废的票会挂起（`moved`） |
| 网站、深链 | 用 `?u=` | 不要再拼格号深链 |
| 执行方（定时） | 有一台开 `GUJI_UID_AUDIT_S`（补漏入账）；只有一台开 `GUJI_UID_CHECKU_S`（人裁自检报告） | — |

## 三、文件与入库

- 位置：数据目录下 `feedback/uid/<册>.jsonl`（feedback 根同裁定库 `feedback/rulings/`），**每册一本，只追加**。
- 进中心库：归 `events` 表（主键 `(src_path, id)`，`stream = uid`），和裁定事件一样走 `guji db sync／push／pull`。只动账时用 `--only feedback/uid/<册>.jsonl`。推库必须设 `GUJI_ACTOR`。
- 册：cv 的册 id。各书写法不同：殿本 `vol31`、全唐文 `001`、史記 `18`、脈經 `01`、北行 `bxgb`。**没有这个文件，就是这册还没启用 u**，这时一切照旧按格号。

## 四、一行的格式（v=1）

一行 = 一页的一份切分入账：

```json
{"id": "uid-vol31-p0012-1a2b3c4d5e6f", "kind": "uid_ledger", "v": 1, "ts": "2026-11-25T01:02:03Z",
 "src": "advance", "by": "CV0-T1", "label": "cv0.7.105-c24-g24-m3-u-on", "book": "vol31", "page": 12, "target": {"book": "vol31"},
 "cells_sha": "<Step3 切分 sha>+<字块 sha>",
 "map":   {"vol31:12:1:1": 3101, "vol31:12:1:2": 3102, "vol31:12:3:5a": 3140, "vol31:12:3:5b": 3988},
 "boxes": {"vol31:12:1:1": [812, 140, 52, 49], "…": "…"},
 "chars": {"vol31:12:1:1": "欽", "…": "…"},
 "lineage": [{"u": 3988, "split_from": 3140}, {"u": 3141, "into": 3140}, {"u": 3150, "gone": true}, {"u": 3989, "new": true}],
 "via": {"iou": 301, "center": 2, "split": 2, "merge": 1, "text": 0, "new": 1, "gone": 1}}
```

| 字段 | 必有 | 含义 |
|---|---|---|
| `id` | 是 | `uid-<册>-p<四位页号>-<map 与 cells_sha 的 sha256 前 12 位>`。同内容同 id，入库按它去重 |
| `kind`、`v` | 是 | 固定为 `uid_ledger`、`1` |
| `ts`、`src` | 是 | 入账时间（UTC）。`src` 取值：`init`（从 book-text 建）、`advance`（手跑，或本机 pipeline 跑完）、`promote`（标 main 钩子）、`sync`（`guji uid sync`／执行机／自检单） |
| `by` | 否 | 谁写的：`GUJI_ACTOR` → `GUJI_JOBS_WHO` → 机器名（0.6.15 起） |
| `label` | 否 | 这份切分来自哪个产物包（sync 和钩子写的行才有） |
| `book`、`page` | 是 | 册、页。`page = 0` 是册级记录（没有格）：从 char 抄来的 `u_max`，或「这个包已对过账」的记号 |
| `target` | 是 | 只有 `{book}`，给中心库 events 表的 book 列。**不写 page**，免得换过图源的册推库时，被页表 rev 闸当成旧页号拦下 |
| `cells_sha` | 是，可 null | 这份切分的戳，口径同 cv `feedback.rulings.page_cells_sha()`（Step3 切分 sha 加字块 sha，用 `+` 连；`alt_cut` 换列的另带 `@alt…`）。旧 cv（如史記 0.7.98 线）没有这个函数时，manager 按 `bindings.page_state` 同口径自己算。从 book-text 建、对不上现行产物的行为 null |
| `map` | 是 | **完整格号**（`册:页:列:格[a|b]`，同 cv 格 id）→ `u`（int）。键按读序 |
| `boxes` | 否 | 格号 → `[x, y, w, h]`，**cord 空间**（左上原点；有字框取字框 `bbox_page`，没有就取格四角的外接框）。下次入账对照用 |
| `chars` | 否 | 格号 → 当时的字。只在两种情况下有：从 book-text 建；或本页 seed_admit 是在现行字块上跑的（manifest 上游 `char_index` sha 等于现行 `cell_shrink` sha）。只重切、没重跑识字时不取字，免得旧字按格号错位 |
| `lineage` | 是 | 这一行里**不是一对一继承**的事：`{u, new: true}` 新号；`{u, split_from: U}` 从 U 拆出；`{u, into: U}` 并进 U、作废；`{u, gone: true}` 格没了、作废。从 book-text 认领的号另带 `src: "book-text"` |
| `via` | 否 | 各档对照配上的格数（统计用），`book_text` 是认领数 |

## 五、读法

- **一页的现行状态** = 该页**最后一行**。
- **按切分找**（cv `seed_admit` 的 `ruling_by_u` 用）：同一个 `(page, cells_sha)` 有多行时取最后一行；`cells_sha` 为 null 的行不用。
- **`u_max`** = 全账发过的最大号（取各行 map、lineage 里的 u 与册级记录的 `u_max` 中最大的）。新号一律从 `u_max + 1` 起。
- **作废号** = 各行 lineage 里的 `into` 和 `gone`，永不复用。
- manager 里的读法：`Ledger.load(册)` → `.page(页)`、`.by_sha(页, sha)`、`.u_map(页=None, full=False)`（缺省键是 book-text 的 `a`，不带册前缀）、
  `.u_max()`、`.retired()`、`.page_pair(页)`（上一份和当前一份，swap、换图源出对照表用）、`.history(u)`。
- 取一格的引用一律经 `cell_ref(格号)`：**有账的册**返回 `u`，查不到报 `UidMissing`，不回退格号；**没账的册**照旧返回格号。反查用 `cell_of(u, 册)`。
- 读旧记录：册有账而记录**没带 u** 的（迁移没配上的旧人裁、旧裁定），读时**不再按格号作数**（`u_stamp.current_cell` 返回 None）。

## 六、入账：什么时候、怎么对照

### 6.1 入账点

| 入账点 | 谁触发 | 做什么 |
|---|---|---|
| **标 main 钩子**（正式入账点） | `products pack push --main`／`promote`（插件 `uid/promote.py`） | 拉这册的账，取回该 main 包入账，有新行就推回中心库。这册还没账、但这部书已有别册的账时，按 main 包首次入账（读序发号）。`GUJI_UID_ON_PROMOTE=0` 关钩子，`GUJI_UID_AUTO_PUSH=0` 只入本机。同一个包重标 main 也会记一笔「已对过」（带时间） |
| 执行机铺底 | 任务库 rerun／ab 单铺好 main 底后，任务的 `uid` 步跑 `guji uid sync --local` | 补标 main 时漏入的账；失败只记录，不挡任务 |
| 定时自检 | 空闲执行方每 `GUJI_UID_AUDIT_S` 秒（建议 14400）跑 `guji uid audit --submit` | 某册账最晚一行早于 main 指针时间就算缺，给它交 `uidsync` 单（同册同标签只交一次）。main 指针记了标 main 时的 `manager_version`，自检据此报出是用旧 manager 标的 |
| 本机 pipeline 跑完 | `hooks.finished` | 只入本机账，推库要另跑 `guji db sync`。执行机（有 `GUJI_JOB_ID`）跑完不入 |
| 手动 | `guji uid advance／sync` | 见第七节 |

cv 按 `(page, cells_sha)` 认的是 **main 包**的切分，所以以「哪份切分成了 main」为准入账。没标 main 的试跑包不入账。

### 6.2 对照规则（`uid/match.py`）

每页先算现行 `cells_sha`，和该页账上最后一行相同就跳过（同一份切分重跑不会动账）；不同就读出这份切分（格号、框、能取到的字），和上一份对照后入一行。一页第一次入账时按读序发新号。

按下面的顺序配，前一档配上的格，后一档不再看：

0. **有字的旧格不配给空格**（0.6.24 起）。空格指 `Cell.c == ""`：切出了格，但 cell_shrink 字块里没有墨（不在 `char_index` 里，或 `cell_type` 是 `empty`），只在识字新鲜时标。
   旧格有字、新格是空格的一对，第 1、2 档都不配；拆格时，空格也不能沿用旧 u。空格只能接空格，或者发新号。
   `c is None` 表示「不知道是什么字」（识字不新鲜，或有墨的待审格还没出字），这种格照旧按框配，因为它们就是同一个字格。只影响以后的入账，已发出的 u 不改。
1. **框 IoU**：IoU ≥ 0.5 的一对一配，按 IoU 从大到小贪心配（口径同 `swap/booktext.cell_table`）。
2. **中心距**：剩下的细字框小，IoU 不够。中心距 < 0.6 × 较大边，并且：两边都有字时要同字；有一边没字时要同格号。
   这比 booktext 严：两边都有字时不认「同号异字」，因为补字后整列顺移，同号的常常不是同一个字。
3. **拆**：一个旧格里落着两个以上新格（新格面积 ≥60% 在旧格里）时，读序在前的沿用旧 u，其余发新号并记 `split_from`。
   例外：拆出的不是夹注 a/b 半格，且恰有一格与旧格同字时，由这一格沿用。典型是漏切补字：旧格「玄」其实压着「地玄」两个字，重切后「玄」留原 u，「地」发新号。旧格已经和某个新格 IoU ≥ 0.85 配上的（框几乎没动）不动。
4. **并**：一个新格里落着两个以上旧格（旧格面积 ≥60% 在新格里）时，留较小的 u，别的记 `into`。新格已经和某个旧格 IoU ≥ 0.85 配上的，留那一格的 u。
5. **字序列兜底**：两边剩下的格按读序取字，用 difflib 对齐，相同的字一对一配（□、〓、空字不参与）。
6. 还剩的新格发新号（`new`），旧格记 `gone`。

**参考 book-text 已发的号**（`uid/booktext.py`）。book-text 改字工具（`char_edits`、意见修订 B′）会自己发 `u_max + 1`，在下次入账前账里没有这一格。所以入账前先读该册的 book-text char：本机有仓就用本机的（`GUJI_BOOK_TEXT`，`--book-text` 指定），没有就从 GitHub raw main 取这一章（缓存在 `~/.cache/guji/book-text`），`--no-book-text` 关掉。
- 新号从 `max(账 u_max, char u_max, char 里最大的 u, char 作废号)` 往上发，绝不发 book-text 用过的号。
- 第 6 档要发新号（`new`／`split_from`）的格，如果和 book-text 里「账上还没有的 u」那一格框对得上（IoU ≥ 0.5，或中心距近且同字），就认领这个 u。有字的 book-text 格不让空格认领。
- 账是从 book-text 建的册却找不到 char 时，`advance` 直接报错，不静默跳过，免得发出撞号。

### 6.3 例子：史記 18 第 2 页第 5 列（0.6.24 修的就是这个）

上一份切分里第 5 列从 `18:2:5:1` 起，「唐」在 `18:2:5:3`（u33）。现行 main 包在列首多切出 4 个空格（`-1`、`1`、`2`、`3`），「唐」挪到 `18:2:5:4`。
旧「唐」的框和新空格 `18:2:5:3` 的 IoU 是 0.378，和新「唐」是 0.41，都不到 0.5，于是走到第 2 档。0.6.24 以前，「有一边没字就要同号」让 u33 按同格号配给了空格，「唐」反而发了新号 u28263，挂在 u33 上的人裁、票也就跟到了空格上。
0.6.24 起空格不接有字旧格，「唐」在第 2 档按同字、中心距配回 u33，空格发新号。11-26 全库扫过：账上「旧格有字 → 新格没字」的 3754 对里，3749 对是有墨的待审格（配得对），真空格只有 5 个，上面都没挂人裁、条目或票。

```
$ guji uid table 18 --pages 2          # 截取第 5 列（0.6.24 前入的账）
旧格      新格      旧字 新字 类别 IoU    说明
18:2:5:3  18:2:5:3  唐        同格 0.378  u33      ← 有字旧格配给了空格
18:2:5:4  18:2:5:5  國   國   改号 0.558  u34
18:2:5:5  18:2:5:6  子   子   改号 0.681  u35
```

## 七、命令

```
guji uid sync    <册> -w <工作区> [--label <包>] [--local] [--products <根>] [--no-push] [--reconfirm]
guji uid audit   [--submit] [--cv <版本>]
guji uid advance <册> -w <工作区> [--products <根>] [--pages 1-20,33] [--dry-run] [--force] [--book-text <仓> | --no-book-text]
guji uid init    <册> -w <工作区> --from-book-text <仓> --text-id <书ID> [--edition default] [--chapter NNN] [--with-products]
guji uid init    <册> --char 031.char.json --cord 031.cord.json
guji uid show    <册> [--page 12 | --cell <完整格号> | --u 1234] [--json]
guji uid verify  <册> [--check-products] [--pages …]
guji uid table   <册> [--pages …] [-o 对照.tsv]
guji uid migrate-plan <册> --items <条目文件…> [-o 目录] [--write] [--close] [--review-items <文件>]
guji uid tidy-recheck --items <条目文件…> [--write]
guji uid stamp <事件文件…> [--write]
guji uid check-u [-o 清单.tsv] [-v]
guji uid anchor-fill [--write] [-o 补不了.jsonl]
guji uid check-u-report [--roots …] [--notify]
guji uid web-backfill <cv册> --ws <工作区> --site-book <书ID> --site-vol <册号> -o <目录> [--write]
```

| 命令 | 什么时候用 | 说明 |
|---|---|---|
| `sync` | **补入账首选**：标 main 钩子漏了（旧 manager 标的、钩子报错）、自检单、执行机 | 拉这册账 → 取 main 包（或 `--label` 指定的包、`--local` 用本机已铺好的产物）入账 → 推库。包的切分没变时写一笔 page 0「已对过」记号。返回 `entered`／`synced`／`unchanged`／`pull_failed`／`push_failed` |
| `audit` | 定时（执行方），或想看哪些册缺账 | 账最晚一行早于 main 指针时间算缺；`--submit` 给缺的交 `uidsync` 单 |
| `advance` | 本机拿现行产物入账（调试、没有 main 包的试点） | 只写本地，推库另跑 `guji db sync --only feedback/uid/<册>.jsonl` |
| `init` | 给还没账的册建账（有账会拒绝） | char 带 `u`（v0.6）就照抄，`u_retired` 进册级记录；不带就按读序 1..N。`--with-products` 时，某页现行产物的格号序列和 char 一致就记上 `cells_sha`；否则记 null，接着跑一次 `advance` 按框接上 |
| `show` | 查一格的 u、一个 u 现在在哪、来历 | 不带选项是全册概况（行数、页数、格数、`u_max`、作废数） |
| `verify` | 动过账以后 | 每行 u 不重复；全册现行 u 不重复、不在作废号里；`into` 指向的 u 还在；每页相邻两行之间，旧 u 要么还在、要么记了作废（不静默丢）。`--check-products` 再核每页现行切分都入了账 |
| `table` | 换包、改挂前看「旧切分 → 新切分」 | 输出 `旧格 新格 旧字 新字 类别 IoU 说明`，和 A31 的 old_new_cells 同格式，`cell_migrate`／`cell_rekey`／swap 直接读 |
| `migrate-plan` | 存量迁移（11-25 已对全库做完）；以后新开有账的书、或从老备份恢复时再用 | 给旧裁定、人裁、待审条目配 u，只追加（`~u` 抄件）。`--close` 收口：救一批，其余作废记档或转待审。口径见第十节 |
| `retire-into` | 重切后旧 u 记了 gone、新格另发了号，看图确认是同一格 | `guji uid retire-into <册> 旧u:新u … --why … --write`：旧 u 改记并入新 u（册级一行 page=0）；之后重新导出新包 char，换包时旧格当改号接到新格，人裁／标点／专名跟过去 |
| `revive` | 新切分漏切了某格、旧 u 记了 gone，book-text 已按旧 u 把这格补回（看图确认） | `guji uid revive <册> u:页:列:格 [--box x,y,w,h] [--char 字] --why … --write`：抄该页现行最后一行（`cells_sha` 不变），map 插入这格，lineage 记 `{u, revived: true}`，`retired()` 从作废号里拿掉。只收 gone，不收已并入的；推库另跑 `db push --only feedback/uid/<册>.jsonl`。注意：切分里仍没有这格，下次重切入账（advance）或导出新包时又会记 gone，要让切分补上这格（切分覆盖）或换包时再补 |
| `dedup-ids` | 推库被拦「主键 … 与第 N 行重复」时（11-26 前的版本入账，页切回账上更早的某份切分，id 撞旧行） | `guji uid dedup-ids <册> --write`：本地账里后出现的重复 id 改成 `…-r2`、`-r3`。0.6.42 起入账（`Ledger.append`）自动避开重复，`uid sync` 推库前也自动改名，一般不用手跑 |
| `items-u` | check-u 报「活条目没 u」时 | 待审条目活着却没 u 的按账补 u（`--write` 才写，追加 op=u-fill 一版）；`pending reconcile／import` 11-26 起换包开条目自动盖 u |
| `tidy-recheck` | 收口转出的 `recheck` 条目太碎时 | 同格并成一条，补候选字（现行字、旧人裁字、票字） |
| `stamp` | 推库被「没带 u」拦下时（脚本直接用 cv `EventLog`、手拼 jsonl 写的事件） | 按身份账给锚在同一份切分上的行就地补 u（人裁锚 `cells_sha` 主段＝账行、裁定 `cells_sha` 命中账行），别的行逐字节不动；补不上的列出来交 `migrate-plan`，退出码 1。缺省只报，`--write` 才改（0.6.26） |
| `check-u` | 改完人裁、迁移后自检 | 有账册每格最新人裁：①没 u 也没记作废／转待审；②`~u` 抄件缺补锚档；③抄件无框无档。都应为 0，不为 0 时退出码为 1 |
| `anchor-fill` | `check-u` 报②③时 | 给 `~u` 抄件补锚档（`feedback/anchors/<册>.jsonl`）：原件有档的照抄；无框无档的按身份账取 u 在现行切分的框。缺省只报数，`--write` 才写 |
| `check-u-report` | 执行方定时（只开一台：`GUJI_UID_CHECKU_S=14400`） | 本机各工作区跑 `check-u`，非 0 且和上次不同就通知 CV0 和该书项目（`GUJI_UID_CHECKU_PROJECTS` 可改对应）。只报不改 |
| `web-backfill` | 网站旧票补 u（11-25 已做完） | 按身份账给 D1 `web_inbox` 的旧票补 `u`。缺省只出提案，`--write` 才写中心库（写前记 D1 时间旅行书签） |

## 八、u 出现在哪里

| 东西 | 字段 | 谁写 | 谁读、怎么用 |
|---|---|---|---|
| 文意裁定（`ctx_ruling`） | `payload.u` | `RulingLog` 追加前自动盖 | cv `RulingStore`（`ruling_by_u` 开）按 (组, 册, u) 建索引，重切后仍命中 |
| 裁定事件（格级 confirm 等） | `target.anchor.u` | `EventLog` 追加前自动盖 | seed_admit、`rulings-hits`、网站票去重；`~u` 抄件另要补锚档 |
| 待审条目 | `u`；网站按章现拼的单每格也带 | land、条目写入 | 对账先按 u 认，再按指纹、格号 |
| 网站票 | D1 `web_inbox` 的 `u`（虚拟列＋索引） | 网站（v0.2.34 起） | `cellvotes` 按 u 分组合到现格；u 已作废的票挂起（`moved`） |
| book-text | char v0.6 每格 `u`，顶层 `u_max`、`u_retired`；norm v0.3 条目带 `u` | 导出（第九节）、book-text 改字工具 | 网站 `?u=` 深链、标点专名按 u 挂（字下标缓存已删，现算） |
| 字形库刻例 | **不带 u**，键仍是 `v2:册:页:列:格` | — | 重切后**不 rekey**：读时 cv `bindings.rebind_library_shapes` 拿库键找同键裁决事件，按绑定顺移到现格。`rekey-cells` 只用于换图源 |

**写入以 u 为准**：manager 里所有写裁定事件、裁定的地方都经 `u_stamp` 子类，追加前自动盖 u。册有身份账而盖不上的（账上没这一格、格号不全），**整批报错不写**（`UidRequired`）。格号照写，方便人读。
**推库闸**（0.6.26）：不经 manager 写的事件（脚本直接 import cv 的 `EventLog`、手拼 jsonl）会绕过上面这一步，所以 `guji db push／sync`（含 `--only`）再核一遍：册有账的格级人裁没有 `anchor.u`、按格裁定没有 `payload.u`，且这条是**新推**的（库里没有这个 id），整批拒收，提示跑 `guji uid stamp`。库里已有的老事件不拦（存量走 `migrate-plan`）。`GUJI_DB_ALLOW_NO_U=1` 放行。

## 九、导出与换包（book-text 的 u 从哪来）

char-cord 导出（`python -m guji_manager.output.guji_format_export --format char-cord`，也就是 `guji output export format`、cv `proof_cycle`／`zl` 走的那条）在册有账时：

1. 按账给每格写 `u`，顶层写 `u_max`（取账的）和 `u_retired`（取账的作废号）；`$schema` 升 char v0.6，norm 条目带 `u` 并升 norm v0.3。有格在账上查不到 u 就报错，不写半截。
2. `u_retired` 里 `into` 的目标不在本章 char 里（空列、插图块占掉等），就降成 `{u, gone}`，记进报告 `u_retired_dangling`（0.6.21）。
3. **保 u 连续**（0.6.23）：参考 book-text 现行的同章 char（缺省按册配置自动找；`--prev-char <文件>` 指定，`--no-prev-char` 关）。
   旧版格里有、本次没导出、作废表里也没有的 u，一律补成 `{u, gone}`，记进报告 `u_unexported`，不复用。旧版 `u_retired` 有、本次没有的照抄。本次格里又出现旧版已作废的 u 时打 ⚠，记进报告 `u_revived`。只导部分页时，只看导出的那几页。
   实测史記 18：旧版 27039 个 u，新导出里全部在格里或作废表里，`u_retired=[{u:33, gone}]`。
4. 插图块占掉的格连 u 一起去掉，记进报告 `u_dropped`。

**版本要求**：换包导出用 manager ≥0.6.23；cv 用殿本线 v0.7.110、全唐文线 v0.7.111、史記线 v0.7.112，或 dev 0.9.x。更早的 patch 线 `proof_cycle`／`zl` 调的是 cv 自带的 `export_guji_format.py`，不写 u，book-text 的 local_check 会报「u 全丢」。

**换包（swap book-text）**：新旧 char 都带 u 时，对照表按 u 出（同一个 u 是同一格；旧 u 不在新版就是删，新版 `u_retired` 里有就写明并进了哪个 u；新 u 不在旧版就是新增），说明一栏写「按u」。R1 闸（刻例对位）放过身份账已作废格的刻例，只计数（0.6.22）。book-text 侧 `check_u_continuity.py` 在 local_check 里核：旧版每个 u 要么还在格里，要么在 `u_retired` 里。

## 十、存量迁移口径（11-25 已对全库做完，留档）

`migrate-plan` 给已有的东西配 u，只追加：裁定、人裁各抄一条带 u 的（id、批次名加 `~u`，时间和序号不变，原事件不动），待审条目追加一版补 `u`。
- **裁定**：记了格锚 `cells_sha` 且等于账上某行 → 取那行的 u；否则比窗口（格号前后各 2 字，按本书异体归一表比）：两侧都同，或一侧同且裁定字 = 账上字。私用码裁定没记窗口，就比裁定字 = 账上字，或账上各版这格都是同一个 u。
- **人裁**：锚里 `cells_sha` 主段 = 账上某行 → 取那行的 u；否则比人裁字（字形或读作）= 账上字；没字可比时，要求账上各版这格是同一个 u。人裁 `anchor.bbox` 是右上原点的原图坐标，和账的 cord 框不能比 IoU。
- **待审条目**：格号在现行账里就补。
- 每册出 `守恒.json`（迁前 = 迁出 + 没迁，对不上直接报错）和 `清单.tsv`。
- `--close` 收口：清单上的人裁再按「高置信异体同字」「同页同列前后 3 格内唯一同字」救一批；其余裁定、没字或格已不在的人裁**作废**（不删原事件，记进 `feedback/lists/u_void/<册>.jsonl`）；字和现行文本不同的人裁转成待审条目（`pending_reason=recheck`）；格号不在账上的待审条目撤下。
- 11-26 起 `--close` 先用 cv 绑定认格：清单上的人裁若 cv `book_bindings` 绑到现行账上某格（valid／rebound）、账上字与人裁字同（归一或异体）、该 u 没被别的人裁占，就认那格的 u（整列平移、格号前后挪了的人裁不再作废）。`--bind-products <目录>` 指现行 main 包产物；没装 cv 或没产物时报一行跳过。
- 作废／转待审记错了要撤：往 `u_void/<册>.jsonl` 追加 `{"kind": "u_unvoid", "id": <事件 id>, …}`，它之前同 id 的记档就不算（`void_seen`／`void_ids`／check-u 都按撤销后的算）。`u_migrate.unvoid` 一次做完：抄 `~u` 件（带补锚档）、记撤销、撤下这些人裁转出的 recheck 条目。
- 结果：裁定 8,220、人裁 34,035（另救回 3,967）、条目 3,910 配上 u；作废裁定 834、人裁 341；转待审 303。网站票 2,411 张中 1,883 张有 u，其余是换图源前的旧票或已作废格，不追溯。

## 十一、常见报错怎么办

| 报错／现象 | 原因 | 怎么办 |
|---|---|---|
| `UidMissing: <格>：<册> 有字格身份账，但现行账里没有这一格（切字后没入账？…）` | 这份切分还没入账（标 main 时 manager 太旧或钩子失败） | `guji uid sync <册> -w <工作区>`；要用本机产物就加 `--local` |
| `UidRequired: N 条写不出字格永久编号 u…整批不写` | 写人裁、裁定时有格盖不上 u | 同上，先入账；格号不全（缺册前缀等）的修调用方 |
| 导出报 `p<页> 格 <a>「<字>」在字格身份账里没有 u——先 guji uid advance` | 导出用的产物切分没入账 | 用 main 包导出；本机试跑产物先 `guji uid advance <册>`（只本地，别推） |
| `✗ <册> 的账是从 book-text 建的，但找不到这册的 char.json…` | 入账要参考 book-text 已发的号，但找不到 | 设 `GUJI_BOOK_TEXT`、`--book-text <仓>`，或让本机能连 GitHub raw；确知没有就 `--no-book-text` |
| book-text local_check：u 全丢 | 换包导出走了 cv 自带导出器（patch 线旧版） | cv 升到 v0.7.110／111／112 或 dev，manager ≥0.6.23，重新导出 |
| book-text local_check：某 u 不在新版、也不在 `u_retired` | manager 0.6.23 以前的导出不保 u 连续 | manager ≥0.6.23 重新导出 |
| swap R1 闸报 orphan 刻例 | 0.6.22 以前不认身份账已作废格 | manager ≥0.6.22；W1 这类重切后换包先别带 `--glyph-db` |
| 重切后「字」的 u 变成新号、旧 u 挂在空格上 | 0.6.24 以前的匹配口径（第 6.3 节） | ≥0.6.24 之后的入账不会再出现；已发的 u 不改，这种 u 在下次导出时记 gone |
| `uid sync` 返回 `push_failed` / `StaleBase` | 推库时别人写过 | 重跑 `guji uid sync`；执行机部分副本要 manager ≥0.6.17 |
| `db push` 被拒：没设 actor | 推库要 `GUJI_ACTOR` | 设好再推 |
| 推库报「N 条新事件的册有字格身份账却没带 u…中心库拒收」 | 事件不是经 manager 写的 | `guji uid stamp <文件> --write` 后再推；补不上的（锚在旧切分）用 `guji uid migrate-plan <册> --write` |
| `check-u` 非 0 | 有人裁没 u 也没记档，或 `~u` 抄件缺锚档 | 「没u没记档」是已推进库的老事件：`guji uid migrate-plan <册> --write` 补 `~u` 抄件（11-26 史記 22 条即此）；后两项跑 `guji uid anchor-fill --write`；第一项看清单，由人定作废还是转待审 |
| `audit` 说某册缺账 | 标 main 时钩子没入上 | `guji uid audit --submit` 交单，或手跑 `uid sync` |
| seed_admit `human_unbound` 突增 | `~u` 抄件缺补锚档，cv 判 unanchored | `guji uid anchor-fill --write`，推库后重放 seed_admit |
