# 字格身份账（字格永久编号 u）

> 状态：v1，2026-11-24 CV0 定（Sheldon 同意用 `u`）。代码 `guji_manager/uid/`，命令 `guji uid`，格的引用出口 `guji_manager/cell_ref.py`。
> 对外格式（book-text char 的 `u`、`u_max`、`u_retired`）见 guji-format `spec/02-guji-char.md` §4.10；本账**不是**对外格式，不进 guji-format。
> 设计与执行方案：A20「字格永久编号 u：设计方案」「字格永久编号 u：执行方案」。

## 一、为什么有这本账

格号 `页:列:格` 是位置：补一个字后面整列格号都变，重切一次整页都可能变。`u` 是身份：册内唯一的正整数，发了永不改、永不复用。
裁定、待审单、网站人审票、人裁、标点、专名都挂 `u`，字怎么挪它们都跟着走。

`u` 要看「上一份切分」才能继承，是跨运行的状态，所以**不写进 cv 产物**（写进去所有书从切字起过期，产物也不再可复现），
而是由 manager 在切字后另记一本账。出 v0.1 以后 book-text 的 char.json 是 `u` 的真源（每格写 `u`，顶层 `u_max`、`u_retired`），
本账只在 v0.1 之前用；中心库清掉以后，cord 的框加 char 的 `u` 就能重建账（`guji uid init --from-book-text`）。

## 二、文件与入库

- 位置：数据目录 `feedback/uid/<册>.jsonl`（feedback 根同裁定库 `feedback/rulings/`），**每册一本，只追加**。
- 进中心库：归 `events` 表（主键 `(src_path, id)`，`stream = uid`），与人裁事件一样走 `guji db sync／push／pull`。每行一页，不会超行长上限。
- 册：cv 的册 id（`vol31`、`001`…）。没有这个文件＝这册还没启用 `u`。

## 三、一行的格式（v=1）

一行＝一页的一份切分入账：

```json
{"id": "uid-vol31-p0012-1a2b3c4d5e6f", "kind": "uid_ledger", "v": 1, "ts": "2026-11-25T01:02:03Z",
 "src": "advance", "book": "vol31", "page": 12, "target": {"book": "vol31"},
 "cells_sha": "<Step3 切分 sha>+<字块 sha>",
 "map":   {"vol31:12:1:1": 3101, "vol31:12:1:2": 3102, "vol31:12:3:5a": 3140, "vol31:12:3:5b": 3988},
 "boxes": {"vol31:12:1:1": [812, 140, 52, 49], "…": "…"},
 "chars": {"vol31:12:1:1": "欽", "…": "…"},
 "lineage": [{"u": 3988, "split_from": 3140}, {"u": 3141, "into": 3140}, {"u": 3150, "gone": true}, {"u": 3989, "new": true}],
 "via": {"iou": 301, "center": 2, "split": 2, "merge": 1, "text": 0, "new": 1, "gone": 1}}
```

| 字段 | 必有 | 含义 |
|---|---|---|
| `id` | 是 | `uid-<册>-p<四位页号>-<map 与 cells_sha 的 sha256 前 12 位>`；同内容同 id，入库按它去重 |
| `kind` | 是 | 固定 `uid_ledger` |
| `v` | 是 | 本格式版本，现为 1 |
| `ts`、`src` | 是 | 入账时间（UTC）；`advance`（切字后入账）或 `init`（从 book-text 建） |
| `book`、`page` | 是 | 册、页。`page = 0` 是册级记录（没有格，见下） |
| `target` | 是 | 只有 `{book}`：给中心库 events 表的 book 列。**不写 page**，免得换过图源的册推库时被页表 rev 闸（cv `RevGate`）当成旧页号拦下 |
| `cells_sha` | 是，可 null | 这份切分的戳，口径＝cv `feedback.rulings.page_cells_sha()`（Step3 切分 sha＋字块 sha，用 `+` 连；`alt_cut` 换列另带 `@alt…`）。从 book-text 建、对不上现行产物的行为 null |
| `map` | 是 | **完整格号**（`册:页:列:格[a|b]`，同 cv 格 id）→ `u`（int）。键按读序 |
| `boxes` | 否 | 格号 → `[x, y, w, h]`，**cord 空间**（左上原点，口径同 book-text 导出 `tr_bbox_to_xywh(quad_bounds(quad_page), W)`）。下次入账对照用 |
| `chars` | 否 | 格号 → 当时的字（从 book-text 建，或本页 seed_admit 是在现行字块上跑的才有：manifest 上游 `char_index` sha＝现行 `cell_shrink` sha；只重切没重跑识字时不取，免得旧字按格号错位）。中心距、拆格、字序列兜底用 |
| `lineage` | 是 | 这一行里**不是一对一继承**的事：`{u, new: true}` 新号；`{u, split_from: U}` 从 U 拆出；`{u, into: U}` 并进 U、作废；`{u, gone: true}` 格没了、作废 |
| `via` | 否 | 各档对照配上的格数（统计用） |
| `u_max` | 否 | 只在册级记录（`page = 0`）上：从 char 照抄的顶层 `u_max`（删过尾号时比现存最大号大） |

## 四、读法

- **一页的现行状态**＝该页**最后一行**。
- **按切分找**（cv `seed_admit` 的 `ruling_by_u` 用）：同 `(page, cells_sha)` 多行取最后一行；`cells_sha` 为 null 的行不用。
- **`u_max`**＝全账发过的最大号（各行 map、lineage 里的 u，与册级记录的 `u_max` 取大）。新号一律 `u_max + 1` 起。
- **作废号**＝各行 lineage 里的 `into`／`gone`，永不复用。
- manager 里读：`Ledger.load(册)` → `.page(页)`、`.by_sha(页, sha)`、`.u_map(页=None, full=False)`（缺省键是 book-text 的 `a`，不带册前缀）、
  `.u_max()`、`.retired()`、`.page_pair(页)`（上一份与当前一份，swap／换图源出对照表用）、`.history(u)`。
- 取一格的引用一律经 `cell_ref(格号)`：**有账的册**返回 `u`，查不到报 `UidMissing`（不回退格号）；**没账的册**照旧返回格号。
  反查 `cell_of(u, 册)`。

## 五、入账：对照规则

`guji uid advance <册>`。自动入账两处：① **标 main**（`products pack push --main`／`promote`，插件 `uid/promote.py`）：先从中心库拉这册的账，取回该 main 包入账，有新行推回中心库——cv 认的是 main 包的切分，这是正式入账点，执行机标 main 也走这里；② 本机 `guji pipeline` 跑完（`hooks.finished`），只入本机账，推库另跑 `guji db sync`；执行机（任务库单）跑完不入。对现行产物每页先算 `cells_sha`，与该页现行账行
相同就跳过（同一份切分重跑不动）；不同就读切分（格号、框、能取到的字）与上一份对照，入一行。一页头一次入账按读序发新号。

对照（`uid/match.py`），前一档配上的格后一档不再看：

1. **框 IoU** ≥ 0.5 一对一，按 IoU 从大到小贪心（口径同 `swap/booktext.cell_table`）。
2. **中心距**：剩下的细字框小、IoU 不够：中心距 < 0.6×较大边，且同字（两边都有字时；有一边没字则要同格号）。
   比 booktext 严：两边有字时不认「同号异字」——补字后整列顺移，同号的常常不是同一个字。
3. **拆**：一个旧格里落着两个以上新格（新格面积 ≥60% 在旧格里）。读序在前的沿用旧 u，其余发新号记 `split_from`。
   例外：拆出的不是夹注 a/b 半格、且恰有一格与旧格同字，由它沿用（漏切补字：旧「玄」格压着「地玄」，重切后「玄」留原 u、「地」新号）。
   旧格已和某新格 IoU ≥ 0.85 配上（框几乎没动，只多切出一小块）的不动。
4. **并**：一个新格里落着两个以上旧格（旧格面积 ≥60% 在新格里）。留较小的 u，别的记 `into`。新格已和某旧格 IoU ≥ 0.85 配上的留那一格的 u。
5. **字序列兜底**：两边剩下的格按读序取字 difflib 对齐，相同的字一对一配（□、〓、空字不参与）。
6. 还剩的新格发新号（`new`），旧格记 `gone`。

消失或被并掉的 u 上挂的裁定、票、待审单、标点，由改挂一侧（T2）列清单交人看，不静默丢。

## 六、命令

```
guji uid advance vol31 [-w <工作区>] [--products <产物根>] [--pages 1-20,33] [--dry-run] [--force]
guji uid init vol31 --from-book-text <book-text 仓> --text-id 96mid1ogzk [--edition default] [--with-products]
guji uid init vol31 --char 031.char.json --cord 031.cord.json
guji uid show vol31 [--page 12 | --cell vol31:12:3:4 | --u 1234] [--json]
guji uid verify vol31 [--check-products]
```

- `init`：给还没账的册用（有账拒绝）。char 带 `u`（v0.6）就照抄、`u_retired` 进册级记录；不带按读序 1..N。`--with-products` 时某页
  现行产物的格号序列与 char 一致就记上该页 `cells_sha`，cv 能直接用；否则 null，接着跑一次 `advance` 按框接上。
- `verify`：每行 u 不重；全册现行 u 不重、不在作废号里；`into` 指向的 u 还在；每页相邻两行之间旧 u 要么还在、要么记了作废（不静默丢）；
  `--check-products` 再核每页现行切分都入了账。
- 写账只写本地数据目录；推中心库另跑 `guji db sync`。写中心库正式数据（试点册、推全库）前先问用户。

## 七、和别处的关系

| 谁 | 怎么用这本账 |
|---|---|
| cv `seed_admit`（T3） | 书级开关 `ruling_by_u` 开时只读：按本页当前 `cells_sha` 找行取 map；账不进指纹 |
| manager 改挂（T2） | 裁定、人裁事件、待审单、网站票、book-text 导出都经 `cell_ref()` 或 `Ledger` 批量取 u；swap／换图源按 `page_pair` 出对照 |
| book-text（T4） | 导出时照抄 u；v0.1 以后改字工具发号（`u_max+1`）、删字记 `u_retired` |
