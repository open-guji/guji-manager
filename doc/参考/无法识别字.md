# 无法识别字（`unk`）：图上有字、认不出、Unicode 没有

> 2026-11-13 Sheldon 定（全唐文 007:77:9:15，左「王」右「旦」，查不到任何码位）。网页暂显示「？」，将来换私用区字符或别的方案。
> 格式真源：guji-format spec 02 §4.9、char v0.5（guji-format#31）。

## 一、什么时候用

| 这格图上是… | 用什么 |
|---|---|
| 一个字，人认出来了 | 定字（`confirm shape=X`） |
| 一个字，**认不出，Unicode 里也没有**（只能描述部件） | **无法识别字 `unk`（本文）** |
| 一个字，有近似的已收字，要记原形 | 组字 `zi` |
| 原有字但磨损缺失，看不出 | 阙文（`damaged`，可带推测字） |
| 一个图形、符号，不是字 | 图片格 `fig` |
| 本来就没有字（墨污、切坏） | `not_a_char` |

## 二、book-text 里长什么样

```json
{"a": "77:9:15", "c": "□", "unk": "左王右旦"}
```

- `c` 写 `□`，`unk` 是**部件描述或 IDS**（`左王右旦`、`⿰王旦`）；没写描述的导出补「无法识别」。
- 与 `lacuna`／`guess`／`guess_c`／`zi`／`fig` 互斥；文件 `$schema` 写 char v0.5（`char_schema_for` 自动选）。
- 分行稿 lines.md 里写 `□`（描述不进分行稿，与 Step9 的 lines.md 逐字节一致）。
- 不进检索、不能被 `apply_pending` 填首选字、换包（`swap`）时不被现行字回填。
- **将来换私用区字符**：造字落定后，该格 `c` 改成那个字符、`zi` 记原形、去掉 `unk`，走普通 0.x 小改。

## 三、怎么录（人裁事件）

对 cv 它和图片格是同一条路（不进字形库、不出卡、字位占住出 □），所以**事件不新增 `v`**：

```json
{"kind": "confirm", "target": {"unit": "cell", "key": "vol07:77:9:15"}, "payload": {"v": "figure", "unk": "左王右旦"}}
```

- `payload.unk` 有值＝无法识别字；没有就是图片格（`alt` 为说明）。同格后到的事件为准：先判无法识别、后改判图片格或定字，都以最新一条为准。
- 网站精校票：`choice=unrec`，票上 `unk` 是描述（可空）；`guji feedback cellvotes` 落成上面这条事件（`web_votes.payload_of`）。
- `crop_exclude` 消费者把描述写进排除名单 evidence 的 `unk=…`（理由仍是 `figure`）。

### 落库以后必须过消费（谁落谁 route）

导出**不直接读事件**：「是不是图片格／无法识别字」以排除名单 `config/crop_exclusions.jsonl` 为准，名单由 `crop_exclude` 消费者写。事件只落库、没过消费，seed_admit 照常认字，导出就没有 `unk`。

| 怎么落的 | 谁 route、什么时候 |
|---|---|
| 网站精校票 → `guji feedback cellvotes write`、`guji feedback collect` | 命令自己写完就消费，不用另做 |
| 手写事件文件（`feedback/events/<批次>.jsonl`）后 `guji db push`／`db sync` | **落库的人**当场跑 `guji pipeline events route <批次> -w <工作区>`（可先 `--dry-run`），再 `guji db push`。`db sync` 的自动落库只跑 `glyphdb_admit`，**不会**替你跑 `crop_exclude` |

归谁（2026-11-20 定）：

- **一条线管**：每本书手写人裁批次的 route 固定归一条线（全唐文＝字形线）。落库的人当场 route、`db push`，并报本书总览「该页从 `seed_admit` 起重跑」。
- **别的线发现漏了只报不补**：报给管 route 的那条线，不在自己机器上补 route、不推库。两处各 route 一遍，后推的会把先推的名单行盖掉。
- **route 前先升 manager**：要 ≥ v0.4.45 才认 `unk`；旧版 route 出来的名单行只有 `figure`、不带 `unk=`，推上去这格就导出成图片格（全唐文 `007:77:9:15` 11-20 险些被这样盖掉）。

落完自查三样（缺一样就是没走完）：

1. 中心库 `consumed` 里这条事件有 `crop_exclude`、`gold_add`、`product_invalidate`（不只是 `glyphdb_admit`）；
2. `config/crop_exclusions.jsonl` 有这一格：`reason=figure`，evidence 带 `unk=<描述>`；
3. 这一页从 `seed_admit` 起重跑、导出、换单后，book-text 该格是 `{"c":"□","unk":"…"}`。排在哪一轮重跑由各书自己定，但要记在轮单上，别只落库不跑。

实例（2026-11-20）：全唐文 `007:77:9:15`（左王右旦）11-13 手写批次 `H-unrec-1113a` 落库后没 route，`consumed` 只有 `glyphdb_admit`，之后六轮导出该格一直是「理」；同期经网站票落的 35 条都正常。补 route 后（rev 1391859）进名单。

## 四、导出

`feedback.figures.figure_cells(book)` 返回 `{字位: 说明}`，无法识别字的值是 `UnkDesc`（`str` 子类，所以 cv 的导出脚本不用改）；
`formats.guji_page_cv.from_cv_products` 据此在字框上写 `unk`（而不是 `fig`）；`guji_char_cord._char_cell` 写 char 格。

要求 guji-manager ≥ 本改动发版（见 CHANGELOG）。
