# 5a 相似度模型（度量学习 CNN）

> 2026-11-16 写（OCR 研究 Project）。汇总 11-09 至 11-16 几轮实验后的用法：这个模型是什么、开关怎么配、怎么训（按书、合训、微调）、怎么换权重、开新书怎么办。
> 代码在 cv：`open_guji_cv/clustering/sim_cnn.py`（模型与接入）、`steps/glyph_match.py`（开关）、`scripts/train_glyph_sim_cnn.py`（训练）、`scripts/eval_sim_bench.py`（基准）、`scripts/fit_glyph_sim_calib.py`（校准）。
> 实验过程与全部数字在 ai-team `domain/CV/字形领域/`：`5a相似度算法-2026-11-09.md`（为什么换 CNN）、`5a相似度CNN深化-2026-11-15/跨书通用底座-2026-11-16.md`（合训与新书）。

## 一句话

5a（`glyph_match`）拿一格的字图去本书字形库里找同字。粗排（HOG 的 kNN）之后要逐对「精验」：这格和库里这个刻例是不是同一个字。精验缺省用覆盖分 cov（两图对齐后墨迹互相盖住多少）；`sim_model` 开关把它换成一个小 CNN 的嵌入余弦。CNN 对污点、偏移、笔画粗细更稳，一个全局门槛下同字和异字分得更开。

## 原理

- **网络**：`SimNet`，4 段卷积加全连接，64×64 二值归一图进、128 维单位向量出，约 94 万参数。两张图的相似度就是两个向量的点积。
- **训练**：度量学习。每个码位一类，CosFace 损失（m=0.25，s=24），让同字的刻例向量挤在一起、异字拉开。训练集是字形库的刻例，推理时不要分类头，所以训练里没见过的字也能比。
- **增强**：±3° 旋转、0.9–1.1 缩放、±4px 平移；膨胀、腐蚀（含 3×3 细笔）；擦掉 1–2 块矩形（残笔）；加小墨点。
- **接入**：`CnnVerifier` 顶替匹配器的 `_verify`。库里每个刻例的向量整库算一次缓存，查询图每格算一次，逐对只是点积。护栏、共识升档、`font_tier` 照旧。
- **校准**：CNN 余弦和 cov 尺度不同，而下游 `seed_admit`、`align_ref` 有约 30 个「cov ≥ X」门槛。权重旁放 `calib.json`，把 CNN 分按「同等误配率」分段线性映射到 cov 尺度（异字对里 CNN ≥ s 的比例＝cov ≥ c 的比例），下游门槛就原样可用。
- **融合**：`fuse: mean` 时再算一遍 cov，逐对分取校准后 CNN 分与 cov 的平均。原因是 CNN 对「库里没有这个字」的格过分自信（全唐文 006：廬 认成 盧、樹 认成 榭），cov 能把这种独断压下去。

## 开关与配置

开关在册配置的 `params.glyph_match.sim_model`（层级与合并规则见 [册配置](册配置.md)），缺省关。关着时不进参数 dump，各书产物逐字节不变。

```yaml
params:
  glyph_match:
    sim_model:
      path: models/glyph_sim_qtw/model.pt   # 权重，相对 cv 仓根或绝对路径
      fuse: mean                            # 可省；"" 只用 CNN，mean 与覆盖分取平均（要有 calib.json）
      same: 0.996                           # 可省；分数 ≥ same 判 same
      low: 0.85                             # 可省；分数 ≥ low 判 unsure，其余 diff
```

| 字段 | 缺省 | 说明 |
|---|---|---|
| `path` | 必填 | 权重文件。也可以整个 `sim_model` 只写一个字符串当 path |
| `fuse` | `""` | 只认 `mean`。没有 `calib.json` 时写 `mean` 会报错 |
| `same` | 有校准表 0.996，没有 0.90 | 有校准表时与覆盖分同档，不用改 |
| `low` | 有校准表 0.85，没有 0.50 | 同上 |

- **校准表不写在配置里**，放在权重同目录、名字固定 `calib.json`，有就自动用。
- **指纹**：开着时权重 sha256、`sim_cnn.py` 代码哈希、校准表哈希都进 `glyph_match` 的参数指纹（`sim_model_sha`，自动填）。换权重、换校准表、改 `sim_cnn.py`，开着的册这一步都判过期；没开的册不受影响。
- **没有校准表时**分数原样交出，`consensus_cov`、`consensus_margin`、`font_tier.cov` 等门槛要按书重标。所以正式用一律带校准表。
- 现役建议写法是 `fuse: mean`。全唐文四册（006／007／008／010）A/B 合计送审 143 降到 114；单用 CNN 送审更少但多放错约 4 格。
- 试一下不改册配置：`guji pipeline … --override '{"params":{"glyph_match":{"sim_model":{"path":"…","fuse":"mean"}}}}'`。

## 权重放哪、怎么取

- 权重不进 git，真源在 R2。cv 的 `config/model-registry.json` 记路径与 sha256，`guji model fetch` 取回到 cv 的 `models/`；`guji pipeline` 开跑前会自动取。
- 现役：`models/glyph_sim_qtw/model.pt` 与同目录 `calib.json`（全唐文库训）。模型种类登记在 cv `core/model_pack.py` 的 `glyph_sim`。
- 11-16 实验的权重在「OCR 研究」Project 共享目录 `5a跨书通用底座-2026-11-16/weights/`：`m_all3_m.pt`（殿本、史記、全唐文三书合训）和三套留一本书的底座。它们没有校准表、没进模型表，不能直接上线。

## 怎么训

环境：cv 的 venv（装了 torch），纯 CPU 即可。云端 4 核实测单线程每秒约 44 张、4 线程约 150 张：全唐文单书（3.5 万例）15 轮 4 线程约 1 小时，三书合训（5.9 万例）8 轮约 1 小时。几个训练并行时每个加 `--threads 1`，4 个单线程进程比 1 个 4 线程进程总吞吐高。

字形库先取到本机：`guji db pull -w <工作区>`，得 `<工作区>/output/glyph.db`。只读取库的做法见 [中心库](中心库.md)。

```bash
# 按书从零训
python scripts/train_glyph_sim_cnn.py --db <书的 glyph.db> \
    --exclude <评测分片>/expected.json --epochs 15 --out models/glyph_sim_<书>/model.pt

# 几本书合训（同一码位跨书合成一类）
python scripts/train_glyph_sim_cnn.py --db <殿本 glyph.db> --db <史記 glyph.db> --db <全唐文 glyph.db> \
    --exclude <004 分片>/expected.json --exclude <005 分片>/expected.json --exclude <006 分片>/expected.json \
    --epochs 8 --resume --out models/glyph_sim_all/model.pt

# 从底座起步、只用本书刻例微调
python scripts/train_glyph_sim_cnn.py --db <书的 glyph.db> --init models/glyph_sim_all/model.pt \
    --lr 1e-3 --epochs 8 --exclude <评测分片>/expected.json --out models/glyph_sim_<书>/model.pt
```

| 参数 | 说明 |
|---|---|
| `--db` | 书的 `glyph.db`。给多次就是合训 |
| `--exclude` | 评测分片的 `expected.json`，里面的物理格不进训练。可给多次，对所有 `--db` 生效。**要拿哪个分片评测就必须排除哪个** |
| `--epochs` | 单书 15；合训 8（数据多，步数相当）；微调 8 |
| `--init` | 起点权重。类中心用起点权重下各类刻例向量的均值初始化 |
| `--lr` | OneCycle 峰值学习率，缺省 3e-3；微调用 1e-3 |
| `--per-book-classes` | 合训时每本书的每个字各一类。实验里处处不如合类，只为复现 |
| `--resume` | 每轮末存档到 `<out>.ckpt`，中断后同一条命令接着训。云端容器会被回收，长训练一律带上 |
| `--limit N` | 每本书只取 N 例，量「刻例只攒到 N 例」时用 |
| `--threads` | torch 线程数 |

合类按码位：同形异码（侯/𠋫、歳/歲）和异体各是各的类，不并（用户 11-16 定）。

## 训完到上线

1. **量逐对分**。
   ```bash
   GUJI_GLYPH_DB=<书的 glyph.db> python scripts/eval_sim_bench.py pool --work <目录> --shard <评测分片>   # 建候选池
   python scripts/eval_sim_bench.py score --work <目录> prod                                              # 现行覆盖分
   python scripts/eval_sim_bench.py cnn --work <目录> --model <权重> --name <分数名>                       # 这份权重的逐对分
   python scripts/eval_sim_bench.py report --work <目录> prod <分数名>
   ```
   看首位命中、auroc、tpr@fpr1%。全唐文那一份登记成了评测 `sim_bench`（`guji_manager/eval/registry.py`）。
2. **拟校准表**。`python scripts/fit_glyph_sim_calib.py --work <目录> --cnn <分数名> --out <权重目录>/calib.json`。校准表按书拟：同一份权重用到另一本书上，要用那本书的池重拟一份，放进那本书用的权重目录。
3. **端到端**。`scripts/eval_match_bench.py` 走整条 5a 栈，确认 same 覆盖与库外误放。
4. **进模型表**。权重和校准表放进 cv `models/<目录>/`，`guji model registry` 重写表，`guji model upload --execute` 传 R2，提交表。新目录名要在 `core/model_pack.py` 的 `glyph_sim` 模式里能匹配到（现在只写了 `models/glyph_sim_qtw/*`）。
5. **单册 A/B 再开**。按 cv `doc/开关登记表.md` 的门槛，用 `--override` 跑单册两臂对比，过了再写进工作区基础配置或册 yaml 并推库。

## 开新书怎么办

11-16 的实验结论（殿本、史記、全唐文三书，留一本书量「没见过这本书」）：

| 情形 | 做法 | 依据 |
|---|---|---|
| 刚开书，一张刻例都没有 | 直接用合训底座 | 没见过本书的合类底座首位命中：史記 94.8%、殿本 92.5%、全唐文 99.6%；按书从零训是 86.2%、93.9%、99.8% |
| 攒到几千例 | 把本书并进去重训一次合训模型 | 只有 1000 例时底座微调对从零训：殿本 92.9% 对 82.6%，史記 95.0% 对 68.7%，全唐文 99.6% 对 95.3%。4000 例时从零训仍落后 |
| 刻例攒齐（两三万例） | 继续用含本书的合训模型，不必切回单书模型 | 三书合训 93.6%／95.8%／99.8%，对只用本书训是 −0.3、+9.6、0.0 点；再按书微调没有明显收益 |

要记住的几条：

- **借的库该尽早换成本书的库，合训的模型不用换。** 同一个没见过本书的模型，库从另两本书换成本书，首位命中殿本 84.7% 到 92.5%，全唐文 96.8% 到 99.6%。
- **开书时首位可信，自动放行要保守。** 没见过本书的底座，全局门槛端偏弱：全唐文剔掉极近字后精度 99.9% 下的召回 0.85，按书训与含本书合训都是 0.98。本书刻例整库进了训练才补回，1000 到 4000 例的微调补不回。
- **库小的书别从零训**（史記可训的只有 4,499 例，从零训 86.2%）。
- 书多了以后可以按字体、朝代分几个底座。选哪个建议实测：新书先人裁几百格，各候选跑一遍 `eval_sim_bench` 挑最好的。三本书还验证不了这一条。

## 已知问题与常见坑

- **形近字组单独处理**（用户 11-16 方针）：天/夭、尸/戸 这类极近的字，任何统一的相似度函数都分不干净，要落到形近字组表里另走字形分析或文意。表与分流规则在 cv `config/near_groups.json`、`clustering/near_route.py`（cv #1589，尚未接进匹配器）。评测时这些格要剔掉再看准确率。
- **殿本、史記的高精度指标现在量不出模型差别。** 剔掉极近字后，任何相似度（含覆盖分）在精度 99% 下的召回都接近 0。高分错几乎全是同形异码（刋/刊、刪/删、別/别、歴/歷、會/㑹、收/𭣣）和殿本库里格号错位的错标刻例。这两本书要先清库、定码位。
- **殿本在中心库的工作区名是 `siku-zongmu`**，不是书 id `96mid1ogzk`；拿书 id 去 `guji db pull` 会报「库里工作区没有文件」。
- **评测格不许进训练。** `--exclude` 漏了，基准上的数会虚高。合训时三本书的分片都要排除。
- **换权重要连着换校准表**，旧表配新权重不报错，但下游门槛全部失准。
- **每个实验配置只跑过一个随机种子**，1 点以内的差别不要当结论。
- 研究用的建池、跨书借库评测、任务队列脚本在 ai-team `domain/CV/字形领域/5a相似度CNN深化-2026-11-15/code-跨书通用底座/`，全部数字在同目录 `results*.json`。
