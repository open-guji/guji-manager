# 反馈迭代：验收标准

## 一批修订做完的标志
- [ ] PR 里 `CHANGES.md` 每行都列了意见 id 与事件 id；PR 正文有「格、前、后、类、意见」表。
- [ ] 本地 `python3 scripts/local_check.py` 通过，book-text 的三项校验（`validate_text_format`、`validate-collated`、索引无 diff）通过，结果贴在 PR 描述里。
- [ ] **char／cord 的每处变动都能对上某条意见 id**（`check_cell_provenance`，GUJI-733，目前先告警，后转红）；对不上就是手改，退回。
- [ ] 图片格未被改动（guji-format char v0.3 起，图列 `kind: figure` 的 `c` 仍为 □）。
- [ ] 合并后意见在池里是 `applied`，且 `publish-status` 已发；网站对应页显示「已改」。
- [ ] Jira 卡留了版本号、PR、批内格数。

## 一轮算法重跑落地的标志
- [ ] 有新旧对比摘要（四类格数），**单列被保护格冲突**，每个冲突格已有用户的逐格结论或默认保留的记录。
- [ ] 人裁没带过来的格数为 0（`human→review` 翻转为 0），否则先查绑定再谈覆盖。
- [ ] 用户已同意覆盖线上文本（记在 Jira 卡上）。
- [ ] 记录了算法版本和受影响册数。

## 检查命令速查
| 检查 | 命令 |
|---|---|
| 本批改动合规 | `python3 scripts/local_check.py`（book-text 仓） |
| 意见当前状态 | `guji opinions show … --ws <工作区> --remote` |
| 汇总 | `guji opinions auto digest` |
| 人裁事件格式 | `guji events lint` |
