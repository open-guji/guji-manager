## 一、结论（先看这个）

1. **一条原则贯穿所有阶段**：人裁是对「某块图」的判定，不是对「某个格号」的判定。格号会变，图块（原图 bbox ＋ 字块指纹）不变。所以覆盖优先级先问「是不是同一块图」，再问「谁说了算」。
2. **优先级（同一块图上）**：新人裁（含明确推翻旧裁的复审）＞ 旧人裁（锚验证通过）＞ 登记在册的手改字 ＞ 机器新结果 ＞ 现行文本里的机器旧字。机器**永远只能挑战人，不能覆盖人**；挑战的结果是进复审单，不是改文本。
3. **三个阶段三条通道，不混用**：无版本号（未发布）→ 整册重导出，自由替换；0.x → 精校落票 / republish，推 dev，可整册替换但人裁叠加；1.x → 只经「意见→裁决→revise」或下面新增的「重切发布批」，不手改，不整册替换。
4. **切分变化进 1.x 的缺口是真的**：`revise` 只认 A／B／B′，C 类没做；`republish push --book-text` 只认 0.x。册1 #419 是人工串起来走通的。建议把这条手工路径固化成**「C 类重切发布批」**：文本线默认升 **patch**（有整体质量提升再议 minor），一批一 PR，对照表随批入库，人裁自动平移，满足条件时自动合并。
5. **能自动的**：算对照表、分类、平移人裁／标点／专名／字形库键、跑红线与校验、出 PR 与差异单。**必须人定的**：覆盖线上（合并）、旧人裁与新图冲突的格（复审）、机器想改人已定的字、major、红线超限、「看不出」类的取舍。

### 一·二　待审不等于阙文（sheldon 11-09 定）

**book-text 不要频繁改。待审状态下，格里显示首选字；□ 只给真阙文。**
- 一个字从定字转到待审，只要首选字与现行文本一致，book-text 就不动，只是多一张待审单。
- 待审且首选字与现行不同：**现行有字则 book-text 不动，等人裁定了再改**，只出待审单（sheldon 11-10 定，取代 11-09「按机器改字放行」；guji-manager#445：`apply_pending(current=)` 写回现行字计 `held_current`，`swap/resolve` 判 `PENDING_KEEP`）。现行是 □／缺格的待审格仍写首选字。`review=human` 的格不受影响；点校放行（两路同字 high）算已定，不是待审。
- 待审且没有首选字：文本保持现行，出待审单。
- 机器认定真阙文（审过定阙），而现行有字：不改文本，进复审单。
- 影响：导出器目前对「机器没给字」的待审格写 □（char v0.4 §4.8）。要落地这条，导出改成待审格写首选字、不带 `pending_reason`、不带 `lacuna`（11-09 用户定，已由 guji-manager#429／v0.4.31 落地，book-text 只录首选字）。代码侧 `swap/resolve` 已按此口径。

## 二、先把对象分层（谁是真源）

| 层 | 内容 | 住哪 | 键 | 变化时怎么办 |
|---|---|---|---|---|
| L0 | 原图与页表（source_rev） | cv 工作区、IIIF | 页 | 换图源／repin → 页图 sha 相同的页可换算，不同的页交切分线 |
| L1 | 机器产物包（切分、识别、放行） | cv 产物包（★main 标记） | 格号（包内） | 重跑即换，格号会变 |
| L2 | **人裁事件** | 中心库 events，只追加 | 格键＋**锚**（bbox、evidence、content_sha） | 靠绑定表（valid／rebound／review／void）跟图块，不改旧事件 |
| L3 | 发布文本 char／cord | book-text | 格号 `页:列:槽` | 1.x 冻结，只经通道改 |
| L4 | 伴生层 punct／entity | book-text | 锚（`pre_char`、entity `text`＋偏移） | 跟 L3：`auto_remap` 平移，对不上进待审 A01–A03 |
| L5 | 意见池、网站状态、字形库刻例 | 中心库 | 意见 id；字形库按格号键 | 意见按 lineage 迁；字形库要 rekey |

铁律：**L2 是人意志的唯一记录；L3 里任何一格的字，要么来自 L1 的机器放行，要么能指到 L2 的某条事件。** 指不到的（存量手改，GUJI-716）必须补成事件或登记为人工格，否则受保护不了。

## 三、阶段 × 通道

「无版本号」指还没并进 book-text 的册（只有产物包）；0.x＝粗校完、精校未完；1.x＝精校完，冻结。

| | 无版本号 | 0.x | 1.x |
|---|---|---|---|
| 文本怎么变 | 随重跑整册重导出，不发布 | 整册替换可以，推 `dev`（`proof_cycle`／`republish`） | **不整册替换**；只换确有变化的页，其余页字节不动 |
| 人裁怎么保 | 写中心库（带锚），不进文本 | 同左；重导出时按绑定表叠加 | 同左，另加 overlay（`char-edits`）与保护格清单 |
| 切分变了 | 无影响，格号随便变 | 格号变＋auto_remap 平移伴生层，版本 patch／minor | **C 类重切发布批**（第六节） |
| 版本 | 无 | patch／minor（0.x 无 major） | 小改 patch、整批／重跑 minor、major 要用户点头 |
| 合并 | 不合 | dev→main 每日合并 | 单独 PR，用户点头 |
| 意见池 | 不用 | 反馈直接进精校 | 一切改动先成意见（含内部发现、机器重跑差异） |

## 五、覆盖优先级规则（核心）

### 5.1 先判「是不是同一块图」

对每个新格 n，用对照表（`old_new_cells`，A31 的 `celltable.py` 出，按 bbox IoU≥0.5 一对一配对；类别：同格／改号／删／新增）找它的旧格。再用绑定表看旧人裁与新格的关系：

| 绑定状态 | 含义 | 旧人裁处理 |
|---|---|---|
| valid | 同块图（IoU≥0.85 或指纹近） | 照用 |
| rebound | 同块图，换了编号 | **平移**到新格号（新事件 id 加 `~q`，旧事件不删） |
| review | 切开／合并／只部分重合／图不像 | **失效**：不采信、不丢，进复审单，旧裁字只作参考 |
| void | 锚框处已没有格 | 同上，进「没迁过去」清单 |
| unanchored | 没锚 | 裁于现行切分之后→同编号照用；之前→不采信（补锚档能救一部分） |

### 5.2 同一块图上，谁覆盖谁

从高到低；每一级只能被**更高**的覆盖，同级按 `replay_key = (ts, batch, seq)` 后到覆盖：

| 级 | 来源 | 说明 |
|---|---|---|
| 1 | **新人裁，且明确推翻旧裁** | 复审单上投了**不同的字**，事件记 `overrides`；"看不出／无字／切坏"不推翻定字，只把格挂起 |
| 2 | **旧人裁**（绑定 valid／rebound） | 含用户亲裁、读者意见经裁决采纳的（策略自动结案的也写事件，同级但可被复审推翻）。后到覆盖对同级有效 |
| 3 | **手改字**：0.x 期间直接改 char 的字，登记在 `NNN.char-edits.json`（只许 0.x，F-OV-15）；1.x 里没有事件对应的格（GUJI-716 盘点） | **一律补录成人裁事件**（`confirm`，带 cord 框做锚，批次名 `H-<名字>-<册>-legacy-handedits-<日期>`，册1 已这样做过一次）。补录后它就是第 2 级，不再有单独一级；补不出锚的才登记为「人工格」暂时保护 |
| 4 | **机器新结果**（新包放行） | 只能进入「现行为 □ 或缺格」的格；对 1–3 级只能提挑战 |
| 5 | **现行文本里的机器旧字** | 最低；新包放行且证据更强时可以被 4 换掉，但 1.x 上默认不换（冻结线「已放行格只增不改」） |

### 5.3 机器新结果与现行文本的四种差异怎么办（1.x）

| 差异 | 例 | 处理 |
|---|---|---|
| 新增放行 | 现行 □，新包有字 | 可采纳；`new_admit` 机器意见，高置信走策略自动结案，仍随批由用户合并 |
| 改字 | 现行 A，新包放行 B（不是待审），无人裁 | **默认放行**（sheldon 11-09 定）：生成机器意见，策略自动结案。前置：先过机器错字检测（重复字、字丢失）；格上无人裁、无手改、无补录事件；CHANGES 逐格列出，度量记数 |
| 定字转待审 | 现行有字，新包把该格转待审 | **看首选字（一·二）**：首选字＝现行→文本不动，只多一张待审单；首选字不同→**文本不动，等人裁**（11-10 定，`PENDING_KEEP`）；现行是 □→写首选字；无首选字→文本保持现字。不再因待审写 □ |
| 真阙文 | 现行有字，新包认定阙文（审过定阙） | 不自动改文本，进复审单让人裁（sheldon 11-09：算法改后置信度降低可能是对的）。册1 教训是新包把**人已定**的字退回 □，属保护格冲突，另见 5.4 |
| 机器错字 | 重复字、字丢失、人裁刻例按旧格号投到别的格（册1 99:2:8 出两个「雯」） | 回退为现行字；根因去修（字形库 rekey），不靠覆盖 |

### 5.4 反过来：人对人、人对机器的冲突怎么报

- **保护格冲突**（新包与 1–3 级不一致）：**固定 `to_user`，策略不许自动采纳**；差异摘要单列「会冲掉的人裁和手改格」，预期 0，非 0 逐格报用户。
- 新人裁与旧人裁不一致但**没有 `overrides`**（如只是别人另投了一票）：不覆盖，挂起，回网站复审单。
- 红线（`closeout/redlines.py`）：人裁丢失＞本册人裁格 1%、锚点余项＞15%、任何一步报错或字形库 verify 不过 → **整册不写**，报告标超红线。

### 5.5 伴生层的优先级

人点校的标点／专名（A33）＞ 平移结果 ＞ 重新投影的机器标点。锚验证（`pre_char`、entity `text` 与现字一致）不过的，**不静默改**，落到待审 A01 `anchor_miss`、A02 `add_del`、A03 `anchor_drift`，留点校阶段统一重挂；改字落在专名 span 内、标点边界、标题分段附近的列复核单。

## 六、格号变化：平移还是失效（逐层）

对照表是**一等产物**，每次格号变化只出一张，下游全部用它，不各自重算（A32 11-09 已定：a/b 子格按带后缀的完整号一对一配，下游整号替换，不自己拆后缀）。

| 层 | 规则 | 工具（现有） | 失效时 |
|---|---|---|---|
| 人裁事件 L2 | 同格不动；改号→新事件（id、批次加 `~q`，补锚档）；删／IoU 低／合并冲突→不迁 | `feedback/cell_migrate` | 进 `pending.tsv`，带原因（表里没有／删／IoU低／合并冲突／旧绑定失效），不丢不自动裁；校验「输入＝迁出＋合并＋没迁」 |
| 字形库刻例 | 按格号为键，必须随表 rekey，**先于下一次 seed_admit**；改键前先用人审票把相关格改回，别当机器错字回退 | `ops/cell_rekey.rekey_glyph_db` | 键对不上则不投，避免投到同号别格 |
| 手改字 | 经表换新号后叠加：新格字＝旧字→覆盖；＝改后字→已含；都不是→**保留人改字**，记 `overturned` 入复审 | `swap/overlay_edits` | 表里是删／新增→`lost`，入复审 |
| 标点／专名 L4 | 档1 纯换字、档2 增删格、档3 复核；写回前修标题符 | `book-text/auto_remap.py`、`closeout/remap_lib` | A01–A03 待审 |
| 意见池 L5 | 意见的 `revision.cells` 优先用「格键＋锚＋mark」，不用裸格号；按 lineage 迁 | 待建（lineage 对照） | 迁不过去的退 `discussing`，说明版本漂移 |
| 网站单、票 | 旧单 rev 作废；页图 sha 相同的页票可换算（`cellvotes rebase`），不同的交切分线 | `cellvotes rebase` | 复审单重投 |
| 外部引用 | 深链接、读者收藏的旧格号→新格号 | 待建（对照表发布 redirect） | 显示「该格已重切」 |

**失效≠丢弃**：任何一层失效都落成可数的待审条目，最终账必须平。

## 七、切分变化进 1.x 的通道方案

### 7.1 现状

- `revise`：A／B／B′，C 跳过并列出。
- `republish push --book-text`：只认 0.x。
- 册1 的做法（#419，v0.6.25，A32 新 char＋A33 标点专名平移＋人审票改回的职名页）：取新 ★main 包 → `export_guji_format.py --format char-cord` → **只换格号变了的页** → 对照 ai-team 格级对照表逐格比 → 新包退回 □ 的暂不采纳、机器错字回退 → `auto_remap --write` → `bump_original --line text --level minor`。可行，但每一步都是人串的，中间踩了：快照旧格号致错字、新包退回 □、人裁刻例按旧格号投错。

### 7.2 建议：C 类「重切发布批」（命令暂名 `guji swap release`）

输入：现行 book-text 版本、新 ★main 包、对照表（可自动出）。一条命令按下面顺序跑，**每步幂等，出错停在原处**：

| 步 | 做什么 | 停点 |
|---|---|---|
| R0 | 出对照表；页分类：未变页（字节不动）／变化页；统计同格、改号、删、新增 | — |
| R1 | **前置闸**：字形库刻例已 rekey、新包钉的字形库＝rekey 后的快照；否则停（册1 99:2:8 的坑） | 停 |
| R2 | 只导出变化页的 char／cord，换进去 | — |
| R3 | 按第五节优先级叠加：人裁绑定（平移）→ `char-edits` overlay → 现行已发布的 revise 改字（`revised`／CHANGES 里列的格）→ 才是机器新字 | — |
| R4 | 差异单四类（5.3）；人裁丢失、保护格冲突、红线；机器错字检测（相邻重复字、字丢失） | **超红线停；保护格冲突非 0 报用户** |
| R5 | `auto_remap` 平移标点专名，档3 列复核单 | — |
| R6 | 升版：文本线默认 **patch**；标点、实体线 patch（平移不是整册重跑）；CHANGES 新增一行格式：`C 类重切｜run id｜对照表 sha｜变化页数｜人裁 迁 n／失效 m｜意见 id 列表` | — |
| R7 | 开 PR：描述含差异单、「会冲掉的人裁和手改格」、对照表附件（入库 `<版本目录>/lineage/revisions/<run id>.tsv` 或中心库 `feedback/lists/revisions/`）、`local_check` 结果 | 满足条件自动合并，否则转用户 |
| R8 | 合并后 `finish-merged`：迁出的事件落库、意见记 applied、字形库钉号、复审单上线、`publish-status`、旧格号 redirect 登记、度量入 `metrics.jsonl` | — |

### 7.3 版本档（sheldon 11-09 定：默认 patch，有整体质量提升再升 minor，判断标准以后讨论）

- 重切发布批**默认升 patch**；整体质量有明显提升时才升 minor，标准待议，暂由做批的人在 PR 里写明理由。
- major 是质量等级，与切分无关，不升。
- 因为 patch 不再提示「格号变了」，更需要下面的 `cell_epoch`：
- 建议在 `index.json`／CHANGES 加 **`cell_epoch`（格号世代）**整数：每次 C 类发布批 +1。外部引用、意见、读者收藏按它判断要不要查对照表。**这一项是新增设计，待用户定。**

### 7.4 要同步改的校验与工具
