# 反馈迭代：常见坑

- **直接调 `revise` 函数、照 Jira 描述手写修订**（GUJI-717 首批 book-text#218）：内容对，但绕过了意见池，「由工具从已采纳意见读取」这一环缺了，applied 也没记。凡改 1.x 文本，一律先有意见与裁决事件，再经 `guji opinions` 管线。
- **自动合并被拦**：合并进 book-text main 会覆盖线上文本，项目规定要用户点头。别尝试打开 `auto.merge.enabled`；用户明说了才改，且策略改动本身走 PR。
- **重跑冲掉人裁**：切分或 Step4 字块一变，人裁靠绑定表跟到新格，框变大、切开、合并、图块指纹变了都会掉，回到待审。重跑后看「人裁没带过来」，不是 0 就逐格查绑定表（`status`、`iou`、`fp_diff`）。
- **插格后旧意见失效**：格号会后移。改字类修订用格键＋锚，不要抄裸格号；用修订产出的「旧→新格号」对照迁移。
- **图片格**：guji-format char v0.3 起图列用 `kind: figure`，图片格不许改、`norm` 不许落在图片格上。
- **别手改 `dev` 之外的生成物**：`index/texts/` 不要手改，dev 上不提交；每日合并统一重建。
- **版本漂移**：意见提交时对应的文本版本已被后来的修订改过，修订单对现行文本干跑会失败，会被退回 `discussing`；不要强行套用。
- **令牌**：令牌只放环境变量，不写进文档、PR、日志。
- **形近字 vs 异体字**：「暂归一」只限意思相同的异体字；意思不同的形近字（如 个／今）按文意字形分，不要因为反馈量大就合并。
