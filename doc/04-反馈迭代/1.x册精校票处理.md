# 1.x 册的网站精校票：从投票到合并

> 来源：殿本册1 001-r6 一轮（2026-11-08，book-text#416、guji-manager#379）。负责：A34。命令名以 guji-manager（dev）当前版本为准。

适用：书已发 1.x（冻结）、读者或用户在网站待审单（`<册>-r<N>`）上投的票。一句话：**票先全部写成人裁事件进中心库；字确定的少量改动再走意见→revise 一批一 PR；结构类问题交切分线，不改文本。**

## 一、先分清这一轮的票是什么

`guji cellvotes draft` 把票分四路（PR #379 起另出 `route.md` 与 `structure.tsv`）：

| 类 | 票 | 去向 |
|---|---|---|
| 选字 | `char` | 写事件 + 改文本 □→字 |
| 切坏但给了字 | `cut` 且有字 | 写事件 + 改文本（框仍待重切） |
| 切坏无字、格位错位、破损、带备注的看不出 | `cut` 无字／`damaged`／`unsure` | **写事件**，文本不动，`structure.tsv` 按页按列交切分线 |
| 无字 | `none` | 默认不落（排除名单只增不删）；要落加 `--include-none`，先问用户 |
| 推翻旧人裁 | 与已有人裁不同 | 挂起，回网站复审单（`recheck.tsv`），用户再投一次才算推翻 |

用户 11-08 定：**所有投票结果都写中心库**，切分线自己按批次去库里找，写库不等于改文本。

## 二、步骤

1. **准备环境**（云会话没有工作区仓）：建目录放 `workspace.yaml`（`id: siku-zongmu`）和 `.central.json`（`{"ws":"siku-zongmu","branch":"main"}`），设 `GUJI_DATA_HOME`；`guji db pull -w <目录> --no-rebuild` **整拉一次，不要 `--exclude`**（部分副本不能 sync，而且待审单 `proofing/` 不拉会让事件的 `pending_reason` 全写成 `unknown`）。要装 cv（`pip install -e`，另需 `opencv-python-headless`）、`psycopg[binary]`。
2. **读票并出草稿（只读）**：`guji cellvotes draft <册> --site-book <书ID> --rev <册>-r<N> --pack rev-<册>-r<N> --from-kv --out <目录> -w <工作区>`。令牌 `CELLREVIEW_TOKEN`。`--pack` 用出单版产物包算锚，格号不漂。
3. **看 `report.md`、`route.md`**，核对：挂起各几格、与机器首选不同的选字（列给用户眼过一遍）、是否撞已修格。
4. **用户同意后落票**：`GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD GUJI_ACTOR=<名字> guji cellvotes write <册> <目录> --batch H-web-<册>-<rev>-<日期> --reviewer <投票人> --no-consume -w <工作区>`，再 `guji db sync -w <工作区> --no-admit --no-glyph`。批次名固定这个形状，切分线按它找。**不要 `db pull --force`**：它会丢掉本地还没推的事件。
5. **改文本（只处理字确定的格）**：每格建一条内部意见，channel `machine:<名字>-web-<rev>`，`category: wrong`，`revision.class: B`（□→字），裁决人写投票人；然后 `guji opinions auto prepare --book <书ID> --ws siku-zongmu --remote --book-text <book-text 检出> --vols <章>`。它改 char、跟随标点实体、写 `CHANGES.md`、跑 `local_check`，出 PR 正文。
6. **开 PR**：book-text 仓，分支 `claude/…`，正文放差异、「会冲掉的人裁和手改格」（预期 0）、5 种要留意的点（见下）、`local_check` 结果；CHANGES 的 PR 列从 `#TBD` 改成真号。覆盖线上文本，合并要用户同意。
7. **收尾**：合并后 `guji opinions auto finish-merged --release <发布批> --pr <号> --commit <sha>`，意见记 `applied`；有网站来源的意见再 `publish-status`。
8. **结构类交接**：把 `structure.tsv` 与批次名发给切分线（A22/A31），并在 Jira 记一笔。重切后格号会变，等对方标 main 前通知再平移锚点、再发复审单。

## 三、PR 里要写的几点

- 与机器首选不同的选字逐格列出，供用户眼过。
- 新字落进专名的（实体随改字重算），列出请 A33 复核断句。
- 推翻旧人裁的挂起格不在本 PR。
- 度量：票数、可写数、文本改动格数、册内 □ 余量（前后）、待审原因分布。

## 四、踩过的坑

- 事件的 `pending_reason` 来自待审单，部分拉库会写成 `unknown`；事件只追加，写错不能改。
- `db sync` 要 `GUJI_ACTOR`，否则拒绝推库。
- 网站读票偶发 `Connection reset`，重试；已落票后重跑 `draft` 会把与已有人裁一致的格报成跳过，这是幂等，不是错。
- 切分类问题（职名页大字雙行分栏、版框碎片被当格）不要靠投票解决，投票只是定位。
- 一个 PR 合并会让后面的 PR 在 `CHANGES.md` 冲突，逐个合 main、保留两边行再重建索引。

- **先核册的版本线**：册4 文本是 0.10.0 不是 1.x，不能走 revise，要走 0.x 精校落票（`proof_cycle`）；第一步先看 book-text `index.json` 的 `text_version`（册2–4 线程 11-09）。
- **网站 rev 号不连续**：册4 新票是 `004-r15`，`004-r3…r11` 是 10 月旧票；逐个用 `_fetch_kv` 探，看票时间，别按最大号猜。
- **云端 `db sync` 先 `pip install websockets`**，否则连 127.0.0.1 被拒。
- **建内部意见目前没有命令**，用脚本建"意见 + triaged + decided"三件，再 `auto prepare`；已有脚本 `a34/mkops_web_votes.py`（A34 项目共享文件夹），建议做成 `guji opinions` 子命令。
- **同一次两册可合一个 PR**：`auto prepare` 各出一个分支，cherry-pick 合并，只在 `CHANGES.md` 冲突，保留两边行。
- **草稿 PR 要先转 ready 才能合**；本地残留的 `origin/claude/…` 跟踪引用会让 push 报 stale info，先删掉。
- **指定分支名可能被另一个线程用过**：先 `git ls-remote` 看远端有没有，有就换名，不要强推。
- **重跑后格号变（增删格、改号）的 1.x 册**：不要整册替换。取新 ★main 包（`products pack fetch`），用 `scripts/export_guji_format.py --format char-cord` 导出，只换格号变了的页，其余页字节不动；再对着 ai-team 的格级对照表逐格比，新包把已定字退回 □ 的不采纳，机器错字（重复字、字丢失）回退；然后落 book-text 一律走 `guji swap book-text`（IoU 对照表一条路，不要单跑不带 `--cell-map` 的 `auto_remap`，会切坏专名、丢挂法；11-10 ZM），它同时平移标点专名并升版；文档见 [换包落book-text-增删格](../02-精校/换包落book-text-增删格.md)。册1 v0.6.25 的 实际合并的是 book-text#419（A32 新 char + A33 标点专名平移 + 人审票改回的职名页 7 格）。
- **对照表键要去掉册前缀**：`vol01:87:9:9b` 取 `[6:]`，否则整表对不上。
- **人裁刻例按格号存，改格号要改键**：字形库里的人裁刻例以格号为键。重跑使格号变了，钉着旧快照（如 g17）的新包会把旧键投到同号的别的格，表现为新包出重复字或与人审票不一致（册1 99:2:8 出两个「雯」，共 7 格）。处理：A23 先按对照表改键并出新字形库快照，A31 改钉后从 seed_admit 重跑、标 main，再对一次差异出修订；改键前先用人审票把这几格改回，别当机器错字回退了事。
- **读者意见修订（无人裁事件）的格，新包不认识**：book-text#416 这类只改文本、没写人裁事件的格，新包按算法重判（如折叠组日／曰回待审）会退回 □；要它们不再上单，需补人裁事件（写库须用户同意）。

## 四·二、殿本 vol01／vol02 逐册清理补充（ZM，2026-11-09）

> 两线实录与汇总见 ai-team `domain/文本/殿本逐册推进-经验汇总.md`。

- **只在正式站投票。** `cellvotes draft --from-kv` 只读 www（`cli_cellvotes.SITE`）；测试站有自己的 KV 和管理令牌，在测试站投的票读不到（vol01 001-r11 实例，只能重投）。测试站只用来看新功能效果。
- **先盘点再动手**：`guji-manager pending-stats --vols N`（缺省 ws=siku-zongmu、text=96mid1ogzk；把书 id 填进 `--ws` 会返回 0 格，不是清零）。交接里说「没同步」的事件先查 `events` 表，不要重复写。
- **机器已放行、但看图存疑的格**：出单时 `republish.py prep/issue --recheck <tsv>` 强制上单（每行一个格号＋说明）。排除格（crop_defect）没有自己的框：网站 0.2.6 起按同列邻格推算位置；manager 0.4.29 起出单补 `box_est`。
- **页表 repin（source_rev 改了）后落旧单的票**：`cellvotes write` 会被「页表 rev 不符」拒。两册页图 sha 逐页相同时可换算：① 把事件先收成文件，`guji cellvotes rebase volNN --source-rev <新> --events <文件>`，再 `EventLog.append`；或 ② 改出单包沙箱 `_source.json` 的 rev（先核逐页 sha）。两法等价。页图不同的不迁，交切分线。
- **文本里是缺格（不是 □）**：revise 管不到。手工在 char／cord 按格号顺序插行（cord 框按同列邻格内插，不编 id）→ `bump_original.py --line text --level patch` → 平移锚点走 `guji swap book-text`（IoU 对照表一条路，不要单跑不带 `--cell-map` 的 `auto_remap`，会切坏专名、丢挂法；11-10 ZM） → 逐条核 punct `pre_char`、entity `text` 与文本一致 → 顺手点校该句（补点号、扩专名）→ PR 投 main 自合。实例 book-text#425。
- **book-text 稀疏克隆**：sparse 要带 `/Book/<书>/manifest.json` 和 manifest 里登记的每个版本目录，否则 `bump_original` 说「不是 original 目录」、`local_check` 报版本目录缺失；「index/texts 一致」是稀疏克隆的已知假失败，不提交 index/texts。
- **册 yaml 已被改钉新 cv**：apply 的重跑会被门挡；人裁在 write＋sync 两步已落库，换单随新包走，不要为过门加 `--allow-cv-mismatch`。
- **新环境先完整 pull 再 sync**：`db pull --no-rebuild` 后本地字形库为空，直接 sync 有清空中心库字形表的风险；用 `--no-glyph` 或先 `pull --force`（#411 起有防清空检测）。
- **看新包是否可用**：`guji products pack list volNN`，★ 才是 main 包；没 ★ 的不出单。
