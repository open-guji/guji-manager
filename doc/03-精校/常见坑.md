# 精校：常见坑

> 迁自 ai-team `domain/CV/经验.md` 的「精校落票」「1.0 之后改一格」两节、《流程自动化方案》§3 的出错清单，以及 A32 的实际经历（2026-10-22～10-29）。新踩的坑往这里加；跨步骤的进 [经验](../经验/)。

## 票与单

- **网页票的格号是脆弱的锚。** 票投在旧单上，新单上线、切分又变，整列格框能移数十到数百像素。防线：①重跑发新单前先把旧单的票落成事件（`republish.py` 有「旧票先落门」）；②每次出单都存那一版产物包，落票用出单版的框当锚；③网站旧单被取代后提示读者；④事件锚到框重叠比。`guji cellvotes draft --iou 0.8` 只是事后补救。
- **单子会过期。** 出单时没扣后来写入的人裁，线上单就挂着已投过的格（册 005-r5 一度 111 格里 102 格已投过）。人裁进库后要重出单；web 的 `proofing-reissue` issue 会在已投格 ≥ 20% 时提醒。
- **草稿数与库里数对不上**（册 005 草稿 141 vs 库里 160）：挂起的格后来被别的会话写入且没留记录。落票前先查中心库有没有该批次事件，避免两个会话做同一件事；对账表要入报告。
- **落票后别只重跑投票所在的页。** 人裁指纹一变，全册 `seed_admit` 都要重跑（只重算过期页，约 3 分钟）。否则像册 005 的 41:9:7，产物比人裁早，文本一直是 □，路由又把它当已裁格扣掉，两边都看不见。全册重跑后机器改判的格（字组降级、参照本改判）不改文本，放进下一版单子请人看。
- **读者看到的是故障就会弃投。** 相似字雪碧图 `alt-<章>.webp` 没登记进 `sprites[]` 时 COS 上 404（册 004–007 都出过）；页面会退回纯文字，但这不算通过，G3c 要求 404 数 = 0。

## 书影与切分

- cord 重切后没同步 `ops/iiif/siku-zongmu-splits.json`、没重出 IIIF、没清 CDN，精校页红框就整页错位（册 04／07／09 的拆页书影出过）。图缓存 30 天，**不清 CDN 等于没修**。
- 换图源（殿本 `siku-qiefen-v2`）会重编页号，票要迁；迁票工具与盘点方法在 open-guji-cv 的设计稿（cv #632、#636）。

## 环境（每个新容器都会踩）

- `joblib`、`scikit-learn` 没进依赖：缺了 `seed_admit` 全败；推库还要 `psycopg[binary]`、`websockets`。
- 语料库清单漂移拒跑：设 `GUJI_CORPUS_DRIFT=warn`。
- 生僻字索引先 `guji cache pull-rare-index`（几秒），现建要 47 分钟。
- 识别前要重新导入两套字体（约 10 分钟）。
- `--from-kv` 读网页票会被站点拒默认 UA（连接被重置）：带上 UA 再读。
- 云端触发 GitHub 工作流要带 `--ref main`（没有 GraphQL 查不到默认分支）。
- 读中心库不必装整套 cv：用读令牌经 `WorkerSource`（`open_guji_cv/datastore/client.py`）查 `imports`、`events`（按 `batch` 过滤）。别在命令里回显含令牌的环境变量。
- `guji db sync` 报 glyph_store 冲突：多半是本地落票的消费者与别的会话同时改库。备份数据目录 `feedback`，`db pull --force`，重新 `cellvotes write`，立刻 sync，中间不插别的事。

## 冻结册上改一格

- 人裁用 `guji cellvotes draft --from <票文件> --pack <冻结包>` 再 `write`，不手写事件：锚按冻结产物算，上下文对得上才写。推库前 `guji db status` 看 unpushed 只有这批。
- 在旧版 cv（如 0.5.7）冻结的册，close-check、exit-check 都要钉旧版 cv 跑（用 dev 跑 1a 会全红）；`guji freeze register` 要用 dev 的代码但 cv 检出须指向旧版，CLI 没有 `--repo`，走 Python API `freeze_register.plan(..., repo=<旧版 worktree>)`，worktree 先 `git fetch --tags`，否则 `cv_version` 记成 None。
- 冻结 worktree 重跑三个坑：中心库里有冻结代码不认识的新事件种类（用删掉它们的数据目录副本，`GUJI_DATA_HOME=<副本>`）；语料漂移；缺原图（`guji source pull <册>`）或缺 sklearn。前两个改变了输入，重跑后必须逐格比对该页 `seed_admit`，只有目标格变才算数。
- 导出器不写 char 的 `review` 签字块，产物 sha 写法也与发布时不同：拿导出与 book-text 逐格比，只差目标格时，只改线上文件的那一格和那一页的 `seed_admit` sha，不整份换文件。
- 重新冻结要用户点头，且在冻结 worktree 那个提交上登记、沿用旧 tag，不要用 dev 登记成新代码。
- 冲 1.0 期间别的会话可能改参照本、格位表、册 yaml，现产物会被判「参数变了」。冲 1.0 前先 `text_release.py pin` 锁输入。

## book-text

- 本地克隆常是单分支（`remote.origin.fetch` 只有 main），`git fetch origin dev` 不更新 `origin/dev`，要显式 refspec。
- 字形归一：别／別 一律选「別」，晚／晩 一律选「晚」；无 Unicode 的特殊符号先标阙字方格，另开卡找人做截图字。
- 改字撞标点／实体锚点：见 [步骤](步骤.md) 第一部分第 6 条。
