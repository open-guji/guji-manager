## 一、边界：框架管到哪，精校从哪接

| 框架（A31） | 精校（A32） |
|---|---|
| S0–S4：开书体检 → 冷启动 → 配置爬降 → 决策层漏斗 → 收口 | 接 S4 收口单交来的「人审底、留后、精校待办」 |
| L0–L3：配置、算法、大模型只读文意、独立复核 | 不在精校做放行规则的升级；发现可放行的类别回报 A31 走 R3 |
| L4 人审批量页 | 精校的人审单与批量页**同一套模板**（见第三节），票落事件仍走 `proof_cycle` |
| D 轮／S 轮、标 main、解冻 | 换单交 A32，按本节「轮类型」处理 |

精校**不重复**框架已有的东西：不自己再造 `pending_reason` 小类，不自己重跑整册，不自己标 main（沿用重跑轮次规矩）。

## 二、对 A32 流程的具体改动（已写入本目录文档）

1. **口径**：报人审数时两个数都报——首审人审率（待审 ÷ 全册格，写明包标签）和净人审队列（扣掉机器已放行的）。1.0 的「看不出 ≤ 待审格 2%」分母不变，仍是最新待审单全部格。
2. **按 `pending_reason` 派活与落票**：落票草稿、质检挑格、退回单都按 `pending_reason` 分组（`hard_pair`、`occluded_no_ref` 单列）；人裁事件 `payload.pending_reason` 必写，不确定写 `unknown`。
3. **轮类型决定换单动作**：
   - **D 轮（从 `seed_admit` 起，不改格号）**：不改格号，裁定按「格号＋上下文哈希」命中。A32 换单前仍先落旧票、查旧单是否过期，不需要逐册比格号。
   - **S 轮（border_detect、cell_shrink、row_segment、页型、图源、语料、库快照）**：标 main 前逐册比新旧格号；换单前旧票必须已落；增删格先通知 A33（标点锚点）。
4. **批量页回流**：人审批量页（一字一卡、字对白名单、码位定夺等）点过即录入，只写改动格；回流事件进 `proof_cycle` 的对账，计入 G0 票账。
5. **验收**：框架第五节的放行验收（新放行类别上线前金标放行子集 0 错、盲读抽样、每轮滚动抽 30 格）管**机器放行规则上线**；精校 G5/G6 管**这一册能不能出 1.0**。两套各自独立，互不替代（见 [验收标准](验收标准.md)）。
6. **交单前检查**：沿用框架第八节事故清单（`db pull` 看 dry-run、设 `GUJI_ACTOR=A32`、轮中不推库、册配置改中心库数据目录）。
7. **流程代码**：新增脚本放 guji-manager，不放 open-guji-cv。

## 三、人审页：精校用同一套模板

- 页型对应：第一次进库字（一字一卡）、字对白名单抽样、码位定夺、金标抽样、切分归因看图、收口单。精校的「复审单」「推翻旧裁」暂仍用现有精校页，模板进仓后再并入。
- 精校页不另做预选逻辑；预选来源（参校本字 / 文本层字 / 大模型读法）以框架模板为准。**大模型看图只做预标注，不放行。**
- 点过即录入、撤出页；审页图按 `cell_shrink` 字框裁。

## 四、与用户既有决定的冲突

### 已定（sheldon 11-05）

- **C1** 同意：未冻结册「变字一律进待审」照旧；框架 L2 大模型放行只用于**非变字**的格（机器原本就放的字被确认）和待审格，不用于已有字的改判。
- **C3** 同意：L3 独立复核只复核机器放行，不复核人裁；人审仍一人裁定即算。
- **C4** 看情况：一本书刚开始时仍需用户人审点一下（R1、R3、R4 点选页），但这些主要是**粗校阶段**的事，基本不涉及精校流程；精校（A32）不承接这些点选页。
