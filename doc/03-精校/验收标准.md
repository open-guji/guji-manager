# 精校：验收标准

> 摘要自 [1.0发布标准](1.0发布标准.md)（v0.3，2026-10-23 用户认可）。有出入以全文为准。
> 全部条件满足才出 1.0.0；**错误率只报数不设门槛**，G0–G5、G7、G8 任一项不过就不放行。

## 条件清单

| 条件 | 要求 | 检查 |
|---|---|---|
| **G0** 票、单、事件对账（硬条件） | 每份在线待审单的每张票都有归宿：票数 = 写入 + 跳过 + 看不出 + 挂起；线上没有过期单（最新单 rev 不早于最后一次人裁，单上不含已有人裁的格）；重跑发新单前旧单的票已落；每次出单都存产物包 | `proof_cycle.py audit`；`guji cellvotes draft` 的三栏对账表入质检报告 |
| **G1** 待审清零 | 分母 = 最新待审单全部格，每格有处理记录（落字／切坏／非字／看不出），覆盖率 100%；「切坏」必须有去向，不混进「看不出」；**「看不出」≤ 待审格 2%**，每格有审阅记录；不能带挂起格出 1.0 | `guji audit count <册> --expect <待审单>`：漏审 0、无锚 0 |
| **G2** 文本 = 冻结产物导出 | 禁止在 book-text 直接改字；改动先是人裁事件，重跑涉及页再导出；CHANGES 每行能追到意见／事件 id | `guji char-diff`（book-text 与冻结导出逐格比，差异 = 0）、exit-check E9／E10 |
| **G3** 机器检查全过 | close-check 终校档退出码 0；`glyph_audit_gate` 退出码 0 且体检时点晚于最后一次改库；排除名单对账；marks id 不重复 | close-check（钉住的引擎） |
| **G3b**（硬条件）书影／切分／文本三方一致 | cord ↔ 裁剪框表 ↔ 线上 IIIF manifest 一致；cord 重切后必须同步 splits 表 + 重跑 IIIF + 按 URL 清 CDN；抽查 20 页（拆页书每个拆页源至少 2 页）红框落在字上；文本与 cord 格数、格号一一对应 | kaiyuanguji-web `ops/iiif/check_cord_vs_splits.py --live`（每日 `iiif-cord-check.yml` 兼跑） |
| **G3c**（硬条件）读者侧可达 | 待审单 `sprites[]` 含所有被引用的图（含 alt 雪碧图及 md5）；引用的每个资源 HEAD 200；`/api/cellreview` 对本册读写各冒烟一次（5 格）返回 2xx；404 数 = 0，不能靠降级通过 | `republish.py issue` 内置冒烟；web `proofing-health.yml` |
| **G4** 已知错单清零 | 中心库 `feedback/lists/known-errors.tsv` 对当前文本逐格核，仍是错字的 = 0（故意保留的测试格除外） | `known_errors check` |
| **G5** 高风险格全看过 | 高风险通道（context、rare_ref、iron、match_solo、seal、witness3、coord_fallback 等）全量；形近组逐格；跨版本／跨模型分歧全部裁完；非正文页通读；alt 与 `sprites[]` 对不上的格也算高风险 | `qa_pick` 挑格 |
| **G6** 错误率只报数 | 一人裁即算；抽查量不限（可为 0），照实报格数、错数、单侧 95% 上界；每个错登记类型、通道、同字组是否已扩查，进 `book-qa/` 分片 | 质检报告 + `review` 记录 |
| **G7** 意见台账清零 | 未处理意见 = 0；冻结册机器意见只进团队单 | 意见台账 |
| **G8** 出口动作齐 + 提交号 | `guji exit-check` 全项 ✓：`proofing=false`、`review` 记录、decision.json、lacuna 与字一致、yaml 有 `freeze:` 与 `cv_version`、cv_commit 在某个 tag 上、R2 冻结包 pin 住、中心库 `freeze_baselines`/`snapshots`/`cv_versions` 各一行、已通知下游；打标签前核提交号两项 | `guji release check` / `guji exit-check` |

## 抽样质检

| 层 | 对象 | 量 | 谁判 |
|---|---|---|---|
| 全量 | G1 待审格、G4 已知错、G5 高风险通道／形近组／分歧格 | 全部 | 人（团队单）＋AI 预判 |
| 机器挑格 | 跨版本分歧、离群、已知错单 | 挑出的全部 | 一人裁 |
| 抽查 | 放行格 | 少于 200 格，挑低置信、易错类别，不随机抽 | 一人裁 |
| 书影／切分 | G3b 抽查页 | 20 页／册 | AI＋用户看红框 |
| 读者侧 | G3c 资源 HEAD、API 冒烟 | 全部引用资源、5 格 | 脚本 |

记录样本集 id、种子、抽样时点文本 sha、每个错的（格、类型、通道、是否扩查）。样本集随报告保存，复跑数字要一致。

## 达不到标准怎么办

不强行放行。用户看报告后判定「不放」时按错误类型退回：切分／书影类退 A30，识别／定字类退 A31；退回单写错误率、类型分布、样本页号；退回后重新计数，不沿用旧样本。

## 版本号规则（与 1.0 相关）

| 事项 | 规则 |
|---|---|
| 0.x → 1.0.0 | major，**手工**改版本号，附 `review` 验收记录，用户点头；`bump_original.py --level major` 报错 |
| 0.x 每合一批人裁 | 一批 ≤ 约 50 处改字且位置已知算 patch；成批规则化改动或覆盖率升 ≥ 10 个百分点算 minor |
| 重跑后 | 至少升 minor |
| 1.0.0 后的改动 | 只走修订通道（意见 → 裁决事件 → `guji opinions revise`，一批一个 PR），不手改文件 |
| 冻结 | 出 1.0.0 当天登记（快照、R2 包、三张登记表、tag），之后默认不随 cv 升版重跑 |
| 旧定义的 1.0.0（册 002、003） | 照实保留；补走本标准后算 minor，不算新的 1.0 |
| 标点、实体层 | 不由本标准管；伴生层 major 不得高于文本线 |

book-text `docs/VERSIONING.md` 第 1 级「可用」一行比本标准宽，**出 1.0 时以本标准为准**。
