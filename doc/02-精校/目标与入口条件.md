# 精校：目标与入口条件

> 负责：A32（精校）。2026-10-30 据 A32 项目文档、1.0 发布标准 v0.3 整理。

## 目标

把一册 0.x 文本（粗校产出的 v0.1）经人审变成可发布的 1.0 文本：

待审单上线 → 读者／审校者投票 → 票落成人裁事件 → 受影响页按人裁重跑 → book-text 升版 → …… 直到达到 [1.0 发布标准](1.0发布标准.md)，冻结。

要点：

- **目标是把流程跑通，不是把某一册跑得更好。** 达不到标准的册不强行放行，按错误类型退回（切分／书影类退 A30，识别／定字类退 A31）。
- 人审**一人裁即算**，不做多人投票或双路复核；质检不随机抽，专挑低置信、易错类别（少于 200 格），只报错误率和类型，不设门槛。
- 重跑结果只算提案，不覆盖已发布文本和人裁事件。

## 入口条件（不满足就退回粗校，不开始精校）

1. 册固定在一个正式 cv tag 上（不用 rc、不用 `+N`），册 yaml 顶层有 `cv_version`。
2. 文本线已在 book-text `main` 上，`proofing: true`，版本 0.x（0.1.0 起）。
3. 整页／整列丢字、错位已修（零散切分问题可在重切清单里带到 1.0 前修）。
4. 书影、切分、文本三方一致：`check_cord_vs_splits.py --live` 对本册全绿（见 [验收标准](验收标准.md) G3b）。
5. 待审单资源齐：`sprites[]` 含所有被引用的图（含相似字 alt 雪碧图）。

粗校出口的这几项如果没钉死，第一张单发出后任何一项再变都会让读者已投的票作废或漂移（票只带格号）。这也是「步骤前移」要解决的问题，详见 A32 项目文件《精校步骤前移方案》（2026-10-29）。

## 现状：停放模式

2026-10-29 起，用户不再亲自审人审格，大部分册停在 v0.1，等网站读者把待审格投完再继续。含义：

- 票是公众零散、长期地投，不再是「一个审校者一次投完」；落票要按增量做，不能假设「投完了」。
- 单子发出之后，格位层（图源 `source_rev`、切分、`manual-cells`）不能再变；定字层（字形库、语料、字组）可以照常升级，格号不动、票不漂。冲 1.0 前再整体 pin。
- 目前只有册 004、005 拿来冲 1.0 做实验；册 001–003 的 1.0 缺口由迭代项目（A34）通过迭代流程修。
