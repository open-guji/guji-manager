# 层1 切分：把格框一次切对（史记，2026-11）

## ① 本轮新经验（一句＋为什么）
- **先分两类毛病**：结构类（漏切、并格、拦腰切、格数不对）动格号，必须第一层清零；装饰类（邻字残笔、界行、版框进框）不动格号，靠发前清格抹墨，不挪框。为什么：挪框会动格号，人裁、刻例、锚全要迁。
- **修法分四级**：公用算法 → 书级代码（书仓 `code/`，出新 k）→ 页型／列参数 → 格钉子（manual-cells）。为什么：为个别格改算法参数会把别处改乱；钉子只影响那一列（Sheldon 11-10）。
- **整列钉坐标、一格两字强拆**：职名页「原任」「三等」挤一格，直接在 manual-cells 里把那一列所有格的坐标写死，重跑时不再算这一列（rev 971280）。为什么：算法切不开的少数列，钉死最省事，将来算法会切了再撤。
- **钉子后格号顺延不用手迁人裁**：人裁按墨框锚绑定，格号变了自动跟过去。为什么：所以敢在第一层就拆格。
- **发前清格（书仓 k4–k6 `patch_clean`）**：只抹字块里别格的墨，框和格号不动；加了「伸入深度 ≤框高 30%」这道闸。为什么：写本上下字常一笔相连，只按墨量会把本字的撇抹掉。
- **墨账前先剥长直线**（竖开运算 200px、横 0.85 列宽）。为什么：写本连笔加界行贯穿整列，不剥会连成一块，墨账全错。
- **漏切块（orphan）要两条框线过滤**：粗框横带（宽 ≥0.8 列宽、高 ≤60、填充 ≥0.25）和外圈 15% 内的稀疏框角。为什么：r41 两个漏切误报全是框线和整页御题印。
- **○ 不是切分问题**：○列切分框全对，待审是对位／字形库的事（A9＝整理本缺字或库误读）。为什么：别在切分层为○改框，r41–r42 的 56 列○都核过框。
- **列格数同而编号不同算过**：题署列大间距不留空位号、只左行小注标 b，都不是错。为什么：避免为编号习惯迁全部人裁。
- **坐标原点在右上**：`cell_shrink.bbox_page` 是 raw_page_px@top-right，x 从右往左；裁图用 `open_guji_cv.core.anchor.crop_patch(img, bbox)`，或 PIL 换算 x0'=(W-1)-x1、x1'=(W-1)-x0。为什么：按左上原点裁会裁到镜像位置。

## ② 可复用脚本与入口
- **一条命令核切分**（guji-manager `tools/seg_check/`，dev 已合 #519 #520）：
  `python tools/seg_check/seg_check.py --products <产物根> --cache <缓存根> --vols 01,02 --pins <manual-cells items.jsonl> --layout <layout_slots.jsonl> --skip <册:页,…> --out <目录> [--reuse-geom]`
  出 `列清单.tsv`（处置：格号不符／版式不符／需钉子／原因码·看图／已钉·复核／对位（○）／公用清格…）、`需看图_*.png`、`report.md`。十册约 6 分钟。
- **推钉子前必跑** cv `scripts/seg_pins_check.py --book NN --items <items.jsonl> --out <目录>`（要 GUJI_WORKSPACE、GUJI_PRODUCTS_DIR、钉好的 glyph-gNN.db、unet 模型）。
- 钉子文件：中心库 `feedback/verdicts/char-segmentation/manual-cells/items.jsonl`；拆格要同时补 `events/` 与 `anchors/NN.jsonl`（同一 (event,key) 不能追加第二行）。
- 准备数据：`guji products pack fetch NN --label <带 job 号> --root <目录>`、`guji cache warm --book NN --jobs 4`。
- 文档：guji-manager `doc/01-粗校/切分快筛.md`（判据、金标、r35/r41 结果、能钉 vs 公用表）。
- cv 发 #1422 后，seg_check 的 orphan 一步改用 cv `scripts/seg_screen.py`。

## ③ 开新书第一层操作清单（顺序）
1. 书仓建好 `code/`（k1），点名跳过页（年表、卷首、整页印），写进 skip。
2. 跑一轮出包 → `cache warm` → `seg_check`。
3. 先看 **格号不符、版式不符、需钉子**：逐列看缩略图，真切错的按四级修法归位（能改公用的报 A22，书级的出新 k，个别列钉子）。
4. 再看 **原因码·看图**：框对就转参校／字形库线程，不在本层动。
5. 装饰类计数高 → 上书级 `patch_clean`，从 cell_shrink 起重跑。
6. 钉子：写 items.jsonl → `seg_pins_check` 全过 → pull、dry-run（`glyph_exported=false`）→ `GUJI_ACTOR=… db push --no-admit`。
7. 重跑后再跑 seg_check，**切坏格 0、格号不符 0** 才进第二层（字形库收样本）。

## ④ 已知坑
- 钉子推中心库前不 pull 会互相覆盖；推前 dry-run 看 glyph_exported，`pull --no-rebuild` 之后不能 push（会用旧 glyph.db 覆盖字形库）。
- 不开 GUJI_ALLOW_LOST_HUMAN；改定框后旧人裁要迁，不能默认丢。
- `guji step` 的 book 是位置参数，不是 `--book`。
- 换 cv 检出后 unet 模型软链会断，要把 `models/partition_unet_v2/model.pt` 拷过去，否则悄悄降级。
- `code_equiv.py check` 会整份复制 `--cache` 两次：只给要测的那一册的缓存目录，不然磁盘撑爆。
- 列中整宽横笔可能是「一」，版框横线只在列首列尾格抹。
