# 层2 字形库：无/少样本字头补刻例（史记，2026-11）

## ① 本轮新经验（一句＋为什么）
- **字形库就是真源，快照要与中心库某 rev 对得上**：改库→`db push --with-glyph`→`glyph-db snapshot --pin N`→`snapshot-upload --execute`→`pin-verify`→`db push`（带上 manifest）。为什么：快照不对 rev，下游钉了也复现不了。g8–g18 都这样出；每轮只钉一个 g。
- **借库撤销（g10 起无借库）**：借来的刻例会把别书的写法带进来、掩盖本书缺样本。为什么：撤后缺样本字头才暴露，补完自有刻例 6,990（g18）。
- **字形库缩水事故（11-10）**：`pull --no-rebuild` 之后 push 把旧 glyph.db 导出覆盖了中心库。为什么：push 会顺带导出本机 db。规矩：pull 不加 --no-rebuild；推前 `push --dry-run` 看 `glyph_exported` 与各表 insert/delete（只增不删）；推要设 `GUJI_ACTOR`、带 `--with-glyph`，不开 allow-delete/shrink。
- **点审默认全 OK 会放错字**：形近格（子/其/宫/採、十/卞、則/元/僕等）被默认 OK 入了库，事后靠改判批撤旧进新。为什么：没点的格≠审过。规矩：形近格逐格对图，不靠默认。
- **○邻字补刻例（g18）**：A31 查明 ○后书名人名字被库误读（令≠今、駱≠路…），把 40 格按整理本唯一定位＋对原页图补进 39 条刻例；无旧条目，不用撤。为什么：cov 高也认错，因为库里没有该字或只有形近字的样本。
- **自动入库闸（本轮结论：先不放）**：三方一致（库首位＝参校＝对位，cov≥.975，gap≥.025）选格→分层盲读≥100 格（或 5%）**0 错**才写 gate.ok，admit 无 gate.ok 拒绝。首轮 168 格至少 8 真错，全在字头自有样本≤3（own≥4 的 64 格 0 真错）；rapidocr 紧框首位字＝参校字能拦 14 个真错/疑似里的 12 个；字体渲染相似度无效。收窄后 495 候选抽 120 格仍有 2 格无法证明对（图糊、刻本同形），闸不过，不入库。为什么：宁可不放，错一条刻例会污染后面所有轮。
- **反例集**：詁/詰、丸/九、荆/判、桀/祭、厪/塵、斤/行、湣/潛、苡/設（真错）；毫/亳、雅/翟（无法证明）。异体与答案一致不算错；盲读者自己也会读错异体（黯/黔、藤/滕），裁决要逐格对图。

## ② 可复用脚本与入口（guji-manager，dev 已合 #518）
- `tools/开书/字形快速入库_自动.py`：`scan`（选格、形近组排除 `--exclude-file`、`--min-own`、`--ocr`）→`ocr`（须在装 rapidocr＋cv2 的 python 里）→`crop`（从原页图裁格）→`sample`（分层抽样，`--list-only`、`--skip-ids`）→读图写 reads.tsv→`gate`→`admit`。
- 坐标约定：`cell_shrink.bbox_page` 原点在页面**右上**、x 从右往左，PIL 裁时 x0'=(W-1)-x1、x1'=(W-1)-x0。
- 人审路径：`guji_manager review-pages build char_grid`＋`scripts/build_newchar_review.py apply … --execute --admit`；快照：`guji glyph-db snapshot / snapshot-upload / pin-list / pin-verify`；同步：`guji db pull/push/status`。
- 文档：`doc/01-粗校/开书/字形快速入库.md` 第八节（8.1–8.7）。

## ③ 开新书第二层操作清单（顺序）
1. `guji db pull`（不加 --no-rebuild）确认 behind=0，备份本机 glyph_store 与 glyph.db。
2. 第一层切分清零后再进本层；出包后 `scan` 统计缺样本格与字头（自有样本<8、<4、=0 分档）。
3. 先补自有样本为 0／<4 的字头：走四层页（char_grid 快审→高→低→难认字），形近格逐格对图。
4. 自动链只作统计与待批台账；要放行须先对新书重测 own 阈值与盲读 0 错。
5. 入库后 `push --dry-run`（只增不删、glyph_exported 已核）→push→snapshot→upload→pin-verify→push manifest。
6. spec 钉新 g，跑一轮，对照缺样本字头是否被纠正，没纠正的再补。

## ④ 已知坑
- 自动入库的 `export_store` 默认写工作区 output/glyph_store，不是数据目录 store；要导到临时目录再复制 admissions/evictions/exemplars/glyphs/instances/v2.jsonl 和 patches。
- `admit_instance` 的 idx 要 int；`glyph_audit` 的撤销消费者在未设 GUJI_WORKSPACE 时会找错库。
- `guji db sync` 会重放未消费事件（dry-run 见 glyph_admit events），要核；只推库用 `db push --with-glyph`。
- 缺 `GUJI_ACTOR` 推不了；磁盘不足先清旧 prod/cache 目录。
- r41 bbox 与 r42 格号一致才能用旧包的 cell_shrink 裁图，换版先核。
