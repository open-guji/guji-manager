# 点校：验收标准

## 机检（每次入库、改动前都跑）
`local_check.py` 全绿，另加六项自检（能抓到抽样抓不到的个案）：
1. 每段 `《》「」『』` 平衡。
2. 相邻点号无异常（`，，`、`，。`、点号后接闭括号）。
3. 同一 `(anchor, mark, pos)` 无重复记录（移动点号常留下旧记录）。
4. 同 `(type, text)` 不既 `matched` 又 `new_candidate`。
5. `《》` 对与 work 实体起止一致。
6. 已知实体名在正文里未被任何 span 覆盖的，逐条核。
并核：汉字未改；`stats` 与实际一致；`matched` 的 `entity_id` 存在；`《》` 内不加 `·`。

## 抽样验收
- 新册入库：抽样（标点约 200 处、已挂专名约 30 条）人工看原图／原文，结果记录。第 21 册为例：标点 199/200 可接受，专名 27/30。
- 升 1.0：成文验收记录——随机种子＋抽样清单＋结果，写进该线顶层 `review`，用户看数据点头（见精校的[验收标准](../03-精校/验收标准.md)）。
- 维基带标点本只作参照，不是真值：「。」少、「；」多、单字经名卦名的《》属风格差异，不当错误。

## 完成标志
两线版本号已入库；库无清单已交付并按结果回挂；剩余 `new_candidate`／`ambiguous` 有清单可追。

## 新自动放行类别的守则（对齐降人审框架第五节，2026-11-05）
点校里凡让算法或大模型替人放行的新类别（hard_pair 裁定、省称自动补全、同名异朝选条等），上线前：
1. 金标放行子集 0 错；独立盲读抽样 0 错。样本量：放行 <100 处抽 30；>300 抽 100；>1000 抽 200。
2. 有错就收紧（只收与外部包一致的、只放白名单、提高置信），再测。
3. 放行后每轮滚动抽 30 处；放行内容变、人裁丢失则停止入库。
4. 金标按书、按类维护，不继承别的书。
5. 速度目标下，抽样验收不再等整本书做完：每册入库时按上面样本量抽，结果记在册里，升 1.0 时汇总。
