# 点校：目标与入口条件

## 目标
给整册文本加标点（punct 线），识别专名（人名、书名、官名、地名、朝代年号等）并匹配到中心库实体（entity 线）。两条线都是 book-text 里每册文本的伴生层，按字格 `anchor` 挂在字符线（char）上，**不改一个字**。

- 标点层：每个点号记录 `(anchor, mark, pos)`，书名号、引号成对。
- 专名层：每个 span 带 `type`、起止偏移，`target` 为已匹配实体（`matched`）、多链接（`matched_multi`）、歧义（`ambiguous`）或候选（`new_candidate`）。
- 新实体不由本步自建大批量：小批量可直接在 book-index 建（含官条、别名），大批量转实体库负责项目（书名／出版者另有归属）。

## 入口条件
1. 该册已入库 book-text，字符线版本已过粗校并进入精校；**待审格较少时即可开做**（2026-10-25 定：精校中就做，随改字局部重标；以册待审低于约 100 为开做线，人审压到每册百字以下也可开做）。
   - **走降人审框架的新书**（[降人审迭代框架](../02-粗校/降人审迭代框架.md)，2026-11-05 起）：开做线改按「格号是否已稳」判——**最后一次 S 轮（结构层，格号会变）标 main 之后**即可预标；D 轮（决策层）不改格号、不影响标点锚点，可与点校并行。待审多少不再卡预标，只决定「有多少字还会被改」（见《步骤》第 8 节的锚点修复）。
2. 页序正确。页序乱的册（读序与页号不一致）先让页序核查项目出读序表，点校按读序拼正文，缺页接缝处硬断句。
3. 字符线之后若有改字：单字替换（不增删字）可只修锚点；增删字、整句改须重标，见《步骤》。

## 与降人审框架的衔接（2026-11-05）
粗校侧目标是一本书一天左右跑到人审率目标线（0.1%–0.3%），点校不能再等粗校收口才开始，也不能让人审成为瓶颈。对齐点：

| 框架里的东西 | 点校这边怎么接 |
|---|---|
| S 轮改格号 | 标 main 前 A31 通知 A33；点校用 `auto_remap.py` 逐册重映射标点与实体锚点；冻结期点校不往 dev 合动 char／cord 的改动 |
| D 轮改字（不改格号） | 每轮标 main 后，按「新旧包的变字清单」批量跑 `punct_redo` plan／apply（单字替换只修锚点，两线升 patch） |
| `hard_pair`（日曰、己已巳）H01，「留给标点／专名阶段」 | 点校按文意出裁定表，交精校走改字清单落字，见《步骤》第 9 节 |
| 五层漏斗（L0 配置→L4 人审批量页） | 点校自己的降人审也按这五层走，见《步骤》第 10 节 |
| 收口单（R5） | 点校待办（`ambiguous`、`new_candidate`、库无清单、hard_pair 未裁）作为一栏写进去 |
| 人审页模板 | 专名待确认、库无专名建档确认、标点抽样验收三种页型，由点校向 A31 提需求，见《步骤》第 10 节 |

点校的速度目标：版式家族成熟后，一册从预标到入库在半天内完成，整本书的点校不拖在粗校收口之后太久。实际用时按册记进台账，累积后再定量化目标。

## 不做什么
- 不改字（改字归精校）。
- 不建大批量实体、不改 guji-format 规范（谁需要谁直接改，改格式前先通知网站与搜索侧项目）。
- 地名暂不建，留 `new_candidate`。
