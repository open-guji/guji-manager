# 第二步　迭代

多册书分批（一般 10 册一批），一轮一轮跑 CV 管线、修切分、补少见字、处理形近字，把人审率压到本书目标线；本批前三小层做完就标 **v0.1**、导入 book-text、上网站。AI 文意判字与标点专名是[第三步](../3-AI文意判字标点专名/)，网站人审是[第四步](../4-网站人审与版本迭代/)。

**主文：[迭代流程](迭代流程.md)**（10 册一批的节奏、一轮的十个固定动作、每层收哪些待审原因、回溯表、判停三问、用户参与点）。本页是入口和摘要。

```
          ┌───────────── 一轮（统一冻结、发版、重跑一次）─────────────┐
          │ 2a 跑 CV 管线：收修复→冻结发版→钉版本→交单→比对→闸→标 main │
          │      │                                                     │
          │      ▼  待审按 pending_reason 归层派活                       │
          │ 2b 切分检查与优化  →  2c 少见字入库、OCR 候选  →  2d 形近字处理 │
          └──── 后层发现前层的问题 → 回到那一层 ──────────────────────┘
                    │ 本批 b–d 判停
                    ▼
            出 v0.1、导入 book-text、上网站 ──▶ 下一批 10 册沿用本批配置
```

## 目标与入口条件

**目标**：用固定的 cv 版本把一批册整册跑完，一轮一轮把人审率压到本书目标线，本批 b–d 判停后出 v0.1。人审率目标 < 1%（不卡出口，但要写原因）；自动放行错放 = 0 是目标，少数错放在成批重跑里是预期内的，只有程序级严重 bug 才拦。

**入口条件**：
- 第一步关口 A 已过（先行册无成片切分错、放行 ≥90%、常用字有本书刻例）。
- 册已进中心库，原图在 R2；册 yaml 钉好 `cv_version`、`code`、`corpus`、`glyph_pin`。**没跑过的册一律钉最新 cv 版本**；老册换版本由本书线自己定、自己改钉。
- 执行环境见 [环境与令牌](../00-总览/环境与令牌.md)。

## 初期人多、后期人少

初期 2b–2d 都要人参与：看切分叠图、点少见字快审页、标形近字金标与定码位口径。数据积累以后要逐步把人换成机器：

| 小步 | 初期人做的 | 换成机器的条件 | 已有的工具 |
|---|---|---|---|
| 2b 切分 | 看新页型叠图 | 本书尺子覆盖已知根因；`seg gate`／`seg premain` 不挡 | 根因台账、`guji seg ruler`、切分快筛 |
| 2c 少见字 | 第一次进库的字人裁 | 自动入库闸：分层盲读 ≥100 格 0 错才开（全唐文、史記试过还没过） | [快审减量](c-少见字入库与OCR候选/快审减量.md)、[放行格回库](c-少见字入库与OCR候选/放行格回库.md)、`字形快速入库_自动.py gate` |
| 2d 形近字 | 金标标注、码位口径、新放行类别上线 | 金标放行子集 0 错，独立盲读抽样 0 错；每轮滚动抽 30 格 | 刻形 CNN、[形近字迁移框架](d-形近字处理/形近字迁移框架.md)、[准确率守则](降人审/准确率守则.md) |

做法细节和人审页模板见 [降人审/](降人审/)：[降人审迭代框架](降人审/降人审迭代框架.md)（人审率口径、判停三问）、[逐轮降人审节奏](降人审/逐轮降人审节奏.md)、[决策层漏斗](降人审/决策层漏斗.md)、[人审页模板](降人审/人审页模板.md)、[数据与跟踪](降人审/数据与跟踪.md)。用户一轮花的时间超过 30 分钟，说明上游预选或金标没做好，要改流程。

## 什么时候重跑、跑多大

- **不是每次有新版本都重跑。** 小修复攒一批再统一跑；预期收益很小的不单独跑。
- 改动只落在 seed_admit（规则、字组、码位、文意表）→ 只从 seed_admit 重落；动了切分或更早的步 → 只重跑受影响页；`guji status` 无过期步 → 不跑。
- 需求单要写：为什么跑、范围、预计收益、起点步（和 `guji status` 对得上）、对比基线。
- **新册首跑**（没有 main 的册）跑完一律直接标 main，已写进代码自动做。
- 重跑完默认直接标 main、推库；标 main 后钩子自动重出线上单（`online_lists`，见 [环境与令牌](../00-总览/环境与令牌.md)）。有 `.punct.json` 的册或旧单已有票的只提示，交精校走 proof_cycle（[第四步](../4-网站人审与版本迭代/)）。
- 结果取用：`guji products pack list/fetch` 取同一份继续分析；**分析必须用出单版的包**（按 cv 版本和出单时间对上），否则格号对不上。
- 换图源、整套迁移之类的大批量重跑见 [4e 1.0 之后的反馈](../4-网站人审与版本迭代/e-1.0之后的反馈/) 与 [重跑需求与执行规范](a-跑CV管线/重跑需求与执行规范.md)。


## 派活：哪类问题交给谁

| 问题 | 交给 | 交什么 | 对方回什么 |
|---|---|---|---|
| 字形库缺字、生僻字识别、模板 | A23 | 字清单、册页格号、整理本字 | 补库／5b 改进，PR 号 |
| 形近字组、文意表缺、护栏 N | A24 | 字组／字对表、带图样例 | cv PR、文意表推库 |
| 对位问题（无整理本对位、对位替换） | A34（或 A23） | 页／列样例、错行类型 | 对位算法改动 |
| 切分系统错（重切清单、seg_defect） | A22 | 页／列清单、看图结论 | cv 修复 PR |
| 精校（人必须细看的格） | A32 | 待审单、数量 | 人裁事件 |
| 要用户定的码位 | 用户 | 带图字对表 | `codepoints.yaml` 决定 |

发现系统性识别错误：记录样例反馈 A22（切分）或 A34（对位／迭代），不要逐个手补。
