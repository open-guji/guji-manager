# 命令速查（按五步）

`guji <步> <命令> …` 按步骤分组：`start` 新书启动、`pipeline` 自动化流程、`text` 文意与知识、`feedback` 反馈迭代、`output` 排版输出。
带前缀与不带前缀等价（`guji start source pull …` ≡ `guji source pull …`），文档一律写带前缀的；`guji <步> commands` 列出本步命令，`guji <步> <命令> -h` 看参数。
`guji pipeline <管线> <册>` 仍是跑管线（`pipeline` 后面跟的不是本步命令名时就是跑管线）。分组与实现见 `guji_manager/steps.py`。
不属于哪一步的公共命令不加前缀（见末节）。令牌只写环境变量名，见 [环境与令牌](环境与令牌.md)。

## start　第一步 新书启动

| 小步 | 命令 | 用途 |
|---|---|---|
| 1a | `guji start source spreads <源件> --vol 01 --out splits.json --sheet 核对图.png` | 对开拆页，出核对图 |
| 1a | `guji start source commons <书id> 01 --djvu <源件> --commons-json commons.json --splits auto --dry-run` | 登记 Commons 来源的原图；`ia`／`register` 是 IA 与老书 |
| 1a | `guji start corpus init／build／verify` | 新书钉最新底库；出语料新版本 |
| 1a | `guji start code status／release／verify -w <书仓>` | 书仓 `code/` 出 `k<N>` |
| 1b | `guji start pagekinds <册>` | 页型对账 |
| 1b | `guji start suggest` | 诊断信号 → 开关建议，点头后写册 yaml |
| 1b | `guji start glyphlib build` | 共享刻例库（借库用） |
| 1c | `guji start source pull <册> -w <工作区>` | 按页表取图到 `raw_dir` |

新工作区进中心库用公共命令 `guji db init／push／status`。选页试跑、叠图、首批快审用第二步的命令（`guji pipeline <管线> <册> --pages dev_set --no-pack`、`guji pipeline product overlay`、`guji pipeline triage`、`guji pipeline review-pages build char_grid`）。

## pipeline　第二步 自动化流程

| 小步 | 命令 | 用途 |
|---|---|---|
| 2a | `guji pipeline <管线> <册> -w <工作区> [--pages …] [--from／--to <步>]`、`guji pipeline step` | 跑管线（cv） |
| 2a | `guji pipeline status --pages all` | 各步过期／缺失（cv） |
| 2a | `guji pipeline book show／split`、`binarize`、`preclean`、`split`、`locate-gutter`、`survey`、`calibrate`、`calibrate-font` | 册配置与页面预处理、版式实测（cv） |
| 2a | `guji pipeline job precheck／submit／ls／show／wait／stats` | 交单前核钉子、交重跑、看结果、时间账（`GUJI_JOBS_WHO=<你>`） |
| 2a | `guji pipeline rerun --stale` | 只重跑标了失效的页及下游 |
| 2a | `guji pipeline products pack list／fetch／push／promote`、`products diff`；`product overlay／raw／patch` | 产物包存取、标 main、逐格比对；叠图与取图 |
| 2a | `guji pipeline cache warm` | 预热图像缓存 |
| 2a | `guji pipeline round-check <册> --pack <候选>` | 收轮检查：seg check×2→gate→diff→premain→待审分四层 |
| 2a | `guji pipeline close-check <册> --tier rough`、`progress` | 交付前逐项体检、每页还挂着的待办 |
| 2a | `guji pipeline iterate auto-round／round-report／gold／audit／leverage` | 轮报告、金标、抽检台账、杠杆排序 |
| 2a | `guji pipeline pending-stats` | 待审格分类统计、诊断信号表 |
| 2a | `guji pipeline exp run／report／flips`、`perf top／show／job`、`eval list／run`、`check quality／round／rate` | A/B 实验、耗时、评测、判据 |
| 2a | `guji pipeline events harvest／route／list`、`gold …` | 人裁事件入库与分派、金标 |
| 2b | `guji pipeline seg check／gate／premain／pin／pins-stale／ruler` | 切分核查、不回退闸、标 main 前检查、整列钉子 |
| 2c | `guji pipeline review-pages build char_grid …`、`triage prepare／train／route／sheet` | 少见字四层页、参校字快审分流 |
| 2c | `guji pipeline glyph-db snapshot／snapshot-upload／pin-list／pin-verify／selfcheck` | 字形库快照、钉版本、自检 |
| 2c | `guji pipeline recheck`、`rare`、`variants`、`pua-table publish` | 点名重算、生僻字候选、本书用字账、PUA 码表 |
| 2c | `guji pipeline collate <册>` | 与整理本对勘 |
| 2d | `guji pipeline groups table／status`、`promote mine`、`pair-attr show／check` | 字组、挖形近对、形近字对归属表 |
| 2d | `guji pipeline model ls／build／verify`、`font registry` | 模型总号、字体 |
| 出 v0.1 | `tools/开书/出v01.py` | 取 main 包→判停→交接单→导出→book-text 加章 |

## text　第三步 文意与知识

| 命令 | 用途 |
|---|---|
| `guji text final-review build／batches／status／finalize／write` | AI 文意终审跨书流水线 |
| `guji text rulings-hits [--rekey]` | 裁定在产物里有没有命中（窗口变了要补写） |

文意判的出段与回读用 `guji pipeline review-pages ctx2-export／ctx2-import`。

## feedback　第四步 反馈迭代

| 小步 | 命令 | 用途 |
|---|---|---|
| 4a | `guji feedback pending list／…／reconcile／export` | 待审条目（一格一条） |
| 4a | `guji feedback online-lists --audit -w <工作区>` | 线上单出单、体检（标 main 后钩子自动重出） |
| 4a | `guji feedback swap run` | 换单：出新单→同步→分批发布→核线上→清盘 |
| 4b | `guji feedback collect` | 收单快路：读票→写人裁→落 book-text→KV 结案→推库→发站核对 |
| 4b | `guji feedback cellvotes draft／write` | 网站格级投票落人裁事件 |
| 4c | `guji feedback swap book-text／finish-merged`、`closeout`、`rekey-cells` | 换包落 book-text、标 main 后收尾、换图源后改键 |
| 4d | `guji feedback exit-check`、`char-diff`、`audit`、`freeze` | 出 1.0 的出口检查、逐格比、定版检查、冻结登记 |
| 4e | `guji feedback opinions ingest／triage／decide／revise／auto…` | 1.0 之后的意见池 |
| — | `guji feedback progress-sync` | 后台看板自动对账 |

## output　第五步 排版输出

| 命令 | 用途 |
|---|---|
| `guji output export md <册>` | 逐列文本 → `reports/<册>/<册>.md` |
| `guji output export format <册> [--format char-cord]` | lines.md／pages.json／norm.json（或 char 格式） |
| `guji output export wikisource <书> -w <工作区>` | 维基文库 wikitext |
| `guji output export reflow <md> --out …` | 分行 md 重排成段 |
| `guji output collation-report --book <册>` | 与整理本对勘的 HTML 报告 |

cv 原 Step9，11-23 代码搬进本包 `output/`；口径见 [5-排版输出](../5-排版输出/)。

## 公共命令（不加前缀）

| 命令 | 用途 |
|---|---|
| `guji db pull／push／status／sync／init／branch／migrate` | 中心库（写用 `GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD`、`GUJI_ACTOR=<你>`） |
| `guji central-gc`、`guji datastore backup／restore-check／verify` | 中心库清理、备份与恢复演练 |
| `guji pipeline job work／workers／board／init` | 任务库执行方、看板 |
| `guji pipeline model upload／fetch`、`guji pipeline font upload／fetch` | 模型、字体进出 R2 |
| `guji snap`、`guji archive fetch` | 快照导入、归档包 |
| `guji version`、`guji-manager check` | 版本、与 pipeline 的契约兼容 |

## 2026-11-22 删掉的命令

`guji release`、`guji deploy`（K 道发版与 production 部署，早已不用）、`guji batch`、`guji label-batch`（审查批次、补标签批）、`guji cards`（控制台直接读 `review.cards`）、`guji store`（用 `guji db push`）。原 `guji-manager <命令>`、`python -m guji_manager.<模块>` 仍能用，文档改写成 `guji <步> <命令>`。
