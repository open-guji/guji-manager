# 命令速查（按四大步）

令牌写环境变量名，不写值；详见 [环境与令牌](环境与令牌.md)。每个命令的参数看 `guji <命令> --help`。
`guji pipeline`／`status`／`step` 是 cv 的命令，其余 `guji` 子命令来自本包（装了本包会并进 `guji`）。`guji-manager <命令>` 是本包另一个入口，`python -m guji_manager.<模块>` 是模块直跑。

## 第一步　新书启动

| 小步 | 命令 | 用途 |
|---|---|---|
| 1a | `guji source spreads <源件> --vol 01 --out splits.json --sheet 核对图.png` | 对开拆页，出核对图 |
| 1a | `guji source commons <书id> 01 --djvu <源件> --commons-json commons.json --splits auto --dry-run` | 登记 Commons 来源的原图（PDF 也收）；`ia`／`register` 是 IA 与老书 |
| 1a | `guji corpus init`／`build`／`verify` | 新书钉最新底库；出语料新版本 |
| 1a | `guji db init -w <工作区>` → `guji db push -w <工作区>` → `guji db status` | 新工作区进中心库（写用 `GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD`、`GUJI_ACTOR=<你>`） |
| 1a | `guji code status／release／verify -w <书仓>` | 书仓 `code/` 出 `k<N>` |
| 1b | `guji pagekinds <册>` | 页型对账：册配置点名的、规则判的、最后怎么处理的 |
| 1b | `guji-manager suggest` | 诊断信号 → A 档开关建议，点头后写册 yaml |
| 1b | `guji-manager pending-stats` | 诊断信号表、全部待审格分类统计 |
| 1b | `guji glyph-db selfcheck -w <工作区>` | 本书库建起来后先看「清边不变式」 |
| 1c | `guji source pull <册> -w <工作区>` | 按页表取图到 `raw_dir` |
| 1c | `guji pipeline <管线> <册> -w <工作区> --pages dev_set --to <步> --no-pack` | 选页试跑（cv） |
| 1c | `guji product overlay` | 叠图看切分 |
| 1c | `guji-manager triage prepare／train／route／sheet` | 参校字快审分流 |
| 1c | `guji-manager review-pages build char_grid …` | 首批字形快审页 |

## 第二步　迭代

| 小步 | 命令 | 用途 |
|---|---|---|
| 2a | `guji job precheck --books <册段> --cv … --code … --glyph-pin …` | 交单前逐册核生效的钉子 |
| 2a | `guji job submit <spec.json>`；`ls`／`show <号>`／`wait`／`stats` | 交重跑、看结果、记时间账（`GUJI_JOBS_WHO=<你>`；跑完不通知，自己查） |
| 2a | `guji status --pages all` | 各步过期／缺失（cv） |
| 2a | `guji rerun --stale` | 只重跑显式标了失效的页及下游 |
| 2a | `guji products pack list／fetch／push／promote`、`guji products diff` | 产物包存取、标 main、逐格比对 |
| 2a | `guji cache warm` | 取包后预热图像缓存 |
| 2a | `guji job submit --kind roundcheck …`；`guji round-check <册> --pack <候选>` | 收轮检查：seg check×2→gate→diff→premain→待审分四层 |
| 2a | `guji close-check <册> --tier rough` | 一册交付前逐项体检 |
| 2a | `guji-manager iterate auto-round／round-report／gold／audit` | 轮报告、金标、抽检台账 |
| 2a | `guji exp run／report／flips` | A/B 实验 |
| 2a | `guji perf top／show／job` | 跑批耗时 |
| 2b | `guji seg check`／`seg gate`／`seg premain` | 切分核查、不回退闸、标 main 前硬检查 |
| 2b | `guji seg pin`／`seg pins-stale`／`seg ruler` | 整列写定钉子、钉子是否过期、人修过的列 |
| 2c | `guji-manager review-pages build char_grid／…` | 少见字四层页 |
| 2c | `guji glyph-db snapshot／snapshot-upload／pin-list／pin-verify` | 字形库出快照、钉版本 |
| 2c | `guji recheck` | 库变了点名重算某些格 |
| 2c | `guji rekey-cells` | 换图源后按格级对照表改键 |
| 2c | `guji glyphlib build`、`guji pua-table publish` | 共享刻例库、PUA 码表共享层 |
| 2c | `guji audit alt` | 给待审卡算相似字 |
| 2d | `guji groups table／status` | 字组总表、每组状态 |
| 2d | `guji promote mine` | 从本书人裁挖形近对、异体对 |
| 2d | `guji-manager pair-attr show／check` | 形近字对归属表 |
| 2d | `guji model ls／build／verify` | 模型总号（册 yaml 写 `model: N`） |
| 出 v0.1 | `tools/开书/出v01.py` | 取 main 包→判停→Step9 产物→交接单→导出→book-text 加章 |
| 出 v0.1 | `guji collate <册>`、`guji export md <册>` | Step9 对勘与逐列文本 |
| 出 v0.1 | `guji closeout` | 标 main 后收尾 |

## 第四步　网站人审与版本迭代

| 小步 | 命令 | 用途 |
|---|---|---|
| 4a | `guji pending list／…／reconcile／export` | 待审条目（一格一条） |
| 4a | `guji swap run` | 换单：出新单→同步→分批发布→核线上→清盘 |
| 4a | `python -m guji_manager.online_lists --audit` | 线上单核对（标 main 后钩子自动重出） |
| 4b | `guji collect` | 收单快路：读票→写人裁→落 book-text→KV 结案→推库→发站核对 |
| 4b | `guji cellvotes draft／write` | 网站格级投票落人裁事件 |
| 4b | `guji db sync` | 写人裁事件并推库 |
| 4c | `guji swap book-text`、`guji swap finish-merged` | 换包落 book-text（格号变时走格级对照表） |
| 4d | `guji exit-check`、`guji char-diff`、`guji audit` | 出 1.0 的出口检查、逐格比、定版检查 |
| 4d | `guji freeze` | 冻结登记 |
| 4e | `guji opinions ingest／triage／decide／revise／auto…` | 1.0 之后的意见池 |
| 4e | `guji events harvest／route／list` | 反馈事件 |
| — | `guji-manager progress-sync` | 后台看板自动对账 |
