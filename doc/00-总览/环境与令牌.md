# 环境与令牌

> 本页讲两件事：一、云端会话怎么装好 guji-manager；二、整理流程里会碰到哪些令牌／密钥（是什么、谁用、放哪、权限多大）。**令牌的值一律不写进仓、Jira、聊天。** 缺令牌时先查本页第二部分，再找负责人要。

## 一、云端会话装 guji-manager

> 迁自 ai-team `通用/经验-云端装guji-manager.md`（2026-10-27 核对）。

- Default 环境 setup script 里有 guji-manager 的 clone + `uv pip install -e`，但快照构建时可能拉不到被吞掉，所以快照里未必有。setup script 读不到环境变量，不能靠令牌。
- `/opt/guji-venv` 是 uv 建的，没有 pip；装包一律 `uv pip install --python /opt/guji-venv/bin/python ...`。
- `/opt/guji-runner` 是 open-guji-cv 的 worktree，没有自己的 venv，也用 `/opt/guji-venv`。
- `guji opinions` 过渡期 cv 自带，不等于装了 guji-manager；用 `importlib.metadata` 看有没有 `guji-manager`。
- 会话里的做法（约十几秒）：
  1. `add_repo open-guji/guji-manager`
  2. `git clone --depth 1 https://github.com/open-guji/guji-manager /home/user/guji-manager`
  3. `uv pip install --python /opt/guji-venv/bin/python --no-deps -e /home/user/guji-manager`

### 标 main 后自动重出线上单（online_lists）

- 钩子在 cv#727（dev）：`pack promote`／`push --main` 后调入口点组 `guji.post_promote`；manager 的 `guji_manager.online_lists` 起后台子进程重出线上单，日志 `<工作区>/reports/<册>/_publish/auto_issue.log`。关闭：`GUJI_AUTO_ONLINE_LISTS=0`。
- 要点：①cv 必须是含 #727 的 dev，且在 `PYTHONPATH` 上；②Default 环境没有 `/opt/guji-venv` 时装进 cv 仓 `.venv`；③manager 缺省找 cv 在 `/home/user/open-guji/open-guji-cv`，克隆在别处时用软链或设 `GUJI_CV_REPO`；④触发 proofing-sync 得 attach `kaiyuanguji-web` 且有 `gh`；⑤会话要有 `GUJI_DATA_TOKEN_PROD`／`_READ`、book-text 仓（`GUJI_BOOK_TEXT`）。缺哪样只在标 main 的输出里提示一行，不挡标 main。
- 不自动重出（只提示）：文本挂了标点／实体层的册、旧单已有票、还没有线上单、线上单没存 rev 包。这些走精校的 proof_cycle 或人工 `republish.py issue`。

## 二、令牌与密钥一览

只列**名字、用途、权限、放哪**。值由用户持有，发放走用户亲手设置，不经聊天转手。

### 1. 整理流程直接用的（会话里就要有）

| 名字 | 是什么 | 谁用 | 权限范围 | 放哪 |
|---|---|---|---|---|
| `GUJI_DATA_TOKEN_READ` | 中心库只读令牌 | 所有整理会话：`guji db pull`、读产物包、读票 | 只读（含 R2 原图／产物包）；默认发给会话 | Claude 云环境（Default）的环境变量 |
| `GUJI_DATA_TOKEN_PROD` | 中心库正式写令牌 | 推库、推产物包、标 main、重出线上单 | 读、写 main，传正式桶；**写前先报条数、等用户点头**（见各步骤文档） | 云环境变量 + 服务器上的控制台；不给无关会话 |
| `GUJI_DATA_TOKEN_EXP` | 中心库实验令牌 | 开 `exp/GUJI-…` 实验分支做会写库的 A/B | 读全部，写／开／删 `exp/*`，只能传实验桶；写不进 main | 云环境变量 |
| `GUJI_DATA_TOKEN` | cv／manager 实际读取的那个变量 | `guji db …`、`guji products …`、opinions 等 | 取决于它的值：用哪档令牌就是哪档权限 | 命令前现设：`GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_READ guji db pull …` |
| `GUJI_DATA_URL`／`GUJI_DATA_BRANCH` | 中心库 Worker 地址／当前分支 | 同上 | 非机密；`BRANCH` 缺省 main | 环境变量 |
| `NEON_DATABASE_URL` | 中心库 Postgres 连接串 | 要直连库的统计脚本（如待审统计，可用 `GUJI_DATA_PG_DSN` 代替）；会话里**读中心库不需要它** | 数据库级权限，比 Worker 令牌大得多 | 只放服务器 `~/.config/guji/neon.env`（600）；云会话尽量不放 |
| book-text 仓读写 | 文本仓（GitHub），`GUJI_BOOK_TEXT` 指向本地检出 | 精校／点校推文本，重出线上单读文本 | 取决于会话的 GitHub 授权（`add_repo` 时选 push 才能写） | 不是令牌：靠会话 `add_repo`，不另存 |

要点：

- 三档令牌的设计是「会话默认只拿读令牌；正式写令牌只给确实要写 main 的会话；实验令牌给试验分支」。Worker 会记审计（令牌名、时间、写了什么）。
- **环境变量面板不展开 `$`**：Default 环境里若把 `GUJI_DATA_TOKEN` 设成字面量 `$GUJI_DATA_TOKEN_PROD`，cv 会按引用展开；自己在 shell 里写命令时要自己展开。命令里的 `GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD` 如果复制自带 `$` 的面板文本，注意在你的 shell 里确实被展开了。
- 变量漏设、值与下一行粘连（例如 `PYTHONIOENCODING` 粘到下一行）会让 Python 整个起不来，改环境变量后先 `python -c pass` 试一下。
- manager 自检：`online_lists` 缺 `GUJI_DATA_TOKEN_PROD`／`_READ` 时只在标 main 的输出里提示一行，不挡标 main。
- 会话没有令牌时，先看这个 Project 是否选了云环境 Default（没选的话是空白内置环境，没有令牌也没有预装依赖）。

### 2. 其他环境变量（非机密，常用）

`GUJI_WORKSPACE`（工作区）、`GUJI_PRODUCTS_DIR`（产物包目录）、`GUJI_DATA_HOME`（本地中心库缓存）、`GUJI_BOOK_TEXT`、`GUJI_CV_REPO`、`GUJI_ACTOR`（写库时记的操作人）、`GUJI_AUTO_ONLINE_LISTS=0`（关自动重出线上单）、`GUJI_NO_REUSE=1`（强制不复用格级结果）。含义以各步骤文档与命令 `--help` 为准。

### 3. 网站／服务器／其他系统的密钥（整理会话一般用不到）

| 名字 | 是什么 | 谁管、放哪 |
|---|---|---|
| `GUJI_DATA_TOKEN_WEB` | 网站 Action 用的中心库令牌（读票、同步） | 用户在 GitHub 仓 secret 里设 |
| `GUJI_ANTHROPIC_API_KEY` | 调 Claude API 的密钥。open-guji-cv 的 `groups/ctx_llm`（文意 L3 在线判断）只从这个环境变量读；没有密钥就先查缓存，缓存没有则弃权（`abstain:no_api_key`） | 跑 L3 的云端会话；必须配成云环境（Default）的**环境变量**，放 Network secrets 程序读不到 |
| `OAUTH_CLIENTS`、`OAUTH_ID_TOKEN_SECRET`、`OAUTH_CODE_SECRET`、`AUTH_JWT_SECRET` | 正式站 OAuth（admin 登录）。`OAUTH_CLIENTS` 里只存 client secret 的 sha256；其余是服务端签名密钥 | 网站项目；经 kaiyuanguji-web 的「EdgeOne env sync」workflow 设到 EdgeOne，不进仓 |
| `GUJI_OAUTH_CLIENT_SECRET`、`GUJI_OAUTH_REDIRECT_URI`、`GUJI_SESSION_SECRET` | CV 控制台登录用的 OAuth 客户端与会话密钥 | 服务器 `~/.config/guji/console.env`（600） |
| `SEND_ROSTER_TOKEN` | 中转站（relay）发消息／花名册令牌 | 服务器 `/etc/claude-relay/env`；各 Project 另有 `CLAUDE_RELAY_TOKEN`；只在 ai-team 通信流程里用 |
| GitHub 令牌（打 tag、读私有仓、触发 workflow） | 例：给 cv 打版本标签、跑 `edgeone-env-sync` | 取自本机 `gh` 登录或会话的 GitHub 授权；`GH_TOKEN` 供脚本调 REST API |
| `NEON_API_KEY`、`CELLREVIEW_TOKEN`、`GUJI_API` | Neon 管理接口密钥；读网页投票 KV 的令牌；API 地址 | 部分在云环境变量，用途以对应项目为准 |

### 4. 规矩

- 令牌不进仓、不进 Jira、不进聊天。万一贴出，立刻告诉用户轮换。
- 用最小的一档：只读的事用 `_READ`，写 exp 用 `_EXP`，只有写 main 才用 `_PROD`。
- 写中心库、传 R2 要用户亲口同意（见 `精校`、`冷启动快审流程` 的写库步骤），不是令牌在手就能推。
- 新增或轮换令牌后，更新本页（只写名字与用途）。
